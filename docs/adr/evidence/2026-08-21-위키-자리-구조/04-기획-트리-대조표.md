## 4. `c_dasiro` 에 실제로 돌렸다 — 육안 2장

```
$ uv run python -m finnect.wiki --company c_dasiro --export /tmp/wiki-export
[c_dasiro] /tmp/wiki-export/c_dasiro 에 47장 썼어요
  채워진 자리 25 · 빈 자리 22
  접힌 자리 17 — 회사마다 개수가 다른 자리예요. 아직 한 장으로 모아 둬요
```

파일 47장이 떨어졌다. `TREE` 가 26을 채울 수 있다고 말하는데 실제로 25인 것은
`c_dasiro` 에 그 자리의 사실이 없어서다 — 표가 아니라 데이터다.

**두 장을 눈으로 읽었다**(`Company/회사소개.md` · `Custom/특허/특허.md`). 잘 된 것과
결함을 같이 적는다.

### 잘 된 것

`Company/회사소개.md` 가 value topic 일곱을 한 장에 모았고 **근거가 파일 여섯까지
매달렸다.** 상호 하나에 근거 여섯이다 — 문서 여섯이 같은 말을 하면 행 하나에 근거
여섯이라는 병합 규칙이 트리 뷰에서도 그대로 보인다. 소재지·업종은 `이전 값` 으로
접혔다.

### 결함 둘 — 둘 다 이미 알려진 것이다

**1. 접힌 자리가 같은 것을 여섯 번 적는다.** `Custom/특허/특허.md` 에 특허 하나가
문서 넷에서 각각 한 줄로 서고, 거기에 상표와 SW 저작권이 더 붙어 여섯 줄이다.
`fact_key` 로 안 묶여서 그렇다. **인스턴스로 갈리면 이 장은 셋이 되고 첫 장은 근거
넷이 매달린 한 줄이 된다** — 위 3절이 말한 컬럼이 그것을 푼다.

**2. 표 부스러기가 그대로 인용됐다.**

```
특허 출원	오프라인 환경에서의 재고 기록 동기화 방법 및 장치	2025. 08. 12.
```

탭이 살아 있는 표 한 줄이 노드 텍스트다. [plan/12](../../../plan/12-사업-위키-구축.md)
T-0078 이고 이 뷰가 만든 것이 아니다 — **다만 내보내기가 그것을 파일로 굳힌다.**

**원문 오타는 우리 것이 아니다** — `장2치` 는 `회사소개서_v3.pdf` 가 그렇게 쓴 것이고
추출기가 원문을 안 고친 결과다.
