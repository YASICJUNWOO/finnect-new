# 값 자리를 LLM 이 가른다 — 나린데이터로 끝까지 재 본 것

2026-08-23 · [plan/24](../../plan/24-양식을-채워서-돌려준다.md) T-0153 · T-0164 ·
[ADR-0060](../0060-양식을-채워서-원본-포맷으로-돌려준다.md) 결정 3 · 6

**같은 양식 한 장이다.** 코퍼스 전체가 아니고, 아래 숫자를 포맷 비율로 일반화할 수 없다.

```
회사   c_narin (나린데이터 · wiki_fact 140 · user_file 7)
양식   bizinfo:PBLN_000000000125460  2026년 서울창업허브M+ 글로벌 오픈 이노베이션 신청서
       sha e679598e… · hwp · 표 4 · 셀 65 · 빈 칸 6 · document 3365 · 항목 17
```

이 파일이 [ADR-0060](../0060-양식을-채워서-원본-포맷으로-돌려준다.md) 결정 3(hwp 덮어쓰기
불가)을 정한 바로 그 파일이고, [2026-08-23 덮어쓰기 실측](2026-08-23-hwp-덮어쓰기가-된다.md)
에서 사람이 손으로 채워 한/글로 확인한 파일이다. **그 손 작업이 이번 측정의 정답지다.**

## 1. 무엇이 막고 있었나 — 좌표 1 / 항목 17

기준선은 **채울 수 있는 칸이 하나**였다.

```bash
FORM_SLOTS=off  plant_anchors(notice=("bizinfo","PBLN_000000000125460"), redo=True)
→ 좌표를 심은 칸 1
```

| 항목 | 오른쪽 칸 | 왜 안 붙나 |
|---|---|---|
| 기업명 | `주식회사 ○○○○` | 빈 칸이 아니다 |
| 사업자등록번호 | `000-00-00000` | 빈 칸이 아니다 |
| 사업장주소 | `본점 (*본점이 …) 기재` | 빈 칸이 아니다 |
| 인력현황 | `총 (  ) 명` | 빈 칸이 아니다 |
| **실무자성명** | (빈칸) | **붙는다** |
| 매출액 | `2023년` | 열 머리다. 붙으면 안 된다 |
| 000백만원 | (빈칸) ×3 | 라벨이 겹친다 |

**막는 것이 둘이고 둘이 같이 풀려야 했다.** `Cell.blank` 가 플레이스홀더를 값 자리로
안 보고(T-0153), 보더라도 `HwpForm.fill` 이 글자 있는 칸을 거절했다(T-0164 · 결정 3).
하나만 풀면 아무것도 안 늘어난다.

### 딸려 나온 결함 — `redo` 가 틀린 좌표를 안 걷었다

기준선을 재려고 `redo=True` 를 돌렸는데 `사업자등록번호` 가 **`0:1:5:3` 을 계속 물고
있었다.** 그 좌표는 옛 규칙(「오른쪽 **첫 빈 칸**」)이 심은 것이고 그 칸은
**`법인등록번호` 의 값 자리**다. 새 규칙은 그 항목을 포기했는데 값이 남아서, 채우기가
사업자등록번호를 법인등록번호 칸에 넣는다 — [ADR-0060] 이후 `label_targets` 를 좁혀
막은 바로 그 사고가 **DB 에 남은 값으로 되살아나 있었다.**

`_plant_anchors` 가 `hit is not None` 일 때만 대입하고 지우지 않았다. 못 찾으면
`None` 을 쓰도록 고쳤다. **틀린 좌표는 없는 것보다 나쁘다** — 파일은 정상으로 열린다.

## 2. 값 자리 판정 — 재현율 100% · 정밀도 83~100%

`forms/slots.py` 가 표를 통째로 보여 주고 칸 번호로 답을 받는다. 정답지는 사람이
채운 26칸이고, 빈 칸 6개를 양쪽에서 빼면 **20칸**이 판정의 몫이다.

```bash
uv run python spike/form_slots_score.py     # 회차마다 1회 호출
```

| 회차 | 판정 | 맞음 | 빠뜨림 | 잘못 고름 | 재현율 | 정밀도 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 24 | 20 | 0 | 4 | 100% | 83.3% |
| 2 | 20 | 20 | 0 | 0 | 100% | 100% |
| 3 | 21 | 20 | 0 | 1 | 100% | 95.2% |
| 4 | 20 | 20 | 0 | 0 | 100% | 100% |
| 5 | 23 | 20 | 0 | 3 | 100% | 87.0% |

**재현율이 다섯 회차 전부 100% 다.** 빠뜨린 칸이 한 번도 없었다.

**정밀도가 회차마다 흔들린다.** 이 레포에서 이미 두 번 본 자리다(위키 추출 정확도가
같은 명령으로 60.2% · 58.5% 로 갈렸고, 같은 회사를 두 번 세우면 사실 수가 166 대 187
이었다). **n=5 로는 폭만 말할 수 있다.**

### 표를 깨뜨리는 칸 아홉은 다섯 회차 전부 걸렀다

틀리는 방향이 대칭이 아니다. 빠뜨리면 사용자가 손으로 옮기고, **잘못 고르면 열 머리가
값으로 덮여 원본 표가 지워진다.** 한 칸만 보면 값처럼 보이는 칸들이다.

```
2023년 · 2024년 · 2025년   매출액 행의 열 머리
국외                      국내/국외 열 머리
주요 투자처 · 누적 투자금액   투자 행의 열 머리
정 규 직                   인력현황 행의 열 머리
남 · 여                    동그라미 치는 보기
```

프롬프트가 「**나란한 칸을 같이 봐라**」와 「**확실하지 않으면 빼라**」를 말한다. 칸을
하나씩 묻지 않고 표를 통째로 싣는 이유가 이것이다.

### 오검출은 두 갈래뿐이었다

- **라벨 칸** — `법인등록번호` · `실무자성명` · `실무자직위`. 셋 다 **오른쪽이 빈 칸인
  라벨**이다
- **긴 안내 문구 칸** — 개인정보 동의서의 `0:3:0:0`. 이 칸을 가리키는 항목이 없어서
  결과에 안 닿는다

앞엣것이 실제 사고로 이어질 수 있었다.

```
사업자등록번호 | 000-00-00000 | 법인등록번호 | (빈칸)
                └ 값 자리      └ 값 자리로 오검출
```

`000-00-00000` 이 라벨로 읽히면 그것이 **`법인등록번호` 라는 라벨 글자를 값 자리로
잡는다.** 플레이스홀더가 항목 이름이 되는 일이 실제로 있어서(같은 양식의 `000백만원`)
그 짝이 걸리면 라벨이 값으로 덮인다.

`label_targets` 가 **값 자리 둘이 나란히 서면 짝을 안 만든다**로 막았다. 어느 쪽이
라벨인지 모르는 자리라 찍지 않는 것이다.

**오른쪽이 빈 칸이면 그 규칙을 안 건다.** 왼쪽이 오검출돼도 오른쪽의 빈 칸은 여전히 그
라벨의 자리이고, 거기까지 버리면 **오검출 하나가 좌표 둘을 잃게 만든다** —
`실무자성명 | (빈칸)` 이 그래서 살았다. 라벨 쪽을 통째로 좁혀 보니 좌표가 13 → 10 이었다.

대가는 짝 하나다. `5개사 내외 기재 | 000백만원` 이 둘 다 값 자리라 버려진다 — 그
왼쪽 글자는 항목 이름이 아니라 안내문이다.

## 3. 좌표 1 → 12

```bash
FORM_SLOTS=llm  plant_anchors(…, redo=True)
→ 좌표를 심은 칸 12 · LLM 이 넓힌 값 자리 20칸 · 호출 1회
```

| 항목 17개 | 좌표 | 왜 |
|---|---|---|
| 기업명 · 서비스명 · 대표자명 · 연락처 · 이메일 · 사업자등록번호 · 사업장주소 · 실무자성명 · 실무자연락처 · 인력현황 · 비정규직 · 기타실적 | **붙었다 12** | |
| 매출액 · 국내 · 투자 | 없다 | 오른쪽이 열 머리다. **판정이 맞게 걸렀다** |
| 000백만원 | 없다 | 라벨이 세 번 나와 겹친다 |
| 5개사 내외 기재 | 없다 | 값 자리 둘이 나란히 섰다 |

**빠진 다섯 중 넷이 「못 해서」가 아니라 「안 해서」다.** 남은 하나(`000백만원`)만
라벨 겹침이고, 그 표는 열 머리가 두 행 위에 있어서 라벨 짝으로는 구조적으로 못 닿는다.

### 판정은 흔들리는데 좌표 수는 안 흔들렸다

같은 명령을 네 번 돌렸다.

| 회차 | 넓힌 값 자리 | 좌표 |
|---:|---:|---:|
| 1 | 20 | 12 / 17 |
| 2 | 21 | 12 / 17 |
| 3 | 21 | 12 / 17 |
| 4 | 23 | 12 / 17 |

오검출이 늘어도 좌표가 안 늘었다. **오검출 세 갈래가 결과에 안 닿기 때문이다** —
오른쪽이 빈 칸인 라벨은 짝을 그대로 남기고(위 규칙), 값 자리 둘이 나란히 선 짝은
버려지고, 아무 항목도 안 가리키는 칸은 애초에 이름이 안 맞는다. **n=4 이고 양식
하나다** — 다른 양식에서도 그럴 근거는 없다.

## 4. 끝까지 — 파일에 들어간 칸 7

```bash
uv run python -m finnect.draft --company c_narin --notice bizinfo:PBLN_000000000125460 --redo
→ 항목 17 (썼음 9 · 쓸 자리 아님 4 · 배분에서 못 받음 4) · 호출 4회

fill_document(…) → 채움 7 · 거절 0 · 좌표없음 2
```

| 단계 | 수 | 빠진 이유 |
|---|---:|---|
| 항목 | 17 | |
| 좌표가 붙은 항목 | 12 | 위 3절 |
| 초안이 나온 항목 | 9 | `no_needs` 4 · `yielded` 4 (겹침 배분) |
| **둘 다 있는 항목** | **7** | |
| 파일에 들어간 칸 | **7** | **거절 0** |

**거절이 0 이다.** 채운 일곱 칸이 **전부 글자가 있던 칸**이라, 결정 3 대로면 일곱 다
거절돼서 **채움 0** 이었다.

```
0:1:0:1   주식회사 ○○○○              → 주식회사 나린데이터
0:1:1:1   OO기술이 적용된 OO기능의 …    → 나린데이터
0:1:2:1   공동·각자 대표의 경우 모두 기재 → 조민서
0:1:5:1   000-00-00000              → 105-88-21734
0:1:6:1   본점 (*본점이 …) 기재        → 서울특별시 성동구 아차산로17길 48, 4층
0:1:14:1  총 (  ) 명                 → 2명
0:1:16:1  수상 실적, 글로벌 진출 실적 등  → 정부지원사업에 선정된 이력이 없으며 …
```

되읽으면 **셀 65 · 문단 6** 으로 원본과 같고, 갈린 칸이 위 일곱뿐이다.

### 좌표는 있는데 초안이 없는 다섯

`연락처` · `이메일` · `실무자성명` · `실무자연락처` 가 `no_needs` 이고 `비정규직` 이
`yielded` 다. **여기는 양식 쪽이 아니라 `draft/needs.py`·`draft/allot.py` 다** —
`item_need` 의 자리 목록(매칭 정보 14 + 폴더 10)에 연락처와 이메일이 아예 없어서 그
항목이 필요한 자리를 못 고른다. 위키에 없는 값이라 그것이 맞는 동작이기도 하다.

## 5. 안 재 본 것

- **한/글 육안이 이 파일 하나다.** 제품 경로로 만든 파일은
  `~/Desktop/2026_서울창업허브M+_신청서_나린데이터_제품경로.hwp` 이고 표가 밀리는지는
  프로그램으로 안 잡힌다. 손으로 만든 판(같은 판본 I)은 확인했다
- **문단 덮어쓰기가 이 측정에 안 들어왔다.** 이 양식의 항목 17개가 전부 표 칸이라
  `ParaAnchor` 경로를 안 밟았다. 손 작업에서는 서명란 넷이 그 경로였고 됐다
- **개체 앵커가 든 문단은 여전히 미지수다.** `_has_object_anchor` 가 거절하는 것으로
  피했을 뿐 채워 본 적이 없다
- **양식 하나다.** 코퍼스 334개에 돌리면 호출이 그만큼 들고, 열 머리가 다르게 생긴
  양식에서 정밀도가 어떻게 되는지 모른다
- **미리보기가 빠진다.** 67,584 → 14,336 바이트이고 `_prv_text` 를 부르는 자리가
  **처음부터 없었다**(`save` 의 주석이 있다고 적어 두고 있었다). 본문 손실은 아니다

## 6. 딸려 나온 품질 문제 둘 — 양식 쪽이 아니다

- `서비스명` 칸에 `나린데이터` 가 들어갔다. 물은 것은 서비스 설명(`OO기술이 적용된
  OO기능의 OO제품·서비스`)인데 회사 이름을 썼다
- `인력현황` 이 `총 (  ) 명` → `2명` 이 되어 **양식이 준 형식이 사라졌다.** 값만 넣고
  틀은 남기는 규칙이 없다

둘 다 `draft/write.py` 와 `draft/allot.py` 의 것이다.
