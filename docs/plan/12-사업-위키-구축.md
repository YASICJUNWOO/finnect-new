## 목표

사용자가 파일 뭉치를 통째로 올리면 이렇게 된다.

```
올린 것 5개 · 완료 4 · 실패 1

  ✓ 2025_초기창업패키지_사업계획서.hwp    노드 9개
  ✓ 회사소개서_v3.docx                    노드 6개
  ✓ 재무제표_2025.xlsx                    노드 3개
  ✓ 사업자등록증.jpg                      노드 4개
  ✗ 피치덱.key                            읽을 수 없는 형식이에요

─────────────────────────────────
 솔루션과 기술
 재고관리 자동화 소프트웨어

 바코드와 QR로 입출고 기록을 자동으로 남긴다.

 근거 2                          ← 펼치면 원문 조각이 그 자리에서 열린다
 ▸ 2025_초기창업패키지_사업계획서.hwp  12쪽
 ▸ 회사소개서_v3.docx                 4쪽
─────────────────────────────────
```

**노드에서 원문이 열리는 것까지가 이 계획이다.** 열리지 않으면 F6 집필이 값만 들고 문단을 쓰게 되고, 그러면 모델이 나머지를 지어낸다([ADR-0014](../adr/0014-통합-그래프와-근거-청크.md)).

**여기 없는 것** — 위키 관리 화면(F1-4) · 정리 제안(F1-5) · 내보내기(F1-6) · 집필에서의 적립(F1-7). 넷 다 위키가 선 다음의 것이다.

## 구상도와의 차이

2026-08-18 전체 구상도를 받았다. **①~⑤(업로드 → 파싱 → 청킹 → 사실 추출 → 결정론적 라우팅)는 그대로 쓴다.** 아래만 다르게 간다.

> 전사본이 [evidence](../adr/evidence/2026-08-18-전체-구상도.md)에 있다. **원본 이미지는 아직 없다** — 대화로 받은 것이라 파일을 꺼낼 수 없었다.

| | 구상도 | 이 계획 | 왜 |
|---|---|---|---|
| 원본 청크 | 저장소 목록(A~E)에 **없다.** 검색 대상이 `Wiki Chunk` | **저장한다.** 노드는 값 대신 청크 주소를 든다 | 요약을 두 번 거치면 집필이 원문을 못 본다. [ADR-0014](../adr/0014-통합-그래프와-근거-청크.md)가 "값만 들고 문단을 쓰면 모델이 나머지를 지어낸다"고 적은 자리 |
| 위키 마크다운 | ⑥이 만들고 ⑦이 SQL로도 저장 | **저장소가 아니라 뷰.** 내보내기(F1-6)에서 만든다 | 이중 저장은 `SPEC.md` §2-1의 "소스가 갈라지면 불일치가 생긴다" |
| 벡터 DB | ⑧⑨에서 바로 붙인다 | **안 붙인다.** [ADR-0021](../adr/0021-인프라-선정을-미룬다.md) A·F가 "PostgreSQL로 되는지부터", "RAG는 F6에서" | 회사당 노드 열다섯에 의미 검색을 붙이면 top-k가 근거를 조용히 놓친다. 벡터가 필요한 쪽은 공고 31,327건이다 |
| `confidence` | 사실마다 0.9 | **안 쓴다.** 근거 청크 유무 · `source_type` · 충돌 여부 셋으로 대신한다 | 0.9와 0.7을 가를 눈금이 없다. 배점 탐지기가 30%→45%→25%로 간 것과 같은 실패다. `DESIGN.md` §4.1이 이미 거절했다 |
| 이벤트 계열 | `meeting` · `decision` · `action_item` · `application_history` | **`application_history`만.** 그것도 이벤트가 아니라 자격 판별 입력으로 | 앞의 셋은 사업계획서·IR·재무제표에서 안 나온다. 도면이 스스로 적은 `선형 증가`가 F1-4의 "노드가 열다섯이라 검색이 필요 없다"를 첫날부터 깬다 |
| topic 26개 | 화면의 단위 | **추출 라벨로만 쓴다.** ⑤가 `SPEC.md` F1-2의 열다섯으로 모은다 | 라벨은 세밀할수록 좋고 노드는 집필 단위와 맞아야 한다. `DESIGN.md` §4.1의 노드 분류색 셋과 [ADR-0017](../adr/0017-위키-그래프-궤도-배치.md)이 열다섯 위에 서 있다 |
| 지원 파일 | HWP가 **없다** | 넣는다 | 정부·창업판 사업계획서의 중심이고 파서가 이미 있다 |
| 노드 간 연결 | 없다 | 넣는다 (F1-1-6) | [ADR-0017](../adr/0017-위키-그래프-궤도-배치.md)과 F1-4-1·F1-4-4가 이 위에 선다 |

## 태스크

### T-0041 사용자 파일을 어디에 두고 어떻게 가르나

> **완료** (2026-08-18) — [ADR-0029](../adr/0029-사용자-파일을-회사-단위-콘텐츠-주소로-로컬에-둔다.md).
> `data/user-files/<company_id>/<sha256[:2]>/<sha256>` · 격리는 경로에서 · **회사 사이 중복 제거를 안 한다** · 저장 인터페이스 한 겹이 되돌리는 장치다.

**[ADR-0021](../adr/0021-인프라-선정을-미룬다.md)이 A(저장소)와 H(격리)를 여기서 함께 정하라고 지정했다.** "나눠서 정할 수 없다"고 적혀 있다.

- 정할 것: 원본을 로컬에 둘지 오브젝트 스토리지에 둘지 · `company_id` 격리를 어느 층에서 거는지 · 보관과 삭제
- **[ADR-0022](../adr/0022-첨부-원본을-콘텐츠-주소로-로컬에-둔다.md)를 그대로 못 쓴다.** 공고 첨부는 공개 파일이고 사용자 파일은 사업자등록증과 재무제표다
- ~~**[ADR-0026](../adr/0026-읽기-경로만-vercel에-올린다.md)이 걸린다.**~~ **로컬로 정했다.** 배포본에서 업로드가 안 되고 시연을 로컬에서 한다 — 그 대가를 받았다
- **콘텐츠 주소와 격리가 부딪힌다.** 중복 업로드를 막으려면 `sha256` 이 키여야 하는데([픽스처 README](../../tests/fixtures/wiki/README.md) 함정 1), **두 회사가 같은 파일을 올리면 해시가 같다** — 정부 양식이나 표준 서식이면 실제로 그렇다. 한 원본을 둘이 공유하게 되고 한쪽이 탈퇴하면 무엇을 지우는가. 첨부에는 없던 문제다([ADR-0022](../adr/0022-첨부-원본을-콘텐츠-주소로-로컬에-둔다.md))
- 완료 조건: **ADR 한 편.** 코드보다 결정이 먼저다

### T-0042 못 읽는 포맷 셋 — XLSX · PPTX · 이미지

> [T-0007](00-미결-해소.md#t-0007-스캔-pdf-처리-판단)을 여기서 닫는다. **OCR로 가는 것은 이미 정해졌고** 남은 것은 엔진과 범위다.

- 건드리는 파일: `src/finnect/attach/formats.py` · `extract.py`
- **XLSX는 표 구조와 셀 좌표를 보존한다.** 뭉개면 연도-항목-값 대응이 깨진다(`SPEC.md` F1-1-3)
- **이미지 OCR이 자격 판별의 입력을 만든다.** 사업자등록증이 거의 사진이고, 위키의 사업체 정보 다섯 중 넷이 거기서 나온다
- 후보 279건이 [실측](../adr/evidence/2026-08-17-첨부-해독-실측.md)에 있다. 엔진 선정은 ADR로 남긴다
- **이 태스크의 크기가 코퍼스에 그대로 보인다** — [`tests/fixtures/wiki/`](../../tests/fixtures/wiki/README.md) 일곱 건 중 **넷을 못 읽는다.** XLSX·PPTX·JPG 가 `unsupported`, 스캔 PDF 가 `empty` 다

### T-0043 청크 계층 — 원문 조각을 저장한다

> **완료** (2026-08-18). 픽스처 7건 중 읽히는 3건에서 **청크 18개**가 나왔고 그중 6개가 쪽 번호를 들고 있다.
> `src/finnect/wiki/{storage,chunk,service}.py` · `user_file` · `chunk` · 마이그레이션 `d31b958915ca`.
>
> **완료 조건을 고쳤다.** 원래 "각 청크가 **쪽 번호**를 들고 있다"였는데 **HWPX·DOCX 에는 쪽이라는 것이 없다.** 없는 번호를 만들어 붙이면 근거가 거짓이 되므로, 항상 있는 것은 문자 좌표이고 쪽은 PDF 만 찬다.

**구상도가 빠뜨린 자리이자 이 계획의 축이다.**

- `Document`(올린 파일) → `Chunk`(원문 조각 + 위치정보) 두 층
- **위치정보는 파싱할 때만 심을 수 있다.** 나중에 붙이는 것은 불가능하다([ADR-0014](../adr/0014-통합-그래프와-근거-청크.md))
- ~~**이름이 이미 쓰였다.**~~ **`UserFile` 로 풀었다.** `Document` 는 공고 첨부 안의 구간이 쓰고 있고([plan/11 T-0038](11-작성-항목-추출과-표시.md#t-0038-저장-모델)) 그 표에는 배포 DB 에 데이터가 있다. 개념은 [ADR-0014](../adr/0014-통합-그래프와-근거-청크.md) 그대로이고 이름만 다르다
- 중복은 청크 내용 해시로 막는다 — 같은 파일을 다시 올려도 안 쌓인다
- 완료 조건: 파일 하나를 넣으면 청크가 나오고 **각 청크를 원문에서 그대로 잘라낼 수 있다**(`text == full[char_start:char_end]`). 쪽 번호는 PDF 만

### T-0044 위키가 담을 것을 확정한다 — 정형 슬롯과 서술 노드

**코퍼스를 보고 쓴다.** CLAUDE.md가 "계층별 상세 사양(노드 스키마…)은 코퍼스를 보고 나서 쓴다"고 정했고, 실제 사업계획서 몇 편을 넣어 보기 전에는 열다섯이 맞는지 모른다.

두 층으로 가른다. **병합 키가 다르기 때문이다.**

| | 무엇 | 키 | 충돌 |
|---|---|---|---|
| **정형 슬롯** | 사업자등록번호 · 사업자등록일 · 소재지 · 업종 · 대표자 생년월일 · 직원 수 | **슬롯 이름** | 값이 다르면 충돌 |
| **서술 노드** | 문제 인식 · 솔루션과 기술 · 목표 고객 · 시장과 경쟁 · 지역 연계 · 매출과 성과 · 팀 구성 · 로드맵 · 자금 현황 | **없다.** 근거 청크를 쌓기만 한다 | 다른 말을 하는 청크가 나란히 매달림 |

- **`SPEC.md` F1-2가 이미 이 선을 그었다** — 정형(M1 자격 판별 입력) 다섯 대 서술(M2·G 입력) 아홉. 판정에 쓰냐 집필에 쓰냐로 나눈 선인데 병합 키의 선과 같은 자리에 떨어졌다
- **`competitor`처럼 여럿이 정상인 것은 upsert가 성립하지 않는다.** "customer_problem을 덮어써라"는 무엇을 덮을지 말하지 않는다
- **업력과 만 나이는 저장하지 않고 계산한다.** 공고마다 기준일이 다르다
- 완료 조건: 슬롯 목록 확정 + 서술 노드 목록 확정 + **ADR 한 편**([ADR-0021](../adr/0021-인프라-선정을-미룬다.md) E)
- 시험 입력은 [`tests/fixtures/wiki/`](../../tests/fixtures/wiki/README.md)다. **직원 수가 넷 다 다른 이름으로 네 시점에 있고**(상시 근로자 7 · 종업원 8 · 구성원 10 · 임직원 15) 슬롯 하나로 모여야 한다

### T-0045 사실 추출과 결정론적 라우팅

> **선행이 하나 걸려 있다.** LLM 제공자가 아직 안 정해졌다. [plan/11 T-0036](11-작성-항목-추출과-표시.md#t-0036-양식-구간-판별--llm을-처음-부른다)이 먼저 부르기로 돼 있고 지금 보류다. **둘 중 먼저 착수하는 쪽이 정한다**([ADR-0021](../adr/0021-인프라-선정을-미룬다.md) G).

- LLM은 **라벨만 붙인다** — `topic` · 근거 청크 주소. 목적지는 안 정한다
- 목적지는 **사람이 만든 표**가 정한다. LLM이 정하면 같은 사실이 어제는 A, 오늘은 B로 가서 위키가 돌릴 때마다 달라진다
- 고정 topic 밖은 버리지 않고 `uncategorized`로 세운다
- 완료 조건: 같은 파일을 두 번 넣으면 **같은 노드 배치**가 나온다

### T-0046 병합과 충돌

- 정형 슬롯: 값이 다르면 **둘 다 보관하고 상태를 붙인다**(F1-1-7). 지우지 않는다
- 서술 노드: 합치지 않고 근거를 쌓는다
- **`source_type`을 여기서 심는다** — `document` · `user_stated`([ADR-0028](../adr/0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md) 5번). F1-7이 붙기 전에 자리가 있어야 나중에 데이터를 다시 안 만든다
- **문서가 `user_stated`를 자동으로 덮지 않는다**
- 완료 조건 둘. **시드 금액 3억(사업계획서·재무제표)과 2.8억(피치덱)은 충돌로 선다.** 반면 **직원 수 7→8→10→15는 충돌이 아니다** — 시점이 다른 시계열이라 충돌로 세우면 오탐이다. 코퍼스가 둘을 나란히 들고 있다

> 픽스처 7건을 한 번에 넣으면 **3건이 청크까지 가고 4건이 이유와 함께 남는다.** 조용한 누락은 0건이다.

- 상태가 파일 단위로 돈다 — `uploaded → parsing → extracting → linking → needs_review / done / failed`
- **전체를 한 트랜잭션으로 묶지 않는다.** 다섯 중 하나가 실패해도 넷으로 위키가 선다
- 병렬로 돌리면 ⑤에서 같은 노드를 동시에 건드린다. **서술 노드는 추가만 하니 순서가 상관없고**, 정형 슬롯만 잠그면 된다
- 완료 조건: 읽을 수 없는 파일을 섞어 넣어도 나머지가 청크를 만들고, 실패한 것이 이유와 함께 남는다
- **`unsupported` 와 `empty` 를 다르게 다룬다.** 포맷이 없는 것은 `failed`, 글자가 안 나온 스캔본은 `needs_review` 다 — 후자는 OCR 이 붙으면 읽힌다(T-0042)

## 순서와 이유

```
T-0041 (저장·격리)  ─┐
                     ├─▶ T-0043 (청크) ─▶ T-0045 (추출·라우팅) ─▶ T-0046 (병합)
T-0042 (포맷 셋)    ─┘         ▲                    ▲
                               │                    │
                        T-0044 (담을 것) ───────────┘

T-0047 (실패 설계) — T-0043부터 같이 간다. 나중에 붙이면 파이프라인을 다시 짠다
```

**T-0041이 맨 앞인 이유**는 파일을 어디 둘지 정하기 전에는 받을 수가 없어서다. **T-0044가 T-0045의 선행인 이유**는 목적지 표가 없으면 라우팅이 성립하지 않아서다.

**T-0042는 T-0043과 나란히 갈 수 있다.** HWP·DOCX·PDF만으로도 청크 계층은 검증된다.

## 검증

**T-0041 · T-0043 · T-0047 은 실행 가능하다.** 나머지 넷은 아직 명령이 없다 — 지어내지 않는다.

```bash
docker compose up -d db && uv run alembic upgrade head
uv run python -m finnect.wiki --company c_dasiro tests/fixtures/wiki/*
```

2026-08-18 실측이다.

```
[올린 것 7개] c_dasiro
  청크까지 됨   3      이미 있음 0      검토 대기 1      실패 3      청크 18개

  [못 읽은 것]
    재무제표_2025.xlsx        —  unsupported
    피치덱_2026H2.pptx        —  unsupported
    현장사진_파일럿매장.jpg   —  unsupported
    사업자등록증_스캔.pdf     —  empty

[c_dasiro 현황]
  chunked          3건   청크   18개
  needs_review     1건   청크    0개
  failed           3건   청크    0개
  합계             청크 18개 · 그중 쪽 번호 있는 것 6개
```

| # | 무엇 | 어떻게 확인하나 | 결과 |
|---|------|----------------|------|
| 1 | **좌표가 원문과 일치한다** | 청크 전부에 `text == full[char_start:char_end]` | 18/18 |
| 2 | **쪽 번호는 PDF 만 찬다** | HWPX·DOCX 청크의 `page` 가 NULL | 12/12 NULL · PDF 6/6 채움 |
| 3 | **쪽 경계를 넘지 않는다** | 청크가 두 쪽에 걸치지 않는다 | 위반 0 |
| 4 | **하나가 실패해도 완주한다** | 읽을 수 없는 4건을 섞어도 3건이 청크까지 | 통과. 조용한 누락 0 |
| 5 | **재업로드가 청크를 늘리지 않는다** | 같은 파일을 다시 넣으면 `duplicate` | 통과 |
| 6 | **다른 회사 것이 안 보인다** | A사 해시로 B사 조회 — DB·파일·청크 전부 0 | 통과 |
| 7 | **경로 탈출이 막힌다** | `../../etc` · `a/b` · 빈 문자열 | `IsolationError` |
| 8 | **탈퇴가 남의 것을 안 지운다** | 같은 파일을 가진 두 회사 중 하나만 purge | 통과 |

```bash
uv run pytest -q            # 152 passed (위키 24건 추가)
uv run ruff check src tests # All checks passed
```

**아직 못 재는 것.** 2·3번이 XLSX 표 좌표를 안 덮는다(T-0042). 4번의 `needs_review` 1건은 OCR 이 붙어야 청크가 난다. 온톨로지가 맞는지는 T-0044 이고 실물 문서를 기다린다.

## 위험

- **T-0044의 코퍼스가 절반만 있다.** 2026-08-18 합성 코퍼스 일곱 건을 만들었다 — [`tests/fixtures/wiki/`](../../tests/fixtures/wiki/README.md). 병합·충돌·실패를 열 군데 심어 뒀고 기대값이 그 README에 있다. **다만 합성이라 못 재는 것이 셋이다** — 실물 HWP 의 문단·표 경계 손실, 회사 둘 이상의 격리, 실제 스캔 품질. **실물 사업계획서를 구하는 일은 여전히 남아 있다**
- **LLM 제공자 미정이 T-0045를 막는다.** [plan/11 T-0036](11-작성-항목-추출과-표시.md#t-0036-양식-구간-판별--llm을-처음-부른다)과 같은 블로커를 공유한다
- **`양식 항목 → 노드 매핑`이 어느 계획에도 없다.** [ADR-0028](../adr/0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md)이 이걸 필수로 만들었는데 plan/11은 양식 쪽만, plan/12는 노드 쪽만 만든다. **둘을 잇는 계획이 따로 필요하다**
- ~~**T-0041에서 로컬을 고르면**~~ **로컬로 정했다**([ADR-0029](../adr/0029-사용자-파일을-회사-단위-콘텐츠-주소로-로컬에-둔다.md)). **시연을 배포 URL 에서 하기로 바뀌면 이 결정을 다시 본다** — 인터페이스가 있어 구현 한 벌을 더하는 일이지만 개인정보 이관 정책을 새로 써야 한다
- ~~**픽스처에 회사가 하나뿐이라 격리를 시험할 수 없다.**~~ **해소** — 같은 파일을 두 회사 이름으로 넣는 테스트로 덮었다(`tests/test_wiki_service.py`). 다만 **회사별로 내용이 다른 코퍼스는 여전히 없다** — 위키가 섞이는지는 T-0044 이후에 다시 본다
