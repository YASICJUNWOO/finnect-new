# 랜딩 — 같은 말을 여섯 가지로 놓는다

`docs/adr/evidence/2026-08-16-v2-기획문서/demo_from_hwi.html` 의 `#s-home`(현행 랜딩)을 대조군으로 두고
**시안 다섯**을 나란히 놓는 자리다.

```
open index.html      # 나란히 — 축소 프리뷰 · 논지 · 대가 · 실측
open switch.html     # 실제 크기로 갈아끼우기
```

각 화면 하단의 검은 바는 **목업 전용이다.** 코드로 옮길 때는 바를 빼고 `값 내보내기` 로 뽑은 값만 전사한다.

---

## 갈리는 것과 안 갈리는 것

**카피는 여섯 다 같다.** 시연의 말을 한 글자도 바꾸지 않았고 `copy.js` 한 곳에서 온다 —
시안마다 길이가 달라지면 밀도 비교가 통째로 깨진다.

**축을 하나로 묶지 않았다**(사용자 지시). 그래서 서체·명도·구조·동작이 시안마다 함께 움직인다.
비교 하네스의 기본 규칙("한 축만 갈라라")을 일부러 어긴 것이라, 대신 **무엇이 갈렸는지를 카드마다 적었다.**

| | 성격 | 서체 | 명도 | 구조 | 예외 |
|---|---|---|---|---|---|
| 현행 | 회색 캔버스 + 흰 카드 | Pretendard | 밝음 | 카드 반복 | — |
| **B 관제** | 데이터 규모 | IBM Plex Sans KR | **어두움** | 캔버스 점 밭 | 카피 한 줄 더 |
| **C 던지기** | 시켜 보기 | Pretendard | 밝은 회색 | 드롭존이 첫 화면 | `how` 절 없음 |
| **D 면** | 장(章)으로 읽기 | Gothic A1 900 | **면마다 뒤집힘** | 색면 교대 | — |
| **E 조립** | 기계장치 | Pretendard (제품 토큰) | 밝음 | 히어로에 조립 모션 | — |
| **F 현행+** | 현행 + 살아남은 셋 | Pretendard | 밝음 | 현행 뼈대 + 드롭존 | 모션이 **반복** |

**B 만 카피가 한 줄 더 있다.** 점 밭 밑의 건수 캡션(`31,327 · 1,538 · 29,789`)이다.
숫자가 없으면 점 3만 개가 근거가 아니라 장식이 된다(`DESIGN.md` §5.3 S9).
값의 출처는 `CLAUDE.md` 와 [plan/06](../../../plan/06-목록-수집과-조회.md).
**밀도를 비교할 때 이 한 줄을 감안해야 한다.**

**C 만 `how` 절이 따로 없다.** 「세 단계로 끝나요」 카피가 드롭존 안에서 동작으로 산다.
그래서 C 의 `크기 종류`·`최장 줄` 은 **쉬는 얼굴 기준**이고, 던진 뒤에는 값이 달라진다.

### F 현행+ 는 합본이다

피드백에서 살아남은 셋을 현행 뼈대에 붙인 것이다 — **C 의 드롭존과 데모 토글 · E 의 조립 애니메이션 ·
E 의 포인트 색**(노드 분류색 셋. §3-7 이 허락한 자리).

**셋을 따로 얹지 않았다.** 드롭존 안에서 조립이 일어난다 — C 는 "던지면 된다"를 말하고
E 는 "던지면 이렇게 된다"를 말하는데, 나란히 두면 같은 말을 두 번 하는 화면이 된다.
그리고 그 동작이 아래 「세 단계로 끝나요」 카드 셋을 **각 노드와 같은 색으로** 켠다 —
카피를 한 벌 더 쓰지 않고 현행의 구조를 그대로 쓴다.

**모션이 반복된다**(요청). E 조립은 한 번 돌고 눌러야 다시 돈다 — 거기가 다른 자리다.
타이머 체인이 아니라 **CSS 한 사이클(`--cycle`)로 묶었다.** 칩 여섯·노드 여섯·연결선 다섯·카드 셋이
각자 `setTimeout` 으로 돌면 반복할수록 위상이 어긋난다.

```
   0 –  800ms   칩이 날아 들어간다
 600 – 1000ms   노드가 켜진다
1000 – 1400ms   연결선이 그려진다
1400 – 2500ms   조립된 채로 머문다
2600 – 3000ms   흩어진다
3200 – 3400ms   칩이 제자리로 돌아온다 → 다시
```

**처음엔 5200ms 에 머무름을 2.5초로 잡았다가 줄였다.** 조립이 끝나고 다시 시작할 때까지
3.3초가 죽어 있어서 "멈춘 그림"으로 읽혔다. 조립이 논지인데 그 논지가 화면에 없는 시간이 길면 안 된다.
지금은 2.0초이고 그중 의미 있는 머무름이 1.1초다. 하네스의 `한 바퀴` 로 조절해 볼 수 있다.

### 대조군에 손댄 자리 하나

**`word-break:keep-all` 을 여섯 다 켰다.** 시연에는 없어서 한글이 어절 중간에서 잘린다 —
"정보로 / 정리하고", "파일마 / 다 값이", "문서 / 가 이미".

시안 다섯에만 켜면 현행이 **비교 축과 무관한 이유로** 나빠 보이고,
여섯 다 끄면 여섯 다 같은 이유로 망가져 줄길이·밀도 실측이 못 쓴 값이 된다.
**이것이 현행을 고친 유일한 자리다.** 그리고 **제품 코드(`web/`)에도 없다 — 따로 고쳐야 한다.**

## 버려진 시안 둘

**`A 접수증` — 피드백에서 폐기.** 서류 한 장의 어법이었다(문서 메타 열 · § 항목 · 붉은 도장 · 괘선).
파일도 지웠다.

**`C 여백` — 에디토리얼이라 버렸다.** 고대비 명조(Hahmlet) 디스플레이 · 단 하나짜리 좁은 본문 ·
아주 큰 여백 · 밑줄 하나짜리 CTA.

실측이 대가를 숫자로 보여 줬다 — **화면 세로 3,654px(현행의 1.9배)** 에 **CTA 가 687px**.
랜딩의 일은 읽게 만드는 것이 아니라 정하게 만드는 것이다(`DESIGN.md` §2-3).

금지를 `DESIGN.md` §5.1-7 과 [ADR-0040](../../../adr/0040-에디토리얼-지면형-방향을-쓰지-않는다.md)에 올렸다.
**명조 자체를 금지하는 것이 아니라 다섯 판정 중 둘이 모이는 것을 금지한다.**
같은 판정으로 `A 접수증` 의 서체를 명조에서 고딕으로 내렸었는데, 그 시안 자체가 폐기됐다.

| B 관제 | 54 | 6.42:1 | 0 |
| C 던지기 | 36 | 5.15:1 | 0 |
| D 면 | 45 | 3.31:1 | 0 |
| E 조립 | 44 | 5.01:1 | 0 |

- **미달 7건이 전부 현행이고 전부 같은 색이다** — `--ink-3` `#949aa2` 2.65:1.
  「세 단계로 끝나요」·「안 하는 것도 밝혀 둘게요」 절 제목, `01/02/03`, 푸터, 「가입 없이 해 볼 수 있어요」.
  **시안과 무관한 기존 제품 문제다** — [위키 그래프 시안](../wiki-graph/README.md)에서도 같은 색이 걸렸다.
- **D 면의 거대 숫자가 처음에 2.11:1 이었다.** 불투명도 0.28 로 흐려 놨는데 86px 큰 글자 기준이 3:1 이다.
  0.46 으로 올려 3.31:1 을 만들었다. **상록 면(`--forest`)을 더 밝히면 다시 재야 한다.**
- **B 히어로의 글자는 "못 잼" 으로 빠진다.** 뒤에 캔버스와 그라데이션 막이 깔려 배경색이 픽셀마다 다르다.
  **조용히 빼지 않고 따로 찍는다** — 빼면 통과한 것처럼 보인다. 눈으로 확인해야 한다.

### 이 스크립트가 한 번 거짓말을 했다

처음엔 **한글 표본**의 폭으로 판별했다. 그래서 IBM Plex Sans KR 의 300·400·600 이 "같은 face" 로 나왔고,
그 말을 믿고 **B 관제의 굵기 위계를 400/500/700 으로 줄였다. 틀렸다.**

```
IBM Plex Sans KR 40px 실측
  한글  400: 187.84   500: 186.77   700: 187.84   ← 400 과 700 이 같다
  라틴  400: 250.38   500: 255.73   700: 262.89   ← 셋 다 다르다
```

한글 글자는 굵기가 달라져도 advance 가 거의 고정이다. **획은 실제로 굵어지는데 폭이 안 변한다.**
`document.fonts` 를 열어 보니 세 face 다 정상 로드돼 있었다.
**B 를 원래 위계(300/400/500/600)로 되돌리고 프로브를 라틴 표본으로 고쳤다.**
등폭 폰트도 같은 이유로 판정에서 뺀다. 지금은 문제 0건이다.

- **등폭에 한글을 넣지 않는다.** IBM Plex Mono 를 한글에 쓰면 대체 서체로 떨어져
  자간이 벌어진 채 렌더된다. B 를 그렇게 만들었다가 고쳤다 — **등폭은 숫자와 라틴에만 쓴다.**

## 고를 때 걸리는 것

| | 어기는 것 |
|---|---|
| B 관제 | **§3-1 라이트로 간다** — 화면 전부의 명도 방향을 다시 정하는 결정이다. ADR 이 필요하다 |
| C 던지기 | 없음. 다만 **데모가 진짜 진행에 안 물리면 화면이 거짓말을 한다** |
| D 면 | **§3-7 색은 위키 그래프와 문서 빈칸에만** · §4.2 굵기 셋(900 을 쓴다) · §3-4 주 버튼은 근검정(면마다 반전된다) |
| E 조립 | 없음 |
| F 현행+ | 없음. 다만 C 와 같은 조건이 붙고, **반복 모션을 언제 멈출지**를 정해야 한다 |

- **C·F 의 대가는 코드에 있다.** 목업은 파일을 실제로 읽지 않고 데모만 돌린다.
  전사하려면 [plan/15](../../../plan/15-파일-올리기와-진행-표시.md)의 `/wiki/files` 진행 상태에 물려야 한다.
  **가짜 진행 막대를 남겨 두면 안 된다.**
- **F 의 반복 모션은 첫 화면에 있다.** 스크롤해도 시야 가장자리에 남는다.
  오래 보는 화면에서 피로하므로, 고르면 **몇 바퀴 뒤 멈출지**를 같이 정해야 한다.
  `prefers-reduced-motion` 에서는 조립된 상태로 선다.
- **E·F 의 논지는 정지 화면에서 안 보인다.** 스크린샷·인쇄에서 조립이 안 돈다.
  고르면 **정지 상태만으로도 말이 되는지**를 따로 봐야 한다.
- **B·D 는 서체를 한 벌 더 들인다.** `DESIGN.md` §4.2 가 "서체를 나누지 않는다"고 이미 판단했다 —
  **고르면 그 판단을 뒤집는 것이다.**

## 만들다 잡은 것

- **한글 줄바꿈을 여섯 다 놓치고 있었다.** `word-break:keep-all` 이 없으면 어절 중간에서 잘린다.
  코드만 읽어서는 안 보이고 **스크린샷으로만 잡혔다**(`DESIGN.md` §9). 시연도 제품 코드도 이게 없다.
- **폰트 프로브가 한글로 재서 틀린 답을 줬다.** 위 `이 스크립트가 한 번 거짓말을 했다`.
  **검증 도구도 검증해야 한다** — 이건 스크린샷으로도 안 잡히고 도구를 의심해야 잡힌다.
- **줄길이를 두 번 잘못 쟀다.** 처음엔 canvas 의 `"0"` 폭으로 나눴는데 한글은 그 두 배쯤 되는 전각이라
  값이 두 배로 부풀었다(114자·160자). 지금은 `Range.getClientRects()` 로 실제 렌더된 줄을 받아 평균을 낸다.
- **본문 최소를 처음엔 모든 글자에서 쟀다.** 배지 안의 11px 숫자가 잡혀 여섯이 전부 "본문 11px" 로 나왔다.
  본문은 산문이다 — 제 텍스트가 25자 넘는 요소만 본다.
- **숨은 요소가 '채운 버튼' 으로 세어졌다.** C 던지기의 완료 화면 버튼은 부모가 `display:none` 이라
  제 `display` 는 살아 있다. 크기로 거른다.
- **D 면의 제목을 104px 로 세웠다가 76px 로 내렸다.** 다섯 줄로 흘러 히어로를 통째로 먹었고
  오른쪽 아래에 앉히려던 설명이 첫 화면 밖으로 밀렸다. CTA 가 737 → 533px 로 올라왔다.
- **F 의 반복 주기를 5200ms 에서 3400ms 로 줄였다.** 머무름이 2.5초라 조립이 끝나고 다시 시작할 때까지
  3.3초가 죽어 있었고, 그 사이에는 "멈춘 그림"으로 읽혔다.
