# ADR-0065: 수집 실행을 배포 API 에 연다 — ADR-0027 의 "안 옮긴 것"을 옮긴다

- 상태: 채택됨
- 날짜: 2026-08-24
- 뒤집는 것: [ADR-0027](0027-운영-화면을-nextjs로-옮긴다.md)의 **"`POST /ingest/run/{source}` 는 안 옮긴다" 한 줄만.** 조회 넷을 Next.js 로 옮긴 결정은 그대로다
- 근거: [ADR-0035](0035-api와-워커를-자체-서버로-내리고-vercel은-화면만-맡는다.md) · [ADR-0064](0064-수집-기본값을-필터링한다.md)

## 맥락

`https://finnect-web.vercel.app/admin/ingest` 를 열면 실행 기록만 보이고 버튼이 없다. ADR-0027 이 그렇게 정했다 — 이유 둘:

1. "응답보다 오래 사는 데몬 스레드다. K-Startup 전량이 요청 149회"
2. "`jobs.Progress` 가 **수집을 돌리는 프로세스 안에서만** 산다. 서버리스가 알 수 없다"

**둘 다 API 가 Vercel 서버리스 함수였던 시절의 이유다.** ADR-0035(2026-08-18)가 그 함수를 이 서버의 상시 `uvicorn` 프로세스로 내렸다. 지금 `finnect-api` 는 배포 트래픽을 받는 프로세스와 CLI 가 수집을 돌리는 프로세스가 **같다.** `jobs.Progress` 가 그 프로세스 메모리에 살아도 API 가 못 읽을 이유가 없다.

**`requirements.txt` 근거도 같이 낡았다.** `api/admin_service.py` 가 `ingest.service`·`attach.service` 를 안 끌어오는 이유로 "서버리스 함수에서 httpx·pdfplumber·olefile 을 뺐다"를 들었는데, 지금 배포 경로(`docs/deploy.md` A 장)는 로컬과 같은 `.venv`(`pyproject.toml` 전체 의존성)로 돈다. 실제로 배포본이 이미 `httpx` 로 LLM 을 부르고(`WIKI_EXTRACTOR=llm`) 사용자가 올리는 hwp·pdf 를 `pdfplumber`·`olefile` 로 파싱한다 — 막는다던 모듈들이 이미 매일 쓰이고 있었다.

**그리고 ADR-0064 가 걱정거리를 줄였다.** 기본 수집이 이제 K-Startup 요청 1~2회·기업마당 1회로, 대부분의 호출이 몇 초 안에 끝난다. `--full`(옛 149회짜리)만 오래 걸린다.

## 결정

**`POST /api/admin/ingest/run/{source}` 를 연다.** `finnect.ingest.service.launch()` 를 그대로 부른다 — 로컬 CLI·로컬 admin 버튼과 같은 경로다.

```python
result = ingest_service.launch(
    source, only_open=not full, skip_mlsfc=not full, limit=limit, trigger="admin"
)
```

**둘째 토큰을 하나 더 둔다.** `x-finnect-token`(`api_token`)은 Next.js 서버가 이 API 로 들어오는 문이라 `/admin/ingest` 를 보는 누구나 이미 통과한 뒤다. **이 동작은 성격이 다르다** — 눌리면 외부 정부 API 에 실제 요청이 나가고 쿼터를 쓴다(K-Startup 일 한도 10,000회 · 기업마당 키는 IP 에 묶일 수 있다). `x-ingest-trigger-token`(`ingest_trigger_token`)이 "이 버튼을 눌러도 되는 사람인지"를 한 번 더 묻는다.

**비어 있으면 503 이다.** `api_token` 은 비어 있으면 검사를 끄는데(로컬 편의), 이 토큰은 반대다 — **설정을 잊었을 때 열리는 쪽이 아니라 닫히는 쪽이어야 한다.** 쓰기이고 쿼터를 쓰기 때문이다.

**`finnect.ingest.service` 를 함수 안에서 임포트한다.** 최상단에 두면 `import finnect.api.app` 자체가 httpx 를 끌고 온다 — 지금은 배포본에도 httpx 가 있지만(위 맥락), 그 자유를 이 커밋에서 새로 쓰지 않는다. `wiki.service` 도 같은 이유로 함수 안에서 임포트하고 있다.

**`GET /api/admin/ingest` 가 `running`·`progress` 를 낸다.** `SourceCardOut` 에 필드 둘이 늘었고 값은 `ingest/jobs.py` 의 메모리에서 온다 — DB 가 아니다. 그래서 **워커를 여러 개 띄우면 진행 상태가 그중 하나에만 보일 수 있다**(지금은 1개). 재시작하면 사라진다 — `runs.reap()` 이 로컬 admin 이 뜰 때만 도는 것과 같은 종류의 대가다.

**`RunOut` 에 `filtered`·`filter_name` 을 더한다.** ADR-0064 가 만든 컬럼인데 화면에 안 보이면 "얼마나 솎았는지"가 배포본에서 안 보인다.

## 결과

- ADR-0027 의 "안 옮긴 것" 표에서 `POST /ingest/run/{source}` 한 줄만 유효기간이 끝났다. 나머지(`runs.reap()` · 첨부 원본 1.7GB)는 그대로 안 옮긴다 — 이유가 여전히 유효하다.
- `docs/api-contract.md` "여기 없는 것 — 수집 실행" 절이 실제 계약으로 바뀌었다.
- **인증이 여전히 화면 단위로는 없다.** `/admin/ingest` 페이지 자체는 누구나 연다(ADR-0027 이 정직하게 적어 둔 대로). 이번에 막은 것은 "버튼을 눌러도 실행되는지"이지 "페이지가 보이는지"가 아니다 — 후자를 막으려면 별도 결정이 필요하다.
- **동시 실행은 그대로 `jobs.launch()` 의 락이 막는다.** 같은 출처를 두 번 누르면 둘째가 "이미 돌고 있다"를 받는다. 반복 클릭으로 쿼터를 쓰는 것 자체는 이 락으로는 못 막는다 — 토큰이 그 문턱이다.
- 미결: `INGEST_TRIGGER_TOKEN` 을 배포 서버에 실제로 채우고 서비스를 재시작하는 것은 이 ADR 밖의 운영 작업이다. 비어 있으면 버튼이 503 으로 조용히 막힌다(의도한 동작이다).
