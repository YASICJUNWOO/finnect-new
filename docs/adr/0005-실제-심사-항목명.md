# ADR-0005: 심사 항목은 공고의 실제 항목명을 쓴다

- 상태: 채택됨
- 날짜: 2026-08-15 (2026-08-16 실측 반영)

## 맥락

계획서를 항목 단위로 쓸 때 그 항목을 뭐라고 부를지 정해야 한다. 선택지는 둘이었다.

1. 우리가 만든 일반적 이름 — "문제 정의", "해결책", "시장", "팀"
2. 공고가 실제로 쓰는 이름

우리 이름을 쓰면 여러 공고에 일관되게 적용된다. 대신 사용자가 실제 공고문을 열었을 때 이름이 달라 대조가 안 된다.

## 결정

**공고가 쓰는 실제 항목명을 그대로 쓴다.**

초기창업패키지는 PSST 구조이고 항목명은 이렇다.

| 항목 | 영문 |
|------|------|
| 문제인식 | Problem |
| 실현가능성 | Solution |
| 성장전략 | Scale-up |
| 팀(기업) 구성 | Team |

2026-08-16 실측으로 공고문과 별첨1 사업계획서 양식 양쪽에서 이 이름을 확인했다.

## 결과

- 사용자가 우리 화면과 실제 양식을 나란히 놓고 대조할 수 있다. 계획서를 옮겨 적을 때 헷갈리지 않는다.
- 대신 **공고마다 항목명이 다르므로 F0-3이 항목명을 공고 단위로 추출해야 한다.** 고정 목록을 코드에 박을 수 없다.
- 공고가 PSST가 아닌 자체 양식을 쓰면 그 이름을 쓴다. F5-3이 "PSST인지 자체 양식인지"를 판별하는 이유다.
- 실측에서 창업도약패키지도 같은 4항목을 쓰는 것을 확인했다. 다만 각 항목의 평가 관점 서술은 다르다. **항목명이 같아도 요구가 같지 않다.**
