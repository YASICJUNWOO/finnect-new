# hwp 저장이 스트림 셋을 잃는다 — 실측 (2026-08-24)

`HwpForm.save()` 가 오래 「미리보기 텍스트는 되살리고 이미지는 안 넣는다」고 적어 두고
**`_prv_text()` 를 부르는 자리가 없었다.** 그 사실은 2026-08-23 에 독스트링으로 정정됐고,
여기서 재는 것은 **무엇이 같이 빠지는지**와 **막고 있던 이유가 맞는지**다.

## 무엇이 빠지나

원본을 열어 **아무것도 채우지 않고** 그대로 저장한 뒤 OLE 스트림 목록을 대조했다.

```
sha256  139432d97877447bc32d143d362b27fadf4460997005a4f6f7c7ede90d34c475
        kstartup:178951 · 2026 현대모비스 CSV 오픈 이노베이션 신청서 · 셀 105개
```

| 스트림 | 원본 | 저장 뒤 |
|---|---|---|
| `PrvText` | 2,046B | **사라짐** |
| `PrvImage` | 48,023B | **사라짐** |
| `DocOptions/_LinkDoc` | 524B | **사라짐** |
| `BodyText/Section0` · `DocInfo` · `BinData/BIN0001.jpg` · `FileHeader` · `Scripts/*` | 있음 | 있음 |

**`DocOptions/_LinkDoc` 소실은 이때까지 아무 문서에도 없었다.** [ADR-0060](../0060-양식을-채워서-원본-포맷으로-돌려준다.md)
결정 4 와 [plan/24](../../plan/24-양식을-채워서-돌려준다.md) T-0151 이 둘 다 미리보기만
말한다. 미리보기를 보고 있었기 때문에 같이 빠지는 것을 못 봤다.

## 막고 있던 이유가 둘이었고 둘 다 틀렸다

같은 자리를 두 문서가 다르게 설명하고 있었다.

| 어디 | 무엇이 막는다고 했나 |
|---|---|
| `forms/hwp.py` `save()` 독스트링 | 「`olefile` 을 제품 의존성으로 들이는 것이라 아직 안 열었다」 |
| plan/24 T-0151 | 「hwplib 이 `DocOptions` 를 디렉터리가 아니라 스트림으로 만들어 둔 것에 걸렸다」 |

**`olefile` 이 필요 없다.** POI 가 `hwp-hwpx-editor` 패키지 안에 이미 들어 있고,
`_start_jvm()` 이 그 디렉터리의 jar 를 전부 클래스패스에 넣는다.

```
hwplib-1.1.10.jar  hwpxlib-1.0.8.jar  poi-3.9.jar  poi-ooxml-3.9.jar  poi-scratchpad-3.9.jar
```

**`DocOptions` 가 디렉터리인 것도 막지 않는다.** POI 의 `createDirectory()` 로 만들면
되고, 그것이 `_graft()` 가 경로를 `/` 로 쪼개 마디마다 `hasEntry` 를 보는 이유다.

새 의존성은 **0개**다.

## 붙인 뒤

`save()` 가 `HWPWriter.toFile()` 뒤에 `_graft()` 를 부르게 하고 같은 대조를 다시 했다.
`PrvText` 는 본문에서 만들고(채운 값이 반영돼야 한다) `_LinkDoc` 는 원본에서 옮긴다.

| | 칸 수 (원본 → 저장) | 잃은 스트림 | 용량 |
|---|---|---|---|
| `139432d9` | 105 → 105 | `PrvImage` | 85,504 → 34,304B |
| `00160075` | 122 → 122 | `PrvImage` | 156,160 → 102,400B |
| `0089fa52` | 44 → 44 | `PrvImage` | 51,712 → 10,240B |
| `021884c3` | 350 → 350 | `PrvImage` | 190,464 → 84,480B |

**`PrvImage` 는 그대로 포기한다**(ADR-0060 결정 4). 렌더링이 필요하고, 원본 것을 옮기면
값이 든 문서에 빈 양식 썸네일이 붙는다.

용량이 여전히 절반 아래인 것은 그 이미지가 원본의 30~55% 였기 때문이다 — `PrvImage`
48,023B 가 85,504B 짜리 파일의 56% 다.

## 미리보기 텍스트를 줄바꿈으로 잇는다

`_prv_text()` 가 `re.sub(r"\s+", " ", …)` 로 줄바꿈까지 공백으로 뭉개고 있었다. 한/글이
넣는 값과 나란히 놓으면 이렇게 갈린다.

```
한/글 원본   <>\r\n<2026 현대모비스 CSV 오픈 이노베이션 신청서>\r\n<>\r\n \r\n<Ⅰ. 기업개요>\r\n…
뭉갠 것      <> <2026 현대모비스 CSV 오픈 이노베이션 신청서> <> <Ⅰ. 기업개요> …
```

상한 1,023자는 hwp 규격이 정한 것이라 **뭉개도 더 담기지 않는다.** 대신 목록에서 두 줄만
보여 주는 자리에 첫 표의 첫 행만 뜬다. 그리고 표만 담고 있어서 **문서 제목이 빠졌다** —
미리보기에서 가장 먼저 읽히는 글자가 그것이다. 문단과 표를 문서 순서대로 섞도록 고쳤다.

## 무엇을 안 쟀나

**육안 확인이 0건이다.** 파일이 열리는지, 미리보기가 탐색기와 그룹웨어에서 실제로 뜨는지를
한/글로 보지 않았다. 프로그램 대조로 아는 것은 스트림이 있고 칸 수가 보존됐다는 것까지다.

[ADR-0060](../0060-양식을-채워서-원본-포맷으로-돌려준다.md) 결정 4 를 갱신하려면 그 확인이
필요하다 — 결정 3 을 판본 일곱 개와 양식 20건으로 정했던 것과 같은 규모다.

## 명령

```bash
uv run --group forms python -c "
import olefile
from pathlib import Path
from finnect.forms.hwp import HwpForm

src = 'data/attachments/13/139432d978…'
out = '/tmp/rt.hwp'
f = HwpForm(src); before = len(f.cells()); f.save(out)
a = {'/'.join(s) for s in olefile.OleFileIO(src).listdir()}
b = {'/'.join(s) for s in olefile.OleFileIO(out).listdir()}
print('칸', before, '→', len(HwpForm(out).cells()), '· 잃은 것', sorted(a - b))
"
```

`olefile` 은 **대조에만** 쓴다. 제품 코드는 POI 로 하므로 그 패키지가 없어도 `save()` 는
돈다.
