# ADR-0038: LLM 호출을 Langfuse 로 남기고, SDK 대신 OTLP 엔드포인트를 부른다

- 상태: 채택됨
- 날짜: 2026-08-20
- 채우는 것: [ADR-0021](0021-인프라-선정을-미룬다.md) 이 비워 둔 자리 하나 — **관측**
- 관련: [ADR-0037](0037-llm-제공자를-openai-로-정하고-gpt-5-6-luna-부터-잰다.md) 결정 2 가 세운 규율을 그대로 따른다

## 맥락

2026-08-19 [ADR-0037](0037-llm-제공자를-openai-로-정하고-gpt-5-6-luna-부터-잰다.md) 이 제공자를 정하고 그날부터 LLM 을 부르기 시작했다. 부르는 자리가 여섯이다 — 사실 추출 · 구간 판별 · 양식 읽기 · 배분 · 집필 · 중복 점검.

**그런데 무엇을 물었고 무엇이 왔는지 남는 곳이 없었다.** 남는 것은 `llm.Usage` 의 토큰 집계와 우리가 세는 `dropped` · `unverified` 뿐이다.

2026-08-20 `--classify 40` 을 처음 돌렸을 때 이 공백이 실제로 걸렸다. **틀린 판정 둘의 원인이 프롬프트가 아니라 스키마에 있었는데**(모델이 `reason` 에 "제목만 있다" 고 적으면서 `fields` 를 냈다) 그것을 알아낸 방법이 **터미널 출력 40줄을 눈으로 읽는 것**이었다. 전량 7,717건에서는 그 방법이 안 통한다.

`--classify` 전량과 초안 한 벌(항목 최대 102개)을 돌리기 전에 **호출 하나하나를 되짚을 수단**이 필요하다.

## 결정

### 1. Langfuse 를 쓴다

사용자가 지목했다. 우리가 고른 것은 아래 2번부터다.

### 2. `langfuse` 패키지를 안 쓴다. OTLP/HTTP 엔드포인트 하나를 부른다

`POST {base_url}/api/public/otel/v1/traces` · Basic 인증(`pk:sk`) · `x-langfuse-ingestion-version: 4`.

**[ADR-0037](0037-llm-제공자를-openai-로-정하고-gpt-5-6-luna-부터-잰다.md) 결정 2 와 같은 이유다.** `requirements.txt` 가 읽기 API 에 필요한 다섯만 싣는데, 새 패키지를 `pyproject` 에 넣으면 누군가 `api/` 에서 임포트했을 때 **로컬은 통과하고 배포본만 죽는다.**

속성 이름은 Langfuse 네이티브(`langfuse.observation.*`)를 쓴다 — OTel 시맨틱 컨벤션(`gen_ai.*`)을 쓰면 매핑을 우리가 맞춰야 하고, 그 매핑이 바뀌면 조용히 안 뜬다.

**Langfuse 가 레거시 적재 API 를 2026-11-16 에 닫는다**([문서](https://langfuse.com/docs/api)). 그래서 처음부터 OTLP 로 간다.

### 3. `llm.Client.json()` 한 곳에만 건다

LLM 을 부르는 **유일한 자리**라 여섯 호출처가 자동으로 다 남는다. 부르는 쪽이 아무것도 안 한다.

포트마다 따로 걸면 새 포트를 팔 때마다 잊는다. 위키 추출기 · 판정기 · 집필기가 각자 `dropped` 를 세는 것과 다른 성질이다 — 그건 도메인 판단이고 이건 배관이다.

### 4. 관측이 본 일을 막지 않는다

**추적은 절대 호출을 막지 않는다.**

- 큐에 넣고 즉시 돌아온다. 뒤에서 스레드가 묶어 보낸다
- 큐가 차면 **버리고 센다**
- 전송이 실패해도 `json()` 은 결과를 그대로 낸다
- 실패는 **한 번만** 말한다. 7,717번 부르는 자리에서 매번 찍으면 진짜 오류가 묻힌다

### 5. 키가 없으면 그냥 꺼진다

`wiki_extractor` 는 키가 없으면 **멈춘다**([ADR-0037](0037-llm-제공자를-openai-로-정하고-gpt-5-6-luna-부터-잰다.md) 결정 4). 여기는 반대로 조용히 꺼진다.

**성질이 다르다.** 추출기가 물러나면 처리하지 못한 것이 "아무것도 안 나온 것" 처럼 보인다 — 결과가 틀린다. 추적이 꺼지면 **볼 수 없을 뿐이고 결과는 같다.** 정확성 기능과 보는 기능을 같은 규율로 다루면, 보는 기능 하나가 파이프라인 전체를 세운다.

공개키와 비밀키 **둘 다 있어야** 켠다. 하나만 있으면 오타일 가능성이 높다.

### 6. 초안 한 벌이 한 추적이다. 구간 판별은 안 묶는다

`trace.session()` 이 묶는다. 초안은 항목 수십 개가 한 화면에 있어야 읽을 수 있고, 구간 판별은 구간이 서로 독립이라 **7,717개를 한 추적에 넣으면 못 읽는다.**

**스레드에는 `current()` / `adopt()` 로 물려 준다.** `contextvars` 는 스레드로 안 넘어가서, 안 물려 주면 [plan/16 T-0069](../plan/16-항목마다-초안을-쓴다.md) 가 병렬로 쓴 항목들이 추적 67개로 흩어진다.

## 결과

- **호출 하나하나를 되짚을 수 있다.** 시스템 프롬프트 · 사용자 프롬프트 · 구조화 출력 · 토큰 · 성공/실패가 남는다. `--classify` 전량과 초안 한 벌을 돌릴 수 있는 조건이 이것이었다
- **`.env` 에 세 줄이 는다.** `LANGFUSE_PUBLIC_KEY` · `LANGFUSE_SECRET_KEY` · `LANGFUSE_BASE_URL`
- **CLI 가 끝나기 전에 `trace.flush()` 를 부른다.** 데몬 스레드라 안 부르면 남은 것이 사라진다. **큐가 비었는지로 판단하면 안 된다** — 펌프가 꺼낸 순간 큐는 비지만 그 묶음은 아직 안 갔고, 실측에서 2건 중 1건이 그렇게 사라졌다. 센 것으로 판단한다
- **의존성이 안 는다.** `httpx` 는 이미 있다
- **포기한 것.** SDK 가 주는 배치·재시도·스키마 버전 관리를 우리가 든다. Langfuse 가 속성 이름이나 엔드포인트를 바꾸면 **조용히 안 뜬다** — `stats.failed` 가 0 인데 화면에 없으면 그것이 신호다. 그리고 프롬프트 캐싱 지표나 비용 계산 같은 SDK 부가 기능을 안 쓴다
- **안 정한 것.** 평가(eval)와 데이터셋을 Langfuse 로 할지는 정하지 않았다. 지금 잣대는 픽스처(`wiki/score.py`)와 손 라벨이고, 그것을 Langfuse 로 옮길 이유가 아직 없다
