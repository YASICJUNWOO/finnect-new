# ADR-0069: 「운영 도구」 링크를 제품 화면에서 뺀다 — 자기 것이 아닌 문을 모든 화면에서 본다

- 상태: 채택됨
- 날짜: 2026-08-24
- 대체하는 것: [ADR-0027](0027-운영-화면을-nextjs로-옮긴다.md)이 제품 헤더에 세운 「운영 도구」 링크. **운영 화면을 Next.js 로 옮긴 결정과 `/admin/*` 경로는 그대로다**
- 채우는 것: [ADR-0067](0067-운영-화면을-basic-으로-막는다.md)이 「숨기는 것은 시각 결정이라 따로 정한다」로 남긴 자리

## 맥락

2026-08-17 부터 제품 화면 상단 막대에 「운영 도구」 링크가 있었다(ADR-0027). 좁은 화면에서도 안 숨겼고 그 근거를 코드가 이렇게 적어 뒀다.

> 숨기면 폰에서 `/admin` 으로 가는 문이 사라지고, 그건 시각 결정이 아니라 기능 축소다.

**그 문장은 보는 사람이 우리뿐일 때 참이었다.** ADR-0066 으로 외부 테스터가 들어오면서 같은 링크가 **자기 것이 아닌 문을 모든 화면에서 보는 일**이 됐다. ADR-0067 이 그 사실을 적으면서도 「막히기는 하지만 보기 좋지 않다」로 미뤄 뒀다.

**미룬 대가가 이틀 만에 나왔다.** Basic 을 걸자 `<Link>` 의 prefetch 가 그 주소를 미리 쳤고, 401 + `WWW-Authenticate` 를 받은 브라우저가 **아무것도 누르지 않은 테스터에게 비밀번호 창을 띄웠다.** 커밋 `9b2a66a` 가 `<a>` 로 바꿔 그 증상은 막았지만, **링크 자체는 여전히 거기 있고 누르면 여전히 창이 뜬다.**

## 결정

**제품 껍데기에서 링크를 없앤다.** 조건부로 감추는 것이 아니라 마크업을 지운다.

**조건부가 불가능해서다.** `web/app/(product)/layout.tsx` 는 클라이언트 컴포넌트이고, 운영 자격은 HTTP Basic 이라 **브라우저와 서버 사이에만 있다.** 「이 사람이 운영자인가」를 그 껍데기에서 물을 방법이 없다. `ExitAccount` 를 상단이 아니라 `/wiki` 에 둔 것과 같은 자리다 — 거기도 `httpOnly` 쿠키를 못 읽어서 자리를 옮겼다.

**운영자는 주소로 간다.** `/admin` 이 `/admin/notices` 로 보낸다(`app/admin/page.tsx`). 북마크 하나면 된다 — **운영자는 이 레포를 아는 사람이고, 테스터는 아니다.**

## 결과

- **상단 막대가 넓은 화면에서 현재 위치 하나만 든다.** `DESIGN.md` §5 의 표에서 「운영 도구」가 빠졌다.
- **`.admin` CSS 세 블록이 없어졌다.** 그중 하나는 「제품 글자가 13px 로 내려간 폭에서 12px 로 한 칸 더 내린다」였는데, 그 대비를 지킬 대상이 없어졌다.
- **폰에서 `/admin` 가는 문이 실제로 사라졌다.** ADR-0027 이 「기능 축소」라고 부른 그것이 맞고, **그 축소를 이번에는 받아들인다** — 잃는 사람이 한 명이고 얻는 사람이 전부다.
- **되돌릴 조건**: 운영자가 여럿이 되거나 세션 기반 인증이 붙어서 껍데기가 「운영자인가」를 물을 수 있게 되면 그때 다시 세운다. 그때는 **자격이 있는 사람에게만 보이는** 링크여야 한다.
