레포 첫 줄이 「들어가면 **문서가 이미 써져 있다**」인데 **그 문서가 파일로 안 나간다.** `src/finnect/draft/` 에 파일을 쓰는 코드가 한 줄도 없어서, 집필기가 만든 글을 사용자가 화면에서 복사해 한/글에 손으로 옮긴다.

여기서 **받은 양식 파일에 값을 넣어 같은 포맷으로 돌려준다.**

### T-0151 포맷 어댑터를 제품 코드로 세운다 — **완료** (2026-08-23)

`src/finnect/forms/` 를 만들고 spike 셋을 인터페이스 하나 뒤로 넣는다.

- `open(path) → Form` · `Form.blanks() → [Blank]` · `Form.fill(anchor, value)` · `Form.save(path)`
- **`Blank` 가 앵커를 든다** — 표 좌표 `(표 번호, 행, 열)` + 섹션. **누름틀에 기대지 않는다**(hwpx 9건 중 1건뿐)
- **덮어쓰기 가부를 어댑터가 답한다.** hwp 어댑터는 이미 글자가 있는 칸에 `False` 를 준다 — 부르는 쪽이 포맷을 알아서 분기하면 그 지식이 두 곳에 산다
- **JVM 을 hwp 어댑터 안에만 가둔다.** `import finnect.forms` 가 jpype 를 끌고 오면 안 된다 — `api/service.py` 가 `match.service` 를 임포트하지 않는 것과 같은 함정이다
- 미리보기 복구(`PrvText` 재생성 · `PrvImage` 포기)는 hwp 어댑터의 `save` 안에 있다
- **2026-08-23 셋이 다 찼다**(hwp · hwpx · docx). `PLANNED` 가 비었고 지우지는 않는다 — xlsx 가 거기 올 자리다
- **hwpx 도 순회를 hwp 와 맞춘다** — `doc.tables` 를 안 쓰고 구역 → 문단 → 그 문단의 표 순으로 센다. 같은 양식을 두 포맷으로 받았을 때 좌표가 같은 자리를 가리켜야 한다
- **미리보기 복구가 아직 코드에 없다.** `_prv_text()` 는 있는데 `save()` 가 안 부른다 — hwplib 이 `DocOptions` 를 디렉터리가 아니라 스트림으로 만들어 둔 것에 걸렸다([ADR-0063](../adr/0063-서술-항목의-좌표를-문단으로-준다.md) 「정하지 않은 것」)

### T-0157 양식 파싱의 입력을 파일 구조로 바꾼다 — **서류 경계만 됐다** (2026-08-23)

**서류 경계를 구조가 찾는다 — 됐다**([실측](../adr/evidence/2026-08-23-구조로-서류-경계를-찾는다.md)). 한글 양식은 서류 제목을 **표 하나로 감싸는데** 텍스트로 납작하게 만들면 그 모양이 사라져서, 표지 낱말(`붙임`·`서식`)이 없는 양식을 못 잘랐다. `segment.doc_titles` 가 「칸 셋 이하인 표의 셀 또는 표 밖 문단이 서류 이름으로 끝나면 경계」로 잡고, `split(titles=…)` 이 원문에서 대조해 오프셋으로 바꾼다(결정 5 와 같은 수법).

```
코퍼스 334개(hwp 255 · hwpx 63 · docx 16)   구간 607 → 761 (+154)
구간이 는 파일 85/334 = 25.4%   ·   오프셋 깨짐 0   ·   못 연 파일 0
```

육안 13건에서 오탐 셋을 찾아 고쳤다(줄머리 기호 · 한글 `ㅇ` 불릿 · `제출서류` 로 끝나는 공고문 절). 마지막 회차 표본 7건은 오탐 0 이다.

- ~~서류 경계를 구조가 찾는다~~ **완료.** `segment.doc_titles` · `extract/service.py` `_form_titles`

- **좌표를 나중에 안 붙인다.** `plant_anchors()` 가 없어진다 — 그 함수는 순서가 뒤집혀 있어서 생긴 것이다
- 텍스트는 **pdf·스캔본이 물러날 자리**로 남는다. `attach/` 는 안 바뀐다
- **이미 깔린 `document_item` 을 어떻게 옮길지 정한다** — 다시 깔면 초안이 지워진다(FK CASCADE)

**남은 것을 하려면 재적재가 먼저다.** 위 숫자는 **경계를 몇 개 찾았나**이지 항목이 몇 개 늘었나가 아니다 — 종류 판별과 항목 추출을 다시 돌려야 그 값이 나오는데 `extract --redo` 가 초안을 지운다(T-0160).

**큰 표의 첫 칸은 못 잡는다.** 경남TP `신청자격 적정성 확인서`(44칸)가 그렇고, 조건을 넓히면 본문 표의 라벨이 딸려 온다. **hwpx 가 파일당 1.5초**로 hwp(7ms)의 200배다 — 전량 재적재에서 보인다.

### T-0162 서술 항목에 문단 좌표를 준다 — **완료** (2026-08-23)

[ADR-0063](../adr/0063-서술-항목의-좌표를-문단으로-준다.md). T-0158 로 서술 항목이 1,701개가 되자 **그중 좌표를 가진 것이 0개**였다 — 채우기가 전부 건너뛰어서 **화면은 「썼어요」인데 파일에는 안 들어갔다.**

```
문단 16   1. 목적 및 필요성           ← 제목
문단 17   - 참가하고자 하는 …작성      ← 지시문
문단 18   (빈 문단)                  ← 글이 들어갈 자리
문단 25   2. 수주 활동 대상           ← 다음 항목
```

- `ParaAnchor`(`p:0:18`) — **`p:` 가 없으면 셀이라 마이그레이션이 없다**
- 제목 다음 첫 빈 문단. **다음 제목을 안 넘고**, 겹치거나 없으면 안 준다
- **빈 문단이라고 서식이 중립이 아니다** — 빨강 기울임이 물려 있었다. 색과 기울임을 뺀다
- **줄 나눔 캐시를 지운다.** 안 지우면 한/글이 한 줄에 다 그려 글자가 겹친다(판본 넷 · 한/글 육안)
- **표 셀에는 안 한다** — 거기는 그대로 정상이다

**결과** — 서술 좌표 0 → **399 (23.5%)** · 좌표가 있는 파일 5 → **135**.

**hwpx 어댑터를 붙이자 443 · 155 가 됐다**(T-0151). hwpx 에도 같은 서식 함정이 있었지만 — 빈 문단이 `#FF0000` 을 물고 있었다 — **해법이 더 낫다.** `ensure_char_property` 로 base 를 복제한 사본을 만들 수 있어서 원본 정의를 안 건드린다. hwp 는 그 API 가 없어 정의를 직접 고치고 「글자 있는 곳도 이 서식을 쓰나」를 보고 물러나므로 **한 자리가 빨강으로 남는데**, hwpx 는 0개다. **줄 나눔 캐시는 안 지운다** — Y1(캐시 그대로)이 한/글에서 정상이었다.

### T-0163 서류 표지를 라벨에서 뺀다 — **완료** (2026-08-23)

**T-0162 를 눈으로 보다 나왔다.** 채운 hwpx 첫 페이지에서 글자가 세로로 눌려 있었고, 원본을 대조하니 **우리가 넣은 것**이었다.

```
| 붙임 1 | (빈칸) | (빈칸) | 임대신청서 및 사업계획서 서식 |
     ↑        ↑
   라벨로    값 자리로 판정 → 회사 이름이 들어갔다. 칸이 좁아 세로로 눌렸다
```

한글 양식이 서류 제목을 **표 하나로 감싸는데**(테두리와 음영을 주려고) `label_targets` 는 「라벨 오른쪽 첫 빈 칸」만 본다. 그 칸은 장식이다.

- **포맷과 무관하다** — 코퍼스에서 그렇게 잡힌 항목이 **166개**이고 그중 **90개에 좌표가 붙어** 있었다
- `fields.is_marker()` 가 텍스트 경로(`fx.rows`)와 파일 경로(`_plant_anchors`) 둘에서 거른다
- **낱말을 `segment.MARKER_WORDS` 로 공유한다** — 갈리면 한 파서가 표지로 자른 자리를 다른 파서가 채울 칸으로 뽑는다
- **번호를 요구한다.** `붙임` 만 있는 낱말은 본문에 흔해서 그것까지 빼면 진짜 라벨을 잃는다

**결과** — 표지가 라벨로 남은 항목 166 → **0**, 그 좌표 90 → **0**.

### T-0159 항목 추출을 LLM 하나로 합친다 — **다음 회차**

[ADR-0061](../adr/0061-양식-파싱의-입력을-파일-구조로-바꾼다.md) 결정 4·5. 표 라벨 정규식과 목차 규칙이 각자 뽑던 것을 한 번의 호출로 합친다.

- **위치는 코드가 준다.** LLM 은 좌표를 받아 「이 칸이 무엇을 묻나」만 답한다
- 서술 항목은 **제목 문자열**을 받아 원문에서 찾는다. 못 찾으면 버린다(앵커 대조)
- **정확도를 재고 나서 붙인다.** 손 분류와 대조하고 불일치를 전부 나열한다
- 규칙이 못 걸러 낸 것 둘이 대조군이다 — `=기업 기본 정보`(표 구분선) · `▸민사집행법에…`(안내문 전체)

### T-0160 다시 뜯는 경로를 막는다 — **다음 회차**

**`extract --redo` 가 초안을 지운다.** `draft_item.document_item_id` 의 FK 가 CASCADE 라 항목을 다시 깔면 그 항목에 쓴 초안과 **사람이 고친 글**이 같이 없어진다([ADR-0055](../adr/0055-사람이-고친-글을-집필-출력-위에-덮지-않는다.md)가 지키려던 값).

T-0159 가 붙으면 더 아파진다 — LLM 은 같은 파일을 매번 똑같이 안 쪼갠다.

- 초안이 있는 문서를 다시 뜯을 때 무엇을 할지 정한다
- 위키 쪽 `--rebuild` 가 같은 문제를 어떻게 풀었는지 본다

### T-0156 hwp 제출 요구 비율을 재고 변환을 정한다 — **다음 회차**

hwp 를 hwpx 로 바꾸면 덮어쓰기가 살아나고 JVM 도 변환 한 번에만 필요해진다. 대가는 **제출 포맷이 달라지는 것**이다.

- 공고 본문에서 「hwp 로 제출」을 요구하는 비율을 센다
- 낮으면 변환이 이긴다. 높으면 hwp 제약을 안고 간다
- **재기 전에는 안 정한다** — 반려되면 그 손해를 우리가 못 갚는다

## 검증

**7 이 이 회차의 진짜 검증이다.** 파일이 프로그램으로 되읽히는 것과 사용자가 화면에서 채워진 것을 보는 것은 다른 문제다.

**8 이 안 된 것이 [ADR-0061](../adr/0061-양식-파싱의-입력을-파일-구조로-바꾼다.md)의 계기다** — `bizinfo:PBLN_…125577` 은 13칸 중 4칸, `kstartup:178687` 은 28칸 중 12칸이 찼다. 나머지는 **채울 대상이 애초에 안 만들어졌다.**

```bash
# 제품 코드 (T-0151~T-0155). `--group forms` 가 있어야 돈다

uv run python -m finnect.draft --company c_dasiro --notice bizinfo:PBLN_000000000125577

uv run --with python-hwpx python spike/hwpx_fill.py
uv run --with python-docx python spike/docx_fill.py
```
