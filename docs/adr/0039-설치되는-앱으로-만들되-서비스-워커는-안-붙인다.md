# ADR-0039: 설치되는 앱으로 만들되, 서비스 워커는 안 붙인다

- 상태: 채택됨
- 날짜: 2026-08-21
- 여는 것: [plan/18](../plan/18-설치되는-앱.md) — 홈 화면에 얹히고 크롬 없이 열린다
- 관련: [ADR-0025](0025-토큰-실값-확정.md) 토큰 실값 · [ADR-0027](0027-운영-화면을-nextjs로-옮긴다.md) 앱 두 겹 · [ADR-0017](0017-위키-그래프-궤도-배치.md) 궤도 배치 · [ADR-0035](0035-api와-워커를-자체-서버로-내리고-vercel은-화면만-맡는다.md) 실행 위치 · `DESIGN.md` §12
- 근거: [앱 아이콘 크기 실측](evidence/2026-08-21-앱-아이콘-크기-실측/)

## 맥락

`web/` 에 **설치와 관련된 것이 하나도 없었다.** 매니페스트도, 아이콘도, `web/public/` 디렉터리조차 없었다. 파비콘 한 장이 없어서 탭에 기본 문서 아이콘이 떴다.

`docs/SPEC.md` 는 모바일·반응형·설치·PWA 를 **한 번도 안 적었다.** §6 범위 밖에도 없다. **충돌이 아니라 공백이다** — 정해야 할 것을 정하지 않은 자리다.

없는 것과 있는 것을 갈라 적는다.

| 무엇 | 상태 |
|---|---|
| 반응형 | **있다.** `@media (max-width: 640px)` 가 아홉 곳 — `NoticeRow` · `WikiBoard` · `FormFill` · `Upload` 등 |
| 토큰 | **있다.** 색·타입·반경 실값이 `web/app/tokens.css` 에 박혀 있다(ADR-0025) |
| 매니페스트 · 아이콘 · `theme-color` | 없다 |
| 안전영역(노치) 대응 | 없다. `viewport-fit` 을 안 줬으니 `env(safe-area-inset-*)` 이 전부 0 이다 |
| 좁은 화면의 내비 | **상단 3축 하나뿐이다.** 폰에서 엄지가 안 닿는다 |

## 고른 것

### 결정 1. 설치까지만 한다. 서비스 워커를 안 붙인다

셋을 놓고 골랐다.

| 안 | 무엇 | 왜 |
|---|---|---|
| **A** | **매니페스트 + 아이콘 + `theme-color`.** 홈 화면에 얹히고 크롬 없이 열린다 | **고름** |
| B | 앱 셸 캐시 | 의존성(Serwist 등)이 하나 붙고 [deploy.md](../deploy.md) 에 **SW 갱신 단계**가 생긴다. 얻는 것은 껍데기가 먼저 뜨는 것 하나고, 데이터는 어차피 네트워크다 |
| C | 본 공고·위키를 오프라인에서도 읽기 | **낡은 데이터를 언제 버리는지를 먼저 정해야 한다.** 위키 마크다운을 저장하지 않기로 한 결정(뷰다)과 같은 자리에서 다시 얘기할 일이다 |

**B 와 C 를 "나중에"로 미루는 것이 아니라, 지금 정할 근거가 없어서 안 하는 것이다.** 캐시는 무효화 규칙이 정본이고, 그 규칙은 사용자가 오프라인에서 무엇을 하려는지를 봐야 정해진다. 지금은 그 관찰이 없다.

**대가를 적어 둔다.** 이 앱은 홈 화면에 얹히고 크롬 없이 열리지만 **비행기 모드에서는 안 돈다.** 그래서 `components/Install.tsx` 의 카피가 '빠르다'가 아니라 **'바로 열 수 있어요'** 다 — 달라지는 것은 닿는 거리 하나고, 그것만 말한다.

### 결정 2. 같은 3축을 좁은 화면에서 아래로 내린다

설치하면 브라우저 크롬이 없어져서 **상단 막대가 유일한 크롬이 된다.** 폰에서 그 자리는 엄지가 안 닿는다.

**축을 바꾸지 않는다.** `SPEC.md` §5.1 의 셋 그대로이고 자리만 바뀐다. §5.1 이 "LNB 3축" 이라고 적었지만 구현은 이미 상단으로 올려 뒀다 — `DESIGN.md` §5.4 가 왼쪽 사이드바를 금지한다. **3축은 개념이고 위치는 개념이 아니다.**

`DESIGN.md` §5.4 의 금지 다섯과 대조했고 걸리는 것이 없다. 하단 탭 바는 그 목록에 없고, 금지 대상은 "표 머리글이 붙은 목록형 관리 화면"이다.

**기준이 뷰포트 폭 하나다.** `(display-mode: standalone)` 을 같이 걸면 데스크톱에 설치한 창에도 하단 바가 깔린다 — 내리는 이유가 '엄지가 안 닿는다'인데 1,200px 창에는 그 이유가 없다. 폰은 설치했든 안 했든 어차피 640 아래다.

**축을 두 곳에 적지 않는다.** `AXES` 배열 하나를 상단 막대와 하단 탭 바가 같이 읽는다. 넷째 축이 생기는 날 한쪽만 고쳐지면 위아래가 다른 메뉴를 보여 준다.

### 결정 3. 앱 아이콘은 궤도를 줄인 것이고, 마크를 둘로 나누지 않는다

**헤더의 근검정 사각형을 그대로 키우지 않았다.** 512px 로 키우면 홈 화면에 검은 네모 하나가 놓인다 — 어느 앱인지 말하지 않는다.

새 마크는 **궤도(S7)를 줄인 것**이다. 중심 하나 · 위성 셋 · 끊긴 고리 · 살 셋. 기하는 `Orbit.tsx` 와 [ADR-0017](0017-위키-그래프-궤도-배치.md)에서 왔다 — **없던 것을 만든 게 아니라 이미 화면에 있는 것을 줄였다.**

**단색이다. `--ink` 바탕에 흰 마크뿐이다.** 노드 분류색 셋(`--n-identity` · `--n-content` · `--n-company`)을 쓰고 싶었지만 안 썼다. `DESIGN.md` §3-7 이 **"색은 위키 그래프와 문서 빈칸에만 몰아 쓴다"** 고 정했다. 앱 아이콘은 그 둘이 아니다. 거기에 색을 쓰면 색이 뜻을 갖는 자리가 하나 더 늘어 궤도의 색이 그만큼 덜 말한다. **§3-6(UI 크롬에 색 금지)의 예외를 만들 필요가 없어진 것이 이 결정의 이득이다.**

**16px 에서 뭉갠다. 그래도 마크를 둘로 안 나눈다**([실측](evidence/2026-08-21-앱-아이콘-크기-실측/)). 32px 부터는 읽히고 16px 에서는 한 덩어리가 된다. 파비콘용 단순 글리프를 따로 만들 수도 있었지만, **그 둘째 글리프를 정하는 것은 `DESIGN.md` §1 이 미정으로 남겨 둔 '시그니처 요소'를 결정 없이 채우는 일이다.** 하나로 가고 한계를 적어 둔다.

### 결정 4. PNG 를 손으로 굽고 커밋한다

이 서버에 PIL·cairosvg·ImageMagick 이 **전부 없다.** `sharp` 를 `web/` 에 넣으면 의존성 셋(next·react·react-dom)에 네이티브 바이너리가 하나 붙는다.

그래서 `tools/make-icons.py` 가 **거리장으로 직접 칠하고 zlib 으로 PNG 를 조립한다.** 표준 라이브러리만 쓴다.

**빌드 단계가 아니다.** 마크를 고칠 때만 돌리고 결과물을 커밋한다. `npm run build` 에 걸면 빌드가 Python 을 요구하고 Vercel 은 그걸 안 준다(ADR-0035 가 화면만 거기 둔다).

**SVG 도 같은 스크립트가 낸다.** 좌표를 두 곳에 두면 파비콘과 앱 아이콘이 다른 마크가 되는 날이 온다.

**모서리 때문에 두 벌을 낸다.** 처음에 각진 PNG 하나를 `any` 와 `maskable` 에 같이 걸고 "잘려도 안 잘려도 같은 그림"이라고 적었는데 **틀렸다.** `maskable` 은 OS 가 깎지만 **`any` 는 아무도 안 깎는다** — 크롬 설치 창과 데스크톱 작업 표시줄이 그대로 그린다. 그래서 각진 것을 `any` 에 주면 같은 순간 파비콘은 반경 22% 인데 앱 아이콘만 검은 네모가 되고, 그게 바로 위 결정 3 이 피하려던 갈림이다. 지금은 `any` 가 둥글고(RGBA) `maskable` 이 각지다(RGB).

### 결정 5. 뷰포트 설정은 한 겹이라 운영 화면도 안전영역을 물어야 한다

앱이 두 겹인데(ADR-0027) **`export const viewport` 는 루트 레이아웃에 하나뿐이다.** ADR-0027 이 나눈 것은 헤더와 `main` 이고 뷰포트 메타는 안 나뉜다.

그래서 `viewportFit: "cover"` 가 `admin/` 에도 간다. **켜기만 하고 CSS 를 안 넣으면 그쪽 상단 막대가 시계 밑으로 들어간다** — 그 전에는 안전영역이 0 이라 브라우저가 레터박스로 막아 주고 있었다. **이 결정이 만든 회귀다.**

막을 길이 아니라 물어야 한다. `scope` 가 `/` 라서 운영 도구가 앱 안에서 열리고(아래 `안 한 것`), 제품 헤더에 거기로 가는 링크가 있다(`ADMIN = "/admin/notices"`). `admin/layout.module.css` 가 `.bar` 위와 `.inner`·`.main` 좌우를 먹는다.

## 결과

- 홈 화면에 얹히고 크롬 없이 열린다. **오프라인은 안 된다**
- 폰에서 3축이 하단 탭 바로 내려온다. 640px 이 경계다
- `web/public/` 이 생겼다. 이 레포의 첫 정적 자산 디렉터리다
- `env(safe-area-inset-*)` 이 값을 갖는다(`viewportFit: "cover"`). **상단 막대와 하단 탭 바가 그 값을 안쪽 여백으로 먹는다**

## 안 한 것과 그 이유

**`scope` 를 좁히지 않았다.** `/` 라서 운영 도구(`/admin`)도 앱 안에서 열린다. 제품 라우트가 `/` · `/notices` · `/wiki` · `/documents` 로 흩어져 있어 공통 접두사가 `/` 밖에 없다 — 좁히려면 제품 화면을 한 접두사 아래로 옮겨야 하고, 그건 URL 을 전부 바꾸는 일이다. **`SPEC.md` §6 이 운영 도구를 범위 밖으로 뒀으니 앱 안에서 열리는 것이 이상하긴 하다.** 라우트를 옮길 이유가 따로 생기면 그때 같이 한다.

**`orientation` 을 잠그지 않았다.** 공고 상세와 궤도는 눕혀서 보는 것이 나을 때가 있다.

**확대를 막지 않았다.** `maximumScale` · `userScalable` 을 안 건드렸다. 앱처럼 보이게 하려고 막는 자리인데, 막으면 접근성이 깨진다.

**스플래시 이미지(`startupImage`)를 안 넣었다.** iOS 는 기기 해상도마다 다른 파일을 요구하고, 지금 그 목록을 정확히 셀 근거가 없다. 없으면 `background_color` 로 뜬다.

**하단 탭 바에 아이콘을 안 넣었다.** `DESIGN.md` 에 아이콘 세트가 없다. 넣으려면 아이콘 언어를 새로 정해야 하고, 그건 이 작업의 결정 범위 밖이다. 글자 셋이 §2-4('표 중심 업무 도구')와도 맞는다.
