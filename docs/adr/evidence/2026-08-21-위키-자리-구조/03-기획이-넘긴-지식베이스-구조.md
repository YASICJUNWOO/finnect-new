## 레포와 다른 곳 — 먼저 읽을 것

| | 이 문서 | 현재 코드 |
|---|---|---|
| 대분류 | 폴더 **10** | `SECTORS` **6** |
| MD 한 장 | **40+ · 동적으로 늘어남** | `ORBIT` **15 · 고정** |
| 안의 내용 | 프론트매터 + 본문 | 슬롯 값 + 노드 문장 |
| 등급 | `실측·1차·2차·가정·미정` **5단계** | `SourceType` **2개**(`document`·`user_stated`) |
| topic 온톨로지 | "지금 23개인데 늘려야 한다" | **25개**(`TOPIC_NODE` 23 + 2) |

**모양은 같다.** 이 문서도 3층이고(폴더 → 파일 → 내용) 코드도 3층이다
(`SECTORS` → `ORBIT` → `SLOTS`/`NODES`). **다른 건 개수와 고정/동적 하나뿐이다.**

대응을 맞추면 이렇다.

```
Company/회사소개·비전·팀·대표자      →  biz · where · what · identity · team · who
Product/{서비스명}/*                 →  solution 하나  (topic 7개가 접힌 자리)
Market/시장규모·트렌드 · Competitor  →  market 하나
Customer/타깃고객 · 고객문제         →  customer · problem
BusinessModel/* · Financial/매출     →  traction
Financial/비용·자금계획              →  finance
Custom/특허·인증·기술                →  solution 안으로 들어감
Plan/일정                            →  roadmap
Events/applications                  →  grants (gov_program)
—                                    →  region (지역 연계)  ← 문서에 없는데 코드엔 있다
```

**문서에 있는데 코드에 자리가 없는 것:**

```
Company/창업계기 · Market/산출식-TAM|SAM|SOM · Market/통계/{항목}
Customer/페르소나 · 인터뷰 · 인용문 · 검증 · Competitor/비교축
Financial/집행계획 · Plan 일곱 중 여섯(KPI·마케팅·채용·고객확장·기술고도화·사회적가치)
```

**레포가 이미 반대로 결정한 것이 하나 있다** — `Events/meetings·decisions·actions`
(`topics.py:19-21`).

> 이벤트 계열 넷 중 `application_history` 하나만 쓴다. `meeting`·`decision`·`action_item` 은
> 사업계획서·IR·재무제표에서 나오지 않는다. 도면이 스스로 적은 **`선형 증가`** 가 F1-4 의

# 20_지식베이스구조

작성 2026년 8월 20일.

LLM 위키의 md 파일과 폴더를 어떻게 나눌지다. 뒷단 아키텍처는 `시스템구조.md`, 집필 파이프라인은 `19_집필에이전트.md`에 있다.

---

## 1. 파일을 나누는 기준

1. **한 파일에 한 주제.** 집필 에이전트가 파일 하나를 통째로 열어 쓴다.
2. **2,000자를 넘으면 쪼갠다.** 집필 프롬프트 하나에 파일이 4장에서 6장 들어간다.
3. **개수가 고정이면 파일, 늘어나면 폴더.** 서비스, 특허, 경쟁사, 인터뷰는 늘어난다.
4. **파일명이 인덱스다.** 에이전트가 경로만 보고 무엇이 들어 있는지 판단한다. 열지 않고 쓰는 경우도 있다.

## 3. 폴더별로 무엇이 들어가나

### 3.1 Company

| 파일 | 담는 것 |
|---|---|
| `회사소개.md` | 법인명, 설립일, 업력, 소재지, 대표자, 업종코드 |
| `비전.md` | 미션, 비전, 핵심가치 |
| `팀.md` | 구성원, 역할, 이력, 합류 상태 |
| `대표자.md` | 경력, 학력, 프로젝트, 수상 |
| `창업계기.md` | 왜 이 문제를 붙들게 됐는지 |

`대표자.md`를 `팀.md`에서 뺀 이유는 파운더 마켓 핏이 별도 평가 항목이라 분량이 크기 때문이다.

`창업계기.md`를 따로 두는 이유는 사업계획서 첫 문단에 그대로 들어가는 서술이라서다.

### 3.2 Product

서비스가 여러 개면 폴더가 늘어난다.

| 파일 | 담는 것 |
|---|---|
| `소개.md` | 서비스 한 줄 정의 |
| `문제와해결.md` | 고객군별 문제와 해결방안 짝 |
| `기능.md` | 기능 목록, 각 기능이 해결하는 문제 |
| `차별점.md` | 경쟁 대비 우위 |
| `개발현황.md` | 기능별 완료 여부, 로드맵 |
| `화면/{화면명}.md` | 와이어프레임, 목업, 사용 흐름 |

`문제와해결.md`가 사업계획서 전 항목에 들어가는 값이다. 문제 정의와 해결방안을 따로 두지 않고 한 파일에 짝으로 담는다. 따로 두면 짝이 어긋난 채로 굳는다.

### 3.3 Market

| 파일 | 담는 것 |
|---|---|
| `시장규모.md` | TAM, SAM, SOM 결과값 |
| `산출식-TAM.md` | 곱셈 과정 전체, 항별 근거와 등급 |
| `산출식-SAM.md` | 같음 |
| `산출식-SOM.md` | 같음 |
| `트렌드.md` | 성장 요인, 정책 동향 |
| `통계/{항목}-{값}.md` | 인용할 통계 하나. 출처와 기준 연도 |

산출식을 결과값과 분리하는 이유가 셋이다.

1. 심사에서 산출 근거를 묻는다. 값만 있으면 답을 못 한다
2. 공고에 맞춰 범위를 조정할 때 곱셈 항 하나만 바꾸면 된다
3. 근거가 약한 항이 어디인지 그 파일 안에서 보인다

통계를 파일 하나에 하나씩 담는 이유는 출처와 기준 연도가 통계마다 다르기 때문이다. 여러 개를 한 파일에 넣으면 어느 출처가 어느 숫자에 붙는지 흐려진다.

### 3.4 Competitor

`시스템구조.md`에서는 `Market/경쟁사.md` 하나였다. 폴더로 분리한다.

| 파일 | 담는 것 |
|---|---|
| `{업체명}.md` | 그 업체가 무엇을 하는지, 고객이 이걸로 하는 일, 대응하는 문제, 남는 불편, 기능 유무, 가격 |
| `비교축.md` | 2x2 매트릭스의 X축과 Y축 |

**대체재와 언멧니즈를 한 파일에 담는다.** 대체재만 있으면 값이 없다. "이게 있는데도 여전히 불편하다"가 기회의 증거이므로 쌍으로 있어야 한다.

업체마다 파일 하나다. 경쟁사가 늘어나면 파일이 늘어난다.

### 3.5 Customer

| 파일 | 담는 것 |
|---|---|
| `타깃고객.md` | 1차 고객, 2차 고객 정의 |
| `고객문제.md` | 페인포인트 자체 |
| `페르소나/{이름}.md` | 인구통계, 문제 2~3개, 현재 대응 방식 |
| `인터뷰/{세그먼트}-{인원}-{시점}.md` | 일시, 대상자 속성, 질문, 답변 원문 |
| `인용문/{세그먼트}-{주제}.md` | 그대로 인용할 발언 하나 |
| `검증/{활동}-{결과}.md` | 사전 신청, 지불 실적, 구매의향서, 베타 피드백 |

두 가지가 중요하다.

**인터뷰는 원문을 남긴다.** 요약만 두면 인용문을 다시 못 뽑고 다음 공고에서 각도를 바꿔 쓸 수 없다. 세그먼트별로 파일을 나눈다. 59명을 한 파일에 넣으면 열었을 때 프롬프트가 터진다.

**인용문을 별도 파일로 미리 뽑는다.** 경로로만 찾는 구조라 인터뷰 원문 안의 한 대목은 검색되지 않는다. 쓸 만한 발언은 파일로 올려 둔다.

설문조사는 `검증/`에 넣지 않는다. 심사위원이 신뢰도를 낮게 본다. 통계 자료 안에 포함된 설문은 `Market/통계/`에 넣는다.

### 3.6 BusinessModel

| 파일 | 담는 것 |
|---|---|
| `수익모델.md` | 런칭 시점에 돈이 들어오는 구조. 누가, 무엇에, 얼마를 |
| `가격정책.md` | 상품별 가격, 수수료율 |
| `판매전략.md` | 판매와 유통 채널 |

`수익모델.md`에 5년 뒤 확장 수익원을 섞지 않는다. 확장은 `Plan/고객확장.md`에 둔다. 섞이면 집필할 때 걸러야 한다.

### 3.7 Financial

| 파일 | 담는 것 |
|---|---|
| `매출.md` | 연도별 실적과 추정 |
| `비용.md` | 원가 구조 |
| `자금계획.md` | 자부담, 투자 유치, 보증, 대출 |
| `집행계획.md` | 지원금 항목별 배분 |

`집행계획.md`를 `자금계획.md`에서 분리한 이유는 인건비 비중 규칙이 걸리는 항목이라 검사 대상이기 때문이다.

### 3.8 Custom

| 파일 | 담는 것 |
|---|---|
| `특허/{상태}-{번호}.md` | 출원번호, 등록번호, 명칭, 청구항 요지 |
| `인증/{인증명}.md` | 연구소기업, 벤처기업, 이노비즈 |
| `기술/{기술명}.md` | 내부 알고리즘, 데이터 자산 |

특허 파일명에 상태를 넣는다. 예비창업은 출원, 초기창업은 등록이 기준선이라 상태가 판정에 직접 쓰인다.

### 3.9 Plan

`시스템구조.md`에 없던 폴더다.

| 파일 | 담는 것 |
|---|---|
| `일정.md` | 단계별 기간과 산출물 |
| `KPI.md` | 시점별 목표값 |
| `마케팅.md` | 분기별 채널별 계획 |
| `채용.md` | 시점별 인원 |
| `고객확장.md` | 2차, 3차 타깃 |
| `기술고도화.md` | 쌓이는 데이터와 그 데이터로 할 것 |
| `사회적가치.md` | ESG |

사업계획서의 성장 전략 항목이 통째로 여기서 나온다. 기존 트리에 담을 자리가 없었다.

### 3.10 Events

| 파일 | 담는 것 |
|---|---|
| `meetings/{날짜}.md` | 회의 요약 |
| `decisions.md` | 의사결정. 무엇을 왜 |
| `actions.md` | 할 일, 담당, 기한 |
| `applications/{공고명}-{연도}-{결과}.md` | 신청 이력, 결과, 탈락 사유 원문 |

`applications/`가 중복 수혜 제한 판정과 다음 지원 보강에 쓰인다.

## 4. 파일명 규칙

1. **숫자가 든 파일은 이름에 값과 기준을 넣는다.**

```
Customer/인터뷰/취준생-59명-2026Q1.md
Market/통계/공고건수-1680건.md
Events/applications/예비창업패키지-2025-탈락.md
```

에이전트가 파일을 열지 않고도 인원수와 결과를 안다. 조회 횟수가 준다.

2. **인스턴스 폴더는 이름을 그대로 쓴다.** 경쟁사는 실명이다. A사, B사로 가리지 않는다.

3. **경로가 곧 노드 제목이다.** `Customer/인터뷰/취준생-59명-2026Q1`이 집필 에이전트가 부르는 이름이다.

4. **규칙을 벗어난 파일은 안 쓰인다.** 임베딩 검색을 쓰지 않으므로 경로 목록에 없으면 없는 것이다.

## 5. 파일 머리

모든 파일이 같은 머리를 갖는다.

```markdown
---
grade: 실측 | 1차 | 2차 | 가정 | 미정
source: 출처 기관명 또는 원본 파일명
source_path: 원본 위치
base_date: 기준 연도나 시점
updated_at: 갱신일
```

## 6. 기존 트리에서 달라지는 것

`시스템구조.md` 1장의 Business Wiki 트리와 비교한 차이다.

| | 무엇 | 왜 |
|---|---|---|
| 1 | `Plan/` 신설 | 성장 전략 항목을 담을 자리가 없었다 |
| 2 | `Competitor/`를 `Market/`에서 분리 | 대체재와 언멧니즈를 담아야 하고 경쟁사가 여러 개다 |
| 3 | `Market/산출식-*.md` 신설 | 시장규모 결과값만 있으면 산출 근거를 못 댄다 |
| 4 | `Product/{svc}/문제와해결.md` 신설 | 문제와 해결 짝이 전 항목에 들어가는데 자리가 없었다 |
| 5 | `Customer/`를 파일에서 폴더로 | 인터뷰, 인용문, 페르소나가 여러 개다 |
| 6 | `Customer/인용문/` 신설 | 원문 안의 한 대목은 경로로 못 찾는다 |
| 7 | `Product/{svc}/화면/` 신설 | 프로토타입 화면을 담을 자리가 없었다 |
| 8 | `Financial/집행계획.md` 분리 | 인건비 비중 규칙이 걸리는 검사 대상이다 |
| 9 | `Company/대표자.md`, `창업계기.md` 분리 | 파운더 마켓 핏과 창업 배경이 별도 서술이다 |
| 10 | `Market/통계/` 신설 | 통계마다 출처와 기준 연도가 다르다 |

`시스템구조.md` 2.5장의 topic 온톨로지도 위 신설 폴더에 맞춰 늘려야 한다. 지금 23개인데 `Plan/` 일곱 개와 `Competitor/` 두 개가 빠져 있다.

## 7. 남은 결정

1. 폴더명을 영문으로 둘지 한글로 통일할지. 지금은 `시스템구조.md`를 따라 영문 폴더에 한글 파일명이다. `19_집필에이전트.md`의 노드 제목 1단 목록도 여기에 맞춰야 한다
2. 파일 하나 2,000자 상한이 맞는지 실측
3. 인용문 파일을 인터뷰에서 자동으로 뽑을지, 사람이 지정할지
4. `Custom/`이라는 이름을 유지할지. 특허와 인증과 기술이 들어 있어 이름이 내용을 안 가리킨다
