# ADR-0036: 도메인 없이 IP 인증서로 HTTPS 를 세운다

- 상태: 채택됨
- 날짜: 2026-08-18
- 대체하는 것: [ADR-0035](0035-api와-워커를-자체-서버로-내리고-vercel은-화면만-맡는다.md) **결정 2 하나** — "화면이 HTTPS 인데 API 가 HTTP 인 것이 문제가 되지 않는다". 나머지는 그대로다
- 관련: [ADR-0029](0029-사용자-파일을-회사-단위-콘텐츠-주소로-로컬에-둔다.md) — 개인정보를 밖으로 안 낸다는 결정

## 맥락

[ADR-0035](0035-api와-워커를-자체-서버로-내리고-vercel은-화면만-맡는다.md)가 "도메인이 없어서 인증서를 못 받는다. Let's Encrypt 는 IP 에 발급하지 않는다"고 적고 평문으로 갔다. **그 전제가 틀렸다.**

Let's Encrypt 가 **2026-01-15 부터 IP 주소 인증서를 정식 발급한다**([발표](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)). 조건이 둘이다.

1. `shortlived` 프로파일이어야 한다
2. 유효기간이 **160시간(약 6.7일)** 이다

그리고 평문으로 두는 대가가 작지 않았다. **토큰이 유일한 방어인데 그 토큰이 매 요청마다 평문으로 공개망을 지난다.** 한 번만 관찰당하면 그대로 넘어가고, 넘어가면 올리기 경로가 열린다 — 총량 쿼터도 레이트 리밋도 없다.

## 결정

### 1. Caddy 가 IP 인증서를 받는다

```
{
	default_sni 49.247.203.210
}

49.247.203.210 {
	tls {
		issuer acme {
			profile shortlived
		}
	}
	reverse_proxy 127.0.0.1:8101 { … }
}
```

받은 것을 확인했다.

```
issuer   C=US, O=Let's Encrypt, CN=YE2
SAN      IP Address:49.247.203.210 (critical)
기간      2026-08-18 12:06 → 2026-08-25 04:06 UTC
검증      ssl_verify_result: 0
```

### 2. `default_sni` 가 없으면 아무것도 안 된다

**이 한 줄이 이 결정의 함정이다.** RFC 6066 이 SNI 를 호스트명으로만 정해서 클라이언트가 **IP 리터럴에는 SNI 를 안 싣는다.** 그러면 Caddy 가 어느 사이트인지 못 골라 핸드셰이크를 `tlsv1 alert internal error` 로 끊는다.

**인증서를 정상 발급받고도 아무도 못 붙는 상태가 된다.** 발급 로그는 성공이라 원인이 안 보인다.

**`tls` 안의 하위 지시어가 아니라 전역 옵션이다.** 사이트 블록에 쓰면 `unknown subdirective: default_sni` 로 **기동이 죽고 컨테이너가 재시작 루프에 빠진다.**

### 3. Caddy 2.11.4 는 IP 인증서를 막지 않는다

[caddyserver/caddy#7399](https://github.com/caddyserver/caddy/issues/7399) 가 `subject '...' cannot have public IP certificate` 로 막힌다고 적었는데 **이 버전에서는 통과한다.** 실측으로 확인했다 — 주문이 들어가고 발급까지 갔다. 이슈를 읽고 포기하지 않는다.

### 4. 6일짜리를 받아들인다

Caddy 가 ACME Renewal Information(ARI)을 받아 갱신 시각을 스스로 잡는다. **짧은 것이 위험이 아니라 자동화의 전제다.**

다만 **Caddy 와 `finnect-caddy-data` 볼륨이 계속 살아 있어야 한다.** 6일 넘게 내려가 있으면 만료된다. 둘 다 `restart: unless-stopped` 다.

### 5. Cloudflare Tunnel 을 안 쓴다

포트를 안 여는 장점이 있지만 **TLS 가 Cloudflare 에서 끝난다** — 사업자등록증과 재무제표가 평문으로 그 구간을 지난다는 뜻이다. [ADR-0029](0029-사용자-파일을-회사-단위-콘텐츠-주소로-로컬에-둔다.md)가 클라우드 OCR 을 뺀 이유와 같은 이유로 안 쓴다.

그리고 **도메인 없이는 주소가 매번 바뀐다**(`trycloudflare.com`). `FINNECT_API` 가 빌드 시점에 박히는 값이라 재시작마다 재배포해야 한다.

## 결과

- **`FINNECT_API` 가 `https://49.247.203.210` 이다.** 고치면 web 을 다시 배포해야 한다
- **평문 구간이 없어졌다.** [ADR-0035](0035-api와-워커를-자체-서버로-내리고-vercel은-화면만-맡는다.md)가 단 "도메인이 생기기 전까지 실제 개인정보를 올리지 않는다"는 단서를 **뗀다**
- **80·443 이 이미 열려 있었다.** Let's Encrypt 가 둘 다로 검증에 성공한 것이 증거다 — `tls-alpn-01`(443)과 `http-01`(80) 둘 다 닿았다. 따로 연 것이 아니다
- **자기 공인 IP 로 서버 안에서 접속하면 안 된다.** 헤어핀 NAT 라 `000` 이 난다. 점검은 `--connect-to 49.247.203.210:443:127.0.0.1:443` 으로 한다. **이걸 모르면 멀쩡한 서비스를 죽은 것으로 오진한다**
- **IP 가 바뀌면 인증서를 다시 받아야 한다.** 지금 IP 는 고정으로 보이지만 확인하지 않았다
- **여전히 레이트 리밋이 없다.** 토큰이 새는 경로는 좁혔지만, 새고 나면 올리기가 무제한인 것은 그대로다. 별 작업으로 남긴다
- **되돌리는 조건: 도메인이 생기면** IP 를 이름으로 바꾸고 `profile shortlived` 를 뺀다(도메인은 90일). `default_sni` 도 같이 뺄 수 있다
