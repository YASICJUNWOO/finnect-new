# ADR-0049: 저장값과 LLM 와이어를 `value`·`event` 로 옮긴다

- 상태: 채택됨
- 날짜: 2026-08-22
- 대체하는 것: [ADR-0048](0048-노드-층을-없애고-topic-을-orbit-에-직접-매단다.md) **결정 3**(「저장을 안 바꾼다. 마이그레이션이 없다」). 결정 1·2·4·5 는 그대로다
- 관련: [ADR-0032](0032-위키가-담을-것-정형-슬롯과-서술-노드.md) · [ADR-0037](0037-llm-제공자를-openai-로-정하고-gpt-5-6-luna-부터-잰다.md) · [ADR-0031](0031-사실-추출을-포트-뒤로-미루고-스텁으로-배관을-먼저-세운다.md)

## 맥락

ADR-0048 이 층을 셋(`sector`·`orbit`·`topic`)으로 줄이고 topic 의 타입을 **`value`·`event`** 로 정했다. 결과 절이 「어휘가 넷 + `topic` → 셋」이라고 적었다.

**그런데 코드가 절반만 따라갔다.** `node` 계열 심볼은 전부 지워졌는데(`NODES`·`TOPIC_NODE`·`node_of` 0건) `slot` 계열은 손도 안 댔다. 새로 만든 `VALUE_TOPICS`·`EVENT_TOPICS` 는 제품 코드에서 **아무 데서도 안 쓰였다** — 테스트 세 곳뿐이었다.

2026-08-22 그 비대칭을 없애면서 남은 자리가 드러났다. 어휘가 `value`·`event` 인데 **저장값과 LLM 와이어가 `slot`·`node` 라서**, 한 사실을 설명하는 데 말이 두 벌 필요했다.

```
LLM  →  kind='slot'  →  place_kind='slot'  →  화면 "value topic"
```

결정 3 은 이걸 **싸게 만들려고** 넘어간 자리였다(「이 결정이 이 ADR 을 싸게 만든다」). 실제로 쌌다. 대신 어휘가 갈린 채로 남았고, 도면을 고칠 때마다 「이건 저장값이라 옛말이 맞다」는 주석을 달아야 했다.

## 결정

### 1. 저장값을 옮긴다. 마이그레이션이 있다

```
wiki_fact.place_kind    'slot' → 'value'    · 'node' → 'event'
wiki_fact.dedupe_key    'slot|…' → 'value|…' · 'node|…' → 'event|…'
item_need.place_kind    같은 매핑
```

`uncategorized` 는 안 바꾼다 — ADR-0048 이 그 이름을 손대지 않았다.

**세 자리가 한 마이그레이션이어야 한다.** `dedupe_key` 를 같이 안 옮기면 유니크 키가 `(company_id, dedupe_key)` 라서, 접두사만 코드에서 바뀐 다음 빌드가 같은 사실을 **새 행으로** 앉힌다. 에러가 아니라 **사실 수가 조용히 는다** — [plan/12](../plan/12-사업-위키-구축.md) T-0092 가 `--build` 에서 겪은 것과 같은 실패다.

`item_need` 를 빠뜨리면 양식 읽기가 만든 자리가 전부 미아가 된다. `company_id` 가 없는 표라 회사 하나가 아니라 **전부** 깨진다.

### 2. LLM 와이어도 같이 옮긴다

프롬프트 「## 두 종류」와 `_SCHEMA` 의 `kind` enum 을 `["value", "event"]` 로 바꾼다.

**경계에서 번역하지 않는다.** `merge.place()` 가 `'slot'→'value'` 로 옮기는 길도 있었고 그쪽이 정확도 위험이 0 이다. 안 고른 이유는 그러면 **어휘가 여전히 두 벌**이고, 이 ADR 이 없애려는 것이 정확히 그것이기 때문이다. 번역 계층은 어휘를 통일한 것처럼 보이게 하면서 실제로는 한 자리 더 만든다.

### 3. 대가 — 재현율을 다시 재야 한다

프롬프트가 바뀌었다. 2,235자 → 2,246자.

```
옛 프롬프트 sha256  ba2d8ed1e7e5
새 프롬프트 sha256  16535ce83132
```

**같은 날 쟀다** — [2026-08-22 실측](evidence/2026-08-22-어휘-교체-전후-추출-정확도.md). 옛 프롬프트와 새 프롬프트를 두 번씩 돌렸다.

```
옛 ba2d8ed1e7e5   재현율 60.2% · 58.5%     정밀도 40.6% · 38.1%
새 16535ce83132   재현율 58.5% · 56.8%     정밀도 32.9% · 33.8%
```

**어휘 교체가 재현율을 해쳤다고 말할 근거가 없다.** 차이가 ~2%p 인데 같은 프롬프트의 회차 간 변동이 1.7%p 다. n=2 로는 안 갈린다 — 「영향이 없다」고도 말하지 않는다.

**대신 기준선 쪽이 흔들렸다.** [2026-08-20 실측](evidence/2026-08-20-위키-추출-정확도-실측.md)의 **70.3% 가 옛 프롬프트로도 재현되지 않는다.** 모델 ID·픽스처·명령이 다 같은데 83건이 오늘 71 · 69 다. 원인을 모르고 가르는 실측을 안 했다 — 그래서 **70.3% 를 이제 성능으로 인용하지 않는다.**

정밀도는 새 프롬프트에서 낮고 낸 것이 175·181 → 210·198 로 늘었다. **그걸로 「정밀도가 떨어졌다」고 보고하지 않는다** — 정답지가 사람이 고른 일부라 이 픽스처로는 정밀도를 못 잰다.

육안 30건을 봤다. 실측 문서에 목록이 있다.

### 4. API 와이어는 안 바꾼다

`api/wiki_schemas.py` 의 `slot: str` · `slots: int` 은 그대로 둔다. 저 이름들이 담는 **값**은 자리 이름(`funding`)이지 `'slot'` 문자열이 아니라, 어휘가 갈리는 자리가 아니다.

바꾸면 `web/lib/wiki.ts` · `WikiPanel.tsx` · `Upload.tsx` · [api-contract.md](../api-contract.md) 가 같이 가야 하고, **웹과 API 가 같은 순간에 배포돼야 한다.** 그 창을 이 변경에 끼워 넣을 이유가 없다.

## 결과

**얻는 것.** 한 사실을 설명하는 말이 한 벌이 된다. LLM 이 `kind='value'` 로 답하고, `place_kind='value'` 로 앉고, 화면이 「value topic」이라고 부른다.

**대가 셋.**

1. **마이그레이션이 생겼다.** ADR-0048 이 자랑한 「마이그레이션이 없다」가 없어졌다. 배포 DB 에도 `alembic upgrade head` 를 돌려야 한다([deploy.md](../deploy.md) §2) — 안 돌리면 **옛 행은 `place_kind='slot'` 이고 새 행은 `'value'` 라 위키가 반쪽만 보인다.** 화면은 안 죽고 자리가 비어 보인다
2. **70.3% 를 잃었다.** 새 프롬프트가 나빠서가 아니라 **옛 프롬프트로도 재현이 안 돼서**다([실측](evidence/2026-08-22-어휘-교체-전후-추출-정확도.md)). 이 ADR 이 의심받아 잰 것인데 기준선이 흔들렸다 — **다음 실측부터 응답의 실제 모델 ID 를 같이 적는다**
3. **`tests/fixtures/wiki/facts.json` 의 `kind` 118건이 바뀌었다.** `anchor` 는 한 글자도 안 건드렸다 — 건드리면 근거를 잃고 사실이 버려진다(`tests/test_wiki_extract.py` 가 막는다)

**안 바꾼 것.** `SlotValue`·`ELIGIBILITY_SLOTS`(`match/profile.py`)는 이름을 남겼다. 저기는 자격 판별의 어휘라 위키 층 이름과 다른 축이고, 이 ADR 의 범위가 아니다.
