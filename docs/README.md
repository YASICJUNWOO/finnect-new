# docs/ — 문서 지도

창업 지원사업 **자격 판별**과 **사업계획서 집필**을 잇는 제품이다.

```
docs/
├─ SPEC.md      제품 정본 — 무엇을 만드는가
├─ design/      화면 — 어떻게 보이는가
├─ adr/         결정 — 왜 그렇게 정했는가
├─ plan/        계획 — 어떤 순서로 만드는가
├─ task/        작업 — 지금 무엇을 하는가
└─ archive/     폐기된 방향
```

---

## 어디부터 읽나

| 목적 | 읽을 것 |
|------|---------|
| 제품이 뭔지 알고 싶다 | [`SPEC.md`](SPEC.md) — 이것 하나면 된다 |
| 지금 뭘 해야 하나 | [`task/README.md`](task/README.md) 보드 |
| 왜 이렇게 정했나 | [`adr/README.md`](adr/README.md) 목록 |
| 화면을 만들려면 | [`design/README.md`](design/README.md) |
| 전체 순서 | [`plan/README.md`](plan/README.md) |

**충돌 시 `SPEC.md`가 우선한다.**

### 막혀 있는 것 하나

[ADR-0010 배점 전제 폐기](adr/0010-배점-전제-폐기.md)가 **미결**이다.

실측 결과 초기창업패키지·창업도약패키지가 **항목별 배점을 공개하지 않는다.** 창업 분야 전체로도 명시율 25%다. 승부처 화면(S3)이 배점 순 정렬을 전제했으므로 축을 다시 잡아야 한다.

이것이 [plan/04](plan/04-화면.md)의 S3·S4와 [plan/05](plan/05-집필.md)를 막고 있다. [plan/00](plan/00-미결-해소.md)에서 푼다.

**막히지 않은 것**: [plan/01 기반](plan/01-기반.md), [02 수집과 추출](plan/02-수집과-추출.md), [03 자격 판별](plan/03-자격-판별.md)은 병행 가능하다.

## 문서를 쓰는 규칙

1. **사실 주장에는 근거 링크를 붙인다.** 근거 없는 주장은 `SPEC.md` §8에 날짜와 함께 올리거나, 올릴 수 없으면 쓰지 않는다.
2. **결정은 ADR에 남긴다.** ADR에 없는 결정은 결정이 아니라 관성이다.
3. **틀린 문서를 미리 쓰지 않는다.** 계층별 상세 사양은 코퍼스를 보고 나서 쓴다([plan/README.md](plan/README.md)).
4. **자동 판정 수치를 육안 검증 없이 쓰지 않는다.** 실측에서 배점 탐지기가 30% → 45% → 25%로 갔고 앞의 둘은 오탐이었다.

이 규칙들은 전부 실제로 당해서 생겼다. 배경은 [ADR-0001](adr/0001-정본-문서-체계.md)에 있다.
