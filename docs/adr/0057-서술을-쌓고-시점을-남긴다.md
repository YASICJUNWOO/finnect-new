# ADR-0057: 서술을 쌓고 시점을 남긴다

- 상태: 채택됨
- 날짜: 2026-08-22
- 대체: [ADR-0056](0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md) **결정 3 의 EVENT 병합 규칙 한 줄**(`(node, key)` → 같으면 근거만 더한다). 나머지는 전부 그대로 산다 — 트랙 둘, 세 층, `key` 가 라벨이자 병합 키라는 것.
- 그대로 사는 것: [ADR-0014](0014-통합-그래프와-근거-청크.md) 근거 청크 · [ADR-0013](0013-판정-두-층.md) 자격과 적합도 분리 · [ADR-0056](0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md) 결정 1·2·4·5·6·7

## 맥락

[ADR-0056](0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md) 결정 3 이 EVENT 의 병합을 `(node, key)` 로 정했다. **같은 key 면 같은 사실이니 근거만 더한다**는 규칙이다. 2026-08-22 실제 위키를 열어 보니 그 한 줄에서 셋이 동시에 무너져 있었다.

**① 둘째 문장이 조용히 사라진다.** `build.py` 가 같은 `dedupe_key` 를 찾으면 `merged += 1` 을 세고 근거만 맨다 — **행의 `text` 를 안 건드린다.** 그래서 먼저 앉은 문장이 이기고, 「먼저」를 정하는 것은 `order_by(UserFile.filename)`, 즉 **파일 이름 사전순**이다.

`c_dasiro` 의 `Company/팀` 이 그 자국을 그대로 들고 있다.

```
대표 윤세라는 2021년부터 3년간 성남에서 식자재 소매점 두 곳을 직접 운영했습니다
> 근거 3 — 피치덱_2026H2.pptx 10쪽 · 회사소개서_v3.pdf 4쪽 · 사업계획서_….docx
```

문서 셋이 같은 key 를 냈고 화면에 남은 문장은 하나다. **나머지 둘이 뭐라고 썼는지 어디에도 없다.** 근거가 셋인데 그 셋이 정말 같은 말인지 확인할 방법도 같이 없어졌다.

**② EVENT 에 시간축이 아예 없다.** `build.py` 가 `as_of=fact.as_of if is_value else None` 로 **시점을 버리고** 있었다. 컬럼(`wiki_fact.as_of`)은 있는데 EVENT 행에는 한 번도 안 들어갔고, 프롬프트도 「as_of — 언제 기준 값인가 (**value 일 때만**)」라고 시켰다. 실측:

```
event  총 31 · as_of 0 · status 0
value  총  1 · as_of 0 · status 1
```

시점이 없고 상태가 없고 `(node, key)` 가 유일하다. **셋이 합쳐져서 이력이 설 자리가 없다.**

**③ 그래서 추출기가 key 로 도망친다.** 시점을 남길 곳이 없으니 시점을 **이름에 박는다.**

```
team_roles_2026_08      / team_roles_2025_11
paid_stores_102_2026_01 / paid_stores_93_2025_12
runway_2027q1           / runway_18m
```

`team_roles` 는 한 자리인데 key 가 둘로 갈렸다. 갈린 순간 「같은 것의 이력」이라는 정보가 사라진다 — 화면은 그냥 관계없는 사실 둘로 읽는다.

**`paid_stores_*` 는 다른 병이다.** 유료 매장 수는 102·93 으로 **값 하나**다. VALUE 로 나왔으면 `paid_stores` 한 key 에 시점 둘이 되어 이미 시계열이 됐을 것이다([ADR-0056](0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md) 결정 3 의 VALUE 규칙이 그것을 한다). EVENT 로 간 이유는 프롬프트의 판정 기준이 「값 하나 / 서술」 두 줄뿐이라서다.

## 결정

### 1. EVENT 의 병합 키에 **시점을 더한다.** 문장은 넣지 않는다

```
event|{경로}|{key}|{as_of}
```

`팀 구성` 의 2026-08 과 2025-11 이 이제 행 둘이고, `key` 는 `팀 구성` 하나면 된다.

**문장을 키에 넣는 안을 검토했고 버렸다.** 같은 사실이 문서마다 다르게 쓰여 있기 때문이다. 픽스처의 재구매율 하나가 네 문서에 이렇게 있다.

```
월 재구매율이 도입 3개월 차 34%에서 5개월 차 51%로 올랐다
월 단위 재구매율이 도입 3개월 차 34%에서 5개월 차 51%로 상승했다
월 재구매율이 도입 3개월 차 34%에서 5개월 차 51%로 올랐습니다
월 재구매율 34% → 51%
```

문장으로 가르면 **이 넷이 사실 넷이 된다.** 픽스처 README §3 이 그것을 「틀렸다」의 예로 세워 뒀고, `tests/test_wiki_build.py` 가 잠가 둔다.

**같은지 아닌지를 정하는 것은 `key` 이고 그것은 추출기가 준다.** 프롬프트가 「같은 내용이 문서 여럿에 다른 문장으로 있으면 같은 key 를 줘라 · 확신이 없으면 새 key 를 만든다」고 시킨 그 판단이다. 코드가 문장을 비교해서 그 판단을 뒤집으면, `key` 를 라벨이자 병합 키로 둔 [ADR-0056](0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md) 결정 3 이 통째로 무의미해진다.

**「둘째 문장이 버려진다」는 관찰은 반만 맞았다.** 같은 key·같은 시점이면 먼저 온 `text` 가 남고 나머지는 안 쓰인다. 그러나 각 문서의 **원래 표현은 `wiki_evidence.quote` 에 그대로 쌓인다** — 근거를 펼치면 문서별 원문이 나온다. `text` 는 우리가 고른 대표 문장이고 `quote` 가 출처다. 잃는 것은 대표 문장의 후보들이지 정보가 아니다.

**남는 한계:** 시점이 없는 서로 다른 서술이 같은 key 로 오면 여전히 하나만 대표 문장이 된다(`팀 변동` 에 「구조조정 10명 감소」와 「신입 채용」). 이건 추출기가 **다른 key 를 줘야** 하는 자리다 — 프롬프트가 이미 그렇게 시키고 있고, 데이터로 갈릴 방법이 없으므로 코드가 대신 판단하지 않는다.

### 2. EVENT 에 시점을 저장한다

`build.py` 의 `if is_value` 를 뗀다. 컬럼은 이미 있고 추출기(`NodeFact.as_of`)도 이미 들고 온다 — **저장 직전에 버리고 있었다.**

프롬프트의 「value 일 때만」도 뗀다. `2026년 8월 기준 개발 8명…` 은 값이 하나가 아니라 EVENT 이지만 **시점은 분명히 있다.**

### 3. EVENT 에 상태를 안 매긴다. 쌓이는 것이지 갈리는 것이 아니다

`status` 는 NULL 로 둔다([ADR-0056](0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md) 그대로). `merge.decide` 를 EVENT 에 돌리지 않는다.

**돌리면 정상 상태를 모순이라고 말하게 된다.** 저 함수는 「한 자리에 값이 둘이면 충돌」인데, EVENT 는 한 key·한 시점에 문장이 여럿인 것이 정상이다. 「구조조정 10명 감소」와 「신입사원 채용」이 같은 달 일이면 그건 충돌이 아니라 그냥 둘 다 일어난 것이다.

**이력은 상태 컬럼이 아니라 정렬이 만든다.** 뷰가 `key` 로 묶고 묶음 안에서 `as_of` 내림차순으로 세운다. 옛 서술은 밀려난 것이 아니라 그때의 기록이라 지우지도 흐리지도 않는다.

| | 정체성 | 병합 | 상태 |
|---|---|---|---|
| key · VALUE | `(key, 한정어, 시점, 값)` | 시점 다름 → 시계열 · 시점 같고 값 다름 → **충돌** | `current`·`superseded`·`conflict` |
| key · EVENT | `(node, key, 시점, 문장)` | 같으면 근거만 더한다 · **다르면 쌓인다** | **없다(NULL)** |

### 4. 뷰가 `key` 로 묶는다

마크다운은 `## {key}` 한 절 아래 사실 여럿, 화면은 이름 줄 하나 아래 사실 여럿이다. VALUE 는 제목에 값이 붙는다(`## 조달액 (시드) — 300000000`).

**값이 갈린 자리도 같은 절에 나란히 선다.** 같은 key 에 값 둘이 곧 충돌이므로([ADR-0056](0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md)) 접으면 값 하나가 사라진다 — 절 안에서 둘이 보이는 것이 그 상태의 표현이다.

**단위를 안 붙인다.** `profile.display()` 의 단위표는 매칭 정보 열넷의 것이고 트랙 A 의 key 는 자유 문자열이라 거기 없다. 없는 단위를 지어 붙이면 값이 거짓이 된다.

### 5. 「값 하나면 VALUE」를 프롬프트가 판정할 수 있게 적는다

지금 프롬프트는 두 줄이다.

```
- `value` — 값 하나. `value` 에 정규화한 값, `text` 에 사람이 읽는 문장
- `event` — 서술. `text` 가 내용이고 `value` 는 비운다
```

`유료 매장 102곳` 이 어느 쪽인지 이걸로는 안 갈린다. **판정 질문과 실패 예시를 넣는다** — 「이 사실을 숫자·날짜·이름 하나로 적을 수 있나」와, 실제로 틀린 `paid_stores` 를 그대로 예시로 쓴다.

이건 모델 변경이 아니라 추출 품질 문제다. **결정 1~4 없이 이것만 해도 `paid_stores` 는 고쳐진다** — 다만 `team_roles` 는 안 고쳐진다. 값이 하나가 아니라서다.

## 결과

- **서술이 사라지지 않는다.** 문서 셋이 같은 key 에 다른 말을 하면 셋 다 남고 근거가 각각 붙는다.
- **`team_roles_2026_08` 같은 이름이 필요 없어진다.** 시점이 컬럼에 있으므로 key 는 `팀 구성` 하나면 된다.
- **`--rebuild` 가 필요하다.** 병합 키가 바뀌므로 옛 행의 `dedupe_key` 가 낡는다. 마이그레이션이 재계산한다 — 안 하면 같은 사실이 새 행으로 앉아 **조용히 는다**(`(company_id, dedupe_key)` 가 유니크라 [ADR-0049](0049-저장값과-llm-와이어를-value-event-로-옮긴다.md) 때와 같은 함정이다). **배포 DB 에도 돌려야 한다.**
- **사실 수가 조금 는다.** 시점이 다른 서술이 이제 행 둘이다. 같은 말을 다르게 쓴 것은 **여전히 하나**다 — 문장을 키에 안 넣었으므로 재구매율 넷은 넷 그대로 하나로 선다.
- **포기하는 것 ①** — **시점 없는 서로 다른 서술은 여전히 대표 문장 하나만 남는다.** 데이터로 「같은 사실의 다른 표현」과 「다른 사실」을 가를 방법이 없어서, 그 판단을 추출기에 맡긴 채로 둔다. 원문은 근거에 남으므로 사라지는 것은 아니다.
- **포기하는 것 ②** — **중복을 코드가 못 지운다.** 두 문장이 같은 말인지는 의미 판단이라 결정론으로 안 된다. **유사도로 접지 않는다** — [ADR-0056](0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md) 결정 6 이 같은 이유로 이미 거절했다.
- **못 하는 것** — **트랙 A 의 정확도는 여전히 못 잰다.** 정답지가 없다는 사정은 이 결정이 안 바꾼다.
