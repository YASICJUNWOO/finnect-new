# ADR-0054: 초안을 만드는 길을 API 에 열고 (공고, 회사) 단위로 잠근다

- 상태: 채택됨
- 날짜: 2026-08-22
- 관련: [ADR-0034](0034-업로드를-같은-api-에-두고-못-쓰는-곳에서는-503-으로-답한다.md) 올리기 · [ADR-0035](0035-api와-워커를-자체-서버로-내리고-vercel은-화면만-맡는다.md) API 위치 · [ADR-0015](0015-무인-생성.md) 무인 생성 · [ADR-0028](0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md) 질문 타이밍 · [plan/21](../plan/21-동선을-끝까지-잇는다.md) T-0121

## 맥락

초안을 만드는 길이 **CLI 하나뿐이었다.** `uv run python -m finnect.draft --company … --notice …` 다.

[plan/16](../plan/16-항목마다-초안을-쓴다.md)이 T-0068 을 *「절반 — 비동기가 없다」* 로 닫았고, [plan/16](../plan/16-항목마다-초안을-쓴다.md)과 [`api-contract.md`](../api-contract.md) 둘 다 *「백그라운드 실행은 화면이 붙는 슬라이스에서 plan/15 의 202 + 락 패턴을 복사한다」* 고 적어 뒀다. 그 슬라이스가 [plan/21](../plan/21-동선을-끝까지-잇는다.md) 이다.

**「초안작성 버튼」이 누를 곳이 없다는 것이 이 결정의 전부다.** 사용자 동선 네 칸 중 셋째가 터미널에 있었다.

두 가지를 정해야 했다.

1. **어디에 두나.** 올리기와 같은 API 인가, 별도 워커인가
2. **무엇을 잠그나.** 위키 빌드는 회사 단위로 잠근다([plan/12](../plan/12-사업-위키-구축.md) T-0094). 초안도 그런가

## 결정

**1. 같은 API 에 둔다. `POST /api/notices/{source}/{external_id}/draft?company={id}` · 202.**

[ADR-0034](0034-업로드를-같은-api-에-두고-못-쓰는-곳에서는-503-으로-답한다.md)가 올리기에 대해 정한 것을 그대로 따른다. 별도 서비스를 세우지 않는다 — 부르는 쪽이 화면 하나이고 DB 가 같다.

**2. `finnect.draft.service` 를 함수 안에서 임포트한다.** `api/app.py` 가 `wiki.service` 에 대해 이미 하는 것과 같다. **최상단에 두면 `import finnect.api.app` 이 `llm` 과 `httpx` 를 끌고 온다** — 읽기 경로만 담은 배포본에서 그 임포트가 죽고, 로컬은 통과한다. `tests/test_admin_api.py` 가 막고 있는 경계를 **넘지 않고 우회한다.**

**3. 락 단위가 `(회사, 공고)` 다.** 위키 빌드와 다르다.

| | 잠그는 단위 | 왜 |
|---|---|---|
| 위키 빌드 | **회사** | 사실이 회사 하나의 표에 병합돼 들어간다. 둘이 같이 돌면 `dedupe_key` 가 경합한다 |
| 초안 집필 | **(회사, 공고)** | `draft` 행의 유니크 키가 `(company_id, notice_id, document_id)` 다. 같은 회사가 공고 둘을 동시에 쓰는 것은 **경합할 자리가 없다** |

같은 회사를 통째로 잠그면 **공고 A 의 초안이 도는 동안 공고 B 를 못 쓴다.** 막을 이유가 없는 것을 막는 것이고, 초안 한 벌이 항목 수십 개라 그 시간이 길다.

**4. 락 키를 `hash()` 로 만들지 않는다.** [plan/12](../plan/12-사업-위키-구축.md) T-0094 가 밟은 함정이다 — `PYTHONHASHSEED` 가 프로세스마다 달라 둘 다 통과한다. 문자열 키를 그대로 쓴다.

**5. 프로세스 안에서만 잠근다.** 위키 빌드는 **트랜잭션 어드바이저리 락**까지 갔는데(CLI 와 서비스가 같이 돌았다) 여기는 `ingest/jobs.py` 의 `threading.Lock` 으로 둔다.

근거가 대칭이 아니다 — 위키는 **CLI 와 API 가 같은 회사를 동시에 세우는 일이 실제로 일어났고** 그 결과가 조용한 되돌림이었다. 초안은 같은 일이 나도 `draft` 유니크 키가 막고, 막힌 쪽이 예외를 낸다. **조용히 틀리지 않는다.** 어드바이저리 락이 필요해지면 그때 이 결정을 대체한다.

**6. 못 쓰는 서버에서 503 을 내지 않는다.** [ADR-0034](0034-업로드를-같은-api-에-두고-못-쓰는-곳에서는-503-으로-답한다.md)의 503 은 **로컬 디스크가 없어서**였다. 초안은 디스크를 안 쓰고 DB 와 LLM 만 쓴다 — [ADR-0035](0035-api와-워커를-자체-서버로-내리고-vercel은-화면만-맡는다.md) 뒤로 API 가 자체 서버라 둘 다 있다. **키가 없으면 그 사실을 그대로 낸다**(`started: false` + 이유). 조용히 빈 초안을 만들지 않는다.

**7. 진행을 `GET …/draft` 가 같이 낸다.** 별도 진행 경로를 안 판다 — 올리기와 다르다. 올리기는 파일마다 단계 다섯이 있어 진행이 응답 하나를 채우지만, 초안은 **항목이 다 써진 뒤에야 볼 것이 생긴다.** `running` 한 값이면 화면이 「쓰는 중」과 「다 썼다」를 가른다.

## 결과

- **동선 셋째 칸이 터미널에서 화면으로 온다.** 공고에 들어가 버튼을 누르면 202 가 오고 화면이 `running` 을 따라간다
- 쓰기 API 가 **하나에서 둘**이 된다(올리기 · 초안 만들기). [`api-contract.md`](../api-contract.md)의 *「나머지는 그대로 전부 `GET`」* 이 한 번 더 틀린다
- [plan/16](../plan/16-항목마다-초안을-쓴다.md) T-0068 이 닫힌다
- **비용이 사용자 손에 들어간다.** 지금까지 LLM 호출은 우리가 CLI 로 냈다. 버튼이 생기면 누르는 만큼 나간다 — 인증이 없는 동안은 **누구나 누를 수 있다**

### 포기한 것

**큐를 안 만든다.** `ingest/jobs.py` 는 스케줄러가 아니라 락이다([ADR-0011](0011-수집-실행-화면.md)). 프로세스가 죽으면 실행도 죽고 자국만 남는다. 올리기가 `_stranded()` 로 이어받는 것처럼, 초안도 **다시 누르면 이어받는다** — 이미 쓴 항목은 `draft_item` 에 있고 집필기가 그것을 다시 쓰지 않는다.

**두 번 누르면 둘째가 거절된다.** 큐에 쌓지 않는다 — 쌓으면 버튼을 두 번 누른 사람이 **두 번 도는 것을 못 본다**(`jobs.launch` 가 처음부터 그렇게 정했다).
