# ADR-0015: 문서는 진입 시 이미 써져 있고 못 채운 곳만 표시한다

- 상태: 채택됨 (질문 타이밍은 **미결**)
- 날짜: 2026-08-16
- 근거: [`01_제품정의.md`](evidence/2026-08-16-v2-기획문서/01_제품정의.md) §4.2, [`02_기능명세.md`](evidence/2026-08-16-v2-기획문서/02_기능명세.md) F6

## 맥락

v1의 집필은 세 단계였다. 공고를 분석하고, 부족한 정보를 묻고, 답을 받아 초안을 만든다. 사용자가 답하기 전에는 아무것도 없었다.

멘토가 그린 그림은 달랐다.

> "이미 사업계획서에 미리 다 써놨으면 좋겠다. 내가 더 채워야 되는 것만 노란색으로 표시되고."

그리고 목표가 바뀌었다.

> "그냥 지원한다기보다 내가 뭘 입력하지 않아도 알아서 문서를 완성해놓는 느낌으로."

## 결정

**진입하면 전 항목 초안이 이미 만들어져 있다. 생성 버튼을 누르게 하지 않는다.**

1. **위키에서 끌어와 쓴다.** 이미 아는 것은 다시 묻지 않는다.
2. **못 채운 곳만 표시한다.** 위키에 정보가 없어 못 쓴 자리를 눈에 띄게 마킹한다.
3. **그 마커가 어느 위키 노드가 비어서 못 썼는지를 가리킨다.** 누르면 그 노드에 대해 묻고, 답하면 노드에 적립되며 문단이 채워진다.
4. **완성도를 표시한다.** `(전체 문단 − 안 채운 빈칸) / 전체 문단`.
5. **목차는 공고 양식에서 온다.** PSST로 고정하지 않는다([ADR-0019](0019-집필의-축을-양식으로.md), [ADR-0005](0005-실제-심사-항목명.md)).

3번이 제품 논지가 화면에 드러나는 유일한 자리다. **표현 방식은 바뀌어도 되지만 "어느 노드가 비어서 못 썼는지" 되짚는 연결은 어떤 형태로든 남아야 한다.** 없으면 적립 루프가 안 돈다.

## 미결 — 질문을 언제 하는가

두 문서가 반대로 적었다.

| | 언제 묻는가 | 작성 중에는 |
|---|---|---|
| [`설계정리_개발논의용.md`](evidence/2026-08-16-v2-기획문서/설계정리_개발논의용.md) [5]·[8] | **온보딩에서 몰아서.** 공통 슬롯(PSST)에 대고 gap을 검사하고 status enum 객관식으로 묻는다 | **안 묻는다.** 남은 gap은 `[확인 필요]` 마킹만 하고 생성을 멈추지 않는다 |
| [`02_기능명세.md`](evidence/2026-08-16-v2-기획문서/02_기능명세.md) F6-8·F6-9 | **작성 중에.** 마커를 누르면 패널이 열린다 | **묻는다.** 답하면 그 자리에서 채워진다 |

시연 동선에서 가장 긴 80초 구간이 후자이고, `01_제품정의.md` §3이 "제품의 전부"라고 적은 되먹임 화살표도 후자다. 다만 전자에는 "**공통 슬롯을 온보딩에서 채워두면 어떤 공고를 고르든 본문 90%가 커버된다**"는 근거가 있다.

**둘은 양립 가능할 수도 있다.** 온보딩에서 공통 슬롯을 채우고, 공고 특화 항목만 작성 중에 묻는 식이다. 다만 그렇게 정해진 것이 아니라 아직 정하지 않은 것이다.

이것이 정해질 때까지 F6-7의 세부는 확정이 아니다.

## 결과

- **핵심 지표가 바뀐다.** "제출까지 걸린 시간"이 아니라 **"사용자가 손댄 분량"**이다. 아무것도 안 채워도 문서가 몇 퍼센트 차 있는가.
- **생성 실패를 흐름 안에서 처리해야 한다.** 진입하자마자 도는 것이라 로딩 구간이 사용자 눈앞에 있다. 항목 단위로 실패를 처리하고 만든 항목은 유지한다.
- 대가로 **위키가 얇으면 빈칸투성이 문서가 나온다.** 온보딩에서 파일을 얼마나 받았는지가 첫인상을 결정한다.
- **F6-12 사실 고정은 그대로 유지한다.** 무인 생성일수록 지어낼 여지가 크다. 금액·자격·마감일·고유명사는 공고 데이터와 근거 청크에서 온 것만 쓴다([ADR-0014](0014-통합-그래프와-근거-청크.md)).
