# ADR-0002: L1/L2/L3 3계층 분리와 계층별 생성 금지

- 상태: 채택됨
- 날짜: 2026-08-15 (2026-08-16 정의 명문화)

## 맥락

이 제품은 공고의 금액·자격·마감일을 근거로 사용자에게 신청 가능 여부를 알려주고 사업계획서 초안을 만든다. **모델이 이 값들을 지어내면 제품이 거짓말을 하는 것이 된다.** 신청 자격을 잘못 알려주면 사용자는 떨어질 공고에 시간을 쓴다.

LLM에게 "지어내지 마"라고 지시하는 것으로는 부족하다. 지시는 검증할 수 없고 재현되지도 않는다.

이전 문서는 L1·L2·L3라는 이름을 화면-계층 대응표에서 쓰고 있었지만 **각 계층이 무엇인지 정의한 곳이 어디에도 없었다.**

## 결정

계층을 셋으로 나누고 **계층마다 생성 권한을 다르게 준다.**

| 계층 | 하는 일 | 생성 권한 | 기능 |
|------|---------|-----------|------|
| **L1 추출** | 공고 원문 → 구조화 데이터 | **없음.** 원문에서 가져오기만 한다 | F0 |
| **L2 판별** | 프로필 + L1 → 신청 가능 여부 | **없음.** 대조·계산만. LLM을 거치지 않는다 | F2 |
| **L3 집필** | L1 + 프로필 + 답변 → 초안 | **문장만.** 수치는 L1을 인용한다 | F5~F8 |

화면별로도 "이 화면이 생성하지 않는 것"을 명시한다(`SPEC.md` §2.1).

**L2가 LLM을 거치지 않는 것이 핵심이다.** 자격 판정은 같은 입력에 항상 같은 답이 나와야 한다(F2-3). 판정에 확률적 요소가 들어가면 "어제는 된다더니 오늘은 안 된다"가 생긴다.

## 결과

- **환각 방지가 프롬프트가 아니라 구조의 문제가 된다.** 테스트할 수 있고 재현된다.
- L1이 근거 구간을 보존해야 한다(F0-5). 그래야 L3가 인용할 원본이 존재한다. 이것이 F7-3 사실 고정의 실질적 근거다.
- 대가로 **L2가 다룰 수 없는 요건이 생긴다.** 자유 텍스트로만 서술된 복잡한 조건은 규칙으로 표현되지 않으면 판정할 수 없다. 이때는 보수적으로 다룬다(F0-6 신뢰도 연동).
- [ADR-0006](0006-사실고정-화면-미표시.md)에서 사실 고정을 화면에 표시하지 않기로 하면서, **계층 구조를 화면으로 보여줄 장면이 없어졌다.** 계층은 데이터로만 증명된다.
