# ADR-0060: 양식을 채워서 원본 포맷으로 돌려준다

- 상태: 채택됨
- 날짜: 2026-08-23
- 그대로 사는 것: [ADR-0019](0019-집필의-축을-양식으로.md) 집필의 축은 양식 목차와 작성 지침 · [ADR-0028](0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md) 질문 타이밍 · [ADR-0014](0014-통합-그래프와-근거-청크.md) 근거 청크
- 실측: 이 문서 «실측» 절 (양식 20건 · 한/글로 눈으로 확인한 것 포함)

## 맥락

레포 첫 줄이 「들어가면 **문서가 이미 써져 있다**」인데 **그 문서가 파일로 나가지 않는다.** `src/finnect/draft/` 에 파일을 쓰는 코드가 한 줄도 없다 — 집필기는 항목마다 글을 만들어 `draft_item.body` 에 넣고, 사용자는 화면에서 그것을 복사해 한/글에 손으로 옮긴다. 마지막 한 칸이 비어 있다.

재료는 이미 있다. 받아 둔 첨부 589건 중 **양식류가 198건**이고 그중 182건(92%)이 표로 짜인 편집 가능한 문서다.

**「원본 파일을 채워서 돌려준다」가 가능한지를 몰라서 미뤄 두고 있었다.** HWP 5.0 이 바이너리라 쓰기가 안 된다고 보았는데, 재 보니 쓰기가 되는 라이브러리가 있었고 되는 범위가 포맷마다 갈렸다. 그 경계를 여기 못 박는다.

## 결정

### 1. 산출물은 채워진 원본 파일이다

집필 결과를 화면에만 두지 않고 **사용자가 받은 그 양식 파일에 값을 넣어 같은 포맷으로 돌려준다.** 복사해 옮기는 일을 사용자에게 남기지 않는다.

**포맷을 바꾸지 않는다.** 공고가 hwp 양식을 주면 hwp 로 돌려준다. 제출처가 무엇을 받는지 우리가 모르고, 바꿔서 반려되면 그 손해는 우리가 못 갚는다.

### 2. 포맷마다 라이브러리를 따로 쓴다

| 포맷 | 라이브러리 | 런타임 | 손대지 않은 부분 |
|---|---|---|---|
| `hwp` | [hwplib](https://github.com/neolord0/hwplib) 1.1.10 (Apache-2.0) | **JVM** | 서식 보존 |
| `hwpx` | [python-hwpx](https://pypi.org/project/python-hwpx/) (Apache-2.0) | 순수 파이썬 | **바이트 보존** |
| `docx` | python-docx | 순수 파이썬 | 구조 보존 |

**hwp 에 대안이 없다.** 쓰기가 되는 것은 hwplib 하나이고, `hwp-hwpx-editor` 는 그 jar 를 감싼 것이며 `hwplibsharp` 는 .NET 포팅, `hwp2hwpx` 도 내부가 hwplib 이다. `hwp-rs`·`hwp-hwpx-parser` 는 읽기 전용이고 `pyhwpx` 는 Windows 와 한컴오피스 설치를 요구해 서버에서 못 돈다.

**`hwp-hwpx-editor` 를 쓰지 않는다.** 1.0.0 의 파이썬 래퍼가 hwplib 1.1.9 시절 클래스 경로를 들고 있어 `extract_text` 등이 `ClassNotFound` 로 죽는다. 번들된 jar 는 멀쩡하므로 **jar 만 쓰고 래퍼는 우회한다.**

**docx 에서 `cell.text = value` 를 쓰지 않는다.** 그 대입은 셀의 문단과 런을 전부 버리고 새로 만들어서 글꼴·크기·정렬이 통째로 날아간다. 첫 런의 글자만 바꾸고 나머지 런을 비우면 그 자리의 서식이 남는다.

### 3. hwp 는 빈 칸만 채운다. 덮어쓰기를 금지한다

**한/글로 눈으로 확인해서 정한 경계다.** 판본 일곱 개를 만들어 갈랐다.

| 판본 | 무엇을 했나 | 한/글 |
|---|---|---|
| A | 읽고 저장만 | 정상 |
| B | `getCharList().clear()` 로 비우고 채움 | **안 열림** |
| C | 개체 앵커 든 칸은 건너뛰고 제어 문자 보존하며 채움 | 열리나 **표가 다음 쪽으로 밀림** |
| D | **빈 칸만 채움** | **정상** |
| E | C + 넣는 값의 글자 수를 원래와 맞춤 | 밀림 |
| F | C + **원래와 똑같은 값**을 다시 써넣음 | 밀림 |
| G | C + 줄 나눔 캐시(`LineSeg`) 삭제 | 밀림 |

**F 가 답을 줬다.** 값이 완전히 같은데도 밀렸으니 값도, 길이도, 캐시도 원인이 아니다. **hwplib 으로 기존 글자를 갈아 끼우는 것 자체가 배치를 깨뜨린다.** hwplib 이슈 [#72](https://github.com/neolord0/hwplib/issues/72)(문단 텍스트 교체 시 한/글에서 오류)가 열린 채로 남아 있는 자리와 같다.

B 가 안 열린 첫 원인은 따로 있었고 그것도 적어 둔다. `clear()` 가 지운 리스트에 보이는 글자만 있는 것이 아니었다 — **문단 끝 문자와 개체 앵커(`HWPCharControlExtend`)가 같이 들어 있었다.** 비어 보이는 칸에 그림이 매달려 있었고, 지우니 컨트롤은 남고 닻이 없어져 한/글이 손상으로 판정했다.

**hwpx·docx 에는 이 제약이 없다.** 둘은 XML 이라 덮어써도 무너지지 않는다(실측에서 hwpx 22칸·docx 4칸을 덮어쓰고 확인했다).

### 4. hwp 미리보기는 텍스트만 되살리고 이미지는 포기한다

hwplib 의 `HWPFile` 은 `PrvText`·`PrvImage`·`DocOptions` 를 **모델에 갖고 있지 않다.** 저장할 때마다 통째로 사라지고, 라이브러리 안에서는 고칠 수 없다.

- **`PrvText` 는 만든다.** 본문에서 재현할 수 있다 — 문단은 그대로 쓰고 표는 행마다 셀을 `<…>` 로 감싸 이어 붙인 뒤 1,023자에서 자른다. **채운 값이 반영되므로 원본 것을 복사해 붙이지 않는다.**
- **`PrvImage` 는 넣지 않는다.** 렌더링이 필요해 만들 수 없고, 원본 것을 옮기면 **값이 든 문서에 빈 양식 썸네일**이 붙는다. 없으면 한/글이 「미리보기 없음」이라고 정직하게 말한다.
- **`DocOptions/_LinkDoc` 은 원본에서 옮긴다.** 내용과 무관한 설정이다.

붙이는 도구는 **hwplib 이 이미 번들한 Apache POI** 다. 추가 의존성이 없다.

### 5. JVM 을 스택에 들인다

hwp 를 쓰려면 Java 8+ 가 있어야 하고 회피로가 없다. hwp2hwpx 로 변환해서 hwpx 로만 다루는 길도 **그 변환기가 hwplib 이라** 같은 자리로 돌아온다.

**JVM 이 필요한 것은 hwp 하나뿐이다.** hwpx·docx 는 순수 파이썬이므로, JVM 을 요구하는 경로를 그 셋 중 하나로 좁혀 둔다. 배포에서 Java 를 넣을 수 없는 곳이면 **hwp 만 빠지고 나머지는 돈다.**

### 6. 빈칸 판정을 규칙으로 하지 않는다

관공서 양식이 빈칸에 형식을 적어 둔다(`000-0000-0000`·`OOOO`·`0000년 00월 00일`). 그것만 있으면 정규식으로 갈리는데, **안내문이 같이 붙으면 안 갈린다.**

```
기업명     → 'OOOOO (법인등기부등본 및 사업자등록증상 상호명)'
개업연월일 → 'OO.OO.OO (법인등기부등본 및 사업자등록증상 개업일)'
```

실측에서 양식 하나가 이것 때문에 **표 115개에서 한 칸도 안 걸렸다.** 안내문은 양식마다 다르게 쓰여 있어서 정규식을 늘려도 따라갈 수 없다. **사람은 괄호 안이 안내라는 것을 바로 아는데 문자열 규칙으로는 안 갈린다** — 여기가 LLM 이 필요한 자리다.

그리고 그런 칸은 **덮어쓰기가 필수다.** 안내문을 지워야 하므로 결정 3 에 따라 **hwp 에서는 손을 못 댄다.**

## 정하지 않은 것

- **hwp 를 hwpx 로 바꿔서 낼 것인가.** 바꾸면 덮어쓰기가 살아나지만 제출 포맷이 달라진다. 공고가 hwp 제출을 요구하는 비율을 재기 전에는 못 정한다.
- **앵커를 어디에 저장할 것인가.** 지금 `document_item` 은 첨부 텍스트 안의 구간만 들고 있어서 파일 안의 위치를 모른다. 표 좌표를 어디에 둘지는 [plan/24](../plan/24-양식을-채워서-돌려준다.md) 가 정한다.
- **사실칸과 서술칸을 갈라 다른 파이프라인에 태울 것인가.** 실측이 사실칸만 다뤘다.

## 결과

- **마지막 한 칸이 닫힌다.** 집필 결과가 파일로 나가고 사용자가 복사해 옮기지 않는다.
- **범위가 92%다.** 양식류 198건 중 182건(hwp 145 · hwpx 27 · docx 10)에서 채운 파일을 돌려줄 수 있다. 남는 것은 pdf 7 · zip 6 · xlsx/xls 3 이다.
- **포기하는 것 ①** — **hwp 에서 플레이스홀더를 못 지운다**(결정 3). `000-0000-0000` 이 그 자리에 남고 사람이 손으로 지워야 한다. 우리 코퍼스에서 hwp 가 **73%** 라 적은 비율이 아니다.
- **포기하는 것 ②** — **hwp 저장본에 미리보기 이미지가 없다**(결정 4). 문서는 정상으로 열리지만 탐색기 썸네일과 그룹웨어 미리보기에서 그림이 안 뜬다.
- **포기하는 것 ③** — **채운 파일을 사용자가 열어 봐야 한다.** 값이 길어지면 셀이 두 줄이 되고 표가 다음 쪽으로 밀린다. 사람이 타이핑해도 같은 일이 일어나므로 결함은 아니지만, **몇 자가 들어가는지는 서체와 여백이 정하는 것이라 우리가 미리 못 센다** — 쪽 수 제한을 글자로 환산하지 않기로 한 것(`draft/limits.py`)과 같은 자리다.
- **배포 조건이 늘어난다**(결정 5). Java 8+ 가 없는 곳에서는 hwp 경로만 꺼진다.

## 실측 (2026-08-23)

받아 둔 첨부에서 사업계획서·신청서 양식 **20건**을 뽑아 라벨로 칸을 찾아 채우고, 저장한 파일을 다시 읽어 대조했다. 코드는 `spike/hwp_fill.py`·`spike/hwpx_fill.py`·`spike/docx_fill.py` 다.

| 포맷 | 파일 | 새로 채움 | 덮어씀 | 계 | 프로그램 검증 |
|---|---:|---:|---:|---:|---|
| hwp | 6 | 51 | **금지** | 51 | 6/6 |
| hwpx | 9 | 65 | 22 | 87 | 9/9 |
| docx | 5 | 23 | 4 | 27 | 5/5 |
| **계** | **20** | **139** | **26** | **165** | **20/20** |

hwp 는 문단·표·셀·글자 수와 서식 넷(글자모양·문단모양·스타일·테두리)이 원본과 같았다. hwpx 는 손댄 것이 `Contents/section*.xml` 뿐이고 나머지 ZIP 엔트리가 바이트까지 같았다. docx 는 표·셀·문단 수가 같았다.

**한/글로 눈으로 본 것은 hwp 4건과 hwpx·docx 각 1건이다.** 나머지는 같은 조건이라 프로그램 검증만 했다. 결정 3 의 판본 A~G 가 그 육안 확인에서 나왔다.

**라벨 대조가 자간을 넘는다.** 관공서 양식이 `기   업   명`·`업 체 명`·`기  업  명` 처럼 글자 사이를 벌려 칸을 맞추는데, 공백을 지우고 대조하니 셋 다 같은 라벨로 걸렸다. 본문에서 어휘를 *찾는* 경우와는 반대 규칙이다(`wiki/topics.py` `slot_of()` 와 같고 `match/sectors.py` 와 반대다).

**누름틀(`fieldBegin`)에 기대면 안 된다.** hwpx 9건 중 누름틀이 있는 것은 **1건**뿐이고 나머지는 전부 표로 짜여 있었다. 앵커는 **표의 (행, 열) 좌표**여야 한다.
