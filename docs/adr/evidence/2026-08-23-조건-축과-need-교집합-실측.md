## 왜 쟀나

두 층이 자유 문자열을 재파싱하고 있었다.

```

### v1 → v2 로 고친 것

```
+ sme            중소·중견·벤처가 갈 곳이 없어 small_business 로 갔다
+ certification  벤처인증·기업부설연구소·특허 보유

```

**`small_business` 오분류 4 → 0 이 이 라운드의 요점이다.** 코드가 인원으로 푸는
유일한 축이라, 중소기업 공고가 거기 앉으면 직원 10명 회사가 통째로 탈락한다.

### `alt`(OR 그룹)는 안 쓴다

v3 에서 "하나만 맞아도 되는" 조건을 모델에게 묶게 했다. 명확한 것은 두 회차 다
맞췄지만(`소상공인 | 중소기업`) **전체 일치율이 9/18 (50%)** 이고 AND 인 것까지 묶었다.

**대신 코드가 축 족보로 정한다.** 실제 OR 은 둘뿐이었다.

```
규모 족이 둘 이상        1~2건 / 50   소상공인 vs 중소기업 — 둘 다 요구될 수 없다
예비창업자 + 업력        4~6건 / 50   예비창업자는 업력이 없다
```

### 실제 자격 판정이 어떻게 바뀌나 (다시로 × 50건)

```
              통과   탈락   확인필요
  지금          46      2       2
  새로          26      4      20
```

**갈린 22건을 전부 눈으로 봤다.**

  성장플러스(업력 `3년 초과` 하한). 셋 다 지금은 **못 읽어서 통과**시킨다

### `biz_enyy` 는 본문보다 먼저가 아니다

K-Startup 138건 **전부**에 `biz_enyy`(창업 기간 코드값)가 있다. 본문과 대조했다.

```

## 2층 — 추천을 need 교집합으로

닫힌 표 열다섯에서 **양쪽이 고른다.** 공고는 "무엇을 주는가", 회사는 "무엇을 쓸 수
있는가".

### 지금 방식(④ 분야표 + ⑤ 키워드)이 무너져 있었다

`맞다` 15건 중 **육안으로 진짜는 2건**이었다.

```
11건   `벤처기업`·`창업기업` 낱말 하나로 만들어졌다        ← STOP 에 없었다
 6회   "성남산업진흥원의 창업기업 성장지원 프로그램에 참여했다"   ← Company/창업계기 (rank 14)
 5회   "중소벤처기업부의 소상공인 디지털 전환 정책은…"        ← Market/트렌드 (rank 7)
```

**둘 다 우리가 무엇을 하는 회사인지 말하지 않는다.** `NODE_RANK` 가 바로 이걸
막으려고 T-0074 에서 들어온 표인데 **정렬의 둘째 자리라 못 막았다** — 노드가 서른
개일 때는 안 보이고 220사실이 되니 드러났다.

**고친 뒤**(plan/17 T-0145):

| | 전 | 후 |
|---|---:|---:|
| `맞다` | 15 | **3** |
| 근거 문장 최다 반복 | 6회 | **1회** |
| 육안으로 진짜 | 2/15 (13%) | **2/3 (67%)** |

### ④ 의 이유는 버킷당 하나로 고정된다 — 이건 버그가 아니다

`애매` 19건에서 같은 문장이 반복된다.

```
10회   "사업화 분야예요. 3단계는 2027년 1월부터 6월까지 다점포 통합 관리를 출시하고…"
 7회   "기술 개발 분야예요. 1단계 모듈 프로토타입 개발을 완료했고…"
```

`_sector_fit()` 은 이미 노드 종류 우선이라 정렬 문제가 아니다. **버킷이 열 개니
이유가 열 종류를 못 넘는다.** 구미 방산클러스터와 전라남도 관광 인센티브와 제주
창업-BuS 가 글자 하나 다르지 않은 같은 이유를 단다.

### need 교집합 라운드

| | n1 | **n2** |
|---|---:|---:|
| 회사 쪽 need | 4 | **8** |
| 이유가 붙은 공고 | 3 | **21** |
| 이유 종류 | 3 | **9** |
| need 이 0개인 공고 | 5 | **2** |

**n1 → n2 로 고친 것 셋**

1. **회사 쪽 질문을 「필요한 것」 → 「쓸 수 있는 것」.** n1 은 이미 출원한 특허를
   안 골랐다 — "필요"가 아니라 "보유"라서다. **틀린 답이 아니라 틀린 질문이었다.**
   그 탓에 `[경기] 성남시 기술자료 임치 수수료`(공고 need = `ip`)가 빠졌다
2. **칸마다 경계를 적었다.** n1 에서 need 0개인 공고 5건 중 **4건은 칸이 있는데 안
   골랐다** — 딥테크 스튜디오에 `ip`, 대기업 매칭에 `open_innovation`, 혁신아이콘에
   `funding_loan`, 1인 창조기업에 `space` 가 있었다. **칸이 모자란 게 아니라 칸의
   뜻이 안 적혀 있었다**(처음 진단은 "칸을 둘 더한다" 였고 틀렸다)
3. **「1~3개」→「1~4개」·「표에 없으면 빈 배열」 톤 완화.** 『글로벌 교류·투자유치
   지원사업』이 제목에 있는 투자유치를 안 골랐다

**n1 이 놓쳤던 셋이 전부 잡혔다.**

```
[경기] 성남시 기술자료 임치      공고 [ip]                          ∩ ip
『글로벌 교류·투자유치』          공고 [funding_investment, 해외판로]   ∩ funding_investment
스타트업-중견/대기업 매칭        공고 [open_innovation, 국내판로]      ∩ sales_domestic
```

### n2 육안 21건

**맞다 약 11 · 애매 약 4 · 오추천 약 6.** ④ 의 3종 대비 이유가 9종으로 갈린다.

오추천 여섯이 한 무늬다 — `시제품·인증` 이 업종과 무관하게 걸린다(생활화학제품 ·
자동차 전장 · 의료기기 · 로봇). **원인은 2층이 아니라 1층이다.**

## 이 실측이 새로 찾은 것 — `industries[]` 가 빈다

위 오추천 여섯의 `notice_profile.industries` 를 봤더니 **전부 `[]`** 였다.

```
2026년 생활화학제품 안전관리 컨설팅        industries []
2026년 SDV 전장부품 보안 평가센터         industries []
AI기반 Age-Tech 디지털의료제품            industries []
산업혁신기반구축 휴머노이드 로봇 안전인증     industries []
```

제목에 업종이 그대로 있는데 안 뽑힌다. 그리고 1층 실험에서 **같은 정보가 조건으로
새는 것**을 봤다 — `생활화학제품을 제조ㆍ수입하는 중소기업` 이 `sme` 로 갔다.

**지역은 안 그렇다.** 조건에 지역이 든 13건을 봤더니 **13건 전부 `regions[]` 에 이미
있었다** — 중복일 뿐 유실이 아니다. `industries` 만 새고 있다.

이건 적합도로 못 고친다. `normalize.SYSTEM` 의 `industries` 지시를 다시 봐야 한다.

## 뒤이어 닫은 셋 (같은 날)

### ① `industries[]` 구멍 — 50/50 이 비어 있었다

`normalize.SYSTEM` 에 **제목·사업명의 업종도 내라**고 적고 실패 사례 넷을 예시로 넣었다.

```
industries 가 빈 공고   50/50  →  26/50      (회귀 0건)
앵커 유실              2~4/50 →  0/50
```

앵커 유실이 0 이 된 것은 다른 수정 덕이다 — 아래.

### ② K-Startup 본문의 HTML 엔티티가 안 풀렸다

앵커 유실 넷 중 둘의 제목에 `&apos;` 가 있었다. 세어 보니 **138건 중 10건**이다.

```
모델   "「민관협력 오픈이노베이션 지원」 '성과기업 후속 지원'"
원문   "「민관협력 오픈이노베이션 지원」 &apos;성과기업 후속 지원&apos;"
```

**2026-08-20 에 기업마당에서 `R&amp;D역량` 으로 같은 것을 봤는데 그때는 저쪽만
고쳤다** — 저쪽은 HTML 이라 태그를 지우는 김에 풀었고, 이쪽은 태그가 없어서
그냥 지나갔다. 안 풀면 그 공고가 **통째로 버려진다.**

`bodies.unescape()` 를 만들었다. **태그는 안 지운다** — K-Startup 본문은 HTML 이
아니라서 `<` 를 지우면 원문에 없는 글자가 되어 앵커가 또 깨진다.

### ③ 회사 표에 `certification` 을 더했다 (열넷 → 열다섯)

자격 판정을 못 한 스무 건 중 **여섯이 이것 하나** 때문이었다. `dated=True` 다 —
벤처기업확인은 유효기간이 있어서 「언제 기준으로 가졌나」가 판정을 가른다.

**`sme`(중소기업 여부)는 안 더했다.** `headcount` 와 `revenue` 로 계산되는 파생값이라
업력·만 나이를 안 넣은 것과 같은 자리다. 저장하면 두 곳이 갈린다.

## 오탈락 실측 — 진짜 파이프라인을 끝까지 돌렸다

스파이크가 아니라 `python -m finnect.match` 다. 공고 234건 정규화(LLM 234회 · $0.15)
뒤 `c_dasiro` 로 퍼널을 돌렸다.

```
후보 234
  ③ 자격      탈락 153 · 확인 필요 44 · 통과 37
  ④ 분야      맞음 19
  ⑤ 적합도    맞다 3 · 애매 16 · 아니다 18
추천 3건
```

### 탈락 153건이 **전부 소재지**다

연령·규모로 떨어진 것이 **0건**이다. 요구 지역은 서울 8 · 대구 7 · 충북 7 ·
부산 6 · 화성 6 · 인천 5 · 경북 5 … 로 흩어져 있고 다시로는 성남이다.

**경기·성남이 섞였는데 탈락한 것은 1건**이고 그것도 옳다 — `['비수도권', '대구']`
이고 성남은 수도권이다.

**오탈락 0건이다.** 지역 축은 `regions` 15/15 정확도가 그대로 값을 한다.

### 그런데 `확인 필요` 가 추천을 막는다 — 실질은 조용한 탈락이다

`industries` 를 고친 효과를 격리해 쟀다.

```
industries 안 봄   통과 81 · 탈락 153 · 확인필요  0
industries 봄      통과 37 · 탈락 153 · 확인필요 44
```

**44건이 통과에서 확인 필요로 옮겨졌다.** 대부분은 옳다 — 식품·농식품·원전·로봇·
자동차·화장품·수산식품·소방장비 공고이고 다시로는 재고관리 소프트웨어다.

**다만 7건이 정보통신·ICT 계열인데 문자열이 안 겹쳐서 못 넘었다.**

```
['정보통신방송 융합서비스']        2026년 2차 ICT 비즈니스 파트너십(일본)
['ICT', '디지털']               2026년 K-Global 해외진출 지원사업
['첨단제조업', '지식·문화·정보통신']  판교 제2테크노밸리 기업성장센터 입주
['AI', '디지털 혁신기술']          DNA 융합 제품·서비스 해외진출 지원
…
```

`eligible.py` 가 **의도한 대로** 동작한 것이다 — 업종은 탈락이 아니라 `확인 필요`이고,
그 이유를 「오탈락이 오추천보다 나쁘다」로 적어 뒀다.

**그런데 `확인 필요` 는 추천에 안 오른다.** 화면에서 사라지지는 않지만 사용자가
받는 것은 같다. **「탈락은 아니다」가 제품에서 뜻하는 바를 다시 봐야 한다** —
`industry_hit` 의 양방향 부분 문자열로는 `정보통신업` 과 `정보통신방송 융합서비스` 를
못 잇는다. 업종은 이름이 아니라 코드(KSIC)로 잇거나, `확인 필요` 를 추천에 올리되
그렇다고 말해야 한다.

## 남은 것
