# ADR-0023: 제품 프론트를 Next.js로 분리하고 FastAPI는 JSON을 낸다

- 상태: 채택됨
- 날짜: 2026-08-17
- 채우는 것: [ADR-0020 "안 정한 것"](0020-스택-확정.md#안-정한-것) — 제품 프론트 프레임워크
- 대체하는 것: [plan/08](../plan/08-사용자-화면-공고-조회.md)의 T-0019 · T-0020 · T-0021 → [plan/09](../plan/09-사용자-앱-분리.md)

## 맥락

**[ADR-0020](0020-스택-확정.md)이 이 자리를 비워 뒀다.** §"안 정한 것"의 첫 문단이다.

> 제품 프론트 프레임워크를 지금 정하지 않는다. plan/01의 API 계약이 아직 없고 제품 화면도 서지 않았다. (…) 정하지 않은 상태가 아무것도 막지 않는다.

**그 전제가 깨졌다.** [plan/08](../plan/08-사용자-화면-공고-조회.md)이 사용자 화면 두 장(S4·S5)을 열면서 제품 화면이 서기 시작했다. 그러자 T-0019가 프레임워크를 정해 버렸다 — `src/finnect/web/`에 `uv run uvicorn finnect.web.app:app`으로 뜨는 Jinja2 앱이다.

**계획이 ADR 없이 결정을 했다.** [ADR-0001](0001-정본-문서-체계.md)이 "여기에 없는 결정은 결정이 아니라 관성"이라고 한 그 상태다. plan/README도 같은 문제를 스스로 적어 뒀다 — "계획은 완료되면 `상태:`만 바뀌는 문서라 결정의 정본이 될 수 없다"([ADR-0020](0020-스택-확정.md) 맥락).

지금 정하는 이유는 셋이다.

1. **plan/08은 아직 코드를 한 줄도 안 썼다.** 지금 바꾸면 버릴 코드가 0이다. T-0019가 실행된 뒤에는 앱 한 벌을 버려야 한다.
2. **ADR-0020이 FastAPI를 고른 이유가 이것이었다.** 웹 행의 근거가 "나중에 제품 프론트에 JSON을 주는 서버와 같은 프로세스다"이고, 관리 화면 행의 근거가 "제품 프론트와 섞지 않고, API 계약을 아직 안 정해도 된다"다. **둘 다 제품 프론트가 따로 선다는 전제 위에 서 있다.**
3. 프론트를 따로 배포할 수 있는 상태가 된다. 배포 위치는 이 문서가 정하지 않는다(아래 "안 정한 것").

## 결정

| 항목 | 결정 | 이유 |
|------|------|------|
| 제품 프론트 | **Next.js (App Router) · TypeScript** | 제품 화면 일곱 중 S7 궤도(그래프)와 S4 문서 집필이 클라이언트 상태를 많이 쥔다([ADR-0017](0017-위키-그래프-궤도-배치.md)). 서버 렌더 템플릿으로 가면 그 두 화면에서 다시 뒤집는다 |
| 위치 | **`web/`** (레포 루트) | `src/finnect/` 아래에 두지 않는다. 빌드 도구와 락파일이 다르다. `.gitignore`가 이미 `node_modules`·`.next`를 들고 있다 |
| 경계 | **FastAPI가 JSON을 내고 Next.js가 부른다** | `views.py`가 매핑 정본으로 남는다. 프론트가 DB를 직접 읽으면 그 매핑이 TypeScript로 복제된다 |
| API 위치 | **`src/finnect/api/`** — admin과 별개 앱 | admin은 `SPEC.md` §6 범위 밖이고 제품 API는 안이다. 한 앱에 섞으면 그 경계가 사라진다 |
| 스타일 | **CSS 변수 한 파일 + CSS Modules** | `DESIGN.md` §4가 토큰을 정본으로 두고 plan/08 T-0019가 "토큰이 한 파일에 있다"를 완료 조건으로 걸었다. 유틸리티 클래스는 값을 화면마다 흩는다 |
| 상태 관리 | **안 넣는다** | S4·S5는 서버 데이터를 읽기만 한다. 라이브러리를 미리 고르지 않는다 |

**`src/finnect/web/`을 만들지 않는다.** T-0019가 지시한 Jinja2 사용자 앱은 실행하지 않는다.

**`admin/`은 Jinja2로 남는다.** 운영 도구는 `SPEC.md` §6 범위 밖이라 제품 프론트로 옮길 근거가 없다. plan/08 T-0023(토큰 입히기)은 그대로 유효하다.

## 결과

- **plan/08의 T-0019 · T-0020 · T-0021이 대체된다.** 셋이 동시에 무의미해졌으므로 땜질하지 않고 [plan/09](../plan/09-사용자-앱-분리.md)를 연다. plan/08은 T-0018 · T-0022 · T-0023 셋으로 남는다 — **전부 프레임워크 중립이다.**
- **[plan/01](../plan/01-기반.md)이 미뤄 둔 `api-contract.md`를 이제 써야 한다.** 프론트가 분리되면 계약이 암묵일 수 없다. plan/09 T-0024가 그것이다.
- **저장소가 두 언어를 갖는다.** Python 3.13과 TypeScript다. `uv run ruff check`와 별개로 프론트 린트가 생기고, 검증 명령이 둘로 늘어난다.
- ADR-0020이 "지우지 않는다"고 남겨 둔 `.gitignore`의 Node 항목이 **근거를 되찾는다.**
- **포기한 것** — 화면 하나를 한 프로세스에서 끝내는 단순함이다. 목록 한 장을 그리는 데 이제 Python 라우트와 TypeScript 컴포넌트 둘을 고쳐야 한다. **S4·S5만 놓고 보면 이 결정은 손해다.** 갚는 것은 S6 집필과 S7 궤도에서다. 거기까지 안 가면 되돌리는 편이 낫고, 그때 이 문서를 대체한다.

## 안 정한 것

**배포 위치를 정하지 않는다.** Vercel이든 컨테이너든 이 문서의 범위가 아니다. 프론트를 원격에 올리려면 API가 공개 주소여야 하고, 그건 [ADR-0021](0021-인프라-선정을-미룬다.md)이 미뤄 둔 인프라 결정을 건드린다. **plan/09는 로컬에서 둘 다 뜨는 것까지만 한다.**

**인증을 정하지 않는다.** 계정과 로그인은 `SPEC.md` §6 범위 밖이다. 지금 API에 사용자 개념이 없다.

**CORS 처리 방식을 계약으로 고정하지 않는다.** 로컬에서는 Next.js dev 프록시로 막고, 원격 배포를 정할 때 다시 본다.

**UI 라이브러리를 고르지 않는다.** `DESIGN.md` §1이 기준 디자인 시스템을 "5.1에서 정함"으로 두고 있고 아직 안 정해졌다. 컴포넌트를 직접 짠다.
