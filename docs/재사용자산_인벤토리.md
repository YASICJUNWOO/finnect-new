## 3. 그대로 쓰는 코드

### `app/rag/extract/` — 5-1의 핵심
LLM이 공고문 자유텍스트 → strict JSON 스키마로 자격조건 추출. 이미 잘 짜여 있다.

- `schema.py`: OpenAI Structured Outputs strict 대응 DTO. 고정 enum 어휘로 **모델이 어휘 밖 필드를 못 만들게** 강제
- `prompt.py`: 11개 규칙 + 금지 예시가 들어간 L0 프롬프트. 인젝션 방어(DATA 블록 격리), 추론 금지, 범위는 `>=`/`<=` 분해 등 실전에서 깎인 흔적이 있음
- `sanitize.py` / `mapper.py`: 후처리·도메인 모델 변환

**교체 필요**: 현재 고정 필드가 자립준비청년 특화다 — `care_ended`, `care_end_years`, `care_duration_years`. 일반 청년 타깃으로 가면 이 3개를 빼고 `edu_work_status`·`household`·주거형태 쪽을 두껍게 해야 한다. **구조는 그대로, 어휘만 교체**하면 되는 형태로 설계돼 있어서 비용이 작다.

### `app/rag/apply_guide/` — 핵심기능 2가 이미 있음
`ExtractedStep(order, title, detail, channel, url)` + `documents` + `contact` + `online_available`.
idea-v1 §3-2 "구비서류 및 발급처, 카드사별 혜택" 중 **구비서류·절차 부분은 이미 추출 중**. 발급처/발급방법 같은 2차 정보는 미포함.

### `app/rag/ingest/` — 수집
온통청년 API, 복지로 API, fill4young 파서, 우선순위 상세조회(`priority.py`), 콘텐츠 해시 diff. API 문서도 `docs/external-apis/` 에 정리돼 있음.

### `app/agents/` — 런타임
- `chat/supervisor.py`: agents-as-tools 패턴 + SSE 스트리밍 → idea-v1 §5-3 도구호출 루프의 뼈대
- `matching/rules.py`: 0단계 태그 게이트 → 조건평가 → 점수정렬. **판정 불가 조건을 버리지 않고 `NEED_REVIEW` + 원문링크로 남기는 설계**가 이번 아이디어의 "왜 안 되는지 이유를 준다"와 정확히 맞는다
- `tools/`, `skills/`: strict 스키마 도구 레지스트리 — idea-v1 §5-5 "도구 등록 구조라 도구 추가만으로 확장" 주장의 실물 근거

## 4. 주의 — 아이디어 문서와 코드가 어긋나는 지점

### ① 하이브리드 검색은 없다
`app/rag/retrieve/policy.py` 상단 주석이 명시한다: *"검색은 결정론 키워드 부분매칭이다(Phase 1 — BM25/임베딩 아님)"*. 조사 제거 + 토큰 AND ILIKE + 페르소나 재정렬 수준.
CLAUDE.md 에는 pgvector + BM25 하이브리드가 **계획으로** 적혀 있고 실제로는 미구현. idea-v1 §5-3의 "BM25 + 임베딩"은 **신규 개발**로 잡아야 한다. `DomainRetriever` 인터페이스는 있으니 교체 지점은 깨끗하다.

### ② "중복배제 C1~C4"는 이번 아이디어의 중복수혜가 아니다
`agents/matching/spec.py` 에 "중복배제(C1~C4)"라는 문구가 있지만, 코드의 `exclusionary` 는 **대상특성 게이트**(장애인 전용 정책을 비장애인에게 안 보여주는 것)다. 정책↔정책 동시수혜 판정이 아니다.

**정책 간 충돌·호환·전환 관계는 코드베이스 어디에도 없다.** 이게 idea-v1 의 유일무이한 차별점이자 100% 신규 개발 영역이다.

### ③ 미검증 전제 — 공고문에 중복 제한 조항이 실제로 있는가
아이디어 전체가 "당락을 가르는 정보가 공고문 자유텍스트 안에 있다"에 걸려 있다. 자격요건은 맞다(43건 추출 경험으로 확인됨). 그런데 **중복 제한 조항이 몇 %의 공고문에 명시돼 있는지는 아무도 안 세어봤다.**

명시율이 낮으면 지식그래프 엣지가 텅 비고, 그러면 남는 건 기존 서비스보다 조금 나은 필터링뿐이다.
→ **가장 먼저 할 일**: youth_policies 2,634건에서 "중복", "동시", "타 사업", "제외", "지원받은 자" 등을 grep 해서 명시율을 실측한다. 표본 30건 눈으로 읽는 것까지. 반나절이면 되고, 이 숫자 하나가 아이디어의 생사를 가른다.
