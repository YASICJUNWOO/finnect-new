## 2. 들어가는 길 — 사실 하나가 자리를 찾는 과정

```
                     파일 하나 (청크 N개)
                            │
                            ▼   LLM 호출 1회 · 파일당
              ┌─────────────────────────────┐
              │  kind    slot | node         │ ← enum 강제
              │  topic   25 중 하나           │ ← enum 강제
              │  key     자유 문자열          │ ← 힌트만 43개
              │  value · as_of · qualifier    │
              │  text · anchor                │
              └──────────────┬────────────────┘
                             │
                  anchor 가 원문에 있나
                   ├─ 없다 ──────────────────────────────► 버린다 (dropped)
                   └─ 있다
                             │
                     kind == "slot" ?
        ┌────────── 예 ───────┴─────── 아니오 ──────────┐
        ▼                                               ▼
   slot_of(key)                                   node_of(topic)
   SLOT_ALIASES 43 ─► 14                          TOPIC_NODE 23 ─► 10
        │                                               │
   ├ 못 찾음 ─► 미분류 "모르는 항목 이름"           ├ 못 찾음 ─► 미분류 "서술 노드가 없는 topic"
   ├ value 빔 ► 미분류 "값이 비어 있음"             │           company_profile · application_history
   └ 찾음                                          └ 찾음
        ▼                                               ▼
   SLOTS 14 중 하나                               NODES 10 중 하나
   key = slot|이름|한정어|시점|값                  key = node|이름|fact_key
   상태 current / superseded / conflict            상태 없음 · 그냥 쌓인다
        └───────────────────┬───────────────────────────┘
                            ▼
                    ORBIT 15 자리에서 만난다
                            ▼
                 MD 한 장  ·  그래프 노드 하나
```

## 3. 슬롯 하나와 노드 하나가 실제로 지나간 길

`_fact_from_llm` → `place()` → `dedupe_key()` 를 그대로 돌린 결과다.

### 슬롯

```
원문        임직원 15명 (2026년 8월 기준)
   ↓ LLM
{ kind:"slot", topic:"company_profile", key:"임직원",
  value:"15", as_of:"2026-08-31",
  text:"임직원 15명 (2026년 8월 기준)", anchor:"임직원 15명" }
              ↑ 문서가 쓴 말 그대로    ↑ 15명 → 15 로 정규화
   ↓ 앵커 검증 · place()   kind=="slot" → slot_of("임직원") = "headcount"
Placement(kind="slot", name="headcount")        ← headcount 가 여기서 처음 등장
   ↓ dedupe_key()
'slot|headcount||2026-08-31|15'
   ↓
wiki_fact  place_kind="slot"  place="headcount"  value="15"  as_of=2026-08-31
           topic="company_profile"   ← 저장은 되는데 라우팅에 안 쓰였다
   ↓ restate() — 회사 전체를 보고
status = "current"
```

### 노드

```
원문        적용 대상은 성남시 관내 식자재·생활용품 소매 사업자 40개소
   ↓ LLM
{ kind:"node", topic:"target_customer",
  text:"적용 대상은 …", anchor:"성남시 관내 식자재·생활용품 소매 사업자 40개소",
  fact_key:"target_small_retail" }
   ↓ _fact_from_llm 이 key·value·as_of·qualifier 를 전부 None 으로 민다
   ↓ 앵커 검증 · place()   kind!="slot" → node_of("target_customer") = "customer"
Placement(kind="node", name="customer")         ← customer 가 여기서 처음 등장
   ↓ dedupe_key()
'node|customer|target_small_retail'
   ↓
wiki_fact  place_kind="node"  place="customer"  text="적용 대상은 …"
           topic="target_customer"   ← 원본 라벨이 남는다. 나중에 쪼갤 때 쓴다
   ↓
status 없음 — restate() 는 슬롯 행만 훑는다
```

**두 줄 다 `Placement` 가 생기는 순간 처음으로 `headcount`·`customer` 라는 글자가 나타난다.
모델은 그 단어를 한 번도 안 썼다.**

## 4. MD 한 장이 나오는 모양

`ORBIT["team"]` 을 `markdown.render()` 로 편 것이다. **슬롯과 노드가 같은 장에 들어간다.**

```markdown
---
node: team
title: 팀 구성
kind: content
sector: 팀과 계획
company: c_dasiro
values: 1        ← 슬롯
statements: 1    ← 노드
sources: 1
---

# 팀 구성

## 직원 수                                    ← slot (headcount)

**15명**  · 2026-08-31 기준

- 근거 — 사업계획서_2026.hwpx 4쪽

대표 포함 개발 4명, 영업 2명으로 구성된다      ← node (team)

> 근거 1 — 사업계획서_2026.hwpx 4쪽

## 근거 파일

- 사업계획서_2026.hwpx
```

**저장하지 않는다.** 읽을 때마다 만드는 뷰다(`wiki/markdown.py`) — 사실이 `wiki_fact` 에
있는데 마크다운으로도 들고 있으면 둘 중 하나가 먼저 낡는다. 프론트매터에 시각을 안 넣는
이유도 같다.

## 5. 이 나무를 읽는 법

**세로는 자리(계층), 가로는 재료(입력)다.**

```
계층 (세로)                      재료 (가로 · 계층이 아니다)
─────────────                   ──────────────────────────
SECTORS   6                     SLOT_ALIASES  43  ──► 슬롯 가지로만
  ORBIT  15                     TOPICS        25  ──► 노드 가지로만
    SLOTS 14 / NODES 10
```

`TOPICS 25` 를 세로줄 뿌리에 놓으면 안 맞는다. **`ORBIT` 한 자리에 든 것 중 절반이 topic 에서
안 온다.**

```
ORBIT["team"] ┌─ headcount 슬롯  ←  key("임직원")     · topic 안 거침
              └─ team 노드       ←  topic("team")     · topic 거침
```

## 6. 층마다 바꾸는 비용

```
SECTORS · ORBIT   ─── 표시 단위       고치면 → 공짜. 화면만 다시 그린다
SLOTS · NODES     ─── 병합 단위       고치면 → 재라우팅 (추출은 그대로)
TOPICS            ─── 추출 세밀도     고치면 → 전량 재추출 (LLM · 돈 · 비결정론)
SLOT_ALIASES      ─── 조회 + 프롬프트  고치면 → 프롬프트가 바뀌어 재추출
```

**재라우팅만 하는 명령이 없다**(`--rechunk` 는 청크, `--rebuild` 는 추출부터). 이것이
[plan/19](../../../plan/19-위키-자리-구조.md) 가 다룰 자리 중 하나다.
