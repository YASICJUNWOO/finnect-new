## 1. 방침

**어떤 디자인 시스템도 통째로 채택하지 않는다.** 우리 토큰을 쓰고 층별로 규칙만 빌린다.

| 층 | 기준 |
|----|------|
| 서체 | Pretendard. 없으면 시스템 한글 서체로 폴백 |
| 색 팔레트 | **GitHub Primer.** 목록과 표가 빽빽한 작업 도구를 위해 만들어진 팔레트라 우리 화면과 맞는다 |
| 색 사용 | 상태와 경고에만 색을 쓴다. 나머지는 무채색이다 |
| 접근성 | 색만으로 상태를 구분하지 않는다. 기호와 텍스트를 함께 쓴다 |
| 카피 | Polaris 방식. 사용자 행동 중심으로 쓴다 |
| 밀도 | Carbon 방식. 행 높이와 여백을 줄인다 |
| 목록 패턴 | Atlassian 방식. 상태별 그룹과 다음 행동 |
| 검사 | Vercel Web Interface Guidelines |

**KRDS는 쓰지 않는다.** 정부 사이트로 읽히면 안 된다. 사용자가 겪는 불편이 바로 공공 포털의 화면이라 그 언어를 옮기면 문제를 재현하는 것이 된다. 서체만 가져온다.

근거는 [ADR-0007](../adr/0007-KRDS-미채택.md).

## 2. 정보 밀도 규칙

이 제품은 읽는 화면이 아니라 **작업 도구**다. 스크롤보다 한 화면을 택한다. 다만 밀도가 혼잡이 되지 않도록 그리드와 정렬을 지킨다.

1. 한 화면의 주요 정보 덩어리는 다섯에서 일곱이다. 넘으면 접는다.
2. 금액과 남은 일수는 우측 정렬한다.
3. 구분은 옅은 선과 여백으로 한다. 굵은 테두리 상자를 쌓지 않는다.
4. 채도 높은 색은 마감 임박과 경고에만 쓴다. 나머지는 무채색이다.
5. 긴 표는 헤더를 고정한다.
6. **목록은 카드보다 행에 가깝게 짠다.** 카드로 하면 한 화면에 세 건, 행으로 하면 여덟 건이 들어간다. 사용자는 목록을 비교하러 온다.

## 3. 화면 설계 원칙

`SPEC.md` §1.4의 제품 원칙을 화면 규칙으로 옮긴 것이다.

1. **판별은 안 보인다.** 목록에 오른 것 자체가 판정 결과다.
2. **공고는 구조로 보여준다.** 원문을 옮기지 않고 항목으로 나눈다.
3. **결론 먼저, 근거는 접는다.** S3에서 특히 지킨다.
4. **집필은 세 번에 나눠 한다.**
5. **밀도는 높이되 구조를 준다.**
6. **확정 어투를 쓰지 않는다.**

---

## 4. 구현 제약

1. 컴포넌트 라이브러리를 쓰지 않고 `tokens.md`의 값으로 CSS를 직접 쓴다.
2. Pretendard는 웹폰트로 불러오지 않고 폰트 스택으로 처리한다.
3. D-day와 금액에 `font-variant-numeric: tabular-nums`를 적용한다.
4. `transition: all`을 쓰지 않는다.
5. `prefers-reduced-motion`을 존중한다.
6. 포커스 링은 키보드로 전 경로가 돌아야 한다.
