# ADR-0007: KRDS를 채택하지 않고 Primer 팔레트를 쓴다

- 상태: 채택됨
- 날짜: 2026-08-15

## 맥락

정부 지원사업을 다루는 서비스이므로 **KRDS(대한민국 정부 디자인 시스템)** 채택이 자연스러운 선택지였다. 공공 데이터를 쓰고 공공 사용자를 대상으로 하며, 이미 만들어진 컴포넌트를 그대로 쓸 수 있다.

## 결정

**KRDS를 쓰지 않는다. 서체만 가져온다.**

이유는 제품의 존재 이유와 충돌하기 때문이다. **사용자가 겪는 불편이 바로 공공 포털의 화면이다.** 수백 건 목록을 직접 판별하게 만드는 그 경험을 우리가 해결하려는 것인데, 그 화면의 언어를 그대로 옮기면 문제를 형태만 바꿔 재현하게 된다. 정부 사이트로 읽히면 안 된다.

대신 **어떤 디자인 시스템도 통째로 채택하지 않고** 층별로 규칙만 빌린다.

| 층 | 기준 | 이유 |
|----|------|------|
| 서체 | Pretendard | 한글 가독성. KRDS에서 유일하게 가져오는 것 |
| 색 팔레트 | **GitHub Primer** | 목록과 표가 빽빽한 작업 도구를 위해 만들어진 팔레트다. 명도 대비가 검증돼 있어 따로 계산하지 않는다 |
| 밀도 | Carbon | 행 높이와 여백을 줄인다 |
| 카피 | Polaris | 사용자 행동 중심 |
| 목록 패턴 | Atlassian | 상태별 그룹과 다음 행동 |
| 검사 | Vercel Web Interface Guidelines | |

## 결과

- 우리 토큰을 직접 정의하고 컴포넌트 라이브러리 없이 CSS를 직접 쓴다. 초기 비용이 있지만 밀도 요구가 특수해서 어차피 기성품을 고쳐 써야 한다.
- **이 제품은 작업 도구로 읽힌다.** 목록은 카드가 아니라 행이고, 색은 상태와 경고에만 쓴다.
- 대가로 접근성을 스스로 챙겨야 한다. Primer 값이 명도 대비를 보장하지만 **색만으로 상태를 구분하지 않는다**는 규칙은 우리가 지켜야 한다.
- 공공 조달이나 정부 협업이 생기면 KRDS 요구가 올 수 있다. 그때 다시 정한다.

토큰 값은 [`../design/tokens.md`](../design/tokens.md)에 있다.
