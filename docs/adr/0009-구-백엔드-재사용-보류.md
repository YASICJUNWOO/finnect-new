# ADR-0009: 구 finnect 백엔드 재사용을 보류한다

- 상태: 채택됨
- 날짜: 2026-08-16

## 맥락

`/home/joonoo3/project/finnect/backend`에 이전 제품의 코드가 있다. 2026-08-13 실사에서 다음이 확인됐다.

| 자산 | 상태 |
|------|------|
| 정책 코퍼스 | youth_policies 2,634건 + policies 460건 |
| 수집 파이프라인 | 온통청년·복지로·fill4young 파서 |
| 구조화 추출 | strict JSON 스키마, 교정 후처리 |
| 룰 엔진 자격 판정 | 게이트 + AND/OR 평가 |
| 에이전트 런타임 | agents-as-tools + SSE |
| 출력 가드레일 | 출처 표기 |

구조만 보면 F0·F2와 겹친다.

**문제는 그 실사가 피봇 전 기준이라는 것이다.** 08-13 조사 시점의 제품은 "청년 개인 정책 추천"이었고, 08-15에 "창업 지원사업 판정 + 사업계획서 집필"로 바뀌었다. 배점 기반 집필 파이프라인(L3)은 실사 대상에 아예 포함되지 않았다.

도메인도 바뀌었다. 추출 스키마가 자립준비청년 특화 필드(`care_ended`, `care_end_years`, `care_duration_years`)로 짜여 있어 어휘를 통째로 갈아야 한다.

## 결정

**재사용하지 않는다. 새로 짠다.** 다만 폐기가 아니라 **보류**다.

- 구 코드는 참고 자료로만 본다.
- 필요해지면 그때 개별 모듈 단위로 다시 판단한다.
- 실사 문서는 [`../archive/재사용자산_인벤토리.md`](../archive/재사용자산_인벤토리.md)에 보관한다. 피봇 전 기준임을 전제하고 읽어야 한다.

## 결과

- 초기 개발량이 늘어난다. 수집·추출·판별을 0에서 만든다.
- 대신 **도메인이 바뀐 코드를 고쳐 쓰는 비용을 피한다.** 특히 추출 스키마는 코퍼스가 모양을 결정하므로, 창업 공고를 보고 새로 설계하는 편이 낫다.
- 2026-08-16 실측에서 나온 발견이 이 결정을 뒷받침한다. **K-Startup API가 업력·연령·지역·대상·마감일을 100% 구조화해서 준다.** 구 코드의 복잡한 추출 파이프라인이 필요 없는 영역이 상당하다.
- 되살릴 후보 1순위는 **추출 프롬프트 설계와 출력 가드레일**이다. 도메인 중립적이고 실전에서 깎인 흔적이 있다.
