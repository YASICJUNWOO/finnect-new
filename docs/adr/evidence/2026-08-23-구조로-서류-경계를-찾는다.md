# 구조로 서류 경계를 찾는다 — 실측 (2026-08-23)

[ADR-0061](../0061-양식-파싱의-입력을-파일-구조로-바꾼다.md) 결정 1 의 첫 조각이다.
`segment.doc_titles` 와 `segment.split(titles=…)` 를 코퍼스에 돌려 **표지 규칙만 쓴
결과와 견줬다.**

## 무엇이 문제였나

구간 나누기가 표지 낱말(`붙임`·`별첨`·`서식`·`별지`·`양식`·`첨부`)을 찾아 자른다.
**그 낱말이 없는 양식이 흔하다.**

```
1. 2026년 0차 타깃마케팅(0000) 기본지원서     ← 붙임도 서식도 없다
2. 2026년 0차 타깃마케팅(0000) 활동계획서     ← 못 자른다
```

텍스트로는 평범한 한 줄이라 다른 줄과 구별할 수단이 없다. 못 자르면 서류 다섯이
한 덩어리가 되고, 뒤따르는 항목 추출이 **동의서 본문 344자를 「기대효과」의 작성
지시문으로** 가져간다(같은 파일 실측).

## 발견 — 낱말이 없어도 모양이 있다

파일 구조로 열면 같은 글자에 정보가 하나 더 붙는다.

```
표0  0:0:0:0  ''
표0  0:0:0:1  '2026. 00. 00.(00) 작성자: 000 직함 (055-000-0000)'
표0  0:0:1:0  '1. 2026년 0차 타깃마케팅(0000) 기본지원서'    ← 칸 셋짜리 작은 표다

표2  0:2:0:0  ''
표2  0:2:0:1  '2026. 00. 00.(00) 작성자: 000 직함 (055-000-0000)'
표2  0:2:1:0  '2. 2026년 0차 타깃마케팅(0000) 활동계획서'    ← 똑같이 생겼다
```

한글 양식은 **서류 제목을 표 하나로 감싼다** — 테두리와 음영을 주려는 관례다.
텍스트로 납작하게 만들면 그 모양이 사라진다.

규칙: **칸이 셋 이하인 표의 셀, 또는 표 밖 문단이 60자 이하이고 서류 이름으로
끝나면 서류 경계다.** 찾은 제목은 원문에서 대조해 오프셋으로 바꾼다(ADR-0061 결정 5).

|---|---:|---:|---:|---:|---:|---:|
| hwp | 255 | 452 | **584** | +132 | 70 (27.5%) | 1.8초 |
| hwpx | 63 | 117 | **134** | +17 | 12 (19.0%) | 97.0초 |

**오프셋이 깨진 파일 0건.** 잘라낸 구간이 원문과 바이트로 같다 — 근거 청크를 여는
경로가 이 값에 걸려 있다(ADR-0014).

**못 연 파일 0건.**

### 손으로 센 파일 셋

사용자가 올린 hwp 세 개다. 서류 장 수를 눈으로 셌다.

|---|---:|---:|---:|

경남TP 에서 하나를 놓쳤다 — `신청자격 적정성 확인서` 가 **44칸짜리 큰 표의 첫
칸**이라 「작은 표」 조건에 안 걸린다.

## 육안 검증

코퍼스에서 **13건**을 눈으로 봤다(회차 겹침 포함 23건). 자동 판정 수치만으로
보고하지 않는다는 규율(CLAUDE.md)에 따른다.

**오탐 세 종류를 찾아 고쳤다.**

| 무엇 | 어디서 | 고친 것 |
|---|---|---|
| `­ (필수) 지정 신청서(온라인 신청서식)` | 벤처나라 제품 지정신청 | 줄머리 기호(`\xad`·`<`)를 목록 항목으로 본다 |
| `ㅇ 참여기업 각서(별지 제3호 서식)` | 붙임 2 완료 보고서 | 한글 `ㅇ`·`ㅁ`·`o` + 공백을 더한다 |
| `6. 신청방법 및 제출서류` | 중동 수출물류비 | `제출서류` 를 서류 이름에서 뺀다 |

셋 다 **제출서류 안내를 서류 제목으로 읽은 것**이다. 표는 「작은 표」 조건이
목록을 걸러 주는데 **문단에는 그런 조건이 없었다.**

## 파이프라인에 붙여서 다시 쟀다

위는 `spike/` 가 구조 규칙만 떼어 잰 것이다. **실제 경로로 한 번 돌렸다.**

```
uv run python -m finnect.extract --redo
```

```
파일 523 · 구간 1,067 · 칸 서식 209 · 칸 4,373 · 건너뜀 0
좌표를 심은 칸 1,024 · 구조가 찾은 서류 제목 494
구간 종류: 858 unknown · 209 fields
```

| | before | after |
|---|---:|---:|
| 구간(`document`) | 944 | **1,067** (+123 · +13.0%) |
| 구조가 찾은 서류 제목 | — | **494** |

**spike 예측(+154)보다 적다.** pdf 197개가 구조를 못 열고, `_merge_heads` 가 표지 줄과
제목이 떨어진 자리를 도로 합치기 때문이다. 실제 값은 이쪽이다.

새로 생긴 구간 제목에 **표지 낱말이 없는 것들이 그대로 보인다.**

```
(해당 시) 공동대표 또는 각자대표 동의서
[예비창업자] 최종선정확인서
창업신청서(상용직용)
2026년 성장플러스 창업사업화 지원사업 사업계획서
2026년 특허출원·등록 비용 바우처 지원사업 신청서
```

**항목 수는 이 회차에서 못 견줬다.** `--redo` 가 규칙 판정만 하므로 LLM 이 붙여 뒀던
`narrative` 77구간이 `unknown` 으로 돌아갔고, `_replace` 는 `fields` 구간에만 칸을 깐다
— 서술 항목 1,701개가 그래서 빠졌다(7,256 → 4,373). `--classify` 808건을 돌려야
복구되고 그때 비로소 **구간이 는 만큼 항목이 늘었는지**를 볼 수 있다.

**초안 1벌(항목 22 · 근거 49)이 지워졌다.** 사용자가 먼저 승인했고 `edited_body` 는
0건이었다. `extract --redo` 의 이 성질은 T-0160 이 막을 자리다.

### 새로 생긴 구간이 제대로 판정되는가 — 표본 40건

```
uv run python -m finnect.extract --classify 40 --dry --title-like 계획서
```

`계획서` 를 고른 이유는 그 후보 63건 중 **45건(71%)이 표지 낱말이 없는 제목**이라
구조가 만든 구간이 많이 걸리기 때문이다. **`--title-like` 는 표본 고르기이고 판정
규칙이 아니다.**

```
판정: 34 narrative · 5 fields · 1 none
호출 40회 · 입력 74,934 · 출력 3,884 토큰 · 약 $0.02
```

**40건을 전부 눈으로 봤고 어긋난 판정이 없다.** 표 칸이 섞인 양식이 `fields` 로
가고(`안양대학교 창업보육센터 신규입주 사업계획서`·`품질관리 계획서`), 동의서가
`none` 으로 갔다(`[상세 사업계획서 양식.2] 개인정보 수집 및 이용 동의서`).

**이 회차에 회수한 서류 둘이 그대로 `narrative` 로 앉았다.**

```
narrative  『경기도 반려동물 창업공모전』 사업계획서
           ← 목차에도 같은 이름이 있어 버려지던 것. 첫 셀 완전 일치로 살렸다
narrative  2. 2026년 0차 타깃마케팅(0000) 활동계획서
           ← 표지 낱말이 없어 앞 서류에 붙어 있던 것
```

경남TP 파일에서 이 구간은 어제까지 **없었다.** 활동계획서가 기본지원서에 붙어
있었고, 그 결과 동의서 본문 344자가 「기대효과」의 작성 지시문으로 들어갔다.

**전량 808건으로 넓히면 대략 $0.40** 이다(40건 $0.02 기준 선형 추정).

## 한계

- **큰 표의 첫 칸은 못 잡는다.** 경남TP `신청자격 적정성 확인서`(44칸)가 그렇다.
  조건을 「표의 첫 칸」으로 넓히면 잡히지만 **본문 표의 라벨이 딸려 온다** —
  서류 하나가 여러 조각으로 갈리는 쪽이 안 자르는 것보다 나쁘다.
- **pdf 197개는 이 길이 없다.** 표 구조가 없어 표지 규칙만 돈다(ADR-0061 결정 2).
- **hwpx 가 느리다.** 파일당 1.5초로 hwp(7ms)의 200배다. 초안 시작 경로에 붙지만
  뒤따르는 LLM 호출이 더 길어 사용자가 느끼지는 않는다. 전량 재적재에서는 보인다.
- **`제출서류` 안내 장 하나를 일부러 놓친다.** `『…』 신청시 제출서류` 가 그것이고,
  오탐 둘을 없애는 대가다.
- **이 숫자는 경계를 몇 개 찾았나이지 항목이 몇 개 늘었나가 아니다.** 뒤따르는
  종류 판별(LLM)과 항목 추출을 다시 돌려야 그 값이 나오는데, `extract --redo` 가
  초안을 지우므로(FK CASCADE · T-0160) 돌리지 않았다.

## 재현

```bash
uv run python spike/segment_check.py --ext hwp --sample 20
uv run python spike/segment_check.py --ext hwpx
uv run python spike/segment_check.py --ext docx
```

`spike/` 는 버리는 코드다. 규칙 자체는 `src/finnect/extract/segment.py` 의
`doc_titles` 이고 `tests/test_extract.py` 가 잠근다.
