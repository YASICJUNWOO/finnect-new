# ADR-0011: 수집 실행을 관리 화면에 붙인다

- 상태: 채택됨
- 날짜: 2026-08-16
- 뒤집는 것: [plan/06](../plan/06-목록-수집과-조회.md) "정한 것 — 수집 실행: CLI" 및 T-0013 "안 하는 것 — 수집 실행 버튼"

## 맥락

[plan/06](../plan/06-목록-수집과-조회.md)은 수집 실행을 CLI로만 두기로 하고 이유를 "버튼·스케줄러·큐는 지금 붙이면 과설계다"로 적었다. T-0013은 조회 화면의 "안 하는 것"에 수집 실행 버튼을 명시했다.

그 판단은 **셋을 한 덩어리로 묶은 것**이 문제였다. 스케줄러와 잡 큐는 지금 과설계가 맞다. 그러나 실행 버튼은 성격이 다르다.

수집을 실제로 돌려 보니 두 가지가 드러났다.

**첫째, 실행 이력이 어디에도 안 남는다.** CLI가 `report.render()`를 터미널에 찍고 끝난다. 터미널을 닫으면 "언제 마지막으로 받았나", "그때 몇 건이었나", "실패한 적이 있나"에 답할 수단이 저장소에 없다. `raw_fetch`에 응답은 남지만 그건 응답이지 실행이 아니다.

**둘째, 실패가 안 보인다.** 두 API 모두 실패를 HTTP 200으로 준다. 봉투 검증이 그걸 잡지만, 잡은 결과가 터미널에만 있으면 화면을 보는 사람은 "공고가 0건"과 "수집이 실패했다"를 구분할 수 없다.

## 결정

**1. 관리 화면에 수집 실행을 붙인다.** 스케줄러와 잡 큐는 여전히 안 붙인다. 이 셋을 분리한다.

**2. 실행은 프로세스 안의 백그라운드 스레드다.** 큐도 워커도 브로커도 없다. K-Startup 전량이 149회 요청이라 요청 안에서 끝낼 수 없어서 스레드로 뗀다. 그 이상은 아니다.

프로세스가 죽으면 실행도 죽는다. 이건 감춰야 할 결함이 아니라 이 설계의 성질이므로 화면이 그대로 말한다. `RUNNING` 행에 pid를 같이 남기고, 기동할 때 죽은 pid의 행을 `INTERRUPTED`로 바꾼다. 끝까지 돌았는지 알 수 없다고 적는다.

**3. 실행 기록을 `ingest_run` 테이블에 남긴다. CLI와 화면이 같은 표를 쓴다.** 경로가 갈리면 둘 중 하나에서만 나는 버그가 생기므로 진입점은 `ingest/service.py` 하나다. CLI는 `trigger="cli"`, 화면은 `"admin"`으로만 다르다.

기록은 **적재와 다른 세션에 커밋한다.** 적재가 실패하면 `session_scope`가 통째로 롤백하는데 실패 사실까지 같이 사라지면 화면에서 아무 일도 없었던 것으로 보인다.

**4. 같은 출처를 동시에 두 번 돌리지 않는다.** 검사가 둘이다. 프로세스 안의 락이 동시 클릭을 막고, `ingest_run`의 살아 있는 `RUNNING` 행 조회가 다른 프로세스(CLI)를 막는다. 하나로는 부족하다.

**5. 건수 제한을 붙이되 잘렸다는 사실을 기록에 남긴다.** 화면에서 반복 확인할 때 3만 건을 매번 받을 이유가 없다. 다만 [plan/06 "수집 원칙"](../plan/06-목록-수집과-조회.md#수집-원칙--서버측-필터를-쓰지-않는다)이 경고한 "아끼려다 조용히 틀린 모집단을 얻는다"가 바로 이 지점이다.

두 API 모두 **잘라 받아도 전량 건수를 같이 준다**(기업마당 `totCnt`, K-Startup `matchCount`). 그래서 `ingest_run`에 요청한 제한(`item_limit`)과 출처가 말한 전량(`expected`)을 나란히 남기면 맛보기 수집과 전량 수집이 건수만 보고도 구분된다. 이 구분이 없으면 이 기능을 붙이지 않는다.

## 결과

- `plan/06`의 "정한 것" 표에서 수집 실행 행이 바뀐다. T-0013의 "안 하는 것"에서 수집 실행 버튼이 빠지고 [T-0014](../plan/06-목록-수집과-조회.md#t-0014-수집-실행-화면)가 생긴다.
- `ingest_run` 테이블이 는다. **코퍼스가 아니라 운영 기록이다.** L1 스키마 설계와 무관하다.
- `python-multipart` 의존성이 는다. 화면 폼 파싱용이다.
- CLI는 그대로 산다. 없애지 않는다. 재현 가능한 명령이 계획의 `검증` 절이고, 화면은 그 위에 얹은 것이다.
- **포기한 것** — 재시도, 취소 버튼, 부분 재개, 여러 출처 동시 실행. 프로세스가 죽으면 그 실행은 끝이고 다시 눌러야 한다. 잡 큐를 안 붙이기로 한 대가다.

## 안 정한 것

스케줄러는 여전히 범위 밖이다. 주기 수집이 필요해지면 그때 별도 결정으로 남긴다. 지금은 사람이 누르거나 CLI를 치는 것뿐이다.
