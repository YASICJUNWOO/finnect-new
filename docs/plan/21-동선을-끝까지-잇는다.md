2026-08-22 코드와 로컬 DB 를 직접 셌다.

| 사용자가 하는 것 | 백엔드 | 화면 |
|---|---|---|
| 1. 회사 문서를 올린다 | **있다** | **있다** |
| 2. 맞는 공고를 추천받는다 | **있다** — `GET /api/companies/{id}/recommendations` | **없다** |
| 3. 들어가서 초안작성을 누른다 | **절반** — 만드는 API 가 없다 | **없다** |

**쓰기 API 가 레포 전체에 하나뿐이다** — `POST /api/wiki/{company_id}/files`(`src/finnect/api/app.py:283`). 나머지 13개 라우트가 전부 GET 이다. 2·3·4 단계는 **사람이 터미널을 쳐야 돈다.**

### 2단계 — 만들어 놓고 안 쓴다

`web/lib/api.ts` 에 추천을 가져오는 함수가 **아예 없다.** 목록 화면은 대신 숫자와 문장을 박아 뒀다.

```tsx
// web/app/(product)/(list)/page.tsx:65
<b data-numeric>0</b>
<span>나에게 맞는 공고</span>

// :83
아직 사업 위키가 없어서 못 고르고 있어요. 파일을 올리면 여기에 세 건이 뜹니다.
```

**둘 다 하드코딩이다.** 파일을 올려 위키가 서고 `--company` 로 추천 3건이 `notice_fit` 에 앉아도 화면은 계속 `0` 과 「위키가 없어서」를 말한다. [17](17-맞는-공고를-고른다.md)이 육안 8/8 로 검증한 판정이 **사용자에게 한 번도 안 나갔다.**

공고 상세의 「왜 맞는지」·「자격이 되는지」 두 칸도 같은 자리에 `NotYet` 고정이다(`web/app/(product)/notices/[source]/[id]/page.tsx:114`).

### 3·4단계 — 데이터가 먼저 없다

로컬 DB 를 셌다.

```
attachment      3,354      ← 메타만 있다
attachment_file     0      ← 첨부 텍스트가 없다
document            0      ← 양식이 없다
document_item       0
item_need           0
draft / draft_item  0
```

**이 값은 로컬 것이고 배포 서버 DB 와 다르다.** CLAUDE.md 가 인용하는 `document_item` 41,330 은 2026-08-19 배포 쪽에서 잰 값이다. 로컬 `kstartup_notice` 는 50건뿐이다. **어느 DB 에서 무엇을 돌릴지가 이 계획의 첫 줄이다** — 정하지 않고 시작하면 「돌렸는데 아무것도 안 나온다」를 두 번 겪는다.

그 위에 `web/` 전체에서 `draft` 라는 낱말이 **주석 한 줄뿐이다**(`web/components/FormFill.tsx:16`). 조회 API 는 스키마까지 완비인데 부르는 쪽이 없다. `FormFill` 의 입력값은 `useState` 로컬 상태라(`:341`) **새로고침하면 날아간다.**

### T-0118 서술형 판별을 돌린다 — **막힘** (2026-08-22 · 데이터가 없다)

[11](11-작성-항목-추출과-표시.md) T-0036 이 **판정기는 붙었고 한 번도 안 불렸다.** 그래서 `document.kind` 가 전부 `field` 고 서술형이 0건이다. 서술형이 0건이면 **초안이 붙을 자리가 없다.**

```bash
# 0. 어느 DB 인가부터 정한다. 로컬은 attachment_file 이 0 이라 아무것도 안 나온다
uv run python -m finnect.extract --classify 40 --dry   # 손 분류 40건과 대조 — T-0036 완료 조건
uv run python -m finnect.extract --classify            # narrative 가 생긴다
uv run python -m finnect.draft --read-forms 20         # item_need 가 생긴다 — T-0063
```

- **`--dry` 를 먼저 돌리고 손 분류 40건과 대조한다.** 규칙이 네 번 실패한 자리라 정확도를 안 재고 전량을 돌리면 **공고문 목차가 작성 항목으로 앉는다**
- **몇 건을 눈으로 봤는지 함께 적는다**(CLAUDE.md 규칙)
- 비용을 잰다 — `llm.Usage.line()`
- 닫히면 [11](11-작성-항목-추출과-표시.md) T-0036 · [16](16-항목마다-초안을-쓴다.md) T-0063 이 같이 닫힌다

#### 2026-08-22 — 못 돌렸다

**로컬 DB 에 판별할 것이 없다.** 세어 보니 이렇다.

```
attachment      3,354      ← 메타만 있다
attachment_file     0      ← 첨부를 한 번도 안 받았다
document            0
document_item       0
item_need           0
```

`--classify` 는 `document` 의 `unknown` 구간을 가르는 명령인데 **그 표가 비어 있다.** 앞에 `uv run python -m finnect.attach`(3,354건 · 약 2GB · 30분)가 서야 하고, 그 뒤에 LLM 비용이 붙는다.

**배포 서버 DB 에는 있다** — CLAUDE.md 가 인용하는 `document_item` 41,330 이 거기서 잰 값이다. 그러면 이 태스크는 **어느 DB 에서 돌릴지를 사람이 정해야 한다:**

| 길 | 대가 |
|---|---|
| 로컬에 첨부를 다시 받는다 | 30분 + 2GB + 정부 서버에 3,354회 요청. 그다음 LLM 비용 |
| 배포 DB 에 직접 돌린다 | **운영 데이터에 쓰기다.** 되돌리려면 `document.kind` 를 되돌려야 한다 |

**둘 다 임의로 고를 일이 아니라서 안 골랐다.** 그래서 T-0121·T-0122·T-0123 은 **배관만 서 있고 실제 초안 위에서 한 번도 안 돌았다** — 아래 «지금 무엇이 안 재졌나» 참조.

### T-0119 추천을 목록 화면에 붙인다 — **완료** (2026-08-22)

API·서비스·테스트·계약이 다 있다. **함수 하나와 배선이다.**

- `:83` 의 고정 문구를 **`computed` 로 가른다.** 세 상태가 다른 문장이어야 한다

  | `computed` | `items` | 화면이 하는 말 |

  | `false` | — | 아직 안 골랐어요. 파일을 올리면 골라 드려요 |
  | `true` | 0건 | 지금 열린 공고 중에 맞는 게 없어요 |
  | `true` | 1~3건 | 추천 카드 |

- **이유 한 줄과 근거를 같이 낸다.** `rank.quotable()` 이 표 부스러기를 인용에서 막는다(T-0078 의 증상 쪽)
- **숫자도 막대도 열도 없다.** 순서가 정보를 담는다
- `company` 를 어디서 얻나 — 인증이 없어서 `?company=` 나 `DEFAULT_COMPANY`. **`/wiki` 와 같은 규칙을 쓴다**(`web/lib/wiki.ts:121`). 두 화면이 다른 규칙으로 회사를 고르면 사용자가 남의 위키를 본다

- **사람이 고친 문단은 근거가 없다.** `draft_evidence` 를 어떻게 하나 — 지우나, 남기고 「사람이 고침」을 다나. **결정 자리다.** 그 값이 [ADR-0028](../adr/0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md) 4번(사실이 갱신되면 어느 항목이 낡았는지 계산된다)의 재료라 지우면 그 계산이 끊긴다
- **재작성이 사람 글을 덮으면 안 된다.** 항목 단위 재작성(T-0121)과 같은 행을 건드린다
- 스키마가 바뀌면 **마이그레이션을 배포 DB 에도 돌린다**(CLAUDE.md 함정)
- **ADR 을 쓴다** — 사람이 쓴 문장과 LLM 이 쓴 문장을 한 표에 섞는 결정이다

### T-0161 초기화가 초안을 다시 세운다 — **완료** (2026-08-23)

**「다시 쓰기」 버튼이 오래 있었고 아무 일도 안 했다.** `POST …/draft` 가 `redo` 를 안 넘겨서 `_draft_row` 가 이미 있는 초안을 보고 그대로 돌아갔다. 사용자는 `started: true` 를 받고 폴링이 돌다가 예전 초안이 그대로 남는 것을 봤다.

**버리는 자리가 늦었다.** `_draft_row` 는 저장 직전이라 배분과 집필이 이미 끝난 뒤다 — 항목 수십 개를 LLM 으로 다 쓰고 통째로 버렸고, 화면에도 `BuildReport` 에도 흔적이 없어서 **돈이 나간 것을 아무도 못 봤다.**

- `redo` 를 쿼리 파라미터로 연다. **경로가 안 늘어난다** — 쓰기 API 는 여전히 셋이다
- `redo` 가 아니면 **조립 단계에서** 이미 초안이 있는 양식을 걷어낸다(`_drafted_documents`). `BuildReport.skipped` 가 그 수를 낸다
- **버튼을 둘로 가른다** — 머리줄의 **「초기화」**(선 버튼 · `redo=true`)와 하단의 **「쓰기」**(`redo=false` · 안 쓴 양식만 더한다). 한 자리가 초안 유무에 따라 두 뜻으로 갈리면 **누르기 전에 화면을 읽어야 한다**
- 초기화는 **사람이 고친 글도 지운다.** 무엇이 사라지는지 **먼저 말하고 누르게 한다** — [ADR-0062](../adr/0062-다시-쓰기가-고친-글을-지우되-먼저-알린다.md)
- 카피가 거짓이었다. 「못 쓴 항목만 다시 써요. 내가 고친 글은 그대로 둬요.」 → 하단은 「아직 안 쓴 양식 N개를 채워요. 이미 쓴 것은 그대로 둬요.」
- 조각 셋을 두 화면이 같이 쓴다(`StartRow` · `ResetButton` · `ConfirmRow`). **카피를 각자 들고 있었고 둘 다 거짓이었다**
- 말로 시켜도 같은 자리로 간다. `readCommand` 가 **「초기화」도 받는다** — 화면에 적힌 말을 그대로 쳤는데 못 알아들으면 그 버튼이 없는 것으로 읽힌다

**테스트 SQLite 에 FK 를 켰다.** 기본이 꺼짐이라 `ON DELETE CASCADE` 가 안 돌았고, `delete(DraftItem)` 이 남긴 근거가 배포 DB(Postgres)에서만 지워졌다 — **재작성이 로컬에서만 깨지는 자리**였다.

**안 한 것:** 초안 버전 쌓기(유니크 키를 바꿔야 한다) · 채운 파일 저장(`filled_document` 가 요청마다 원본에서 만들어서 이미 「원본으로 교체」다) · 되돌리기 창.

### T-0124 못 채운 자리에서 묻는다 — **다음 회차**

[ADR-0028](../adr/0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md)이 정한 마지막 조각이다. 초안이 먼저 다 나오고, 항목 옆에서 묻고, 답하면 **위키에 먼저 저장한 뒤** 그 항목만 재작성한다. 답변은 `user_stated` 등급이라 문서가 자동으로 덮지 않는다.

**이번에 안 한다.** 두 가지가 먼저 서야 한다.

1. **T-0123 이 저장 모델을 정한다.** 사람이 쓴 것을 어디에 어떻게 두는지 모르고 질문 답변을 얹으면 같은 결정을 두 번 한다
2. **위키에 사람이 값을 넣는 길이 없다.** `wiki_fact` 쓰기 경로가 지금 추출기 하나뿐이다

## 순서와 이유

```
T-0117 (이름)  ──┐
                 ├─▶ T-0119 (추천 화면) ──▶ T-0120 (상세 칸)
T-0118 (데이터) ─┴─▶ T-0121 (생성 API) ──▶ T-0122 (초안 화면) ──▶ T-0123 (저장)
                                                                      └─▶ T-0124 (다음 회차)
```

**T-0119 를 맨 앞에 두는 이유는 크기가 아니라 성질이다.** 이미 만들고 검증까지 끝낸 판정이 화면에 안 나가고 있다 — 새로 만드는 것이 아니라 **끊긴 선을 잇는 것**이라 위험이 가장 낮고 동선이 한 칸 늘어난다.

**T-0118 이 3·4단계 전부의 선행이다.** 안 돌리면 T-0121 을 붙여도 쓸 양식이 0건이라 「쓸 양식이 없어요」만 나온다. **비용이 드는 유일한 태스크이기도 하다.**

**T-0117 은 T-0122 앞에만 서면 된다.** 새 화면에 어느 번호를 적을지가 거기서 정해진다.

### 지금 무엇이 안 재졌나

**15번이 이 계획에서 가장 중요한데 못 했다.** [16](16-항목마다-초안을-쓴다.md)이 초안 한 벌을 냈지만 *「문장을 아직 아무도 안 읽었다」* 로 닫혔고, 화면에 띄우는 것은 **그 문장을 처음 사람 앞에 놓는 일**이었다. 로컬에 `draft` 가 0건이라 그 일이 아직 안 일어났다.

**배관과 사용이 다르다.** 아래가 지금 상태다.

| | 상태 |
|---|---|
| 추천을 부르는 코드 | **있다.** `notice_fit` 이 로컬에 0건이라 **화면에 뜨는 것은 못 봤다** |
| 초안 만들기 · 고치기 | **있고 테스트가 돈다.** 집필기를 실제로 안 불렀다(`_write_draft` 를 갈아 끼운다) |
| 초안 화면 | **있다.** 띄울 초안이 없어서 **한 번도 안 그려졌다** |

**「테스트가 통과한다」를 「돈다」로 읽지 않는다.** 여기서 통과한 것은 계약과 배선이고, 초안이 좋은지도 추천이 맞는지도 말하지 않는다 — [16](16-항목마다-초안을-쓴다.md) 검증 12번이 적어 둔 것과 같은 경계다.
