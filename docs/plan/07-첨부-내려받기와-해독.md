**첨부를 내려받아 텍스트를 뽑고, 못 읽은 것을 못 읽었다고 남긴다.** 뽑은 텍스트로 무엇을 판단하지는 않는다.

## 목표

기업마당 첨부 3,354건이 디스크에 내려오고, 포맷별 해독률이 숫자로 나오고, **미해독 건이 화면에서 보인다.**

## 왜 이걸 먼저 하는가

06이 닫히면서 열린 계획이 없어졌다. [plan/README](README.md)가 다음 후보를 셋 뒀고 그중 **첨부 파싱이 가장 위험한 자리**였다. 다만 그 셋 중 T-0006(양식 목차 구조화)은 보류하기로 했다. 여기는 그 아래층, **"파일이 손에 들어오는가"** 만 한다.

T-0004의 완료 조건이 그대로 이 슬라이스의 목표다.

> 미지원 포맷을 만나면 기록에 남는다. **조용히 건너뛰지 않는다.**
> 공고 단위로 "첨부 N개 중 M개 해독"이 보인다.

**실측에서 실제로 당한 사고를 막는 일이다.** DOCX 파서가 없어 초기창업패키지 첨부 20개 중 4개를 못 읽었고, 못 읽었다는 사실이 아무 데도 안 남아서 그 상태로 "배점이 없다"는 결론을 냈다. 결과적으로는 같았지만 **몰라서 같았지 확인해서 같았던 게 아니다.**

그리고 이 슬라이스의 출력이 [T-0007](02-수집과-추출.md#t-0007-스캔-pdf-처리-판단)의 입력이다. OCR을 붙일지는 **"몇 건이 OCR 없이는 0바이트인가"** 를 보고 정한다.

## 이미 확인된 것

2026-08-17 이 저장소에서 실측했다.

| 항목 | 값 |
|---|---|
| 첨부 행 | 3,354건. **전부 기업마당** |
| K-Startup | 0건. API에 첨부 필드가 없어 `UNKNOWN` 상태 |
| URL 유일성 | 3,354 / 3,354 |
| 내려받기 | **`HEAD` 403 · `GET` 200.** 브라우저 UA와 Referer가 필요하다 |
| 파일명 | `Content-Disposition`에 온다. URL에는 없다 |

포맷 분포다. **`ext`는 API가 준 파일명에서 딴 것이고, 실제 내용과 다를 수 있다.**

| 포맷 | 건수 | 해독 계획 |
|---|---|---|
| hwp | 1,502 | OLE + 레코드 워크 (실측 100%) |
| pdf | 1,167 | pdfplumber (실측 91%) |
| hwpx | 309 | ZIP + XML (100%) |
| zip | 166 | **목록만 읽는다.** 안까지 안 푼다 |
| xlsx · xls · xlsm | 70 | 미지원으로 기록 |
| **png · jpg** | **121** | **미해독으로 기록.** 어떤 파서로도 0바이트 |
| docx · doc | 12 | docx만 ZIP + XML |
| pptx | 7 | 미지원으로 기록 |

**공고문 자리에 이미지가 붙은 게 62건이다**(png 43 · jpg 19). 스캔 PDF와 별개로 이미 존재하는 미해독 덩어리다.

## 할 것

`SPEC.md` F2-2의 앞부분이다. F2-3 이후(정규화·구조화 추출)는 여기서 안 한다.

### 저장

[ADR-0022](../adr/0022-첨부-원본을-콘텐츠-주소로-로컬에-둔다.md)로 정했다. 요약만 옮긴다.

- 원본은 `data/attachments/<sha256[:2]>/<sha256>`
- 상태는 `attachment_file` **별도 표.** `attachment`는 재수집 때 지워지고 다시 깔린다
- 추출 텍스트는 원본 옆에 `.txt`로. DB에는 문자 수만

### 해독

지원 포맷 목록을 **설정으로** 관리한다. 코드를 고치지 않고 끄고 켠다.

미지원과 실패를 상태로 가른다. **"안 해봤다"와 "해봤는데 안 됐다"와 "해봤는데 빈 파일이었다"는 다른 사실이다.**

| 상태 | 뜻 |
|---|---|
| `ok` | 텍스트가 나왔다 |
| `empty` | 파서는 돌았는데 0바이트다. **이미지 PDF가 여기 걸린다** |
| `unsupported` | 지원 목록에 없는 포맷 |
| `failed` | 파서가 예외를 던졌다 |
| `container` | ZIP. 안의 목록만 읽었다 |

## 안 하는 것

- **텍스트로 무엇을 판단하지 않는다.** 배점·요건·양식 추출은 F2-3 이후다
- **OCR을 붙이지 않는다.** [T-0007](02-수집과-추출.md#t-0007-스캔-pdf-처리-판단)이 이 슬라이스의 출력을 보고 정한다
- **양식 목차를 구조화하지 않는다.** [T-0006](00-미결-해소.md#t-0006-양식-목차-파싱-가능성-확인)은 보류다
- **K-Startup 첨부를 긁지 않는다.** 상세 페이지 스크래핑은 별개 작업이다
- **ZIP 안을 풀지 않는다.** 목록만 본다
- **실행 기록 표를 만들지 않는다.** 행마다 상태가 남아 실패가 스스로 보인다([ADR-0022](../adr/0022-첨부-원본을-콘텐츠-주소로-로컬에-둔다.md) 7번)
- **큐도 워커도 안 붙인다.** 한 프로세스에서 순서대로 받는다

### T-0016 내려받기

- 상태: 완료

URL 하나를 받아 콘텐츠 주소로 저장한다. 이미 받은 것은 건너뛴다.

**완료 조건**

- `HEAD`가 아니라 `GET`으로 받는다. UA와 Referer를 단다
- 실패가 행에 남는다. `http_status`와 `fetch_error`
- **HTML 오류 페이지를 파일로 저장하지 않는다.** 두 API가 실패를 200으로 주는 것과 같은 함정이다
- 같은 명령을 두 번 돌리면 두 번째는 안 받는다

**건드리는 것** — `src/finnect/attach/`


> **실측 정본은 [`adr/evidence/2026-08-17-첨부-해독-실측.md`](../adr/evidence/2026-08-17-첨부-해독-실측.md)다.** 아래는 통과 여부이고, 값이 어긋나면 evidence가 이긴다.

- [x] 첨부 3,354건이 디스크에 내려오고 포맷별 해독률이 나온다 — **내려받기 3,354/3,354 · 실패 0 · 1,711MB.** 해독 `ok` 2,827 (지원 4포맷 모수로 94.6%)
- [x] 같은 명령을 두 번 돌리면 두 번째는 아무것도 안 받는다 — `처리 0 · 건너뜀 3,354 · 받음 0MB`
- [x] **미지원 포맷과 파싱 실패가 전부 기록에 남는다 (조용한 누락 0건)** — `첨부 3,354건 · URL 3,354 · 상태 행 3,354 · ✓ 조용한 누락 0건`
- [x] 공고 상세에 "첨부 N개 중 M개 해독"이 뜬다 — `PBLN_000000000117118`에서 `첨부 5개 중 5개 해독`
- [x] 이미지 첨부가 `empty`가 아니라 `unsupported`로 갈린다 — png 64 · jpg 57이 `unsupported`, PDF 158만 `empty`
- [x] **텍스트가 0바이트인 PDF 건수가 나온다** — **158건.** 이미지 첨부 121건을 더해 OCR 후보 279건
- [x] 공고를 재수집해도 해독 상태가 안 날아간다 — 아래

```
재수집 전   attachment 최소 id = 1      · 해독 ok 2,827
재수집 후   attachment 최소 id = 3,355  · 해독 ok 2,827
```

**세 번째 항목이 이 슬라이스의 핵심 검증이다.** 나머지는 숫자고, 이건 "숫자를 믿어도 되는가"다.

### 하면서 알게 된 것 넷

1. **PDF 추출률이 스파이크보다 낮다.** 91% → **86.1%**. 표본이 22개에서 1,167개가 됐다. 낮아지는 쪽이라 그냥 못 넘긴다
2. **ZIP 166개 안에 우리가 읽을 수 있는 문서가 799개 있다.** 풀면 해독 대상이 27% 는다. 안 풀기로 한 결정을 이 숫자로 다시 봐야 한다
3. **기업마당은 재수집마다 1,538건 전부가 '변경'으로 잡힌다.** 해시 재료에 조회수(`inqireCo`)가 들어 있다. [ADR-0022](../adr/0022-첨부-원본을-콘텐츠-주소로-로컬에-둔다.md) 2번이 가정한 일이 실제로 매번 일어난다
4. **HWP 추출기에 서로게이트 버그가 있었다.** 스파이크가 UTF-16 코드유닛을 `chr()` 로 하나씩 옮겨서 BMP 밖 글자가 짝 잃은 서로게이트로 남았다. 첫 20건 안에서 터졌다. 승격하면서 고쳤다
