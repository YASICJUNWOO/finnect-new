# 근거 — 측정 기록

`notice-filter` 본체는 의존성이 없다. 이 폴더는 **축을 정할 때 무엇을 열어 봤는지**를
남긴 기록이고, 재실행에는 DB·네트워크·`psycopg`·`requests` 가 필요하다.
본체를 돌리는 데는 필요 없다.

| 파일 | 내용 |
|---|---|
| `축2d_첨부실측_20건.json` | 축2d 를 정한 실측. T4 5개 층 × 표본 3~5건의 첨부를 전부 열어 선정 방식·제출물·4분류 토큰을 기록했다 |
| `축2d_첨부실측.py` | 위를 만든 스크립트. `spike/hwp_text.py` 와 `coverage48.py` 의 추출기를 쓴다 |

읽는 법 — 한 건의 레코드는 이렇다.

```json
{"sn": "125203", "layer": "내수(행사·부스)", "chars": 5623,
 "A": 11, "G": 4, "B": 0, "E": 3,        // 행정·성장·예산·설비 라벨 종류 수
 "plan": false,                          // 첨부에 '사업계획서' 문자열이 있는가
 "sel": ["추첨", "서류심사"]}             // 공고문에서 찾은 선정 방식
```

**`G`(성장 라벨)가 4여도 계획서가 아닐 수 있다.** 안양춤축제의 `G4` 는 참가신청서의
`시장규모`·`연간 총매출액` 칸에서 나왔다. 그래서 축2d 는 토큰 수가 아니라
`sel`(선정 방식)과 제출물 목록으로 판정했다. 자세한 것은 `../로직과근거.md` §4a 에 있다.
