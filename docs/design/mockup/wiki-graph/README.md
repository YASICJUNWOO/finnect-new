# 사업 위키 그래프 — 자리를 무엇으로 그릴 것인가

S7 위키 화면(`web/components/Orbit.tsx`)의 노드를 **납작한 원 말고 무엇으로 그릴지** 고르는 자리다.

## 갈리는 것은 하나뿐이다

**궤도 구조는 넷 다 같다.** 중심 하나 · 안쪽 다섯 · 바깥 아홉, 각도가 구획을 뜻하고
자리는 고정이다(ADR-0017). 색이 말하는 것도 그대로 종류 하나다(DESIGN.md §4.1).
빈 자리는 속을 비우고, 값이 갈린 자리는 표시를 하나 더 붙인다.

기하는 `orbit.js` 한 곳에서 나오고 데이터는 `data.js` 한 곳에서 나온다.
시안이 가진 것은 **구체를 그리는 코드와 제 팔레트**뿐이다.

```
open index.html      # 나란히 — 축소 프리뷰 · 논지 · 대가 · 실측
open switch.html     # 실제 크기로 갈아끼우기
```

각 화면 하단의 검은 바는 **목업 전용**이다. 코드로 옮길 때는 바를 빼고
`값 내보내기` 로 뽑은 값만 전사한다.

| | 재질 | 배경 | 빈 자리 | 값이 갈린 자리 |
|---|---|---|---|---|
| 현행 | 납작한 원 | 회색 `#f7f7f8` | 속 빈 점선 원 | 배지 점 하나 |
| **A 행성** | 대기광이 도는 행성 | 어두운 `#0e1116` | 아직 안 뭉친 윤곽 | 고리를 두른다 |
| **B 유리** | 속에 알이 든 구슬 | 미색 종이 `#f2efe9` | 구슬이 앉을 홈 | 알이 둘이다 |
| **C 젤리** | 광택 큰 무른 젤리 | 서늘한 회색 `#e9e9ef` | 안 굳은 젤리(속이 비침) | 방울이 하나 더 붙는다 |

셋 다 **색을 하나 더 만들어 상태를 말하지 않는다.** 형태나 개수로 말한다 —
색조 하나에 뜻 둘을 얹으면 종류가 먼저 망가진다(DESIGN.md §4.1).

## 실측 (`node assets/measure.mjs`)

```
                       자리 수    화면 세로   자리 범위 가로   자리 범위 세로   이름표 수  이름표 겹침  최소 타깃  중앙 타깃
현행                       15       1139         646         565        14        0       44       48
A 행성                     15   1199 +60    723 +77     641 +76        14        0   78 +34   85 +37
B 유리                     15   1199 +60    727 +81     645 +80        14        0   64 +20   64 +16
C 젤리                     15   1199 +60    727 +81     645 +80        14        0   66 +22   66 +18
```

1. **구체로 그리면 44px 타깃 문제가 같이 풀린다.** 현행 도트는 지름 30px 인데
   음영이 보이려면 그 크기로는 안 돼서 46px(r 23)로 키웠다. 결과적으로
   `DESIGN.md` §8.2 의 44px 을 넘긴다. **궤도 반지름을 132/258 → 158/286 으로 넓힌 것이 그 대가다.**
2. **세로가 60px 늘어난다.** 셋 다 1199px 로 같다 — 껍데기가 같고 그래프 판만 640→700 이다.
3. **이름표 겹침은 넷 다 0이다.** 구체를 키워도 이름표는 안 부딪힌다.

## 대비 (`node assets/contrast.mjs`)

글자 tier 는 셋 다 AA 를 넘겼다. **처음엔 셋 다 미달이었다.**

| 어디 | 처음 | 고친 값 | |
|---|---|---|---|
| A 빈 자리 이름표 · 구획 라벨 | `#6f7b8a` 4.39:1 | `#7c8898` 5.25:1 | AA |
| B 빈 자리 이름표 | `#8b857a` 3.19:1 | `#6f695c` 4.75:1 | AA |
| C 빈 자리 이름표 | `#83889a` 2.92:1 | `#63687a` 4.58:1 | AA |
| C 손봐야 해요(글자) | `#e08a10` 2.69:1 | `#8a5500` 5.14:1 | AA |

C 는 **글자용과 방울용을 갈랐다**(`--blank` / `--blank-lit`). 하나로 쓰면 글자가 흐리거나
방울이 탁해진다 — 둘 다 만족시키는 값이 없다.

**남은 미달 다섯은 전부 구체 자체다.** 글자가 아니라 UI 요소라 기준이 3:1 이고(WCAG 1.4.11)
B 유리가 3.9 · C 젤리가 3.1 로 걸쳐 있다. **단색 기준으로 잰 값이라 실제 구체는 그라데이션이다** —
고르면 가장 어두운 지점으로 다시 재야 한다.

**현행의 빈 자리 이름표(`--ink-3` 2.65:1)는 아직 미달이다.** 시안과 무관한 기존 문제라
여기서 고치지 않았다 — `web/components/Orbit.module.css` 의 구획 라벨이 이 색을 쓴다.

## 고를 때 걸리는 것

- **A 는 `DESIGN.md` §3-1 을 뒤집는다.** "라이트로 간다"고 정한 것을 어두운 배경으로 바꾼다.
  위키만 어두우면 목록·상세를 오갈 때 눈이 계속 적응해야 한다. 화면 전부를 어둡게 갈 것인지가
  같이 정해져야 하는 결정이다.
- **B 는 색이 가장 약하다.** 유리가 알을 덮어 종류색의 채도가 떨어진다. 종류를 색 하나로만
  말하는 지금 규칙에서는 이게 손해다.
- **C 는 채도가 가장 세고 유일하게 기본 애니메이션이 돈다.** `DESIGN.md` §3-7 이
  "색은 위키 그래프에만"이라고 허락한 자리이긴 하지만, 목록 화면과 나란히 두면 위키만 튄다.
- **셋 다 종류마다 색이 셋 필요하다.** 밝은 면 · 본색 · 그늘. 지금 토큰에는 하나뿐이라
  나머지 둘을 시안이 임의로 만들었다. 같은 색조에서 뽑았으므로 말하는 것은 여전히 종류 하나지만,
  고르면 `DESIGN.md` §4.1 에 **색 셋을 정식으로 올려야 한다.**

## 만들다 잡은 것

- **처음에 CSS 3D 로 세웠다가 버렸다.** 카메라를 향해 되돌린 원이 바닥 면과 **교차**하면
  브라우저가 교차선에서 잘라 그려 도트가 부채꼴로 나온다. `filter: blur()` 도 같은 증상을 만든다 —
  `preserve-3d` 를 끊는다. **SVG 그라데이션으로 그리면 이 문제가 통째로 없다.**
- **B 의 유리를 처음에 너무 희게 깔았다**(흰색 0.95 → 0.34). 속의 알이 통째로 씻겨
  구슬이 아니라 얼룩으로 보였다. 유리는 흰 게 아니라 맑은 것이다.
- 둘 다 **코드만 읽어서는 안 보이고 스크린샷으로만 잡혔다**(DESIGN.md §9).
