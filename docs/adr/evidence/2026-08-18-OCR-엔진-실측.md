# OCR 엔진 실측 — 2026-08-18

> [T-0007](../../plan/00-미결-해소.md#t-0007-스캔-pdf-처리-판단)이 "OCR 로 가기로 정했고 엔진과 범위는 T-0007 이 정한다"로 남긴 자리다. [plan/12](../../plan/12-사업-위키-구축.md) T-0042 가 흡수했다.
>
> **눈으로 본 것은 7건이다** — 합성 픽스처 1건 + 실물 스캔본 6건. 158건 전체가 아니고, 정답 텍스트가 없어 **정확도를 퍼센트로 말하지 않는다.**

## 0. 한 줄 결론

**RapidOCR + PP-OCRv5 한국어 모델로 간다. 다만 검출은 `server` 여야 한다.**

`mobile` 검출로는 사업자등록증의 **소재지와 업종이 아예 안 나온다.** 그 둘이 자격 판별의 입력이라 5배 느린 것을 받는다.

---

## 1. 왜 RapidOCR 인가

| | |
|---|---|
| **로컬이다** | [ADR-0029](../0029-사용자-파일을-회사-단위-콘텐츠-주소로-로컬에-둔다.md)를 안 어긴다. 사업자등록증과 재무제표가 외부로 안 나간다 |
| **가볍다** | PaddleOCR 모델을 ONNX 로 옮긴 것이라 PaddlePaddle 프레임워크가 필요 없다. `onnxruntime` 하나 |
| **한국어 전용 인식 모델이 있다** | `korean_PP-OCRv5_rec_mobile`. 중국어 모델로 한글을 읽는 것이 아니다 |

클라우드 API(Google · Naver Clova)가 정확도로는 앞설 것이나 **개인정보를 외부로 내보내는 결정**이라 ADR-0029 와 정면으로 부딪힌다. Tesseract 는 한국어와 표에 약하다.

## 2. 검출 모델 비교 — 사업자등록증 픽스처 1건

정형 슬롯 여덟(등록번호 · 법인명 · 대표자 · 개업일 · 법인등록번호 · 소재지 · 업태 · 종목)이 나오는지 셌다.

| 설정 | 슬롯 | 1쪽 소요 | 비고 |
|---|---|---|---|
| PP-OCRv6 `small` 검출 (기본값) | **5/8** | 3.6초 | **소재지·업태·종목 없음** |
| PP-OCRv5 `mobile` 검출 · 300dpi | **5/8** | 3.1초 | 〃 |
| **PP-OCRv5 `server` 검출 · 300dpi** | **7/8** | **13.7초** | 업태만 놓침 |
| `mobile` + `box_thresh=0.3` · `unclip_ratio=2.0` | 4/8 | 2.8초 | **완화가 더 나빴다** |

**검출 모델이 결정적이고 해상도와 임계값은 아니다.** 200 → 300dpi 는 차이가 없었고 임계값 완화는 역효과였다.

`server` 로 나온 값들.

```
등록번호:501-86-33271
:주식회사다시로
: 윤세라
2024년03월11일
110111-8842301
경기도성남시분당구판교로255,3층(삼평동)     ← mobile 로는 안 나왔다
응용 소프트웨어개발및공급업                  ← 〃
tax@dasiro.example
```

### 라벨은 거의 다 깨지고 값은 정확하다

| 원문 | 인식 결과 |
|---|---|
| `법 인 명 (단 체 명)` | (없음) |
| `법 인 등 록 번 호` | `후눌을` |
| `개 업 연 월 일` | `…2` |
| `사 업 의 종 류` | `울` `:` |

**자간을 넓힌 글자에서 무너진다.** 그런데 사업자등록증은 양식이 고정이라 **라벨을 읽을 필요가 없다.**

```
\d{3}-\d{2}-\d{5}   → 사업자등록번호
\d{6}-\d{7}         → 법인등록번호
'주식회사' 포함      → 법인명
행정구역으로 시작    → 소재지
```

**패턴으로 슬롯을 정하는 것이 라벨 OCR 보다 견고하다.** 이게 이 실측의 설계 소득이다.

## 3. 실물 스캔본 6건 — 첨부 158건에서 뽑았다

`attachment_file.parse_status = 'empty'` 이고 `detected_ext = 'pdf'` 인 것 중 작은 순으로 여섯. **1쪽만** 돌렸다.

| 파일 | 1쪽 소요 | 줄 | 글자 | 평균 신뢰도 |
|---|---:|---:|---:|---:|
| [공고문] 2026 소셜 비즈니스 육성 지원사업 기업 모집 | 11.8초 | 10 | 203 | 0.92 |
| 2026년 수산물 전시회 및 박람회 참가지원 사업 공고 | 8.3초 | 10 | 90 | 0.83 |
| 3. (참고) 신산업 창업 분야 해당업종 | 10.0초 | 46 | 184 | 0.88 |
| 2027년 기업환경 개선사업 신청 안내 | 12.3초 | 40 | 311 | 0.96 |
| 양산시 2026년 수산물 가공공장 스마트화 지원사업 | 10.1초 | 74 | 301 | 0.96 |
| 2026년 양산시 해외무역관 지사화 지원사업(추가모집) | 23.9초 | 71 | 571 | 0.89 |

**6/6 이 0자에서 판정 재료로 바뀌었다.**

```
모집기간 : 2026.8.7.(금)~8.18.(화) 오전9시까지
지원대상:수협,어촌계,영어조합법인
지원내용:부스 임차료등지원
이메일 접수(yeoyk612@bepa.kr)
광주시 공고 제2026-2207호   ·   기업지원과   ·   031-760-3787
1.사업명:2027년기업환경개선사업
신청기간: 2026. 8. 6.(목) ~ 8.20.(목)
```

**마감일·지원대상·접수방법·문의처가 나온다.** [실측](2026-08-17-첨부-해독-실측.md)이 "158건 중 34건이 그 공고의 유일한 근거"라고 적은 것에 직접 답한다 — **OCR 을 붙이면 그 34건이 살아난다.**

### 못 믿을 것

| 무엇 | 실물 |
|---|---|
| 굵은 제목 · 장식 글자 | `름눌을` `H거3` `융기공Yㅇ` `[프] 여` `남해우 융` |
| 공백 | `1.사업명:2027년기업환경개선사업` — 띄어쓰기가 뭉개진다 |
| 줄 분해 | 양산시 건이 74줄에 301자. **줄당 4자** — 표를 낱칸으로 쪼갠다 |
| 표 구조 | 행·열 대응이 안 나온다 |

**본문은 쓸 만하고 제목과 표는 못 믿는다.** 그래서 OCR 텍스트로 판정할 때는 **제목에 기대는 규칙을 만들지 않는다.**

## 4. 재현

```bash
uv pip install rapidocr onnxruntime pypdfium2
```

```python
from rapidocr import RapidOCR
from rapidocr.utils.typings import LangRec, ModelType, OCRVersion
import numpy as np, pypdfium2 as pdfium

eng = RapidOCR(params={
    "Rec.lang_type": LangRec.KOREAN,
    "Rec.model_type": ModelType.MOBILE,
    "Rec.ocr_version": OCRVersion.PPOCRV5,
    "Det.ocr_version": OCRVersion.PPOCRV5,
    "Det.model_type": ModelType.SERVER,   # ← 이 한 줄이 5/8 을 7/8 로 만든다
})
img = np.array(pdfium.PdfDocument(path)[0].render(scale=300 / 72).to_pil())
res = eng(img)
```

**`Rec.lang_type="korean"` 을 그냥 주면 터진다** — 기본 검출이 PP-OCRv6 이고 그 버전에 한국어 인식 모델이 없다(`Unsupported rec.lang_type='korean' for PP-OCRv6 small model`). 인식과 검출을 **둘 다 PP-OCRv5 로** 맞춰야 한다. 그리고 값은 문자열이 아니라 **Enum** 이어야 한다.

## 5. 이 실측이 못 말하는 것

- **정확도를 숫자로 말할 수 없다.** 정답 텍스트가 없다. 신뢰도 0.83~0.96 은 **모델이 스스로 매긴 값**이라 근거로 쓰지 않는다
- **표본이 7건이다.** 실물은 6건이고 전부 1쪽만 봤다. 158건 전체도, 여러 쪽 문서도 안 돌렸다
- **사업자등록증 픽스처는 합성이다.** 회전 0.55°에 노이즈 정도라 실제 사진(기울고 그림자 있고 접힌)보다 쉽다
- **`server` 검출의 총 비용을 모른다.** 1쪽에 8~24초인데 158건의 총 쪽수를 안 셌다
