# ADR-0070: hwp 를 바이트로 읽고 쓴다

- 상태: 채택됨
- 날짜: 2026-08-24
- 채우는 것: [ADR-0060](0060-양식을-채워서-원본-포맷으로-돌려준다.md) 결정 5 가 남긴 「Java 가 없는 서버에서는 hwp 경로가 통째로 꺼진다」 · `label_targets` 독스트링이 적어 둔 「라벨이 열 머리로 위에 있는 표를 못 잡는다」
- 좁히는 것: [ADR-0060](0060-양식을-채워서-원본-포맷으로-돌려준다.md) 결정 4·5 — 뒤집는 것이 아니라 **hwplib 경로에 한정된 결정**이 된다
- 그대로 사는 것: ADR-0060 결정 1·2·6 · [ADR-0061](0061-양식-파싱의-입력을-파일-구조로-바꾼다.md) 전부 · [ADR-0063](0063-서술-항목의-좌표를-문단으로-준다.md) 전부
- 실측: 이 문서 «실측» 절 (2026-08-24 · 한/글 육안 1건 · 폴라리스 렌더 3건)

## 맥락

`forms/hwp.py` 의 `Anchor.col` 이 **격자 열이 아니라 그 행의 셀 리스트 인덱스**였다.

```python
for ci in range(cl.size()):
    out.append(Cell(Anchor(si, ti, ri, ci), _cell_text(cl.get(ci))))
```

HWP 는 가로 병합된 칸을 한 번만 저장한다. 3칸 병합이 앞에 있으면 다음 칸의 `ci` 는 1 인데 실제 격자 열은 3 이고, **행마다 어긋나는 양이 다르다.**

읽기와 쓰기가 같은 `ci` 를 쓰므로 **채우기는 안 틀렸다.** 대신 다른 것을 잃었다 — **열 축에 세로 의미가 없어진다.** 위 칸과 아래 칸이 같은 열인지 알 방법이 사라져서 `label_targets` 가 같은 행 오른쪽만 볼 수 있었고, 그 독스트링이 대가를 이미 적어 뒀다.

> 대가는 `투자 | 주요 투자처 | 누적 투자금액` 처럼 **라벨이 열 머리로 위에 있는 표를 여전히 못 잡는다**는 것이다.

**`hwp` 만 그랬다.** `hwpx.py` 는 `_cell(table, ri, ci)` 로 격자를 쓰고 `docx.py` 는 `row.cells` 가 격자 자리를 준다 — 같은 `Anchor` 를 세 어댑터가 **다른 뜻으로** 채우고 있었다.

그리고 hwplib 이 짊어지던 것이 셋 더 있었다. 저장할 때마다 `PrvText`·`PrvImage`·`DocOptions/_LinkDoc` 를 잃어서 따로 이식해야 했고(ADR-0060 결정 4), Java 가 없으면 hwp 가 통째로 꺼졌고(결정 5), 표 258개 중 **중첩 표 57개(22%)를 한 번도 못 봤다** — `sec.getParagraph(i).getControlList()` 만 봐서 칸 안 문단에 매달린 표가 목록에 없었다.

## 결정

### 1. 좌표는 격자다

`Anchor.col` 이 `LIST_HEADER` 의 `colIndex` 다. `Cell` 이 `colspan`·`rowspan`·`width`·`height` 를 같이 나른다.

```
offset  8  <HH>  col, row
offset 12  <HH>  colspan, rowspan
offset 16  <ii>  width, height   HWPUNIT(1/7200 inch)
```

**hwplib 도 같이 올린다.** `ListHeaderForCell` 이 그 주소를 처음부터 들고 있었고 안 읽고 있었을 뿐이다 — 두 경로의 축이 갈리면 폴백이 다른 칸에 쓴다.

**병합과 크기는 기본값을 갖는다**(`1x1` · `0`). `hwpx`·`docx` 어댑터가 못 주면 그 값을 보는 규칙이 안 걸린다 — 모르는 것을 1 로 아는 척하는 것과 0 으로 모른다고 말하는 것은 다르다.

### 2. 읽기와 쓰기를 레코드 편집으로 한다

`forms/hwp5.py` 가 `olefile` + `zlib` + 레코드 파싱으로 연다. **새 의존성이 0 이다** — `olefile` 은 이미 기본 의존성이고(`attach/hwp.py` 가 텍스트를 뽑는 데 쓴다) 레코드 층도 거기 것을 그대로 쓴다(`iter_records`·`para_text`·`reject_flags`).

되쓰기는 `BodyText/Section*` 스트림만 바꾼다. **`olefile` 은 CFB 를 새로 못 만들고 같은 크기 덮어쓰기만 되므로**, 채운 본문을 원본 스트림 크기에 정확히 맞춰 포장한다 — 빈 stored block(`00 00 00 FF FF`) 5바이트 단위 패딩에 압축 조합 45개로 나머지 1~4바이트를 흡수한다. 규격 그대로라 뒤에 붙은 찌꺼기가 아니다.

**레코드 규칙 넷을 실측으로 확정했다.**

| | 실측 |
|---|---|
| `PARA_TEXT` 끝 | 원본 146/146 이 **U+000D** 로 끝난다 |
| `PARA_HEADER.nChars` | **글자수 + 1**(문단 끝 문자) · 마스킹하면 예외 0 |
| `nChars` bit31 | 개수가 아니라 **플래그다** — 보존한다 |
| 빈 문단 | `PARA_TEXT` 레코드가 **아예 없고** `nChars` 가 1 |

마지막 것이 ADR-0060 판본 I 를 반대편에서 본 것이다. 「빈 칸이 통했던 이유가 글자가 없어서가 아니라 `ParaText` 가 아예 없어서」라면, 채우는 것은 **없던 레코드를 만드는 일**이다.

### 3. JVM 은 포장이 안 되는 파일의 폴백으로만 남는다

`pack()` 이 `None` 이면(실측 5~8%) `forms/hwplib.py` 로 넘긴다. **넘기기 전에 두 경로가 같은 격자를 보는지 확인한다** — 표 번호가 어긋나면 hwplib 이 다른 칸에 쓰고 **파일은 정상으로 열려서** 제출 직전에야 드러난다. 어긋나면 안 쓰고 `FormsUnavailable` 이다.

**ADR-0060 결정 4 는 순수 경로에서 문제 자체가 없어진다.** `HWPFile` 모델을 안 거치니 버릴 스트림이 없다 — `PrvText` 를 다시 만들 일도, `PrvImage` 를 포기할 일도, `_LinkDoc` 를 POI 로 옮길 일도 생기지 않는다. **폴백에는 그대로 걸리므로 그 코드와 테스트를 지우지 않는다.**

**결정 5 는 「Java 가 없으면 hwp 가 꺼진다」에서 「그 5~8% 만 꺼진다」로 좁아진다.** 파싱·항목추출·좌표 심기는 Java 없는 서버에서 돈다.

### 4. 중첩 표를 센다

두 경로 모두 레코드 순서(깊이 우선)로 표를 센다. 표 A 안의 중첩 표가 표 B 보다 먼저 온다. hwplib 쪽은 칸 안 문단의 컨트롤까지 재귀한다.

### 5. 라벨은 행 덩어리와 열 머리로 푼다

값 자리에서 **왼쪽의 라벨**을 찾는다. 라벨에서 오른쪽 값을 찾던 방향이 뒤집힌 것이고, 그러면 건너뛸 일이 없다.

- **행 라벨은 가장 가까운 연속 덩어리만.** 끊기면 멈춘다 — 안 끊으면 `대표자 › 성명` 과 `실무자 › 성명` 이 같은 이름이 된다
- **열 머리는 행 라벨 블록 위로 안 넘어가고, 머리 행(라벨 3개 이상)에서만 인정한다** — 값이 하나 있는 행을 머리로 읽으면 `사업자등록번호 × 2000-00-00` 이 나온다
- **바로 왼쪽이 먼저다.** 건너뛴 라벨은 열 머리가 뒷받침할 때만 쓴다 — 뒷받침 없이 건너뛰면 셋이 같은 이름을 들고 겹침으로 전부 버려진다
- **플레이스홀더(`00 명`·`2000-00-00`·`OOOOO (상호명)`)는 라벨이 아니라 채울 자리다.** LLM 판정(`forms/slots.py`)을 대신하지 않는다 — 그 아래 깔리는 값싼 바닥이고, 판정이 꺼진 경로에서도 돈다
- **8pt 미만 칸은 후보가 아니다.** 양식 저자가 여백을 주려고 넣은 칸이라 글자를 넣으면 **파일엔 있는데 안 보인다**

이름이 둘로 갈린다. `label_targets` 는 **안쪽 이름 하나**(`매출액`)를 내고 이미 깔린 항목과 짝짓는 데 쓴다. `label_paths` 는 **한정된 경로**(`매출액 × 2022년`)를 내고 **어댑터가 항목을 만드는 자리**에서 쓴다 — 거기는 대조가 없어서 겹침이 문제가 안 되고, 안쪽 이름으로 만들면 2020~2023 년 넷이 겹쳐 전부 버려진다.

## 정하지 않은 것

- **`hwpx`·`docx` 어댑터가 병합·크기를 안 준다.** 규칙이 양쪽 모양을 다 견디게 짰다(크기를 모르는 어댑터에서만 되풀이를 접는다). 저 둘이 값을 주기 시작하면 접기가 자동으로 꺼진다
- **포장이 안 되는 5~8% 를 Java 없이 쓰는 길.** CFB writer 를 짜야 하고, 그것은 이 결정의 범위가 아니다
- **`is_placeholder` 가 `2000년` 같은 진짜 라벨을 잡을 수 있다.** `00` 두 자만 보는 규칙이고, 걸리면 그 칸이 라벨 노릇을 못 할 뿐 값이 딴 데 가지는 않는다

## 결과

- Java 없는 서버에서 `extract` 와 좌표 심기가 돈다
- 저장이 스트림을 안 잃는다 — 12개 중 `BodyText/Section0` 하나만 바뀐다
- 열 머리를 걸어 올라가는 라벨 해석이 열린다
- 중첩 표 22% 가 처음으로 보인다
- **좌표의 뜻이 바뀌었으므로 이미 심긴 값은 다른 칸을 가리킨다.** 전부 지우고 다시 심는다

## 실측 (2026-08-24)

코퍼스(`data/attachments`)가 비어 있어 **`spike/data/files` 의 HWP5 12건**으로 쟀다. 규모가 작다 — 이 숫자로 「hwplib 을 대신한다」를 확정하지 않는다.

```
파싱 성공                     12 / 12 = 100.0%     예외 0
칸                            3,180
빈 칸을 전부 채운 뒤 같은 크기 포장  11 / 12 =  91.7%
   실패한 하나는 본문 4,127B 가 스트림 1,490B 로 이미 촘촘히 눌린 파일이다
```

라벨 규칙이 이름을 붙인 자리 524개의 출처.

```
행 라벨만          130 = 24.8%
행 라벨 + 열 머리   310 = 59.2%
열 머리만           84 = 16.0%
  → 열 축에서 오는 것 394 = 75.2%
```

**한/글 육안 1건.** 양식 하나(`강원브릿지 화요IR 참가신청서` · 표 7 · 칸 165)에 라벨로 20칸을 채워 20/20 이 제자리였고, 파일 크기가 156,160B 로 같았고, 밀림·겹침이 없었다. 폴라리스 엔진으로 HWP→HWPX→PDF 를 태워 3페이지를 따로 확인했다.

**육안 규모가 ADR-0060 결정 3(양식 20건 · 판본 7개)에 못 미친다.** 코퍼스를 다시 받아 그 규모로 재기 전에는 hwplib 폴백을 지우지 않는다.
