### 2. 데이터 모델

`SPEC.md` §2의 3계층을 실제 테이블로 옮긴다.

| 영역 | 담을 것 |
|------|---------|
| 공고 | 출처, 원문 링크, 접수 기간, 지원 규모, 콘텐츠 해시 |
| 첨부 | 파일명, 포맷, 원문 텍스트, 파싱 상태 |
| 요건 (L1) | 항목, 기준, **근거 구간**, 신뢰도 |
| 평가 (L1) | 단계, 항목명, 평가 관점, **배점(있을 때만)**, 커트라인, 가점 |
| 양식 (L1) | 목차 항목, 세부항목, 분량 제한 |
| 프로필 | 판별용 정형 항목, 집필용 서술 항목 |
| 판정 (L2) | 공고 × 프로필 → 가능 여부, 판정 시각 |
| 문서 (L3) | 계획서, 항목별 본문, 사용자 수정 여부 |

**근거 구간(F0-5)을 모든 L1 값에 붙이는 것이 핵심이다.** 이게 없으면 F7-3 사실 고정이 성립하지 않는다([ADR-0002](../adr/0002-3계층-분리.md)).

**배점은 nullable이다.** 실측 결과 주요 공고가 배점을 주지 않는다([ADR-0010](../adr/0010-배점-전제-폐기.md)). 없는 것이 정상 상태다.

## 태스크

### T-0003 스택 확정

- 상태: 대기
- 선행: —

백엔드 언어, DB, 프론트 프레임워크, LLM 제공자를 정하고 ADR로 남긴다.

**왜.** **어디에도 결정으로 기록된 적이 없다.** `.gitignore`가 Python(`__pycache__`, `.ruff_cache`, `.mypy_cache`, `.pytest_cache`)과 Node(`node_modules`, `.next`)를 전제하지만, 그건 관성이지 결정이 아니다. 스택은 나중에 바꾸면 전부 뜯어야 하는 것이라 여기서 먼저 정한다.

| 항목 | 후보 | 고려사항 |
|------|------|----------|
| 백엔드 언어 | Python (`.gitignore` 전제) | HWP·HWPX·DOCX·PDF 파싱 라이브러리 가용성. 스파이크는 Python으로 전부 확인했다 |
| DB | — | 공고 + 근거 구간 + 판정 결과. 전체 재판정(F2-4)이 공고 수천 건 × 요건 수십 개 |
| 프론트 | Next.js (`.gitignore` 전제) | 밀도 높은 목록·표 중심. 컴포넌트 라이브러리를 쓰지 않기로 했다([ADR-0007](../adr/0007-KRDS-미채택.md)) |
| LLM 제공자 | — | L1 추출(strict schema)과 L3 집필(스트리밍) 둘 다 필요 |

**완료 조건**

- 각 항목이 정해지고 이유가 ADR로 남는다
- `.env.example`에 필요한 키가 추가된다 (현재는 수집용 3종뿐)
- 빈 저장소가 실행 가능하고 `README.md`에 실행 방법이 있다

**건드리는 것** — `adr/` 새 문서, 저장소 루트(`README.md`, 의존성 파일), `.env.example`
