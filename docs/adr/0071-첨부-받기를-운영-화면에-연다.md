# ADR-0071: 첨부 받기를 운영 화면에 열고, 아직 안 받은 것만 대상으로 잡는다

- 상태: 채택됨
- 날짜: 2026-08-24
- 잇는 것: [ADR-0065](0065-수집-실행을-배포-api-에-연다.md) — 실행 버튼이 배포 API 에서 도는 자리를 그 결정이 열었다
- 대체하는 것: 없음

## 맥락

첨부를 내려받아 해독하는 길이 **CLI 하나뿐이었다**(`uv run python -m finnect.attach`). 운영 화면(`/admin/attachments`)은 그 결과를 **보기만** 했고, 화면에 "첨부는 메타데이터만 담고 내려받지 않는다" 고 적혀 있었다.

그리고 그 CLI 가 **매번 전량을 대상으로 잡았다.** `_targets()` 가 `attachment` 의 URL 3,354개를 통째로 돌려주고, 루프가 URL 마다 `attachment_file` 행을 한 줄씩 다시 읽어 `_is_done()` 으로 건너뛰었다.

**결과는 맞았다.** 이미 받은 파일을 다시 받지 않았다. 틀린 것은 **숫자가 말하는 것**이었다.

    [첨부] 대상 3,354건 · 처리 12 · 건너뜀 2,827

2,827건이 끝난 상태에서 「대상 3,354건」은 이번 실행이 할 일이 아니다. `--limit 40` 도 "안 받은 것 40건" 이 아니라 "전량 중 앞에서 40건" 이라 **이미 받은 것만 40번 건너뛰고 끝나는 실행**이 가능했다. 진행률도 마찬가지다 — 분모가 3,354 면 막대가 84% 에서 시작한다.

화면에 버튼을 붙이려면 이 숫자가 먼저 참이어야 했다. **버튼 옆에 "3,354건 받아요" 라고 적을 수는 없다.**

## 결정

### 1. 이미 끝난 것을 대상에서 뺀다. 루프 안에서 건너뛰지 않는다

`_is_done(row)` 을 `_done_urls(s, source=…)` 로 바꾼다. 규칙은 그대로다 — 받기 실패는 끝난 것으로 치고(404 를 3,354번 다시 두드리지 않는다), 받았고 해독까지 됐고 **파일이 디스크에 실제로 있으면** 끝난 것이다.

**판정이 한 곳에 있는 것이 요점이다.** `run()` 이 대상을 고르는 함수와 화면이 "아직 안 받은 N건" 을 세는 함수(`backlog()`)가 같다. 셈을 화면 쪽에 베끼면 **화면이 527건이라 하고 눌러 보니 3,354건이 도는** 일이 생기고, 둘 다 그럴듯해서 어느 쪽이 틀렸는지 알 수 없다. `api/admin_service.py` 가 `coverage()` 를 베낀 자리가 이미 하나 있고 `tests/test_admin_api.py` 가 그것을 지키느라 존재한다 — **그 자리를 하나 더 만들지 않는다.**

**디스크 확인을 SQL 로 옮기지 않는다.** `stored_path` 가 차 있어도 파일이 지워졌을 수 있고, 그건 컬럼으로 알 수 없다. 컬럼만 세면 빠르지만 **그 경우에 조용히 틀린다** — 지운 파일이 영영 다시 안 받아진다.

### 2. 버튼은 `/admin/attachments` 에 둔다. `/admin/ingest` 가 아니다

수집 화면이 "첨부는 메타데이터만 담고 내려받지 않는다" 고 적은 것은 **지금도 참이다.** 수집은 목록 API 를 받고, K-Startup 은 상세 페이지에서 첨부 *목록*까지 긁지만(`attach/kstartup.py`), **파일은 안 받는다.** 그 문장을 거짓으로 만들면서 버튼을 옆에 두는 것보다, 결과가 나타나는 화면에 두는 편이 낫다.

**「조용한 누락」 아래에 둔다.** 그 화면이 스스로 "이 화면에서 가장 먼저 봐야 하는 값" 이라고 적어 둔 것이 첫 절이고, 동작을 그 위에 올리면 그 문장이 거짓이 된다.

### 3. 수집과 같은 문을 쓴다. 토큰을 하나 더 만들지 않는다

`x-ingest-trigger-token` 이다. 토큰을 나누면 "수집은 되는데 첨부는 안 되는 사람" 이 생기는데 **그 구분이 필요하다는 근거가 없다** — 둘 다 운영자가 이 서버에서 돌리는 같은 종류의 일이고, 둘 다 외부 서버에 실제 요청을 수천 번 내보낸다. `_require_trigger_token()` 이 그 문 하나다.

`api_token` 과 반대로 **비어 있으면 503 으로 막는다.** 사용자 것이 아닌 경로는 잊었을 때 닫히는 쪽이어야 한다.

### 4. 실행 기록 표를 만들지 않는다. 대신 `jobs.Outcome` 에 남긴다

수집은 `ingest_run` 이 있어서 실패가 행으로 남는다. 첨부 받기에는 그 표가 없고, **이번에도 안 만든다** — 마이그레이션은 배포 DB 까지 가야 하고(그 함정은 이미 한 번 밟았다) 이 버튼 하나가 그 값을 아직 못 낸다.

대신 `ingest/jobs.py` 가 마지막 결과를 **메모리에** 든다(`Outcome`). **프로세스가 죽으면 사라진다.** 진행 상태가 이미 같은 성질이라(ADR-0065 · `api-contract.md` 가 그렇게 적어 뒀다) 새 성질을 들이는 것이 아니다.

**남기는 이유는 실패다.** 실패가 「아무 일도 없었음」과 구분되지 않으면 버튼은 없느니만 못하다 — `models.py` 의 `IngestRun` 이 같은 이유로 실패한 실행도 행으로 남긴다.

### 5. `jobs.py` 가 어느 진행 표인지 모르게 한다

`jobs._progress` 가 `Progress`(수집의 것)를 들고 있었고 `launch()` 가 빈 `Progress()` 를 깔았다. 첨부 받기는 표가 다르다(`AttachProgress` — 받을 것 · 처리 · 바이트). 그 자리에 수집의 표가 깔려 있으면 **화면이 없는 칸을 묻는다.**

`report`/`progress_of` 를 표에 무관하게 열고, 처음에 깔 값은 **부르는 쪽이 준다**(`launch(..., initial=…)`). 안 주면 첫 보고 전까지 `None` 이고 **그것이 "아직 세는 중" 이다.** 이 모듈의 독스트링이 원래 "DB 를 모른다" 였는데 이제 "어느 표인지도 모른다" 가 더해진다.

## 결과

- **`finnect.attach` 의 숫자가 뜻이 바뀐다.** `대상` 이 「받을 것」이 되고 `건너뜀` 이 「이미 받아 둠」이 된다. `--limit 40` 이 **안 받은 것 40건**이다. 예전 실행 로그와 나란히 놓으면 안 맞는다.
- **쓰기 API 가 여섯이 됐다.** 제품 셋 + 입장 하나 + 운영 둘. `tests/test_draft_start.py` 가 그 전량을 잠근다.
- **`GET /api/admin/attach` 가 `/api/admin/attachments` 와 따로다.** 저건 집계 다섯을 훑는 무거운 질의라 실행 중에 1.5초마다 부를 것이 아니다.
- **한 프로세스 안에서만 막힌다.** CLI 로 `finnect.attach` 를 돌리는 동안 버튼을 누르면 **둘 다 돈다.** 수집은 `runs.live` 로 다른 프로세스까지 봤는데 여기는 볼 표가 없다(결정 4 의 대가다). 같은 URL 을 두 번 받을 수는 있어도 저장이 콘텐츠 주소라 덮어써도 같은 파일이고 행은 URL 이 유일 키다 — **느려질 뿐 깨지지 않는다.**
- **버튼에 출처 고르기가 없다.** CLI 에는 `--source` 가 있지만 화면에서 고를 이유가 아직 없고 락이 하나라 둘을 동시에 못 돌린다. **`--only` 도 없다** — 그 목록은 `notice-filter/` 가 만들어 파일로 오고, 화면에서 파일을 받는 것은 다른 결정이다.
- **되돌릴 조건**: 첨부 받기가 실패 원인을 되짚어야 할 만큼 자주 실패하면 그때 `attach_run` 표를 만든다. 그때 결정 4 가 대체된다.
