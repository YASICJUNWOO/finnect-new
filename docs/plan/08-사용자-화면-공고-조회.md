# plan/08 — 사용자 화면: 공고 조회

> 상태: 계획중
> 종류: 슬라이스 (S4·S5 관통)
> 선행: [06](06-목록-수집과-조회.md) · [07](07-첨부-내려받기와-해독.md)
> 시각 정본: [`DESIGN.md`](../../DESIGN.md) · 시연 [`redesign.html`](../adr/evidence/2026-08-16-v2-기획문서/redesign.html)

**사용자가 보는 공고 목록과 상세를 처음으로 만든다.** 운영 도구(`admin/`)는 손대지 않는다.

---

## 목표

`DESIGN.md` §4의 빈칸이 실값으로 차고, **사용자 전용 앱**이 그 토큰으로 공고 목록과 상세를 그린다.

---

## 왜 지금인가

[plan/README](README.md)가 **"화면은 DESIGN.md 토큰 실값을 기다린다"**고 적어 뒀다. `DESIGN.md` §4가 색·타입·반경을 전부 "5.1에서 확정"으로 비워 두고 있었기 때문이다.

**2026-08-17 기획 시연 코드가 들어왔고 거기 실값이 있다.** 기다리던 것이 도착했다. `redesign.html`은 단일 파일이고 [ADR-0014](../adr/0014-통합-그래프와-근거-청크.md)까지 반영돼 있다.

---

## 정해 둔 것 (2026-08-17)

| 무엇 | 어떻게 |
|---|---|
| **`admin/`** | **손대지 않는다.** 운영 도구로 남는다. CLAUDE.md의 "DESIGN.md 토큰을 따르지 않는다"는 문장이 그대로 유효하다 |
| 사용자 화면 | **새 앱으로 만든다.** `src/finnect/web/` |
| 목록 형태 | 시연의 **'전체 공고' 행 형태**를 쓴다. 카드 3열은 추천용이고 우리는 추천이 없다 |
| **데이터가 없는 자리** | **자리를 놓고 "아직 없어요"로 버틴다.** 레이아웃은 시연과 같게 두고 빈 화면 카피를 넣는다 |
| 예시 데이터 | **안 쓴다.** 근거 없는 값을 화면에 두지 않는다 |

**"아직 없어요"로 버티기로 한 것이 이 계획의 성격을 정한다.** 지금 채울 수 있는 것은 개요와 첨부뿐이고 나머지는 전부 빈칸이다. 화면이 미완성으로 읽히는 것을 받아들인다 — **가짜 값으로 완성돼 보이는 것보다 낫다.**

## 이미 확인된 것

### 토큰 실값 — `redesign.html`에서 실측

`DESIGN.md` §4가 비워 둔 자리에 들어갈 값이다.

| 역할 | DESIGN.md가 요구한 것 | 실값 |
|---|---|---|
| 캔버스 | 순백이 아닌 회색 | `#f7f7f8` |
| 표면 | 흰 카드 | `#fff` |
| 잠잠한 면 | — | `#f4f5f6` |
| 본문 글자 | 순검정이 아닌 근검정 | `#16181b` |
| 보조 글자 | 중성 회색 | `#5f656d` · `#949aa2` · `#cbd0d6` |
| 경계선 | — | `#e9eaec` · `#dfe2e6` |
| 마감 | 사용자가 손대야 하는 자리에만 | `#d92d20` (+ `#fff5f4` · `#f7d4d0`) |
| 빈칸 | 〃 | `#b45309` (+ `#fffbeb` · `#fde68a`) |
| 노드 분류색 | 상태색과 **다른 팔레트** | `--n-identity #5b5bd6` · `--n-content #0f766e` · `--n-company #9a3412` |

- **간격** 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 — `DESIGN.md` §8.2의 4px 스케일에 64가 붙었다
- **반경** `--r 16` · `--r-sm 10` · `--r-pill 999` — §4.3의 역할별 구분 그대로
- **서체** Pretendard 하나. 굵기 400 / 500 / 600 / 700
- **포커스** `:focus-visible{outline:2px solid var(--ink);outline-offset:3px}` — §3-9와 §7-1 충족
- **모션** `prefers-reduced-motion:reduce`에서 전부 끈다
- **숫자** `tabular-nums` 20곳

**타입 스케일은 정리되지 않았다.** 13~44px 사이에 15단계가 있다. `DESIGN.md` §4.2가 지적한 V2(타입 위계 없음)는 대비가 생겨 나아졌지만 **단계는 여전히 임의값이다.** 이 계획에서 스케일로 정리한다.

### 데이터 — 2026-08-17 실측

**사용자 화면의 모수는 31,327건이 아니다.**

| | K-Startup | 기업마당 |
|---|---:|---:|
| 아직 열림 | 270 | 662 |
| 마감됨 | 29,420 | 0 |
| **날짜가 아님** | 99 | **876 (57%)** |

**K-Startup 29,789건 중 29,420건이 이미 마감된 과거 공고다.** 목록에 그대로 쏟으면 화면이 아카이브가 된다.

기업마당 876건은 접수 기간이 날짜가 아니다. 원문이 이렇다.

```
예산 소진시까지  597 · 상시 접수 123 · 선착순 접수 43
모집 완료시       29 · 세부사업별 상이 28 · 차수별 상이 7
```

**이건 결측이 아니라 정상 상태다.** 마감 임박순에 어디에 놓을지가 [`SPEC.md`](../SPEC.md) §9-5 미결이고, plan/README가 **"제품 화면을 만들 때 정한다"**고 적었다. 지금이 그때다 → [T-0022](#t-0022-접수-기간-표현-결정)

## 안 하는 것

- **`admin/`을 건드리지 않는다.** 운영 도구는 그대로다
- **수집 화면을 만들지 않는다.** 사용자가 수집을 돌리지 않는다. 시연 8화면에도 SPEC S1~S7에도 없다. `admin/ingest`가 이미 있고 admin은 놔두기로 했다
- **예시 데이터를 넣지 않는다.** 빈 자리는 빈 자리로 둔다
- **배점을 화면에 두지 않는다.** 시연에 `25 / 25 / 30 / 20`과 "이 공고는 지역 연계 계획에 30점을 줘요. 네 항목 중 배점이 가장 커요"가 있는데 [ADR-0019](../adr/0019-집필의-축을-양식으로.md)와 정면으로 어긋난다. **옮기지 않는다**
- **적합도순 정렬을 만들지 않는다.** 순서를 정할 근거가 없다
- 위키 그래프(S2), 문서 집필(S6), 신청 현황 칸반(S7)

## 태스크

### T-0018 DESIGN.md §4 토큰 실값 확정

- 상태: 계획중
- 선행: —

`DESIGN.md` §4의 "5.1에서 확정"을 위 실값으로 바꾸고 **타입 스케일을 정리한다.**

**왜.** §1이 "미정 항목을 임의로 채우지 않는다. 채워야 하면 열린 질문으로 올린다"고 했다. **지금은 임의로 채우는 게 아니다** — 기획 시연에 실값이 있고 그것이 §3의 확정 방향과 맞는지 대조할 수 있다.

**완료 조건**

- §4.1 색 표의 "5.1에서 확정"이 전부 실값으로 바뀐다
- §4.2 타입이 **단계 목록**으로 정해진다. 15단계를 그대로 옮기지 않는다
- 시연이 §3·§5를 어기는 곳이 있으면 **시연이 아니라 DESIGN.md를 따른다.** 어긴 곳을 §10에 적는다
- ADR로 남긴다

**건드리는 것** — `DESIGN.md` §4 §10, `docs/adr/` 새 문서
