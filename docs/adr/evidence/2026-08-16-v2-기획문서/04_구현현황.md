## 7. 알려진 한계

1. **실제 생성이 없다.** 문서 본문, 적합도, 판정 모두 고정 데이터다. 시연에서 값을 바꿔 보여줄 수 없다.
2. **공고가 3건뿐이다.** 목록이 짧아 좁혀 준다는 느낌이 약할 수 있다.
3. **위키 노드가 21개다.** `05_그래프설계근거.md`가 말한 헤어볼 임계는 200개다. 지금 구조로 그 규모를 견디는지는 확인되지 않았다.
4. **자격 판별 엔진이 없다.** v1에서 만든 결정론 판별이 v2 코드에는 들어오지 않았다.
5. 온보딩에서 실제 파일을 올려도 **파일명만 읽고 내용은 안 읽는다.** 결과는 항상 같은 목업이다.

## 8. redesign.html에 없는 것

`redesign.html`은 **디자인 시안**이다. 화면이 어떻게 보일지를 정하려고 만든 것이라 위 3장의 동작 중 일부가 빠져 있다. 기능 판단은 이 문서로, 화면 판단은 `redesign.html`로 한다.

**시안에서 도는 것**

시안은 `03_데이터모델.md` 11장의 GraphRAG 구조를 이미 반영했다. 원본 파일이 노드가 아니고 노드가 근거 청크를 갖는다. 그래서 노드 15개, 연결 21개다.

| 화면 | 무엇이 도는가 |
|------|---------------|
| 파일 올리기 | 끌어다 놓기와 파일 고르기, 세 단계 전환, 파일별 읽는 과정 애니메이션 |
| 내 사업 | 노드를 누르면 상세가 열린다. 그래프·목록·이어진 항목 세 곳에서 열린다. 1촌만 남기는 국소 뷰. **노드마다 근거 청크를 열어 원문 조각을 본다** |
| 신청 현황 | 칸반 드래그로 상태 전환. 열 건수가 따라 바뀐다 |
| 전체 | 마감 카운트다운, 해시 라우팅 |

**시안에 없는 것**

| | 기능 | 어디 |
|---|------|------|
| 1 | **문서 빈칸을 눌러 답하고 위키에 적립하는 흐름** | F6-8 · F6-9 · F6-10 · F1-7 |
| 2 | 피드백으로 항목 다시 쓰기 | F6-12 |
| 3 | 제출 서류 체크리스트 토글 | F7-4 |
