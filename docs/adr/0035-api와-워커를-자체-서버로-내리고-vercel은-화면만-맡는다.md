# ADR-0035: API 와 워커를 자체 서버로 내리고 Vercel 은 화면만 맡는다

- 상태: 채택됨 — **결정 2 만 대체됨**([ADR-0036](0036-도메인-없이-ip-인증서로-https-를-세운다.md), 2026-08-18). 도메인 없이 IP 인증서로 HTTPS 가 섰다. 나머지 결정 다섯은 그대로다
- 날짜: 2026-08-18
- 대체하는 것: [ADR-0026](0026-읽기-경로만-vercel에-올린다.md) — API 가 Vercel 에서 내려온다. 화면이 거기 남는 것은 그대로다
- 채우는 것: [ADR-0021](0021-인프라-선정을-미룬다.md) **B(큐와 워커)의 일부** — 실행 위치만 정하고 큐는 여전히 안 고른다
- 근거: [2026-08-18 OCR RAM·CPU 실측](evidence/2026-08-18-올리기-경로-자원-실측.md)
- 관련: [ADR-0029](0029-사용자-파일을-회사-단위-콘텐츠-주소로-로컬에-둔다.md) · [ADR-0030](0030-OCR은-rapidocr-로컬로-하고-검출은-server-를-쓴다.md) · [ADR-0034](0034-업로드를-같은-api-에-두고-못-쓰는-곳에서는-503-으로-답한다.md) 올리기 503 가드

## 맥락

[ADR-0026](0026-읽기-경로만-vercel에-올린다.md)이 "읽기 경로만 올린다"로 정했을 때는 올리기가 없었다. [plan/15](../plan/15-파일-올리기와-진행-표시.md) 가 `POST /api/wiki/{company_id}/files` 를 만들면서 그 전제가 깨졌다.

**Vercel 이 못 하는 것이 셋이다.** 자원 한도가 아니라 성질이다.

| | |
|---|---|
| **파일 저장** | 함수 파일시스템이 읽기 전용이다. [ADR-0029](0029-사용자-파일을-회사-단위-콘텐츠-주소로-로컬에-둔다.md)가 정한 `data/user-files/` 에 못 쓴다 |
| **OCR 모델** | `rapidocr` 가 모델 128MB 를 `site-packages/models/` 에 **런타임에 내려받는다**. 거기가 읽기 전용이다 |
| **응답 뒤 작업** | 지금 구조가 202 를 먼저 답하고 스레드로 돈다. 서버리스는 응답 뒤 인스턴스를 언제 재우는지 보장하지 않는다 |

**자원은 오히려 넉넉했다.** 그래서 이 결정의 이유가 "사양 초과"가 아니라는 것을 적어 둔다.

| 사양 | Vercel 한도 | 실측 | |
|---|---|---|---|
| 메모리 | 3,009 MB | **1,820 MB** | 통과 |
| 패키지 | 5 GB | 약 450 MB | 통과 |
| 실행 시간 | 300초 | 8.5초/쪽 | 35쪽 넘으면 초과 |

**무거운 쪽이 LLM 이 아니라는 것도 적어 둔다.** [ADR-0031](0031-사실-추출을-포트-뒤로-미루고-스텁으로-배관을-먼저-세운다.md)이 미뤄 둔 추출기가 붙어도 그건 네트워크 대기라 CPU 도 RAM 도 안 쓴다. 지금 무거운 것은 [ADR-0030](0030-OCR은-rapidocr-로컬로-하고-검출은-server-를-쓴다.md)이 붙인 로컬 ONNX 추론이다.

## 결정

### 1. Vercel 은 화면만 맡는다

```
브라우저 ──▶ finnect-web (Vercel · Next.js · HTTPS)
                  │  서버 컴포넌트와 라우트 핸들러가 부른다
                  ▼
             Caddy :80 (이 서버 · Docker)
                  ▼
             uvicorn 127.0.0.1:8101 (systemd --user)
                  ▼
             Docker PostgreSQL :55433  +  data/user-files/
```

`finnect-api` Vercel 프로젝트가 없어진다. `FINNECT_API` 가 이 서버를 가리킨다.

**Neon 이 필요 없어진다.** [deploy.md](../deploy.md) 3장의 `pg_dump` → `psql` 왕복이 통째로 사라진다 — 수집한 자리와 서비스하는 자리가 같아졌다. 스냅숏이 낡는 문제도 같이 없어진다.

### 2. 화면이 HTTPS 인데 API 가 HTTP 인 것이 문제가 되지 않는다

도메인이 없어서 인증서를 못 받는다. Let's Encrypt 는 IP 에 발급하지 않는다.

**mixed content 가 안 걸리는 이유는 브라우저가 API 를 직접 안 부르기 때문이다.** 확인했다 — `web/lib/api.ts` 를 임포트하는 파일 일곱 중 `use client` 가 하나도 없고, 올리기도 `web/app/api/wiki/[company]/files/route.ts` 가 받아서 넘긴다. 전부 서버 대 서버라 브라우저는 이 서버 주소를 모른다.

**다만 Vercel 과 이 서버 사이가 평문이다.** 사업자등록증이 그 구간을 지난다. 도메인이 생기면 `deploy/Caddyfile` 의 `:80` 을 이름으로 바꾸는 것이 전부이고 Caddy 가 인증서를 받는다. **그때까지는 실제 개인정보를 올리지 않는 전제로 쓴다.**

### 3. 토큰이 Vercel Authentication 을 대신한다

API 가 Vercel 에 있을 때는 Vercel Authentication 이 문이었다([deploy.md](../deploy.md) §6). 내려오면서 그 문이 없어졌고, **대체물 없이 두면 `POST /api/wiki/{company_id}/files` 가 인터넷에 열린 업로드 창구가 된다** — 아무나 아무 회사 이름으로 파일을 밀어 넣고 디스크와 OCR 을 태울 수 있다.

`X-Finnect-Token` 헤더를 요구한다. **`settings.api_token` 이 비어 있으면 검사하지 않는다** — 로컬이 지금까지처럼 돌아야 해서다.

**토큰을 `.env` 에 두지 않는다.** 거기 두면 개발 서버도 읽어서 `npm run dev` 가 401 을 받는다. `~/.config/finnect/api.env` 에 두고 systemd 가 환경변수로 넣는다 — pydantic-settings 가 환경변수를 `.env` 보다 우선한다.

### 4. 배포 서비스는 8101, 개발은 8100

**포트를 나눈 것이 이 결정의 실무적 요점이다.** 배포 서비스가 떠 있어도 `uv run uvicorn finnect.api.app:app --port 8100` 이 그대로 되어야 한다. 8100 은 `config.py` 기본값이자 `web` 의 기본 API 주소라 개발에 남긴다.

**둘이 같은 DB 와 같은 `data/user-files/` 를 본다.** 그래서 아래 대가가 따른다 — 결과 4번.

### 5. 워커를 하나로 묶는다

`--workers 1` 이다. `ingest/jobs.py` 의 락이 `threading.Lock` 이라 프로세스 안에서만 산다. 늘리면 같은 회사의 위키 구축이 두 번 동시에 돌고 청크가 두 벌 생긴다.

**동시성의 상한을 정하는 것은 RAM 이 아니라 코어다.** OCR 한 쪽이 1.5코어를 쓰는데 이 서버가 2코어다. 둘이 겹치면 서로 밀린다.

### 6. Caddy 를 호스트 네트워크로 둔다

이 계정은 80 번을 못 연다(sudo 에 비밀번호가 걸려 있다). Docker 데몬이 root 라 컨테이너가 대신 연다.

**다리 네트워크가 아니라 호스트 네트워크다.** uvicorn 이 `127.0.0.1` 에만 붙어 있어서 `host.docker.internal`(172.17.0.1)로는 안 닿는다. 대안이 uvicorn 을 `0.0.0.0` 에 여는 것인데, 그러면 **사내망(10.3.1.231)에서 토큰 검사 앞의 API 가 그대로 보인다.** 프록시를 호스트에 붙이는 편이 노출이 작다.

## 결과

- **`vercel.json` 과 `api/index.py` 와 `requirements.txt` 가 당장은 남는다.** `finnect-api` 를 지우고 나면 쓰이지 않지만, 되돌릴 때 필요하고 `tests/test_admin_api.py` 가 아직 `requirements.txt` 를 근거로 임포트를 막고 있다. **지우는 것은 별 작업이다**
- **`FINNECT_API` 를 고치면 web 을 다시 배포해야 한다.** `next.config.ts` 의 `env` 가 빌드 시점에 박는다([deploy.md](../deploy.md) 5장). 토큰(`FINNECT_API_TOKEN`)은 `env` 에 없어서 런타임에 읽히고, 그래서 **토큰만 바꿀 때는 재배포가 필요 없다**
- **서버가 죽으면 화면도 죽는다.** Vercel 은 살아 있어도 목록이 안 뜬다. 전에는 Neon 이 받쳐 줘서 이 서버와 무관했다 — **가용성을 하나 잃고 올리기를 얻은 것이다**
- **개발 서버와 배포 서비스가 DB 와 디스크를 공유한다.** 포트는 갈렸지만 그 아래가 한 벌이다. `jobs` 락이 프로세스를 못 넘으므로 **양쪽에서 같은 회사의 위키를 동시에 세우면 청크가 두 벌 생긴다.** 지금은 규칙으로 막는다 — 한쪽에서 구축이 도는 동안 다른 쪽에서 올리지 않는다
- **[ADR-0034](0034-업로드를-같은-api-에-두고-못-쓰는-곳에서는-503-으로-답한다.md) 의 503 가드가 이 서버에서는 안 걸린다.** `storage.writable()` 이 실제로 써 보고 판정하는데 여기는 로컬 디스크라 통과한다 — 확인했다. **가드를 지우지 않는다** — 되돌리거나 다른 읽기 전용 환경에 얹을 때 그 자리가 다시 필요하고, 없으면 사용자가 파일을 다 올린 뒤에 500 을 본다
- **포트 80 을 밖에서 열어야 한다.** OpenStack 보안 그룹의 일이라 이 저장소 밖이다
- **되돌리는 조건: 도메인과 인증서가 생기고 나서도** 이 결정은 그대로다. 되돌릴 이유는 자체 서버 운영이 부담이 될 때이고, 그때는 올리기를 포기하거나 오브젝트 스토리지로 [ADR-0029](0029-사용자-파일을-회사-단위-콘텐츠-주소로-로컬에-둔다.md)를 같이 뒤집어야 한다
