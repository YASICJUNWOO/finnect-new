# design/components.md — 컴포넌트

라이브러리를 쓰지 않고 [`tokens.md`](tokens.md)의 값으로 직접 만든다.

| 컴포넌트 | 용도 | 사용처 |
|----------|------|--------|
| LNB 항목 | 3축 네비게이션과 현재 위치 | 전역 |
| 목록 행 | 사업명, 기관, 규모, D-day, 액션 | S1 S7 |
| D-day 표기 | 우측 정렬. D-7 이내 강조. `tabular-nums` | S1 S7 |
| 필터 탭 | 출처 구분 | S1 |
| 정의 목록 | 항목명과 값 두 열 | S2 S8 |
| 평가 항목 표 | 항목명과 평가 관점 | S2 S3 |
| 배점 막대 | 배점 크기 시각화. **공고가 배점을 줄 때만 그린다** | S2 S3 |
| 항목 태그 | 서술과 질문에 붙는 "○○ 항목에 씁니다" | S3 S4 |
| 접이 블록 | 결론 먼저, 근거는 펼치기 | S3 |
| 진행 단계 표시 | 집필 3단계 | S3 S4 S5 |
| 진행률 바 | 계획서 작성 진척 | S7 |
| 다음 할 일 행 | 상태별 행동 유도 | S7 |
| 분량 카운터 | 공고 제한 대비 현재 분량 | S5 |
| 경고 배너 | 마감 임박, 탈락 조건 | S2 S7 |
| 준비 시작 버튼 | 신청 현황에 추가 | S1 S2 |
| 책임 고지 | 최종 확인은 사용자 책임 | S2 S6 |

---

## 상태를 가진 컴포넌트

각 컴포넌트는 필요한 상태를 모두 정의한다.

| 컴포넌트 | 정의할 상태 |
|----------|-------------|
| 목록 행 | 기본 / 호버 / 포커스 / 마감 임박 |
| 진행률 바 | 0% / 진행 중 / 100% |
| 다음 할 일 행 | 상태 5종 각각 (검토 중, 준비 중, 작성 중, 제출 준비 완료, 제출함) |
| 분량 카운터 | 여유 / 근접 / 초과 |
| 에디터 | 대기 / 스트리밍 / 완료 / 실패 |

## 두지 않기로 한 것

| 안 만드는 것 | 이유 |
|--------------|------|
| 요건 대조 표 | 판별을 화면에 노출하지 않는다. [ADR-0003](../adr/0003-판별-비노출.md) |
| 출처 배지 (생성문 안) | 사실 고정을 화면에 표시하지 않는다. [ADR-0006](../adr/0006-사실고정-화면-미표시.md) |
| 판별 조건 칩 | 조건이 궁금하면 내 정보에서 본다 |
| S5 우측 근거 패널 | 집필 중 봐야 하는 것은 분량과 항목뿐이다 |
| 카드 | 밀도. 행으로 하면 한 화면에 여덟 건이 들어간다 |
