### 스파이크의 전제가 틀렸다

스파이크는 스캔 PDF 3건을 보고 **"전부 K-Startup 회원가입·마이데이터 매뉴얼이라 OCR 실익이 없다"**고 적었다. 표본 3건이었다.

**158건에서는 성립하지 않는다.** 그중 34건이 **그 공고의 유일한 근거**다 — 다른 첨부가 전부 못 읽히는 공고에 붙어 있다.

### 공고문이 이미지인 62건, 그중 29건이 통째로 안 보인다

공고문 파일 자리에 png·jpg가 붙은 공고가 62건이다. **그중 29건은 다른 첨부도 전부 못 읽혀서 통째로 안 보인다.** 나머지 33건은 다른 첨부가 살려 준다.

**"공고문이 이미지면 그 공고는 안 보인다"고 말하면 틀린다.** 절반은 다른 첨부로 건진다.

## 7. 부산물 — 기업마당은 재수집마다 전건이 '변경'으로 잡힌다

검증 중에 나왔다. 목록을 그대로 다시 받았는데 이렇다.

```
[bizinfo] 응답 1건 · 공고 1,538건
  신규 0 · 변경 1,538 · 그대로 0
```

콘텐츠 해시가 **item 통째**를 재료로 쓰는데(`ingest/base.py` `content_hash`), 기업마당 item에 **조회수 `inqireCo`가 들어 있다.** 조회수는 계속 오르므로 해시가 매번 바뀐다.

**결과적으로 재수집 한 번에 `attachment` 3,354행이 매번 통째로 지워지고 다시 깔린다.**

[ADR-0022](../0022-첨부-원본을-콘텐츠-주소로-로컬에-둔다.md) 2번이 상태를 별도 표에 둔 이유가 정확히 이것이고, **가정이 아니라 실제로 매번 일어나는 일**이었다. 검증에서 확인했다.

```
재수집 전   attachment 최소 id = 1      · 해독 ok 2,827
재수집 후   attachment 최소 id = 3,355  · 해독 ok 2,827
```

행은 전부 갈렸고 해독 상태는 그대로다.

**이건 이 슬라이스에서 고치지 않는다.** 변경 감지가 조회수에 반응하는 것 자체는 별개 문제고, 여기 적어 둔다.
