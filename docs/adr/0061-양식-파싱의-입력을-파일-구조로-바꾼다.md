# ADR-0061: 양식 파싱의 입력을 텍스트에서 파일 구조로 바꾼다

## 맥락

양식 파싱이 **파일을 텍스트로 납작하게 만든 뒤** 그 텍스트에서 칸을 찾는다. 첨부 해독(`attach/`)이 먼저 서고 그 위에 얹혔기 때문이다. 그때는 **값을 파일에 되돌려 넣는다는 요구가 없었다.**

[ADR-0060](0060-양식을-채워서-원본-포맷으로-돌려준다.md)이 그 요구를 만들었고, 구현하면서 벽 넷에 부딪혔다. 넷이 **같은 뿌리**를 갖는다.

```
파일 → 텍스트로 뭉갬 → 구간으로 자름 → 칸을 찾음 → 파일을 다시 열어 좌표를 붙임
                                                    ↑ 한 바퀴 돌아온다
```

| 증상 | 실측 |
|---|---|
| 텍스트로는 칸이 안 보인다 | 같은 양식의 docx 판이 **라벨 0개**, 파일로 열면 **52개** |
| 표와 서술이 섞인 서식에서 절반을 잃는다 | `붙임 2. 모집공고신청서류.hwp` 가 `fields` 로 판정돼 활동계획서 목차 **통째로 유실** |
| 좌표를 못 심는 파일이 많다 | 파일 하나에 `fields` 구간이 여럿인 것이 **31%** — 표가 어느 구간인지 못 가린다 |
| 좌표를 나중에 붙이는 경로가 따로 필요하다 | `plant_anchors()` 를 별도로 만들어야 했다. 다시 뜯으면 **초안이 지워진다**(FK CASCADE) |

**설계가 나빠서가 아니라 순서 때문이다.** 파일에는 표 구조가 이미 있는데 그것을 버렸다가 다시 찾고 있다.

## 결정

### 1. 양식 파싱의 입력은 파일 구조다

파일을 열어 **구조를 그대로 항목화한다.** 표 칸은 `(구역, 표, 행, 열)` 좌표와 함께, 서술 항목은 제목과 지시문으로 만든다. 텍스트를 경유하지 않는다.

```
파일을 연다
  → 구조 그대로 항목 + 좌표
  → LLM 이 각 항목을 읽고 성격과 필요한 자리를 답한다
  → 위키에서 값·글을 만든다
  → 같은 좌표로 파일에 넣는다
```

**좌표가 처음부터 항목에 붙는다.** [ADR-0014](0014-통합-그래프와-근거-청크.md)가 「위치정보는 파싱 단계에서만 심을 수 있다」고 한 것을 이제 곧이곧대로 지킨다 — 나중에 붙이는 경로(`plant_anchors`)가 없어진다.

### 2. 텍스트 추출을 없애지 않는다. 물러날 자리로 둔다

**구조를 열 수 있으면 파일을, 없으면 텍스트를 쓴다.** pdf 와 스캔본은 표 구조가 없고, 검색·요약·위키 청킹은 그대로 텍스트를 쓴다.

`attach/` 는 아무것도 안 바뀐다. 바뀌는 것은 **양식 파싱이 무엇을 입력으로 받나** 하나다.

### 3. 갈래를 문서에서 칸으로 내린다

`document.kind` 로 추출기를 고르는 스위치를 없앤다. 지금은 이렇게 갈린다.

```python
if kind is FIELDS:     return _add_fields(...)    # 표 라벨만
if kind is NARRATIVE:  return _add_outline(...)   # 목차만
```

**한 신청서에 표와 서술이 같이 있는 것이 흔하다.** 그때 어느 쪽으로 판정되든 절반을 잃는다. 갈래는 **칸마다** 정한다 — `document_item.input_kind`(`field`/`narrative`)와 `item_need.place_kind`(`value`/`event`)가 이미 그 축이고, **모델은 준비돼 있는데 추출만 한쪽으로 갈라져 있었다.**

`document.kind` 는 남기되 뜻이 약해진다. 「채울 것이 있나」(`none` 이냐 아니냐) 정도이고, **무엇을 뽑을지 고르는 데 안 쓴다.**

### 4. 항목 추출을 LLM 하나로 합친다

표 라벨 정규식(`fields.py`)과 목차 규칙(`outline.py`)이 각자 뽑던 것을 **한 번의 호출**로 합친다. 사람이 양식을 볼 때 하는 일과 같다 — 표 칸과 서술 항목을 같이 본다.

규칙이 못 하는 것이 셋이고 실측이 전부 확인했다.

- **부스러기를 못 거른다.** `=기업 기본 정보`(표 구분선)와 `▸민사집행법에 기하여 채무불이행자명부에…`(안내문 전체)가 채울 칸으로 잡혔다
- **안내문이 든 칸을 빈 칸과 못 가른다.** `000-00-00000 (법인등기부등본상)` 이 채울 자리인지 규칙으로 안 갈린다([ADR-0060](0060-양식을-채워서-원본-포맷으로-돌려준다.md) 결정 6)
- **서식 경계를 못 찾는다.** 한 파일에 서식이 다섯인데 구간이 하나였다

[plan/11](../plan/11-작성-항목-추출과-표시.md)이 「서술형 판정은 규칙으로 네 번 실패했다」고 적어 뒀고 그 판정은 이미 LLM 으로 갔다([classify.py](../../src/finnect/extract/classify.py)). **판정만 옮기고 추출은 규칙으로 남긴 것이 이 어긋남의 원인이다.**

### 5. 위치는 LLM 에 맡기지 않는다

LLM 은 문자를 정확히 못 센다. **좌표는 코드가 준다** — 파일을 순회하며 매긴 `(구역, 표, 행, 열)` 이고, LLM 은 그 좌표를 받아서 「이 칸이 무엇을 묻나」만 답한다.

서술 항목처럼 좌표가 없는 것은 **제목 문자열**을 받아 원문에서 우리가 찾는다. 못 찾으면 버린다 — 위키 추출의 앵커 대조와 같은 수법이다([ADR-0037](0037-llm-제공자를-openai-로-정하고-gpt-5-6-luna-부터-잰다.md) 결정 5).

### 6. 큰 문서는 규칙이 자른다

코퍼스 최대가 **56만 자**라 한 번에 못 넣는다. 자르는 것은 규칙(`segment.py`)이 계속한다.

**다만 경계가 틀려도 치명적이지 않게 된다.** 결정 3 이 갈래를 칸으로 내렸으므로, 경계가 어긋나면 항목 몇 개가 두 조각에 걸칠 뿐이고 **종류가 통째로 틀리는 일은 안 생긴다.** 지금은 경계 하나가 서식 전체를 잃게 만든다.

## 정하지 않은 것

- **LLM 에 표를 어떤 모양으로 넘길 것인가.** 셀 좌표를 붙인 마크다운 표인지 JSON 인지. 정확도를 재고 정한다
- **한 파일을 몇 조각으로 나눌 것인가.** 지금 `segment.split` 을 그대로 쓸지, 표 단위로 묶을지
- **이미 깔린 `document_item` 을 어떻게 할 것인가.** 다시 깔면 초안이 지워진다(FK CASCADE) — 옮기는 절차를 plan 이 정한다
- **pdf 양식.** 표 구조가 없어 텍스트로 물러나는데, 그러면 좌표가 없어 채우지 못한다. 코퍼스의 몇 %인지 재야 한다

## 결과

- **벽 넷이 한꺼번에 없어진다.** 텍스트가 못 살린 칸, 섞인 서식의 절반 유실, 좌표를 못 심는 31%, 나중에 붙이는 경로가 전부 같은 뿌리였다
- **LLM 호출이 는다.** 파일마다 1회 이상이고 지금은 0회다(규칙). 파싱이 초안 시작에 붙어 있어 공고당 몇 회이며, 집필이 항목마다 부르는 것에 비하면 작다
- **비결정론이 들어온다.** 같은 파일을 두 번 뜯으면 항목이 달라질 수 있다. `extract --redo` 가 초안을 지우므로(FK CASCADE) 다시 뜯는 경로를 막아야 한다
- **포기하는 것** — pdf 양식은 좌표를 못 얻어 채우지 못한다. 텍스트로 항목은 뽑히므로 **화면에서 글을 보고 사람이 옮긴다**
- **살아남는 것** — `forms` 어댑터와 좌표(`Anchor`), `item_need`·`place_kind` 축, 집필·값 경로·채우기·뷰어가 그대로다. 바뀌는 것은 **항목이 어디서 오나** 하나다

**세 번째가 이 ADR 의 계기다.** 파일 하나에 서식이 다섯(기본지원서·활동계획서·사용인감·청렴서약서·자격확인서)인데 구간이 하나였고, `fields` 로 판정돼 표 칸 13개만 나왔다. 활동계획서는 `1. 목적 및 필요성`·`2. 수주 활동 대상` 처럼 번호와 지시문이 있는 **명백한 서술형 목차**인데 `document_item` 에 한 줄도 없다.

**두 번째가 방향을 가리켰다.** 같은 양식의 docx 판이 텍스트로는 라벨 0개인데 파일을 열자 52개가 나왔다. 그 항목들로 채운 값이 원본 양식의 제자리에 떴다 — 업체명·대표자명·업종·설립일·투자유치금액·현주소.

라벨 대조가 부러지는 것도 함께 쟀다(`spike/anchor_check.py`). `kstartup:178881` 에서 채운 17칸 중 둘이 겹치는 라벨이었다(`기업명` 3회 · `합계` 3회). **틀려도 파일은 정상으로 열려서 제출 직전에야 드러난다** — 좌표를 쓰는 이유가 이것이다.
