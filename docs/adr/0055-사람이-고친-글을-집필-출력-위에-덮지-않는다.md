# ADR-0055: 사람이 고친 글을 집필 출력 위에 덮지 않는다

- 상태: 채택됨
- 날짜: 2026-08-22
- 관련: [ADR-0028](0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md) 질문 타이밍 · [ADR-0014](0014-통합-그래프와-근거-청크.md) 근거 청크 · [ADR-0015](0015-무인-생성.md) 무인 생성 · [plan/21](../plan/21-동선을-끝까지-잇는다.md) T-0123

## 맥락

동선 넷째 칸이 「초안을 보고 고친다」인데 **고친 것이 아무 데도 안 남았다.** `FormFill` 의 입력값이 `useState` 라 새로고침하면 날아간다.

저장을 붙이려면 **사람이 쓴 문장을 어디에 두는지**부터 정해야 한다. `draft_item.body` 에 덮어쓰는 것이 가장 쉬운데, 그러면 셋이 깨진다.

1. **`draft_evidence` 가 문단 번호로 매달려 있다.** 사람이 문단을 합치거나 나누면 3번 문단의 근거가 다른 문장에 붙는다. 화면이 **없던 근거를 있는 것처럼 보여 준다**
2. **[ADR-0028](0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md) 4번의 파급 관리가 `fact_id` 로 돈다.** 어느 항목이 낡았는지 계산하려면 「이 항목이 무슨 사실로 써졌나」가 남아 있어야 한다
3. **재작성이 사람 글을 지운다.** 항목 하나만 다시 쓰는 것이 이 제품의 단위인데(ADR-0028 3번 · ADR-0015), 재작성이 `body` 를 갈면 사용자가 고친 것이 조용히 없어진다

## 결정

**1. 칸을 나눈다. `body` 는 집필기의 것이고 `edited_body` 는 사람의 것이다.**

```
draft_item.body         집필기가 쓴 글. **사람이 못 고친다**
draft_item.edited_body  사람이 쓴 글. NULL 이면 안 고친 것이다
draft_item.edited_at    언제 고쳤나
```

화면과 API 가 보여 주는 것은 `edited_body ?? body` 다. **덮어쓰기가 아니라 가리기다.**

**2. `status` 를 안 늘린다.** 일곱 개가 전부 **집필이 어떻게 됐나**를 말한다(`blank` · `no_needs` · `yielded` · `unwritten` · `drafted` · `answered` · `stale`). 「사람이 고쳤다」는 다른 축이라 여덟째 값으로 넣으면 **`drafted` 였는지 `blank` 였는지가 지워진다.** `edited_at` 의 존재 여부가 그 축을 든다.

**3. 고친 항목은 문단 근거를 안 낸다.** `edited_body` 가 있으면 API 가 문단마다 `evidence: []` 를 내고 항목에 `evidence_detached: true` 를 단다.

**`draft_evidence` 행은 지우지 않는다.** DB 에 그대로 남아 [ADR-0028](0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md) 4번의 파급 계산이 계속 돈다. **화면에만 안 낸다** — 사람이 고친 문장 옆에 「이 문장은 이 사실에서 나왔어요」라고 적으면 그것이 거짓이 될 수 있고, 근거 대조는 이 제품에서 장식이 아니다.

**4. 재작성이 `edited_body` 를 안 건드린다.** 집필기는 `body` 만 쓴다. 재작성한 뒤에도 사람 글이 위에 있고, 화면이 **「새로 쓴 글이 있어요」를 말한다** — 어느 쪽을 쓸지는 사람이 고른다. **자동으로 안 고친다**(F1-5-5 와 같은 규율).

**5. 되돌리기가 삭제다.** `edited_body` 를 `NULL` 로 만들면 집필기의 글이 다시 보인다. **원본이 안 지워졌으니 되돌릴 수 있다** — `body` 에 덮어썼으면 못 한다.

**6. 빈 문자열과 `NULL` 이 다르다.** 빈 문자열은 **사람이 일부러 비운 것**이고 `NULL` 은 안 고친 것이다. 둘을 섞으면 지운 항목에 초안이 다시 나타난다.

## 결과

- 고친 것이 남는다. 새로고침해도 있다
- **초안의 출처가 셋으로 갈린다** — 집필기(`body`) · 사용자 답변(`answered` 문단) · 사람이 직접 고친 것(`edited_body`). 화면이 이 셋을 색이 아니라 **글자로** 가른다(ADR-0028 결과 절과 같은 규칙)
- 마이그레이션이 하나 붙는다. **배포 DB 에도 돌려야 한다** — 안 돌리면 `PUT` 이 500 이다
- [plan/21](../plan/21-동선을-끝까지-잇는다.md) T-0124(못 채운 자리에서 묻는다)가 이 자리를 딛는다. 답변은 `edited_body` 가 아니라 **위키에 먼저 저장되고 재작성이 `body` 를 채운다** — 두 경로가 다르다는 것이 [ADR-0028](0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md)의 요점이다

### 포기한 것

**문단 단위로 안 고친다. 항목이 단위다.** 문단 단위로 두면 근거 매핑을 살릴 수 있지만, 사람이 글을 고치는 단위는 문단 경계를 넘는다 — 두 문단을 하나로 합치는 편집을 표현할 수 없다. **재작성·실패·질문의 단위가 전부 항목이라**(ADR-0028 3번) 편집도 항목으로 맞춘다.

**동시 편집을 안 막는다.** 마지막에 쓴 사람이 이긴다. 인증이 없어서 「누가」가 없고, 없는 사용자 사이의 충돌을 지금 설계하면 **인증이 붙을 때 다시 만든다.**

**고친 이력을 안 쌓는다.** `edited_body` 한 칸이고 이전 편집은 남지 않는다. 되돌아갈 자리는 집필 원본 하나다.
