### 데모 표본 — `--demo`

전량 첨부는 55.3GB 인데 이 서버 여유가 24GB 다. 데모에는 그만큼이 필요 없다.

```
15,643  필터 통과
   591  --demo (% 36)          ← 기업마당 통과분 563 공고와 같은 규모
 1,308  --read-only 첨부         0.83GB · 내려받기 약 12분
   118  그중 계획서 양식 보유       기업마당은 같은 규모에서 28건이다
```

**접수중 122건은 전부 넣는다.** 제품 API 가 기본으로 마감된 공고를 빼서
(`open_only=True`) 접수중이 아닌 공고는 **화면에 아예 안 뜬다** — 데모에서 실제로
보이는 것이 그 122건이다. 나머지는 적합도·집필의 재료라 표본이면 된다.

**무작위 시드를 안 쓴다.** 공고 번호를 36으로 나눈 나머지라 언제 돌려도 같은 집합이
나온다. 넓히려면 나눗수만 줄인다(`--demo 20` → 899건).

`--read-only` 는 지금 한 글자도 못 읽는 포맷을 뺀다. **jpg·png 가 전량 바이트의
43%인데 첨부 OCR 은 꺼져 있다**([ADR-0030](../docs/adr/0030-OCR은-rapidocr-로컬로-하고-검출은-server-를-쓴다.md)).
안 받아도 `attachment` 행과 URL 은 남아 있어 나중에 받을 수 있다.

덤프는 우리 DB 에서 뜬다. `notice` 표가 아니라 `kstartup_notice` 와 `attachment` 를 읽는다.

```python
COLS = ["pbanc_sn","biz_pbanc_nm","aply_trgt_ctnt","supt_biz_clsfc","biz_enyy","pbanc_ctnt"]
# [{"notice": {COLS…}, "attachments": [{"filename","ext","url"}…]}, …] 로 저장한다
```

### 축2d′ 는 분류로 빼고 양식으로 되살린다

첨부 파일명 67,300개로 분류별 계획서 첨부율을 쟀다.


**`시설ㆍ공간ㆍ보육` 을 안 뺀 것이 요점이다.** 7,353건으로 제일 큰 덩어리인데 계획서
첨부율이 가장 높다 — 대부분 창업보육센터 입주기업 모집이다. 축2g 커밋이 적어 둔
"분류로 빼지 않고 주는 물건으로 뺐다" 와 같은 자리다.

**구제는 문서 포맷일 때만 한다.** 파일명에 `사업계획서` 가 있어도 png 면 포스터다 —
포맷 무관 구제 542건 중 20건이 그림이었고, 무작위 12건 육안에서 오구제가 3건→0건이 됐다.

> **`filter.py` 의 원칙 2 를 어기지 않았다.** 거기 "첨부 파일명 `사업계획서` = 정밀도
> 21% · 재현율 50%" 로 적힌 것은 **고르는** 신호로 쓸 때다. 여기서는 이미 배제된
> 집합만 **되살리는** 데 쓴다 — 방향이 반대라 재현율만 올라간다.

## 코드 구조

```
filter.py       순수 함수 + 픅스처. 의존성 0
  clean_summary   bsnsSumryCn 은 HTML 이다. 태그·&nbsp; 처리를 빼먹으면 축1 이 깨진다
  first_clause    첫 ☞ 절 = 지원대상 (☞ = U+261E, 1,538건 전부에 있다)
  head_noun       절의 끝 명사 = 신청 주체
  axis1           기업 / 기관 / 공급자 판정
  parse_age       업력 상한·하한. 문맥 단어가 ±22자 내에 있어야 인정
  filter_notice   단건 판정. 통과 여부와 근거를 함께 돌려준다
  run             전량 + 퍼널

run.py          수집 → 필터 → out/ → 로컬 서버
fixtures.json   픅스처용 원문 41건 (2026-08-16 스냅샷)
로직과근거.md    로직 전문과 선택 근거
out/            산출물. .gitignore 됨
```

`filter_notice()` 는 dict 하나를 받아 dict 하나를 돌려준다. 다른 데서 쓰려면 이것만 임포트하면 된다.

```python
from filter import filter_notice
r = filter_notice(notice_dict)     # 기업마당 응답 item
r["pass"]      # True / False
r["reasons"]   # ["축2b 과업 실증"] 처럼 배제 근거
r["tier"]      # 1~4. 필터가 아니라 정렬용
```

## 믿을 수 있는 범위

| 단계 | 기준을 정한 주체 | 검증 |
|---|---|---|
| ⑤ 마감 | 날짜 비교. 판단 없음 | 라이브 호출로 4방향 검증 |
| ⑨ 업력 | 상한·하한 산술 | 픅스처 13건 |
| ⑦ 규모 | `근로자 N인 이상` 산술. OR 조건이라 `min()` | 단위 3건 |
| ④ 계획서없음 | **첨부 20건 열어 선정 방식 확인** | 픅스처 6건 |
| ⑤ 신호없음 | **남은 24건 전건 첨부 확인** | 픅스처 5건 · **오배제 1건 확인** |
| ② 축1 | **사람이 사전 작성** | 알려진 9건 9/9 · **버그 3건 남음** |
| ③ 축2 | 첨부 7건 열어 확인 | 3개 값 + 국가R&D 수행형태 3개 값 |
| ⑤ 소상공인 | 지원대상 절 전체 검사 | 픅스처 3건 |
| ④ 축2b | **사람이 어휘 3개로 좁힘** | 정밀도 6/6 · **재현율 미측정** |
| 순서(T1~T4) | 판단 | 미검증 |

**가장 큰 공백은 ④의 재현율이다.** 원래 배제하던 51건 중 7건만 첨부를 열어 확인하고
어휘를 3개로 좁혔다. 좁힌 뒤 통과된 48건을 전건 검수하지 않았다.

**T3 485건(81%)은 "타겟 신호가 없는 것"이다.** 배제된 게 아니라 키움 어휘도 업력 조건도
없어서 판단 근거가 없는 층이다. 통째로 버리면 포항 건이 함께 나간다 — 근거를 재보니
정당하게 뺄 수 있는 건 특수 인증 필수 7건(1.4%)뿐이었다.

**T4 는 없어졌다.** 175건에서 축2d 로 146건, 순서 수정으로 5건(T1·T2 승격),
축2e 로 마지막 24건을 처리했다. 축2e 는 **24건 전건의 첨부를 열고** 정했다 —
23건이 컨설팅·상담·보고서·번역·교육이었고, 사업에 투입되는 자원(자금·장비·시제품)이
있는 것은 **0건**이었다.

**세부분야 값으로는 뺄 수 없었다.** 같은 `교육` 안에 정반대 두 건이 있다.

```
119373  [인천] 세대융합 청년창업 멘티   예비창업자·3년 이내·사업화 1,000만원
123341  [울산] 찾아가는 사업장 안전교육  산업안전보건법 법정 의무교육
```

그래서 값이 아니라 **3중 조건**으로 뺀다 — `미검증 분야 AND 키움 어휘 없음 AND 업력 조건 없음`.
119373 은 키움 `창업` 이 있어 T1 로 빠져나가고, 123341 은 셋 다 없어서 걸린다.

**알려진 오배제 1건.** `민관 공동 전략형 상생협력사업(창의트랙)`은
`제출한 사업계획서 및 발표 내용을 바탕으로 과제 평가 · 대면 평가가 원칙`으로,
24건 중 유일하게 계획서로 경쟁 심사한다. 첨부를 열지 않으면 나머지 23건과
구분되지 않아 함께 빠졌다(오배제율 4%). 픅스처 `125217` 에 명시해 뒀다.
알려진 버그 3건과 그 원인은 [`로직과근거.md`](로직과근거.md) §10 에 있다.

**이 필터는 "사업계획서로 심사받는가"를 판정하지 않는다.** 그건 첨부 양식을 열어야 나오고,
`로직과근거.md` §11 에 방법과 실측(48건 표본)이 적혀 있다.
