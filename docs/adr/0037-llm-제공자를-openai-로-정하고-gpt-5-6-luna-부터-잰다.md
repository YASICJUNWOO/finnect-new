# ADR-0037: LLM 제공자를 OpenAI 로 정하고 gpt-5.6-luna 부터 잰다

- 상태: 채택됨
- 날짜: 2026-08-19
- 채우는 것: [ADR-0021](0021-인프라-선정을-미룬다.md) **G(LLM 제공자)** — "각각을 실제로 필요로 하는 작업에서 정한다" 고 비워 둔 자리
- 관련: [ADR-0031](0031-사실-추출을-포트-뒤로-미루고-스텁으로-배관을-먼저-세운다.md) — 포트를 판 결정. 이 ADR 이 그 포트에 구현을 꽂는다

## 맥락

**LLM 을 한 번도 안 불렀다.** [ADR-0021](0021-인프라-선정을-미룬다.md) G 가 제공자 선정을 미뤘고, [ADR-0031](0031-사실-추출을-포트-뒤로-미루고-스텁으로-배관을-먼저-세운다.md) 이 그 자리에 Protocol 을 파고 스텁을 끼워 [plan/12](../plan/12-사업-위키-구축.md) 를 닫았다.

**그래서 위키가 준비된 파일 7건에서만 선다.** 다른 파일을 넣으면 `UnknownFile` 이 난다. 지식 베이스의 배관은 다 됐는데 **청크에서 사실을 뽑는 함수 하나가 비어 있다.**

제공자를 기다리는 자리가 둘이고 **결정이 하나다.**

| | 무엇 | 출력 |
|---|---|---|
| [plan/12](../plan/12-사업-위키-구축.md) T-0045 | 위키 사실 추출 | 구조화된 객체 여럿 |
| [plan/11](../plan/11-작성-항목-추출과-표시.md) T-0036 | 양식 구간 판별 | 라벨 하나 (`unknown` 7,717 구간) |

## 결정

### 1. OpenAI 를 쓴다. 모델은 `gpt-5.6-luna` 부터 잰다

2026-08-19 확인 — 라인업이 `gpt-5.6-sol` · `terra` · `luna` 다. **`gpt-5.5-mini` 는 없다**([모델 목록](https://developers.openai.com/api/docs/models)).

`luna` 는 "비용에 민감한 대량 작업용" 이고 예전 nano 티어에 해당한다. **$0.2 / $1.2** (1M 토큰) · 컨텍스트 105만 · **구조화 출력과 프롬프트 캐싱을 지원한다**([문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna)).

**비용이 선택 기준이 아니다.** 위키 추출은 파일 7건이라 몇 센트이고, 양식 판별 7,717 구간도 구간당 2천 토큰으로 잡아 $3 남짓이다. 전부 합쳐 $5 아래다.

**그래서 정확도만 보고 고른다. 그리고 잴 수 있다** — 아래 3번.

### 2. `openai` 패키지를 안 쓴다. `httpx` 로 직접 부른다

이미 의존성인 `httpx` 로 `POST /v1/responses` 하나만 부른다.

**패키지를 안 넣는 이유가 배포다.** `requirements.txt` 가 읽기 API 에 필요한 다섯만 싣는데, `openai` 를 `pyproject` 에 넣으면 누군가 `api/` 에서 임포트했을 때 **로컬은 통과하고 배포본만 죽는다.** `api/admin_service.py` 에서 `attach.service` 를 임포트하지 않는 것과 같은 규율이다.

우리가 쓰는 것은 엔드포인트 하나와 구조화 출력뿐이라 SDK 가 주는 값이 작다.

### 3. 정확도를 픽스처로 잰다. **스텁이 채점표가 된다**

`tests/fixtures/wiki/facts.json` 이 **코퍼스 7건에서 사람이 손으로 옮긴 사실 118개**다. ADR-0031 이 "진짜 추출기가 오면 이 파일이 정답지가 된다" 고 적어 둔 그대로다.

**모델을 고르는 문제가 아니라 재는 문제다.** `luna` 로 돌려 118개와 대조하고, 부족하면 `terra` · `sol` 로 올린다. **어느 쪽이든 숫자를 근거로 남긴다** — 육안 검증 건수와 함께.

### 4. 키는 환경변수 하나다. 없으면 **명확하게** 죽는다

`OPENAI_API_KEY` 하나만 넣으면 켜진다. 없는데 `wiki_extractor=llm` 이면 무엇이 없는지 말하고 멈춘다 — **조용히 스텁으로 물러나지 않는다.**

물러나면 스텁이 아는 7건만 처리하고 나머지를 조용히 버리는데, 그건 ADR-0031 이 `UnknownFile` 로 막은 바로 그 상황이다.

### 5. 앵커가 원문에 없으면 그 사실을 버린다. **고쳐 쓰지 않는다**

`Fact.anchor` 는 원문에 글자 그대로 있어야 근거 청크를 찾는다(`build.py` 가 `_squash` 후 부분 문자열로 찾는다). LLM 이 조사 하나를 바꾸면 그 사실은 근거를 잃는다.

**세 겹으로 막는다.**

1. 프롬프트가 "원문에서 그대로 복사하라" 고 요구한다
2. 추출기가 **자기 출력을 원문에 대조한다.** 없으면 그 사실을 버리고 센다
3. `build.py` 가 한 번 더 찾고 못 찾으면 문제로 보고한다

**버린 건수를 보고한다.** 조용히 사라지면 "이 파일에서 아무것도 안 나왔다" 와 구분이 안 된다.

## 결과

- 지식 베이스가 **준비된 7건 밖에서도 선다.** 키를 넣으면 켜진다
- 추출 정확도를 **처음으로 잰다.** 스텁은 사람이 옮긴 것이라 정의상 100% 였고 그 숫자를 어디에도 안 썼다
- [plan/11](../plan/11-작성-항목-추출과-표시.md) T-0036 이 같은 클라이언트를 쓴다. 제공자 결정이 두 번 필요 없다
- **`openai` 패키지가 안 들어와서** 배포본 임포트 경로가 그대로다

## 2026-08-20 첫 실측

[실측](evidence/2026-08-20-위키-추출-정확도-실측.md) — **재현율 70.3%** (정답 118 중 83) ·
7건에 $0.03. **이 프로젝트가 추출 정확도를 처음 잰 것이다.**

- **정형 슬롯은 거의 풀렸다** — 미스 6건. 남은 27건은 서술 문장 쪼개기가 사람과 다른 것이라
  정확도라기보다 **분해 단위**의 문제다
- **정밀도 40.5% 는 그대로 읽으면 틀린다.** 정답지가 사람이 고른 일부라, 정답에 없는
  169건 중 무작위 25건을 보니 **22건이 진짜 사실**이었다. **이 픽스처는 재현율에만 쓴다**
- **틀린 것 셋 중 셋이 우리 쪽이었다** — 채점기가 앵커만 먹인 것 · 앵커 매칭이 엄격했던 것 ·
  프롬프트가 슬롯 어휘와 작성 기준일 규칙을 안 적은 것. 모델을 바꾸기 전에 우리를 먼저 고쳤다
- **`terra` · `sol` 과 비교하지 않았다.** 결정 1 이 "여기서부터 잰다" 고 한 그 자리에 있다

## 안 정한 것

- **`luna` 로 충분한지.** 재기 전에는 모른다. 이 ADR 은 "여기서부터 잰다" 를 정한 것이지 최종 모델을 정한 것이 아니다
- **재시도·레이트 리밋 정책.** 파일 7건과 구간 7,717개는 규모가 달라서, 뒤쪽을 실제로 돌릴 때 정한다
- **프롬프트 캐싱.** `luna` 가 지원하지만 우리 호출이 파일마다 다른 본문이라 이득이 불확실하다. 7,717 구간을 돌릴 때 잰다
