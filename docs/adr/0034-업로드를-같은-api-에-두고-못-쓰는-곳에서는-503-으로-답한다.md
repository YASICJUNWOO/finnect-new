# ADR-0034: 업로드를 같은 API 에 두고, 못 쓰는 곳에서는 503 으로 답한다

- 상태: 채택됨
- 날짜: 2026-08-18
- 여는 것: [plan/15](../plan/15-파일-올리기와-진행-표시.md) — S1 파일 올리기와 구축 진행
- 뒤이어: [ADR-0035](0035-api와-워커를-자체-서버로-내리고-vercel은-화면만-맡는다.md)가 **같은 날 실행 위치를 바꿨다.** 아래 `맥락`이 세는 Vercel 의 제약 셋이 그 ADR 의 이유가 됐고, **그래서 이 가드는 이제 안 걸린다** — 아래 `ADR-0035 뒤에 무엇이 남나`
- 관련: [ADR-0029](0029-사용자-파일을-회사-단위-콘텐츠-주소로-로컬에-둔다.md) 로컬 디스크 · [ADR-0026](0026-읽기-경로만-vercel에-올린다.md) 읽기 경로만 올린다(0035 가 대체) · [ADR-0023](0023-제품-프론트를-nextjs로-분리한다.md) 프론트 분리

## 맥락

[plan/12](../plan/12-사업-위키-구축.md)가 파일 → 청크 → 사실 → 노드를 세웠고 [plan/14](../plan/14-사업-위키-화면.md)가 그것을 보여 주는 화면을 세웠는데, **파일이 들어가는 입구가 CLI 하나뿐이었다.** `uv run python -m finnect.wiki --company … ` 를 아는 사람만 이 제품을 쓸 수 있다. [SPEC](../SPEC.md) F1-1-1 이 "파일을 통째로 받는다"를 첫 기능으로 적었고 §5.2 가 S1 을 첫 화면으로 적었으니, 여기가 제품의 시작점이다.

**그런데 업로드는 이 API 의 첫 쓰기 경로다.** 지금까지 `/api/*` 는 전부 `GET` 이었고 [ADR-0026](0026-읽기-경로만-vercel에-올린다.md)이 "올라가는 것은 읽기 경로뿐"이라고 정한 것이 그 이유였다.

배포본(Vercel Python Function)에서 업로드가 도는지 따져 보면 **두 곳에서 막힌다.**

| 무엇 | 왜 막히나 |
|---|---|
| 저장 | [ADR-0029](0029-사용자-파일을-회사-단위-콘텐츠-주소로-로컬에-둔다.md)가 원본을 `data/user-files/` 로컬 디스크에 두기로 했다. 함수 번들은 읽기 전용이고 쓰기 가능한 자리는 요청 사이에 사라진다 |
| 해독 | `requirements.txt` 가 pdfplumber·olefile 을 뺐다. 파서가 아예 없다 |

즉 **경로를 올려도 안 도는 것이 아니라, 안 도는 것이 맞다.** ADR-0029 가 "업로드는 배포본의 첫 쓰기 경로가 되는데 그 문을 데이터가 하나도 없는 상태에서 열지 않는다"고 이미 적어 뒀다.

## 고른 것

셋을 놓고 골랐다.

| 안 | 무엇 | 왜 안 골랐나 |
|---|---|---|
| A | 업로드를 `src/finnect/admin/`(로컬 :8000)에 붙인다 | **`web/` 이 API 를 둘 알게 된다.** `lib/api.ts` 가 "유일한 경계"인 이유가 사라지고, 타임아웃·인증·리다이렉트 규칙이 두 벌이 된다 |
| B | 별도 로컬 전용 앱을 판다 | A 와 같은 문제에 프로세스가 하나 더 는다 |
| **C** | **같은 API 에 두고, 배포본에서는 미리 물어보고 503 으로 답한다** | 고름 |

### 결정 1. 라우트는 어디서든 존재한다. 못 쓰는 곳에서는 503 이다

**환경별로 라우트를 넣었다 뺐다 하지 않는다.** 지우면 **404 가 돌아오고 원인이 화면에 안 남는다.** "없는 주소"와 "여기서는 못 하는 일"은 사용자가 할 일이 다르다. 앞의 것은 버그 신고이고 뒤의 것은 로컬에서 하면 된다.

판정은 **실제로 써 보는 것**으로 한다(`wiki/storage.py` `writable()`). `os.access` 는 컨테이너에서 거짓말을 하고, 파서 유무는 파일을 열기 전까지 모른다. 쓸 수 있는지가 두 조건 중 먼저 걸리는 쪽이라 그것 하나만 본다.

```python
if not storage.writable():
    raise HTTPException(503, "이 서버는 파일을 못 받아요. 올리기는 로컬에서만 돼요")
```

**미리 묻는 것이 요점이다.** 안 물으면 사용자가 파일 일곱 개를 다 올린 뒤에 500 을 본다 — 가장 늦고 가장 안 좋은 자리다.

### 2. 파서는 함수 안에서 임포트한다

`api/app.py` 최상단에서 `finnect.wiki.service` 를 부르면 `import finnect.api.app` 이 pdfplumber 를 끌고 오고 **로컬은 통과하고 배포본만 `ModuleNotFoundError` 로 죽는다.** `CLAUDE.md` 함정에 이미 적혀 있는 종류이고 `tests/test_admin_api.py` 가 admin 쪽에 같은 것을 막고 있다. `tests/test_wiki_progress.py` 가 이 경로를 막는다.

### 3. `python-multipart` 는 `requirements.txt` 에 넣는다

"안 쓰는 것을 서버리스 함수에 싣지 않는다"는 그 파일의 원칙과 부딪히는 것처럼 보이지만 아니다. **`UploadFile` 을 선언한 라우트는 이 패키지 없이 임포트 시점에 죽는다** — FastAPI 가 데코레이터에서 검사한다. 503 은 라우트가 뜬 다음 이야기라 이게 없으면 API 전체가 안 뜬다.

### 4. 받는 것과 읽는 것을 나눈다. 응답은 202 다

`POST` 는 바이트를 저장하고 `uploaded` 행을 만든 뒤 바로 답한다. 해독과 구축은 응답을 보낸 뒤 스레드에서 돈다(`ingest/jobs.py` 의 락을 그대로 쓴다). 화면은 `GET …/progress` 로 따라온다.

붙여 두면 **OCR 이 걸린 파일 하나에 요청이 몇 분씩 묶이고**(사업자등록증 스캔본이 실제로 그렇다 — [ADR-0030](0030-OCR은-rapidocr-로컬로-하고-검출은-server-를-쓴다.md)), 그동안 화면은 몇 개를 받았는지도 말할 수 없다. [SPEC](../SPEC.md) F1-1-9 가 요구하는 것이 정확히 그 말이다.

## 결과

- **올리기가 로컬에서 된다.** 파일 일곱을 던지면 18초 뒤 자리 15개가 찬다(실측 · [plan/15](../plan/15-파일-올리기와-진행-표시.md) 검증)
- **그날의 배포본(Vercel Python Function)은 읽기 전용으로 남았다.** 쓰기 경로가 존재하지만 열려 있지 않은 상태였다
- **큐를 아직 안 골랐다.** [ADR-0021](0021-인프라-선정을-미룬다.md)의 F 가 그대로 남는다. 스레드 하나로 버티는 것은 사용자가 한 명이고 파일이 열 개 안쪽이기 때문이다

## ADR-0035 뒤에 무엇이 남나

같은 날 [ADR-0035](0035-api와-워커를-자체-서버로-내리고-vercel은-화면만-맡는다.md)가 **API 를 Vercel 에서 자체 서버로 내렸다.** 위 `맥락`이 센 제약 셋(파일 저장 · OCR 모델 · 응답 뒤 작업)이 그 ADR 의 이유 셋과 같은 것이다. 이 문서가 "여기서는 못 한다"로 답한 자리에, 그쪽이 "그러면 할 수 있는 곳으로 옮긴다"로 답했다.

**그래서 결정 1의 가드는 이제 안 걸린다.** 자체 서버에서는 `writable()` 이 참이고 올리기가 실제로 돈다. 남는 것은 이렇다.

| 결정 | ADR-0035 뒤 |
|---|---|
| 1. 못 쓰면 503 | **안 걸린다.** 코드는 그대로 두는 안전망이다 — 서버리스로 되돌아가거나 디스크가 차면 그때 이게 답한다 |
| 2. 파서를 함수 안에서 임포트 | **그대로 필요하다.** `requirements.txt` 와 `tests/test_admin_api.py` 가 남아 있고(ADR-0035 `결과`), 되돌릴 길을 막지 않는다 |
| 3. `python-multipart` 를 requirements 에 | 〃 |
| 4. 202 + 응답 뒤 스레드 | **그대로다. 오히려 이것이 0035 를 불렀다** — "서버리스는 응답 뒤 인스턴스를 언제 재우는지 보장하지 않는다"가 그쪽 맥락의 셋째 줄이다 |

**이 문서를 `대체됨`으로 두지 않는 이유가 그 표다.** 뒤집힌 것은 배포처이지 여기서 고른 구조가 아니다.

## 되돌리는 조건

**오브젝트 스토리지가 붙으면 결정 1이 완전히 무의미해진다.** ADR-0029 결정 2의 저장 인터페이스(`put`/`read`/`delete`/`purge`)를 갈아 끼우면 `writable()` 이 어디서나 참이 된다. 그때 남는 질문은 저장 위치가 아니라 **해독을 어디서 도느냐**이고, [ADR-0035](0035-api와-워커를-자체-서버로-내리고-vercel은-화면만-맡는다.md)가 그 답을 먼저 냈다 — 파서와 OCR 이 서버리스 함수에 안 맞는다.

**사용자가 둘 이상이 되면 스레드 하나가 무너진다.** `ingest/jobs.py` 는 회사별 락이라 서로 안 막지만, 프로세스가 죽으면 실행도 죽는다. 지금은 `uploaded` 로 남은 행을 다음 올리기가 이어받게 해 뒀다(`_stranded`). 그것으로 안 되는 날이 큐를 고르는 날이다.
