# ADR-0047: 브레이크포인트를 1024px 과 640px 으로 못 박는다

- 상태: 채택됨
- 날짜: 2026-08-21
- 여는 것: 공고 목록·상세 시안 비교 — [`docs/design/mockup/notice/`](../design/mockup/notice/README.md) `R 적응` 채택
- 관련: [ADR-0042](0042-좌측-레일을-넓은-화면에서만-세운다.md) 좌측 레일 · [ADR-0044](0044-보조-글자-크기를-폭에-따라-가른다.md) 보조 글자 · [ADR-0039](0039-설치되는-앱으로-만들되-서비스-워커는-안-붙인다.md) 하단 탭 바

## 맥락

`DESIGN.md` §5 는 간격 묶음(4 · 8 · 12 · 16 · 24)과 줄길이(62ch)와 터치 타깃(44px)을 정했지만 **브레이크포인트를 정한 적이 없다.**

그런데 코드는 이미 하나를 쓰고 있다. `640px` 이 `layout.module.css` · `NoticeRow.module.css` · `WikiBoard` · `FormFill` 등 **아홉 곳**에 리터럴로 박혀 있다. 근거가 문서에 없는 채로 관성으로 퍼진 값이다.

`R 적응` 이 둘째를 요구한다. 1024px 위에서 좌측 레일이 서고 행이 4열 그리드로 접히고 보조 글자가 13px 로 내려간다.

**1024px 의 근거는 산수뿐이다** — 레일 60 + 콘텐츠 992 = 1052 가 들어갈 최소 폭. 관측값이 아니다. 640px 도 마찬가지다.

## 결정

**1. 브레이크포인트를 둘로 못 박는다. `1024px` 과 `640px` 이다. 셋째를 만들지 않는다.**

| 경계 | 위 | 아래 |
|---|---|---|
| **1024px** | 좌측 레일 + 상단 2단 · 4열 그리드 행 · 보조 글자 13px · 콘텐츠 1040px | 상단 1단 · 세로 스택 행 · 보조 글자 16px · 콘텐츠 100% |
| **640px** | 3축이 상단 막대에 | 3축이 하단 탭 바로([ADR-0039](0039-설치되는-앱으로-만들되-서비스-워커는-안-붙인다.md)) |

**2. 모바일 우선으로 쓴다.** 좁은 쪽이 기본 규칙이고 넓은 쪽이 `min-width` 로 얹힌다. 반대로 쓰면 브레이크포인트 밖 화면에서 조밀한 쪽이 새고, **그쪽이 더 위험하다** — 13px 이 폰에 나가는 것이다.

**3. 좁은 화면 규칙을 기본 규칙보다 뒤에 둔다.** 미디어쿼리를 앞에 두면 뒤의 shorthand 가 덮는다. `@media` 안의 `padding-left` 를 뒤에 오는 `padding: 24px 24px 64px` 이 지운다. **시안을 만들면서 실제로 밟은 함정이다.**

**4. 좁은 화면은 넓은 화면 CSS 를 「안 쓰면 되는」 게 아니라 제 규칙을 가져야 한다.** 4열 그리드 마크업을 좁은 화면에서 그냥 flex 로 뒀더니 행이 **279px** 로 터졌다. 자식 넷이 390px 안에서 서로 밀며 접힌 것이다.

**5. 값을 CSS 변수로 두지 않는다.** `@media` 는 커스텀 프로퍼티를 못 읽는다. 리터럴이 파일마다 반복되는 것을 **받아들이고**, 대신 이 표를 `DESIGN.md` §5 에 올려 정본을 한 곳에 둔다.

**6. 값 자체가 관측 밖이라는 사실을 §5 에 같이 적는다.** 근거는 산수다. 지어낸 것을 관측인 척하지 않는다.

## 결과

- `DESIGN.md` §5 «제품 라우트» 에 브레이크포인트 표가 붙는다. 이제 아홉 곳의 `640px` 이 근거를 갖는다.
- **1024px 을 새로 쓰는 곳이 다섯이다** — `layout.module.css` · `page.module.css`(S4) · `NoticeRow.module.css` · `Filters.module.css` · `tokens.css`(`--t-aux`).
- **포기하는 것 하나 — 브레이크포인트에서 인상이 튄다.** 1024px 을 넘나들며 창을 줄이면 레일이 나타났다 사라지고 행이 접혔다 펴지고 글자가 커졌다 작아진다. 창을 줄이는 사람에게는 다른 제품으로 보인다. 이것을 없애려면 넓은 화면도 좁은 화면 규칙을 쓰거나(밀도를 버린다) 그 반대여야 한다(13px 이 폰에 나간다). **둘 다 이 시안을 고른 이유를 지운다.**
- **포기하는 것 둘 — 태블릿 세로(768~1023px)가 좁은 화면 규칙을 받는다.** 그 폭은 레일이 들어갈 자리가 없어서 상단 1단이 되고, 행은 세로로 쌓이고, 보조 글자는 16px 이다. 밀도가 필요한 폭인데 좁은 쪽 규칙을 받는 것이 맞는지는 **재 보지 않았다.** 셋째 브레이크포인트를 만들 자리가 여기이고, 만들려면 그 폭에서 재고 이 ADR 을 대체한다.
