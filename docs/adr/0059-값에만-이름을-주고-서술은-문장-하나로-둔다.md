# ADR-0059: 값에만 이름을 주고, 서술은 문장 하나로 둔다

- 상태: 채택됨
- 날짜: 2026-08-23
- 대체: [ADR-0058](0058-자리표를-기획-트리로-고정하고-key-를-없앤다.md) **결정 3**(`key` 를 없앤다 — **절반만 되돌린다**) · **결정 4**(트랙 A 값에 상태를 안 매긴다 — 이유가 바뀐다) · [ADR-0056](0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md) **결정 3 잔여**(`kind` 를 추출기가 준다)
- 그대로 사는 것: [ADR-0058](0058-자리표를-기획-트리로-고정하고-key-를-없앤다.md) **결정 1·2·5·6**(자리표 46 고정 · 번호로 답한다 · 자료 등급 다섯 · 기획이 반대로 적은 것 둘) · [ADR-0057](0057-서술을-쌓고-시점을-남긴다.md) **결정 2·3** · [ADR-0056](0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md) **결정 1·4·5** · [ADR-0014](0014-통합-그래프와-근거-청크.md) 근거 청크

## 맥락

[ADR-0058](0058-자리표를-기획-트리로-고정하고-key-를-없앤다.md) 이 `key`(사실의 이름)를 없앴다. 자리가 곧 이름이라고 봤기 때문이다.

**하루 만에 이름이 돌아왔다.** 옆 칸으로.

```
한정어 99건 / 83종  →  종당 1.19건        (2026-08-22 · c_dasiro)
```

`qualifier` 는 「한 자리에 같은 것이 여럿일 때 어느 것인가」를 가르는 칸이다(`TAM`/`SAM`). **사실마다 하나씩이면 아무것도 안 가른다 — 그건 이름이다.**

```
Company/회사소개 의 사실 열한 개
  q='법인명'  q='대표자'  q='개업연월일'  q='업태'  q='종목'  q='소재지'
  q='종업원 수'  q='자본금'  q='직전연도 매출'  q='주력 제품'
  q='2026년 말 목표 월 반복 매출'
```

프롬프트를 두 번 손봤고 두 번 다 같은 자리로 돌아왔다. **번호 겹침 버그를 고쳐 다시 받은 회차에서도 종당 1.14 · 시점이 이름에 박힌 것 22종 그대로였다.**

판정은 이것이다 — **모델이 규칙을 안 지키는 것이 아니라, 이름을 쓸 칸이 없어서 있는 칸에 쓴다.**

## 칸을 다 없애 봤고, 그건 틀렸다

한 번은 `kind`·`value`·`qualifier` 를 **전부** 없애고 문장만 남겨 봤다(2026-08-23). 이름은 확실히 사라졌다(한정어 0종). 대신 둘이 나왔다.

**① 중복이 커졌다.** `Company/회사소개` 가 **11건 → 25건**. 문서 여섯이 회사 기본 정보를 각자 조사만 바꿔 적었고, 없앤 그 칸들이 실제로 그걸 접고 있었다.

```
법인명 4번 — 주식회사 다시로다 / 주식회사다시로이다 /
             주식회사 다시로이다 / 주식회사 다시로 (DASIRO Inc.)이다
```

**② 값만 살리면 사실이 사라진다.** 이름 없이 값만 키에 넣으면 이 짝이 한 행이 된다.

```
Company/팀   2026-01-31
  · 경영은 1명이며 대표이사가 전략, 투자, 대외 협력을 담당한다.
  · 운영은 1명이며 고객 응대 및 매장 온보딩을 담당한다.
```

**중복은 보기 싫은 것이고 이건 데이터 손실이다.**

## 모호했던 것은 서술 쪽뿐이었다

되짚어 보면 [ADR-0058](0058-자리표를-기획-트리로-고정하고-key-를-없앤다.md) 의 논거가 값에는 안 걸린다.

```
서술   Company/팀  +  key="팀 구성"     ← 자리 이름과 겹친다.  모호
값     Company/팀  +  key="경영 인원"    ← 안 겹친다.          모호하지 않다
```

**`key` 를 통째로 없앤 것이 과했다.** 서술에서만 없애면 됐다.

## 결정

### 1. 값에는 이름을 주고 서술에는 안 준다

```
서술   spot instance                text  as_of grade source anchor
값     spot instance  key  value    text  as_of grade source anchor
```

**가르는 물음이 바뀐다.** 「값 하나로 적을 수 있나」(모호했다)가 아니라 **「이 사실에 이름을 붙일 수 있나」**다.

### 2. `kind` 를 안 받는다

**이름과 값이 짝으로 왔나가 곧 종류다.** 따로 받으면 「값이라고 했는데 값이 없는」 상태가 표현되고, 그 행은 화면에 이름 없는 빈칸으로 뜬다.

반쪽(이름만·값만)은 **서술로 떨어뜨린다.** 이름만 있으면 무엇의 값인지 모르고, 값만 있으면 화면에 이름 없는 숫자가 뜬다.

### 3. `qualifier` 를 트랙 A 에서 없앤다. `key` 가 흡수한다

```
조달액 + "시드"      →   key="시드 조달액"
월 구독료 + "기본"    →   key="기본 요금제"
```

한정어가 필요했던 건 **이름을 뭉뚱그렸을 때**다. 구체적으로 쓰면 칸 하나로 끝난다. 실측에서 한정어가 제 일을 한 것이 **71종 중 10종**뿐이었고 그 열이 전부 이름으로 표현된다.

**트랙 B 는 그대로 둔다.** 거기는 `key` 가 enum 열다섯 **고정**이라 `funding` 이라는 이름을 구체적으로 쓸 수가 없고, 충돌 판정이 실제로 `(key, qualifier)` 로 돈다.

### 4. 이름에서 시점을 뗀다 — 프롬프트가 아니라 코드로

한정어 71종 중 **22종이 시점을 이름에 박았다**(`2024년 구독 매출`). 그러면 2024년 것과 2025년 것이 다른 이름이 되어 **이력이 안 쌓인다.**

```
"2024년 매출액"  →  "매출액"        같은 이름이 되고 as_of 가 가른다
"2025년 매출액"  →  "매출액"
"2024년 구독 매출" → "구독 매출"      "매출액" 과는 여전히 다르다
```

`extract_nodes.bare_key()` 가 정규식 하나로 뗀다. **프롬프트로 두 번 막아 봤고 두 번 다 돌아왔으므로 코드로 막는다** — `tree.norm` 이 공백·구두점을 떼는 것과 같은 층이다.

**전부 떼고 나면 원래 이름을 돌려준다.** `2024년` 처럼 시점뿐인 이름을 빈 문자열로 만들면 그 사실이 이름을 잃는다.

### 5. 중복 방지 키가 종류마다 다르다

```
값     value|<자리>|<이름>|<시점>|<값>
서술   event|<자리>|<시점>|<문장>
```

**값이 키에 들어가는 것이 요점이다.** 같은 자리·같은 이름·같은 시점인데 값이 다르면 행이 둘로 서고, 그것이 곧 사용자가 봐야 할 어긋남이다(F1-1-7) — 시드 3억과 2.8억이 둘 다 남는 이유다.

**여전히 병합이 아니라 중복 방지다.** 다르게 쓰인 같은 **서술**은 둘로 선다([ADR-0058](0058-자리표를-기획-트리로-고정하고-key-를-없앤다.md) 결정 3 의 대가가 서술 쪽에는 그대로 남는다).

### 6. 트랙 A 값에 상태를 안 매긴다 — 이유가 바뀐다

[ADR-0058](0058-자리표를-기획-트리로-고정하고-key-를-없앤다.md) 결정 4 는 「견줄 축이 없어서」였다. 이제 축(`이름`)이 생겼으니 **`current`/`superseded`/`conflict` 를 되살릴 수 있다.**

**그래도 안 켠다.** 이름이 자유 문자열이라 회차마다 흔들릴 수 있고, 흔들리면 「지금 값」이 회차마다 바뀐다. 트랙 B 는 enum 이라 그 위험이 없고 자격 판별이 실제로 그 판정을 쓴다 — **필요한 곳에 이미 있다.**

켜려면 **이름이 얼마나 안정적인지를 먼저 재야 한다**([plan/23](../plan/23-자리표를-기획-트리로-고정한다.md) T-0147).

## 결과

- **이름이 있어야 할 곳에만 있다.** 서술에서는 자리 이름과 겹쳐 모호했고, 값에서는 겹치지 않는다.
- **한정어가 없어진다.** 어휘가 하나 준다 — `key`·`value`·`as_of` 셋으로 값이 서술된다.
- **`kind` 를 안 받는다.** 「값이라고 했는데 값이 없는」 행이 구조적으로 안 생긴다.
- **시점이 이름에서 떨어진다.** 프롬프트가 아니라 코드라 회차마다 안 흔들린다.
- **마이그레이션이 없다.** `key`·`norm_key` 는 `d9a4e17c6b52` 가 이미 nullable 로 내렸고 `value`·`qualifier` 는 원래 nullable 이다. `qualifier` 는 **컬럼만 남고 트랙 A 가 안 쓴다.**
- **포기하는 것 ①** — **다르게 쓰인 같은 서술은 여전히 둘로 선다.** 값 쪽은 이름+값으로 접히지만 서술 쪽은 묶을 근거가 없다. 문장 유사도를 쓰면 비결정론이라 안 쓴다.
- **포기하는 것 ②** — **이름이 갈리면 값도 안 접힌다.** `매출액` 과 `직전연도 매출` 은 같은 값이어도 다른 이름이라 두 행이다. 접힌 것이 확인된 건 **이름이 자명한 것들**(`법인명`·`대표자`·`소재지`)이고 그것이 25 → 11 을 만든 실체다.
- **안 풀리는 것** — **트랙 B 와의 중복.** `Company/회사소개` 11건이 매칭 정보 열다섯과 같은 것이다. 접히긴 해도 **같은 사실이 두 표에 남고 값이 어긋날 수 있다**([ADR-0056](0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md) 「포기하는 것 ②」). 진짜 답은 그 자리를 트랙 B 값으로 **그리는** 것이고(뽑지 않아도 화면에 낼 수는 있다) 그건 `read_nodes` 에 「가상 자리」가 필요해 이번 회차 밖이다 — [plan/23](../plan/23-자리표를-기획-트리로-고정한다.md) T-0148.

**①→② 가 이 ADR 의 근거다.** 검토 대기는 버그라 고치니 0 이 됐고 **한정어는 안 움직였다** — 프롬프트로 못 막는다는 뜻이다.

**②→③ 이 「칸을 다 없애면 된다」를 기각했다.** 이름은 사라졌지만 회사소개가 11 → 25 가 됐고, 값만 살리면 `Company/팀` 의 경영 1명·운영 1명이 서로를 지운다.

**④ 가 이 결정을 적용한 회차다.** 노린 것이 걸렸다.

```
2024-12-31   매출액   24100000     2024년 매출액은 2,410만원이다.
2025-12-31   매출액   86400000     2025년 매출액은 8,640만원이다.
                ↑ 같은 이름 · 시점이 가른다  →  한 자리에 이력으로 쌓인다

2026-01-31   경영 인원   1
2026-01-31   운영 인원   1          ← 값이 같은데 이름이 달라 안 접힌다
```

**남은 것 둘도 예상대로다.** `Financial/매출` 에 `매출` 과 `매출액` 이 따로 섰고(같은
값·같은 시점인데 이름이 갈렸다 — 「포기하는 것 ②」), `Company/회사소개` 26건이
매칭 정보와 겹친다(「안 풀리는 것」).
