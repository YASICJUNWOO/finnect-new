> 상태: 진행중 (2026-08-18) — **수집기는 있고 아직 안 돌렸다.** T-0048 완료, T-0049~T-0051 남았다
> 종류: 슬라이스 (F2-2 관통)
> 선행: [07](07-첨부-내려받기와-해독.md) — 내려받기·해독을 그대로 쓴다
> 근거: [2026-08-18 K-Startup 첨부 조사](../adr/evidence/2026-08-18-kstartup-첨부-조사.md)

**[07](07-첨부-내려받기와-해독.md)이 `안 하는 것`에 "K-Startup 첨부를 긁지 않는다. 상세 페이지 스크래핑은 별개 작업이다"라고 적고 넘겼다. 그 별개 작업이 이것이다.**

---

## 목표

```
공고 31,327건
  기업마당   1,538건 ( 4.9%)  ← 첨부 3,354건
  K-Startup 29,789건 (95.1%)  ← 첨부 0건        ← 이걸 채운다
```

**지금 우리가 보는 공고는 전체의 5%뿐이다.** 그리고 [CLAUDE.md](../../CLAUDE.md)의 함정이 **"평가 정보는 공고 본문에 0%"**라고 못 박았으므로, 나머지 95%는 **자격 요건도 양식도 작성 지침도 하나도 없는 상태**다. [plan/11](11-작성-항목-추출과-표시.md)이 만든 "낼 서류" 화면도 기업마당에서만 뜬다.

끝나면 이렇게 된다.

```
uv run python -m finnect.attach --scrape-kstartup   # 첨부 목록 (파일은 안 받는다)
uv run python -m finnect.attach --source kstartup   # 받고 해독. 07 의 코드 그대로
```

---

## 왜 지금인가

**막는 것이 없다.** 조사가 끝났고 기술적 불확실성이 없다 — 파서를 확정했고 다운로드도 확인했다. 남은 것은 시간과 디스크다.

그리고 **효과가 이 레포에서 가장 크다.** OCR([ADR-0030](../adr/0030-OCR은-rapidocr-로컬로-하고-검출은-server-를-쓴다.md))이 기업마당 공고 59건을 열었는데, 이건 **공고 29,789건**을 연다.

## 태스크

### T-0048 상세 페이지에서 첨부 목록 긁기

> **완료** (2026-08-18). `src/finnect/attach/kstartup.py` · CLI `--scrape-kstartup`.
> **아직 안 돌렸다** — 코드만 있다.

- **마감 공고는 `bizpbanc-deadline.do` 로 들어간다.** 실측 29,515/29,789(99.1%)가 마감이라 사실상 전부에 필요하다. 안 바꾸면 18KB 짜리 껍데기가 온다(첨부 0개)
- **파일명은 `file_bg` 의 `title` 에서 가져온다.** 링크 텍스트는 전부 `다운로드` 이고, `Content-Disposition` 은 CP949 를 ISO-8859-1 로 보내 깨진다
- **`fnPdfView` 는 미리보기라 첨부가 아니다.** 세면 개수가 두 배가 된다
- **껍데기와 '첨부 없음'을 구분한다.** 껍데기는 우리가 주소를 잘못 고른 것이고, 첨부 없음은 그 공고의 사실이다
- **재수집이 이걸 안 지운다** — `_flush` 의 삭제 대상이 "이번 적재에 첨부가 딸려 온 공고"로 한정되고 K-Startup 정규화기는 `attachments=[]` 를 낸다. `tests/test_attach_kstartup.py` 가 막아 둔다

### T-0049 전량 긁기

- **약 4.4시간.** 상세 페이지 응답 0.14초 + 예의 지연 0.2초 × 29,789건
- 모집중(274건)을 먼저 돈다. 지금 신청할 수 있는 공고가 제품에 먼저 필요하다
- **일 한도를 모른다.** 웹 페이지라 `X-RateLimit` 이 없다. **맛보기로 재고 나서 전량을 돌린다**
- 완료 조건: `attachment` 에 K-Startup 행이 쌓이고 껍데기 건수가 보고된다

### T-0050 내려받기와 해독

> **07 의 코드를 그대로 쓴다.** `attach.service.run()` 은 출처를 안 가린다.

- **약 59,578건 추정** (공고당 2.00개 × 29,789). 지금 3,354건의 **18배**
- **용량을 모른다.** 표본 1건이 191KB, 기업마당 평균은 610KB. **11GB~36GB 라 세 배 차이고 예산을 못 세운다** — 맛보기 200건으로 먼저 잰다
- 시간은 **약 9시간** 추정 (기업마당 3,354건 30분에서 비례)
- 포맷이 유리하다 — 표본에서 hwp 53% · pdf 30%. **절반 이상이 우리가 100% 읽는 포맷이다**
- **오류를 HTTP 200 으로 주는지 안 봤다.** 기업마당이 그랬다. `download.py` 의 HTML 판별이 그대로 걸리는지 맛보기에서 확인한다

### T-0051 커버리지 재측정

- [07 의 실측](../adr/evidence/2026-08-17-첨부-해독-실측.md)이 기업마당 3,354건 기준이다. 모수가 18배가 되면 **그 숫자가 근거를 잃는다**
- 포맷별 해독률을 다시 재고 evidence 를 새로 쓴다
- **공고 단위로도 센다** — "첨부를 하나도 못 읽는 공고"가 K-Startup 에서 몇 건인지

## 위험

- **일 한도가 미지수다.** 29,789회를 연속으로 때렸을 때 차단되면 전량이 멈춘다. 맛보기로 재고 나서 간다
- **용량을 세 배 범위로밖에 모른다.** 36GB 쪽이면 디스크를 먼저 봐야 한다
- **공고당 2.00개가 표본 15건이다.** 첨부가 몰린 공고가 있으면 총량이 크게 움직인다
- **HTML 구조가 바뀌면 조용히 0개가 된다.** 껍데기 판정(`MIN_RENDERED`)이 그걸 잡게 돼 있으나, 구조만 바뀌고 크기는 그대로면 못 잡는다
- **[plan/11](11-작성-항목-추출과-표시.md)의 숫자가 전부 바뀐다.** 문서 구간 7,415개와 공고 953/1,474 가 기업마당 기준이다
