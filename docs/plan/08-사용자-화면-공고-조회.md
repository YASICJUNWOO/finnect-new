## 정해 둔 것 (2026-08-17)

| 무엇 | 어떻게 |
|---|---|
| **`admin/`** | **토큰만 입힌다. 구성은 그대로다.** 표·사이드바·행 버튼을 카드로 바꾸지 않는다 |
| 사용자 화면 | **새 앱으로 만든다.** `src/finnect/web/`. admin과 템플릿을 공유하지 않는다 |
| 목록 형태 | 시연의 **'전체 공고' 행 형태**를 쓴다. 카드 3열은 추천용이고 우리는 추천이 없다 |
| **데이터가 없는 자리** | **자리를 놓고 "아직 없어요"로 버틴다.** 레이아웃은 시연과 같게 두고 빈 화면 카피를 넣는다 |
| 예시 데이터 | **안 쓴다.** 근거 없는 값을 화면에 두지 않는다 |

**"아직 없어요"로 버티기로 한 것이 이 계획의 성격을 정한다.** 지금 채울 수 있는 것은 개요와 첨부뿐이고 나머지는 전부 빈칸이다. 화면이 미완성으로 읽히는 것을 받아들인다 — **가짜 값으로 완성돼 보이는 것보다 낫다.**

### admin에 무엇을 하고 무엇을 안 하는가

**두 문서를 동시에 어기지 않으려면 선을 그어야 한다.**

- CLAUDE.md는 `admin/`이 **"`DESIGN.md` 토큰을 따르지 않는다"**고 적었다. **이 문장을 뒤집는다.** T-0023과 같은 커밋에서 고친다
- `DESIGN.md` §5.4는 **사이드바 + 표 머리글 + 행 체크박스 + 도구 막대 + 행마다 채워진 버튼** 조합을 금지한다. **이건 제품 화면 기준이고 admin은 예외다.** §5.4 본문이 그 이유를 적었다 — 금지의 근거는 "대체하려는 화면(기업마당)과 닮으면 안 된다"이고, admin은 대체 대상이 아니라 우리 관찰 도구다

| admin에 하는 것 | admin에 안 하는 것 |
|---|---|
| 색·타입·간격·반경 토큰 | 표를 카드로 바꾸기 |
| 포커스 표시 (§3-9 · §7-1) | 내비게이션 구조 변경 |
| `tabular-nums` | 컬럼 늘리고 줄이기 |
| 해요체? **아니다** — 아래 참고 | 기능 추가·삭제 |

**admin 카피는 해요체로 안 바꾼다.** `DESIGN.md` §8.0이 "화면 카피는 해요체"라고 한 대상은 **창업 3년 이내 사업자**다. admin을 보는 사람은 우리다. 지금 문체를 유지한다.

- **`admin/`의 구성과 기능을 안 바꾼다.** 토큰만 얹는다. 위 표 참고
- **사용자 앱에 수집 화면을 만들지 않는다.** 사용자가 수집을 돌리지 않는다. 시연 8화면에도 SPEC S1~S7에도 없다. **수집 화면은 admin 쪽에 이미 있고 거기서 토큰만 입는다**

- **배점을 화면에 두지 않는다.** 시연에 `25 / 25 / 30 / 20`과 "이 공고는 지역 연계 계획에 30점을 줘요. 네 항목 중 배점이 가장 커요"가 있는데 [ADR-0019](../adr/0019-집필의-축을-양식으로.md)와 정면으로 어긋난다. **옮기지 않는다**
- **적합도순 정렬을 만들지 않는다.** 순서를 정할 근거가 없다
- 위키 그래프(S2), 문서 집필(S6), 신청 현황 칸반(S7)

### T-0023 운영 도구에 토큰 입히기

- 상태: **완료** (2026-08-17) — [ADR-0027](../adr/0027-운영-화면을-nextjs로-옮긴다.md)
- 선행: T-0018

**옮기면서 입혔다.** 아래 계획은 "Jinja2 템플릿의 인라인 값을 토큰으로 간다"였는데, 실제로는 화면 넷이 `web/app/admin/`(Next.js)으로 갔고 거기서 토큰을 처음부터 썼다. **완료 조건은 그대로 다 만족한다** — 다만 검사 대상 경로가 `src/finnect/admin/templates/`가 아니라 `web/app/admin/`이다.

**왜 옮기게 됐는가는 이 계획의 몫이 아니다.** 배포본에서 운영 화면이 안 열리는 것이 문제였고 근거는 ADR-0027에 있다. 여기서는 "토큰이 목업 없이도 서는가"라는 이 태스크의 질문에만 답한다 — **섰다.** `/admin/ingest`는 시연에 대응 화면이 없는데 나머지 셋과 같은 물건으로 보인다.

`admin/` 세 화면(`/notices` · `/ingest` · `/attachments`)에 **토큰만** 얹는다.

**왜.** 지금 admin 스타일은 `base.html`에 인라인으로 박힌 임시값이다(`#0645ad` 링크, `#ccc` 경계선). 색이 제각각이라 **첨부 해독 상태 배지 다섯을 눈으로 가르기 어렵다.** 토큰이 생기면 그 구분이 규칙을 갖는다.

**수집 화면(`/ingest`)에는 대응하는 목업이 없다.** 시연 8화면에 수집이 없어서다. **베낄 것이 없으므로 토큰 규칙만으로 짠다** — 그래서 이 화면이 "토큰이 목업 없이도 서는가"를 시험한다.

**완료 조건**

- 인라인 임시값(`#0645ad` · `#ccc` · `#767676` 등)이 **전부** 토큰으로 바뀐다
- 상태 배지(`ok` · `empty` · `unsupported` · `failed` · `container`)가 **상태색 팔레트 안에서** 갈린다. 노드 분류색을 쓰지 않는다(§4.1)
- 포커스 표시가 세 화면 전부에 있다. **표가 길어 위치를 잃는 것이 §3-9의 이유다**
- 금액·건수·날짜에 `tabular-nums`
- **구성이 안 바뀐다.** `git diff`에 라우트·쿼리·템플릿 구조 변경이 없다
- CLAUDE.md의 "`DESIGN.md` 토큰을 따르지 않는다"를 **같은 커밋에서** 고친다

**건드리는 것** — `src/finnect/admin/templates/`, `CLAUDE.md`, `README.md`
