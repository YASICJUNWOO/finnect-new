### T-0125 저장을 노드 트리로 옮긴다

- `wiki_node` 신설 — `(company_id, path)` 유니크 · `category` · `name` · `parent`

### T-0126 추출을 트랙 둘로 가른다 — **완료** (2026-08-22)

- `extract.py` → `extract_nodes.py`(A) · `extract_profile.py`(B). 포트는 [ADR-0031](../adr/0031-사실-추출을-포트-뒤로-미루고-스텁으로-배관을-먼저-세운다.md) 그대로이고 **셋이 남는 자리를 `port.py` 가 받았다** — `FileView` · 앵커 규칙 · 갈라짐 장치
- **A 스키마** — `node_ref | node_category + node_path` · `key_ref | key_new` · `qualifier_ref | qualifier_new` · `kind` · `value`/`text` · `anchor`. **`node_new` 를 중첩 객체로 안 받고 두 칸으로 폈다** — `strict: true` 에서 nullable 중첩 객체를 제공자가 받아 주는지가 불확실하고 틀리면 호출 전체가 400 이다
- **B 스키마** — `key`(enum 14) · `value` · `as_of` · `qualifier` · `anchor`. **`ALIASES` 가 라우팅에서 빠지고 프롬프트 힌트로만 남았다** — 이 한 줄이 [ADR-0056](../adr/0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md) 맥락 ②(값 이름이 사전이 되어 간다)를 끝낸다
- **anchor 규칙은 안 바뀌었다.** 원문에서 그대로 복사 · 못 찾으면 버리고 센다
- **라우팅 단계가 통째로 없어졌다.** `merge.place`·`Placement`·`tree.EVENT_PATH` 를 지웠다 — 추출기가 자리를 알고 나온다. 옛 표는 `extract_nodes.FIXTURE_PATH` 로 **스텁 전용 번역표**가 됐다(`facts.json` 이 옛 어휘로 적혀 있고, 앵커 118개가 원문에 박혀 있어서 그 표를 다시 쓰면 정답지가 정답지가 아니게 된다)
- **트랙 A 에 값 사실이 생겼다**(`wiki_fact.kind == "value"`). `restate` 가 `(노드, key, 한정어, 시점)` 으로 상태를 매긴다 — 노드를 안 끼우면 트리 어디에 있든 이름만 같으면 서로를 밀어낸다
- **마이그레이션이 없다.** 스키마를 안 건드렸다

### T-0127 갈라짐을 막는다 — **완료** (2026-08-22)

- 프롬프트에 **현재 노드·key·한정어를 번호로** 준다(`port.Roster`). 경로를 다시 쓰게 하지 않는다. 번호는 **1부터** — 0 이면 「없음」과 「첫째」가 JSON 에서 구분이 안 된다
- 코드 그물 — 정규화 정확 일치(`Roster.fold`). **부를 때마다 목록이 자라서 같은 호출 안에서도 걸린다.** 노드는 마디마다(`tree.norm_path`), key·한정어는 통째로(`tree.norm`)
- **없는 번호는 지어내지 않는다.** 범위 밖이면 새 이름 쪽으로 떨어지고, 그것도 없으면 `Custom/검토 대기` 다
- **유사도를 안 쓴다.** `tests/test_wiki_roster.py` 마지막 절이 그 결정을 잠근다 — `기능` 과 `주요기능` 은 다른 자리다
- 트랙 B 는 key 가 enum 이라 번호 장치가 없다. **자유 문자열이 `qualifier` 하나뿐이라 거기만 접는다**

### T-0128 계측 — 신규 노드 수를 센다 — **완료** (2026-08-22)

**이걸 빼면 위키가 갈라지는 걸 볼 방법이 없다.** 사용자는 노드가 셋인 게 정상인지 모른다.

- 회사 총계 — `BuildReport.nodes_new` · CLI 「노드 N개 (새로 만든 것 M개)」
- 파일마다 「새로 만든 노드 N · 기존에 붙인 것 M」 — `BuildReport.per_file` · CLI `[파일마다 트리에 한 일]`
- **총계만으로는 판정이 안 된다.** 파일 다섯을 한 번에 올리면 첫 파일이 트리를 세우고 나머지가 거기 붙는 것이 정상인데, 총계는 그것과 「다섯이 각자 제 트리를 세웠다」를 **같은 숫자로 보여 준다.** 뒤쪽 파일이 계속 새 노드를 만드는지는 파일별로만 보인다
- 「기존에 붙인 것」은 **이 파일이 사실을 얹은 노드 중 이미 있던 것**만 센다. 새로 만든 몫에는 조상이 포함된다 — `Custom/특허/등록-10-2025` 하나가 노드 셋을 세우고 그게 「트리가 자랐다」의 실제 크기다
- **회사마다 노드 수 추이는 안 만들었다.** 빌드마다 행을 남길 자리가 없고, 그걸 만드는 것은 `ingest_run` 같은 운영 기록 표를 하나 더 세우는 일이다 — T-0133 이 「얼마나 갈리는지 보고」 정하기로 한 것과 같은 자리라 거기서 같이 정한다

### T-0130 그래프를 방사 트리(마인드맵)로

**궤도·링·구획 호를 걷어낸다.** 저것들은 깊이가 둘로 고정일 때만 성립한다.

```
        중심(회사)
           │
   ┌───┬───┼───┬───┐        카테고리 열. 각도 구간을 갖는다
 회사  제품 시장 …  기록
   │       │
  팀      기능                노드
   │
 (하위)                       깊이 제한 없음
```

- **간선이 보인다.** 부모 → 자식 곡선. 그게 마인드맵이고, 지금 구조가 실제로 트리다
- 카테고리 각도 폭은 **제 아래 잎 수에 비례한다** — `Plan` 이 자라면 넓어진다
- 카테고리 열은 **비어도 뜬다**(`DESIGN.md` §7-5)
- **점마다 이름이 붙는다.** 가지를 따라 라벨이 퍼져서 47개가 들어간다 — 한 링에 몰면 26px 간격이라 못 붙였다
- 색을 안 쓴다. 상태는 채움·선·크기로만

## T-0132 를 검수하다 나온 것 다섯

트랙을 가르면서 **아래쪽이 트랙 B 를 못 보게 됐다.** T-0132 가 `match/` 쪽만 `company_value` 로 잇고 `draft/` 와 진행 화면은 트랙 A 만 읽는 채로 남았다. 아래 다섯은 그 검수에서 나왔다(2026-08-22).

**넷이 같은 모양이다** — 트랙 B 를 안 읽거나 안 세는 자리. 그리고 **전부 오류가 아니라 빈칸으로 나온다.**

### T-0134 집필이 매칭 정보 열넷을 못 읽는다 — **완료** (2026-08-22)

**조용히 틀린다.** 오류가 안 나고 「위키에 없어요」가 뜬다 — 사용자는 파일을 더 올리려 든다.

배관이 세 자리에서 어긋나 있다.

| 자리 | 지금 하는 일 |
|---|---|
| `draft/needs.py` `PLACES` | 매칭 정보 14 + 카테고리 10 → **LLM 이 `headcount` 를 고를 수 있다** |
| `wiki/build.py` | `spot.kind == "value"` 면 `company_value` 에만 넣고 **`continue`** — `wiki_fact` 에 안 앉는다 |
| `draft/service.py` `_company_facts` | `WikiFact ⋈ WikiNode` 만 읽는다 → `place` 가 **항상 노드 경로** |

`allot._index` 의 키가 노드 경로의 조상들이라 `headcount` 는 **구조적으로 안 나온다.** 재현했다 — `company_value` 에 직원 수 15를 넣고 `item_need.place="headcount"` 로 돌리면 `missing=['headcount']` · `status=blank` 다. **열넷 전부가 영구 「못 채움」이고**, [ADR-0028](../adr/0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md)의 질문 목록이 위키에 이미 있는 값을 계속 묻는다.

- `_company_facts` 가 `CompanyValue` 도 읽어 `wr.FactMaterial` 로 합친다. 근거는 `value_evidence` 에서 온다. **`place` 가 경로가 아니라 key 라** `allot._index` 가 마디 하나짜리 경로로 그대로 받는다
- **재료 id 를 한 공간으로 합쳤다**(`draft/refs.py`). 배분·집필 스키마가 둘 다 `{"type":"integer","enum":[...]}` 이고 모델이 고른 것이 `draft.allotment` 에 앉는다 — 표 둘 다 1부터 시작하는 자동증가라 그냥 섞으면 `#3` 이 어느 표인지 모른다. **트랙 B 는 부호를 뒤집는다.** 상수를 더하지 않는 이유는 언젠가 그 경계를 넘고 **넘는 날 조용히 틀리기** 때문이다 — 부호는 넘을 수 있는 경계가 아니다
- **값을 근거로 들 자리가 없었다.** `draft_evidence.fact_id` 가 `wiki_fact.id` 를 **NOT NULL FK** 로 든다 — 문단이 `company_value` 를 인용하면 적을 곳이 없고, 그러면 ADR-0028 4번의 파급 계산이 값 쪽에서 안 돈다. **나중에 붙일 수 없다**(ADR-0014). `draft_value_evidence` 를 세웠다(`e2d5a71c0f43`) — **표를 나눈 이유는 ADR-0056 이 `wiki_evidence`/`value_evidence` 를 나눌 때와 같다.** **배포 DB 에도 돌려야 한다**
- **값에 라벨을 붙여서 넣는다.** 저장값(`120000000`)만 주면 집필이 단위를 지어낸다. 단위를 붙이는 자리는 `profile.display()` 하나이고, `api/draft_service.py` 가 근거 줄에 **같은 모양**을 낸다 — 다르면 집필이 읽은 문장과 화면이 보여 주는 문장이 갈려 근거 대조가 눈으로 안 된다
- **`conflict` 도 재료로 보낸다.** 트랙 A 와 같은 규칙(`superseded` 만 뺀다)이다. 여기서 하나를 고르면 **고른 근거가 어디에도 안 남는다** — 충돌은 화면이 물어볼 자리다(T-0131)
- **`PLACES` 에서 열넷을 빼는 길을 안 골랐다.** 사업계획서 항목이 직원 수·매출·소재지를 실제로 요구한다 — 빼면 집필이 그것들을 영영 못 쓰고, T-0131 의 「빈 칸이 물어볼 자리다」와도 어긋난다
- 테스트 `Test매칭_정보` 넷. **`tests/test_draft_service.py` 의 `_PATH` 가 노드 경로만 다뤄서 이 길을 한 번도 안 밟았다** — 그래서 결함이 테스트 150개 통과 상태로 살아 있었다. 「값이 없으면 그때는 못 채움이다」를 같이 잠근다(반대쪽을 안 잠그면 「항상 채워짐」으로 고쳐도 통과한다)

- `f4b8c02e91d7` 이 옛 이름 → 카테고리로 옮긴다. **배포 DB 에도 돌려야 한다**
- **표를 손으로 안 짰다.** 옛 `TOPIC_ORBIT` 과 새 `FIXTURE_PATH` 를 topic 으로 합성해 뽑았다 — 손으로 짜면 열 줄 중 하나를 조용히 틀린다
- **셋이 카테고리 둘로 갈린다**(`solution`→Product·Custom · `market`→Market·Competitor · `traction`→Financial·BusinessModel). **한 행을 둘로 편다** — 하나만 고르면 「솔루션과 기술」을 요구했던 항목이 기술·특허·인증을 통째로 못 받는다. **재료를 잃는 쪽이 넓어지는 쪽보다 나쁘다**(넓어진 대가는 T-0136 이 잰다)
- **갈아 끼우지 않고 넣고 지운다.** `UPDATE ... SET place='Product'` 는 같은 항목이 이미 `Product` 를 요구하고 있으면 `(document_item_id, place)` 유니크에 걸려 **마이그레이션 전체가 죽는다** — 옛 어휘와 새 어휘가 한 항목에 섞여 있는 것은 드문 일이 아니라 양식을 두 번 읽었으면 나오는 정상 상태다. 실측에서 이 경계를 바로 밟았다
- **되돌리지 않는다.** 한 행이 둘이 된 것을 다시 하나로 접으면 어느 쪽이 원래였는지 알 방법이 없다 — 옛 orbit 이름이 어디에도 안 남는다
- **다시 읽히는 길을 안 골랐다** — `needs_decided_by` 를 비우면 LLM 을 양식 수만큼 다시 부른다. 배포 DB 의 양식이 몇 건인지 모르는 상태라 비용이 미지수다
- 값 키 열넷은 **이름이 하나도 안 바뀌었다**(옛 `VALUE_SPECS` 와 새 `PROFILE_KEYS` 의 대칭차 0). 옮길 것이 없다
- `_label()` 폴백이 **영어 키를 그대로 화면에 냈다**(「solution」이 한국어 라벨 자리에). 이 함수의 요점이 「우리가 한국어를 짓지 않는다」인데 폴백이 영어를 내면 그 문장이 거짓이 된다 — `UNKNOWN_PLACE` 로 바꿨다. **노드 경로(`Financial/매출`)는 그대로 낸다** — 마디 이름을 추출기가 한국어로 짓고, 그 경로가 곧 사용자가 위키에서 보는 자리 이름이다

### T-0136 자리가 뭉툭해진 대가를 잰다

옛 orbit 10 과 새 카테고리 10 이 **개수만 같고 뜻이 안 대응한다.**

```
problem + customer          → Customer      문제 인식 · 목표 고객
identity + team + region    → Company       우리가 하는 일 · 팀 구성 · 지역 연계
traction + finance          → Financial     매출과 성과 · 자금 현황
```

옛 열 중 일곱이 셋으로 접혔고 나머지 셋(`solution`·`market`·`roadmap`)만 일대일이다. **문제를 쓰라는 항목과 고객을 쓰라는 항목이 이제 같은 자리를 가리킨다.**

`allot._index` 가 사실을 조상 전부에 걸어 두므로 `Customer` 한 자리로 `Customer/*` 가 **통째로 딸려 온다.** 재료가 넓어지고 겹침 다툼이 는다. T-0132 가 의도한 것이지만 **집필 품질이 어떻게 변했는지는 안 쟀다.**

- 같은 양식·같은 회사로 **항목당 재료 사실 수**와 **다툰 쌍 수**를 옛 구조와 대조한다
- **육안 없이 안 쓴다**(CLAUDE.md 규칙). 몇 건을 읽었는지 같이 적는다
- 넓어진 것이 해로우면 고르는 길은 둘 — `item_need` 가 **깊이 2 까지** 가리키게 하거나(그러면 회사마다 다른 경로 문제가 돌아온다), `_index` 가 조상에 안 걸고 **가장 가까운 카테고리에만** 걸거나

### T-0137 옛 어휘 잔여물과 안 도는 테스트 — **완료** (2026-08-22)

한때 **`uv run pytest` 가 collection 에서 죽었다** — 이 계획의 검증 첫 줄이 실행이 안 됐다.

- 안 도는 테스트 다섯(`wiki/topics.py`·`WikiPlace` 임포트 · `NODE_RANK` 옛 이름)은 T-0126 회차에서 닫혔다
- 독스트링 다섯이 지워진 모듈을 가리키던 것을 고쳤다 — `models.py` `ItemNeed` · `draft/needs.py` · `draft/allot.py` · `api/wiki_schemas.py`
- **`draft/write.py` 가 프롬프트에 경로를 내는 것을 그대로 뒀다.** 라벨이 아니라 자리 이름이고 `[Customer/고객문제]` 는 사람이 읽을 수 있다. **재료 id 가 음수로도 나온다**(`#-3` · T-0134) — 스키마 enum 이 같은 정수라 모델이 고를 것이 흔들리지 않는다
- **`item_need.place_kind` 를 안 지웠다.** `slot`·`node` 는 이미 `a1e0c7d4f2b9` 가 `value`·`event` 로 옮겼고, 남은 문제는 **아무도 안 읽는다**는 것뿐이다(쓰는 곳이 `draft/service.py` 하나). 컬럼을 지우는 것은 마이그레이션 하나 값이 없어서 **주석에 「안 읽는다」를 적어 두는 것으로 갈음한다**
- **`eligibility` 를 `match/` 로 안 옮겼다.** ADR-0056 이 그러라고 적었는데 **위키 화면도 「자격 판별에 써요」 배지에 읽는다** — `match/` 에 두면 `wiki` 가 `match` 를 임포트하게 되고 방향이 거꾸로다. 이유가 `wiki/profile.py` 에 적혀 있다

### T-0138 진행 화면이 트랙 B 를 안 센다 — **완료** (2026-08-22)

**T-0134 와 같은 모양이 화면 쪽에도 있었다.** `fact_count` 가 `wiki_evidence` 만 세고 `spots` 가 트랙 A 노드 경로만 담는다. 그래서 **매칭 정보만 낸 파일이 「사업 정보를 못 찾았어요」가 된다**(`progress.EMPTY_LABEL`).

사업자등록증이 정확히 그 파일이다. 실측 `c_dasiro` —

```
사업계획서_2026_초기창업    A=22  B=14
사업자등록증_스캔.pdf       A= 0  B= 7     ← 「못 찾았어요」로 떴다
피치덱_2026H2.pptx          A=15  B= 5
회사소개서_v3.pdf           A=14  B= 8
```

CLAUDE.md 가 「자격 판별 입력 다섯 중 넷이 여기서 나온다」고 적어 둔 파일인데 화면이 아무것도 못 찾았다고 말한다. **[T-0095](15-파일-올리기와-진행-표시.md)가 닫은 증상이 트랙이 갈리면서 이 경로로 돌아왔다.**

- `fact_count` 가 트랙 둘을 더한다. 사용자에게는 「이 파일에서 몇 개가 나왔나」 하나이고 **어느 표에 앉았는지는 우리 사정이다**
- `empty` 판정이 `not made and not got_values` 다. **트랙 B 는 트리에 자리가 없어서 `spots` 로는 못 센다** — 칸 수로 대신 센다
- `spots` 는 그대로 트랙 A 다. `build.read_files` 의 뜻(「그 파일이 채운 노드」)을 안 바꾼다 — 바꾸면 S1 과 S7 이 같은 자리를 다르게 부른다

### 2 가 스텁으로는 반쪽이다 (2026-08-22)

**스텁은 고정 표를 돌려주므로 갈라질 수가 없다.** 위 27·0·0 은 배관이 붙었다는 뜻이지
「이름이 안 갈린다」는 뜻이 아니다 — 갈라짐은 LLM 이 만들고, 그건 실제 회사 코퍼스를
한 벌 돌려야 나온다. `--score` 도 못 잰다(정답지가 파일끼리 서로를 모르는 채로 채점돼서
`Known` 이 늘 비어 있다).

대신 **진짜 제공자로 한 벌 돌려 눈으로 봤다.** 파일 하나(직접 만든 6줄) · 호출 둘 ·
사실 8건 전부 육안. `gpt-5.6-luna` 로 불렀고 **응답의 실제 모델 ID 는 안 적었다** —
`llm.Client` 가 그걸 안 돌려준다. 다음 실측 전에 고칠 자리다.

- **`strict: true` 스키마 둘이 통과했다.** 여기가 가장 큰 미지수였다 — nullable enum과
  정수 ref 가 섞여 있어서 틀리면 호출 전체가 400 이고, 그건 배포에서만 터진다
- **번호 장치가 실제로 돈다.** `Known` 에 `Company/팀`·`Product/기능`·`팀 구성` 을 주니
  모델이 **새 경로를 안 만들고 `node_ref`·`key_ref` 로 답했다.** 사실 5건이 전부 그 둘에
  앉았고 신규 노드가 0 이었다
- **트랙 B 가 열넷 안에서만 나왔다** — `company_name`·`founded_on`·`headcount` 셋
- **버린 것 0.** 앵커가 여덟 다 원문에 있었다

눈으로 본 것 중 **이번에 안 고친 것 둘**을 적어 둔다.

- **같은 값이 두 트랙에 따로 나왔다.** 개업일과 직원 수가 트랙 A 의 `Company/팀` 에도
  앉고 트랙 B 에도 앉았다. [ADR-0056](../adr/0056-위키를-동적-노드-트리로-바꾸고-매칭-정보를-따로-뽑는다.md)
  「포기하는 것 ②」가 이미 인정한 것이고 **줄이는 길도 거기 적혀 있다**(B 를 먼저 돌려
  그 결과를 A 프롬프트에 넣는다). 표본 하나로 그 배관을 붙이지 않는다
- **번호 장치가 과하게 끌어당긴다.** 직원 수 15명이 기존 key `팀 구성` 에 붙었다 —
  갈라짐을 막으라고 준 목록이 **뜻이 다른 값을 기존 이름으로 끌어들였다.** 대가가
  갈라짐보다 큰지는 표본 하나로 모른다. 실제 코퍼스를 돌릴 때 이 축을 같이 본다

**7 을 반드시 본다** — 자격이 달라지면 사용자가 보는 공고 목록이 달라진다. [ADR-0013](../adr/0013-판정-두-층.md) 이 「자격은 결정론」이라고 한 자리이고, 트랙 B 로 옮기면서 그게 깨졌는지는 **옛 결과와 대조해야만** 안다.

**8 이 없으면 T-0134 가 다시 난다.** 지금 이 결함은 테스트 150개가 전부 통과하는 채로 살아 있었다 — **집필이 트랙 B 를 한 번도 안 밟아 봐서**다. 배관이 붙었나가 아니라 **값이 실제로 문단에 들어갔나**를 본다.
