## 할 것

### F5 공고 분석 (S3)

이 제품의 승부처다. 결론 3줄을 먼저 띄우고 근거는 접는다.

입력으로 쓸 수 있는 것(실측 확인):

| 확보되는 것 | 초기창업패키지 실측값 |
|-------------|----------------------|
| 평가 항목 이름 | 문제인식 · 실현가능성 · 성장전략 · 팀(기업) 구성 |
| 항목별 평가 관점 | "사업기간 내 개발 또는 구체화 계획 등" |
| 양식 목차·세부항목 | 별첨1 전체 |
| 분량 제한 | 15페이지 내외 |
| 커트라인 | 단계별 60점 |
| 가점 | 최대 3점 |
| 평가 단계 | 서류 → 심층인터뷰(30분) → 발표 |
| **배점** | **없음** |

### F6 내용 채우기 (S4)

F5-5가 특정한 부족 정보만 묻는다. 질문마다 어느 심사 항목에 쓰이는지 붙인다.

**답변은 즉시 F1-2 집필용 정보에 저장한다.** 다음 공고에서 다시 묻지 않는다.

### F7 초안 작성 (S5)

| 요구 | 내용 |
|------|------|
| F7-2 | 첫 출력까지 5초 이내. 스트리밍 |
| F7-3 | **사실 고정.** 금액·자격·마감일은 L1 값만 쓴다 |
| F7-5 | 사용자가 고친 문단은 재생성해도 덮지 않는다 |
| F7-7 | 분량 카운터. 공고 제한 대비 현재 분량 |

**F7-3이 이 단계의 핵심이다.** 프롬프트로 지시하는 것이 아니라 L1 근거 구간을 컨텍스트에 넣고 그 밖의 수치를 못 쓰게 한다([ADR-0002](../adr/0002-3계층-분리.md)).

검증 방법을 함께 만든다 — 생성문에 나온 금액·날짜가 L1에 존재하는 값인지 자동으로 대조한다.

### F8 문서 산출 (S6)

미리보기 → 누락 항목 알림 → 책임 고지 → PDF.
