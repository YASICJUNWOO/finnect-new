# 내 사업 위키(S7) — 무엇을 노드로 그리고, 근거를 어디에 둘 것인가

`/wiki` 재설계 하네스. **축이 둘이고 각 축에서 갈리는 것은 하나씩이다.**

```
open index.html      # 나란히 — 축소 프리뷰 · 논지 · 대가
open switch.html     # 실제 크기로 갈아끼우기
```

각 화면 하단의 검은 바는 **목업 전용이다.** 코드로 옮길 때는 바를 뺀다. 노브가 셋이다.

| 노브 | 값 | 어디에 |
|---|---|---|
| 밀도 | 일곱 장(근거 117) · 두 장(근거 29) | 열한 장 전부 |
| **재질** | 평면 · 발광 · 구체 · 유리 · 링 | G 다섯 |
| **색** | 종류 셋(§2) · 구획 여섯 · 단색+강조 | G 다섯 |

**재질과 색은 시안과 직교한다.** 시안 다섯 × 재질 다섯 × 색 셋 = 조합 75가지를
파일 다섯으로 본다. 시안을 스물다섯 개로 늘리지 않는 이유이고, 하네스가 원래
이런 것을 위해 있다.

껍데기는 `docs/design/mockup/notice/r-adaptive.html` 이 확정한 것을 그대로 쓴다 —
레일 60px + 상단 2단(≥1024px) · 상단 1단(<1024px) · 운영 도구 숨김(≤640px).
값은 `web/app/tokens.css` 를 **직접 링크한다.** 그래야 「적용」이 판단이 아니라 전사가 된다.

## 축 둘

| | 갈리는 것 | 고정된 것 |
|---|---|---|
| **G** 그래프 다섯 | 무엇을 노드로 그리는가 | 패널이 전부 현행(`current.js`) |
| **P** 패널 다섯 | 근거를 어디에 어떻게 두는가 | 궤도가 전부 현행(`current.js`) |

**둘 다 바꾼 시안은 없다.** 무엇 때문에 좋아 보이는지 분간이 안 된다.

### 재질은 시안이 아니라 노브다 — 한 번 틀렸던 자리

**처음엔 다섯이 전부 평면 원 + 종류색 셋이었다.** 축을 하나로 묶으려고 재질을 고정
변인으로 둔 것인데, **원래 물음이 「노드 퀄리티가 떨어진다」였으므로 그건 축을 잘못
고정한 것이다.** 개수만 갈리고 생김새는 현행 그대로면 물음에 답을 안 한 셈이다.

시안을 다섯 배로 늘리는 대신 **노브 둘로 뺐다**(`materials.js`). 재질과 색은 어느
시안에도 얹히므로 시안 축과 직교하고, 그래서 「G2 를 고르되 구체로」 같은 조합이
파일을 안 늘리고 나온다.

**색조 하나에 뜻 둘을 얹지 않는다는 §2 규칙은 재질을 바꿔도 그대로다.** 빈 자리와
충돌은 여전히 형태와 개수로 말한다 — **재질은 「무엇인가」를 안 말하고 「얼마나
도드라지나」만 말한다.** 그래서 재질을 상태에 쓰면 안 되고, `materials.js` 가
빈 자리를 재질과 무관하게 점선 원으로 그리는 이유가 이것이다.

대조군은 `base.html` 이고 `web/components/Orbit.tsx` · `WikiPanel.tsx` 의 재현이다.
**값을 하나도 안 바꿨다** — 알고 있는 결함 둘(빈 자리 이름표 AA 미달 · 구획 라벨이 바깥에만
있음)도 그대로 뒀다. 고치면 대조군이 현행이 아니게 된다.

### 왜 「재질」이 아니라 「무엇을 노드로 그리는가」인가

레퍼런스로 받은 화면 셋의 공통점은 재질이 아니라 **개수**였다 — 2,387 · 70 · 50.
현행은 자리 15개를 그리고 근거 117개를 클릭 **두 번** 뒤에 숨긴다. 구체로 그리든
유리로 그리든 15개는 15개라 저 인상이 안 나온다. 그래서 축을 개수 쪽으로 잡았다.

레퍼런스에서 가져온 것 셋 — **선택적 라벨링**(중요한 것만 이름, 나머지는 점) ·
**거의 안 보이는 에지** · **좌측 패널이 범례가 아니라 카운트 달린 조작기**.
안 가져온 것 하나 — 이미지 2의 **구획 6색**은 §2 의 「종류 셋」을 뒤집는다. G2 에서만
노브로 재 보고 나머지는 셋을 지킨다.

## 데이터 — 지어낸 값이 없다

`tests/fixtures/wiki/facts.json` 118건을 `src/finnect/wiki/topics.py` 의 라우팅
(`SLOT_ALIASES` · `TOPIC_NODE` · `ORBIT`)으로 자리 열다섯에 앉혔다. 전부 `tests/fixtures/wiki/`
의 실제 파일에 적힌 문장이고 `anchor` 는 그 파일의 해독 텍스트에 그대로 있다
(`tests/test_wiki_extract.py` 가 118개를 하나씩 막는다).

```
사실 118  →  자리 배치 117 · 못 찾음 1
표시 단위 47 (슬롯 값 17 + 문장 30)  ·  근거 117  ·  파일 7
쪽 번호가 붙은 근거 42 — 실제로 파싱해서 얻었다. PDF·PPTX 에만 있다
```

**자리별 근거가 3~19 로 갈린다.** 이 6배 차이가 이 하네스의 출발점이다 —
현행은 도트 지름이 열다섯 다 15px 로 같다.

```
문제 인식 19 · 매출과 성과 13 · 자금 현황 13 · 사업자 정보 10 · 팀 구성 9
우리가 하는 일 8 · 지역 연계 8 · 업종 7 · 대표자 6 · 솔루션과 기술 6
소재지 5 · 로드맵 4 · 목표 고객 3 · 시장과 경쟁 3 · 수령 이력 3
```

**밀도가 문장이 아니라 근거에 있다.** 문제 인식은 문장 6개에 근거 19개이고,
문장 하나가 파일 넷을 근거로 든다(`fact_key` 가 묶는다 — 재구매율 34→51% 가 네 문서에
다른 문장으로 있어서 문자열로는 못 묶는다).

### 밀도 둘

| | 무엇 | 사실 | 자리 |
|---|---|---:|---|
| 무거움 | 일곱 장 전부 | 118 | 15/15 |
| 가벼움 | 등록증 + 회사소개서 | 29 | 10/15 |

**가벼움은 무거움의 부분집합이다.** 파일 둘로 좁힌 것이라 빈 자리 다섯(수령 이력 ·
목표 고객 · 시장과 경쟁 · 자금 현황 · 로드맵)은 지어낸 공백이 아니라 그 두 파일에
실제로 없는 것이다.

### 픽스처가 심어 둔 함정 넷 — 시안이 이걸 어떻게 그리는지가 판단 기준이다

1. **직원 수가 넷이다** — 7 → 8 → 10 → 15. 이름이 전부 다르다(상시 근로자 · 종업원 수 ·
   구성원 · 임직원). 시계열이지 충돌이 아니다.
2. **마지막 직원 수 15의 `as_of` 가 2026-08-31 이다.** 오늘(2026-08-21)보다 열흘 뒤다 —
   `current` 는 「가장 늦은 시점」이라 **미래 날짜도 current 다.** 자격 판정은 신청일 이전의
   최신값을 골라야 하므로 화면이 이걸 숨기면 안 된다. P 시안 다섯이 전부 배지로 적는다.
3. **매출액에 진짜 충돌이 있다** — 24,100,000 과 86,400,000 이 둘 다 재무제표 2025-12-31
   에서 나왔다. 같은 슬롯 · 같은 시점 · 다른 값.
4. **`업력 1년 6개월` 은 갈 자리가 없다.** `topics.py` 가 일부러 슬롯에서 뺐다(공고마다
   기준일이 달라 개업일로 계산한다). `uncategorized` 로 서야 맞고, 실제로 헤더가 그렇게 센다.

### 손으로 맞춘 곳 하나

**스캔본 둘의 파서 메타를 OCR 기준으로 적었다**(`사업자등록증_스캔.pdf` ·
`현장사진_파일럿매장.jpg`). 이 파일을 만든 서버에 `uv sync --group ocr` 이 없어 파싱이
`empty`·`unsupported` 로 나왔는데 제품은 사용자 파일에 OCR 이 켜져 있다(ADR-0030).
안 맞추면 화면에 **「안 읽혔어요 · 근거 1」** 이라는 스스로 모순된 줄이 뜬다 — G5 에서
실제로 그렇게 나왔다. 나머지 다섯의 파서·쪽수·청크 수는 전부 실제로 파싱해서 얻었다.

다시 만들려면 레포 루트에서:

```bash
uv run python docs/design/mockup/wiki/assets/make-data.py
```

## G · 그래프 다섯

| | 노드로 그리는 것 | 개수 | 면 | 논지 |
|---|---|---:|---|---|
| **G1 성층** | 자리 + 표시 단위(위성) | 62 | 라이트 | 자리는 제자리에 두고 안에 든 것을 밖으로 꺼낸다 |
| **G2 성운** | 자리 + 단위 + **근거** + 파일 | 186 | 다크 | 있는 것을 다 올린다. 근거가 파일과 자리를 동시에 잡는다 |
| **G3 구체** | 자리 + 근거를 구면에 | 132 | 다크 | 가려짐이 거리를 말한다. 의존성 0 |
| **G4 별자리** | 고른 자리 하나 + 그 근거 | 1+n | 다크 | 한 번에 자리 하나를 깊게 |
| **G5 이분** | 파일 ↔ 자리 | 22 | 라이트 | 어느 파일을 지우면 무엇이 사라지나가 구조 자체 |

**대가**

- **G1** 판이 640 → 860px. **위성은 44px 타깃이 안 된다**(지름 8px) — 그래서 위성을 직접
  누르게 하지 않는다. 「얼마나 들었나」를 말하는 표시이지 조작 요소가 아니다.
- **G2** 셋을 한꺼번에 뒤집는다 — 다크(§7) · 힘 배치(ADR-0017) · 구획 6색 후보(§2).
  힘 배치의 「열 때마다 달라진다」는 **시드 고정으로 없앴지만**(mulberry32 · `Math.random` 0회)
  「두 번째 볼 때 찾는다」는 안 풀린다. 파일을 하나 더 올리면 배치가 통째로 다시 잡힌다.
- **G3** canvas 라 **DOM 이 없다.** 옆의 자리 목록이 유일한 접근 가능한 길이고 캔버스는
  그림이다. 모션이 기본으로 돈다. 셋기 편해 보이는 3D 를 실제로 쓰려면 three.js ≈ 150KB gz
  가 `web/` 에 처음 들어간다 — **이 목업은 손으로 투영해서 그 비용을 안 숨겼다.**
- **G4** 전체가 안 보인다. 근거가 19를 넘으면 링이 여럿 되고 「한 눈에」가 깨진다 —
  **진짜 회사는 사실이 143개였고 밀도 노브로 그걸 미리 못 본다.**
- **G5** 그래프처럼 안 생겼다. 자리끼리의 관계와 구획이 아예 없다. 파일이 수십 장이면
  왼쪽이 길어지고 띠가 다 교차한다.

## P · 패널 둘

현행 `WikiPanel.tsx` 는 주석에 **「출처를 툴팁이나 각주로 빼지 않는다. 빼는 순간 값과
근거가 떨어지고, 떨어지면 아무도 안 연다」**고 적어 뒀다. 그런데 실제로는 `<details>` 안이라
**원문까지 두 번 눌러야 한다.** 접힌 것은 각주와 다르지 않다. 실측이 이걸 숫자로 말한다 —
현행은 **열린 원문 0 · 접힌 근거 7**, P 시안 둘은 **열린 원문 10 · 접힌 것 0**.

| | 자리 | 안쪽 | 논지 |
|---|---|---|---|
| **P2 곁** | 오른쪽 384px 고정 | 세로로 쌓는다 | 궤도를 안 가리고 스크롤이 따로 논다 |
| **P3 시트** | 누른 자리 반대쪽에 겹침 | 한 단 | SPEC §5.3 이 원래 적은 「겹쳐 뜬다」 |

**대가**

- **P2** 궤도가 632px 로 좁아진다. **1024px 아래에서는 이 구조가 아예 없다** — 접히면
  아래로 펴는 구조가 되고, 그건 뺀 P1 과 같다. `notice/README` 가 「우측 드로어」를 한 번
  거절했다(다만 그건 목록 화면 이야기라 그대로 오지는 않는다).
- **P3** **제품에서 처음으로 그림자가 켜진다**(§6 · 실측에서 이 시안만 그림자 1). 스크롤이
  둘이 되고 딥링크·인쇄가 나빠진다. 좁은 화면 바텀 시트가 `env(safe-area-inset-bottom)` 을 먹는다.

**둘 다 같은 것을 판다** — 궤도를 화면에 남긴 채 근거를 편다. 갈리는 것은 **곁에 세우느냐
위에 띄우느냐**뿐이고, 폭이 좁아지면 P2 는 구조가 사라지고 P3 는 바텀 시트로 살아남는다.
좁은 화면을 먼저 보는 것이 이 둘을 가르는 가장 빠른 길이다.

### 닫은 것 셋 — 같은 안이 다시 올라오는 것을 막는다

**2026-08-21 육안 검토에서 P 다섯 중 셋을 뺐다.** 파일은 지웠고 여기 무엇이었는지만 남긴다.

| | 무엇이었나 | 그때 적어 둔 대가 |
|---|---|---|
| **P1 아래** | 현행 자리(궤도 아래). 두 단 — 왼쪽 값 · 오른쪽 원문 | 근거 19개짜리 자리를 열면 화면 세 배. 궤도가 위로 밀려 자리를 바꾸려면 되돌아간다 |
| **P4 문서** | 자리 하나가 전체 화면 문서(`/wiki/<node>`). 근거가 여백 곁주 | 그래프를 떠난다. 라우트가 하나 늘고 빈 문서로 이동시키는 일이 생긴다 |
| **P5 두 단** | 왼쪽에 자리 목록 상시 + 오른쪽 내용. 궤도는 접은 개요 | 위키가 그래프처럼 안 보인다. 껍데기 레일과 합쳐 왼쪽에 세로 띠가 둘이 된다 |

**왜 뺐는지는 여기 적혀 있지 않다.** 육안 검토의 판단이고 이유가 기록되지 않았다 —
지어내지 않는다. 다시 올릴 이유가 생기면 위 표의 대가부터 다시 읽는다.

**셋을 빼면서 잃은 것 하나는 적어 둔다.** P4 만이 **자리에 주소를 줬다**(`/wiki/<node>`).
딥링크·인쇄·뒤로 가기가 거기서만 됐고, 남은 둘은 전부 한 화면 안의 상태다.
주소가 필요해지면 그건 P2·P3 위에 따로 얹어야 하는 일이지 저절로 따라오지 않는다.


1. **G3 과 P4 의 노드가 0인 것은 결함이 아니라 그 시안의 정의다.** G3 은 canvas 라 DOM 이
   없고, P4 는 자리를 고르면 그래프를 떠나 문서가 된다. **둘 다 이 표에서 그렇게 보여야 한다** —
   숫자를 채우려고 규칙을 바꾸면 그 사실이 사라진다.
2. **접힌 근거가 축을 증명한다.** 현행과 G 시안 다섯이 전부 7이고 P 시안 둘이 전부 0이다.
   G 축은 패널을 안 건드리기로 했으므로 이게 맞다.
3. **최소 타깃이 여덟 다 44px 미달이다**(12~19px). §5 위반이고 **그래프 도트의 구조적
   문제다** — 열다섯을 한 화면에 넣으면서 44px 을 지킬 방법이 궤도 반지름을 키우는 것뿐이다.
   시안이 이걸 어떻게 감당하는지가 고르는 기준의 하나다.
4. **본문 최소 11~13px 은 §3 위반이 아니다.** `--t-aux` 가 ≥1024px 에서 13px 이고
   (ADR-0044) 이 표를 1440px 에서 쟀다. **다만 11·12px 은 그 토큰도 아니다** — 그래프
   이름표라 `--t-caption`(12) 아래로 내려간 자리가 있다.
5. **G5 최장줄이 처음에 73ch 였다**(§5 는 62ch 이하). 판이 940px 이라 그 아래 설명글이
   판 너비를 따라간 것이다 — `max-width: 62ch` 를 걸어 고쳤다. **판을 넓히면 글도 넓어진다.**

페이지 배경을 읽는다. 실제로는 읽힌다. **다만 그 자리에 진짜 결함이 따로 있다** —
「우리가 하는 일」 일곱 자가 12px 이면 84px 이라 지름 80px 원을 **넘는다.** `base.html`
에서 눈으로 볼 수 있고 G1 은 이름표를 원 밖으로 내려 피했다.

떨어진다.** 토큰 주석의 두 숫자에 그 배경이 없다 — **배경을 바꾸면 대비를 다시 재야 한다.**

## 서체 — `node assets/font-probe.mjs`

```
굵기   잉크    폭        판정
300     765  307.94   구분됨
400     765  307.94   ← 300 과 같은 face 로 떨어진다
450     926  305.68   구분됨
500     926  305.68   ← 450 과 같은 face 로 떨어진다
600    1089  307.94   구분됨
700    1177  306.81   구분됨
800    1191  306.81   구분됨
```

**우리가 쓰는 넷(400·500·600·700)은 전부 구분된다.** 붙은 것은 안 불러온 300·450 뿐이다.

### 이 도구가 한 번 틀린 답을 줬다 — 고쳤다

원래 판별법은 **같은 문자열을 weight 만 바꿔 재고 폭이 같으면 같은 face** 였다.
라틴에서는 맞고 **한글에서는 틀린다** — 한글 글리프는 대개 고정폭이라 굵기가 바뀌어도
advance 가 거의 안 변한다. 그래서 처음에

```
"400·600 이 같은 face" · "실제 구분되는 굵기 3종"
```

이라고 보고했다. 사실이면 **`--w-medium`(600)이 무효**라는 뜻이라 확인했더니 아니었다 —
canvas 알파 합(잉크량)으로 재니 400: 984 · 500: 1,209 · 600: 1,413 · 700: 1,546 으로
넷이 다 갈렸다. 폭은 398.41 · 399.71 · 404.50 · 405.85 로 **1.9% 안에 모여 있었다.**

`assets/font-probe.mjs` 를 잉크량 판정으로 바꿨다. 폭도 같이 찍되 **판정에는 안 쓴다.**

## 만들다 잡은 것

- **`layout.js` 의 `fit()` 에 `{right: 132}` 를 넘겼더니 viewBox 가 통째로 무효가 됐다.**
  `var p = pad || 24` 가 객체를 그대로 받아 `x0 - {}` 가 NaN 이 됐다. SVG 는 조용히
  아무것도 안 그린다 — 콘솔에 `Trailing garbage` 한 줄만 남는다.
- **힘 배치의 틀을 먼저 고정하면 이름표가 오른쪽에서 잘린다.** 경계에 가두면 이번에는
  테두리에 노드가 줄지어 붙는다. **배치를 먼저 하고 틀을 나중에 맞춘다.**
- **G3 의 이름표가 구면에서 겹친다.** 2D 처럼 밀어낼 수가 없어서 **앞에서부터 놓고
  부딪히면 버린다** — 뒤로 돌아간 자리의 이름은 어차피 지금 볼 것이 아니고, 돌리면 돌아온다.
- **`quotable()` 이 표 부스러기를 놓쳤다.** `rank.quotable()` 처럼 탭·줄바꿈만 봤더니
  `합계 49200000 37200000 86400000` 이 P1 에서 인용문으로 나갔다 — 해독 과정에서 탭이
  공백이 된 재무제표 한 줄이다. 숫자 토큰 셋 이상 규칙을 얹었지만 **증상마다 규칙을 붙이는
  것은 이미 진 싸움이다.** 뿌리는 [plan/12](../../../plan/12-사업-위키-구축.md) T-0078 이고
  화면에서 완전히 못 막는다.
- **`common.css` 에 서체 로드가 없었다.** `tokens.css` 의 `--font-sans` 는 `--font-plex` 가
  없으면 이름으로 떨어지는데 제품에서는 `next/font/google` 이 그 이름을 심어 준다. 목업에는
  그게 없어 **선언만 있고 로드가 없는 상태**였고, `getComputedStyle` 은 선언된 스택을 그대로
  돌려주므로 코드만 봐서는 안 걸린다.
- **다섯 시안의 재질을 일부러 같게 뒀다가 되돌렸다.** 「축 하나만 갈린다」를 지키려고
  평면 원 + 종류색 셋을 고정 변인으로 뒀는데, **고정할 것을 잘못 골랐다** — 물음이
  생김새였다. 규칙을 지키느라 물음에 답을 안 한 꼴이라 노브로 뺐다.
- **`switch.html` 에 전환 바를 하나 더 만들었다가 겹쳤다.** 프레임 안 시안에도
  `harness.js` 가 만든 바가 있고 **둘 다 하단 중앙 고정**이라 정확히 포개졌다.
  `harness.js` 는 이미 계약을 갖고 있었다 — 프레임 안이면 버튼이 `location.href` 대신
  부모로 `hns-switch` 를 postMessage 한다. **부모는 받아서 프레임만 갈아끼우면 되고,
  조작기를 또 두면 상태가 갈린다.** `notice/switch.html` 이 이미 그렇게 돼 있었다.
- **`<g>` 의 bbox 중심이 빈 자리라 playwright 의 진짜 클릭이 안 먹는다.** 이름표가 원에서
  떨어져 있어 중심에 아무것도 없다. 검증 스크립트는 DOM 이벤트로 부른다.
- 위 여섯 중 셋은 **코드만 읽어서는 안 보이고 스크린샷과 실측으로만 잡혔다.**
