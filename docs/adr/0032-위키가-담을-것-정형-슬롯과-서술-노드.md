# ADR-0032: 위키가 담을 것 — 정형 슬롯 열넷과 서술 노드 아홉

- 상태: 채택됨 — **결정 3(서술 노드 아홉)만 [ADR-0033](0033-정체성을-서술-노드로-올린다.md)이 열로 고쳤다.** 나머지는 그대로다
- 날짜: 2026-08-18
- 채우는 것: [ADR-0021](0021-인프라-선정을-미룬다.md)이 미룬 **E(노드 스키마)**
- 닫는 것: [plan/12](../plan/12-사업-위키-구축.md) T-0044
- 근거: [`tests/fixtures/wiki/`](../../tests/fixtures/wiki/README.md) 코퍼스 7건 — **파일을 전부 열어 보고 썼다**
- 관련: [ADR-0014](0014-통합-그래프와-근거-청크.md) · [ADR-0017](0017-위키-그래프-궤도-배치.md) · [ADR-0028](0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md) · [ADR-0031](0031-사실-추출을-포트-뒤로-미루고-스텁으로-배관을-먼저-세운다.md)

## 맥락

CLAUDE.md 가 "계층별 상세 사양(노드 스키마…)은 **코퍼스를 보고 나서 쓴다**"고 정해 뒀다. [`tests/fixtures/wiki/`](../../tests/fixtures/wiki/README.md) 일곱 건이 그 코퍼스이고, 이 문서는 그걸 다 읽고 쓴 것이다.

[plan/12](../plan/12-사업-위키-구축.md) T-0044 가 층을 둘로 가르라고 했다. **병합 키가 다르기 때문이다.**

| | 키 | 충돌 |
|---|---|---|
| 정형 슬롯 | 슬롯 이름 | 값이 다르면 충돌 |
| 서술 노드 | 없다 | 근거를 쌓기만 한다 |

코퍼스를 열어 보니 **저 표의 왼쪽 칸이 부족했다.** 직원 수가 7 · 8 · 10 · 15 로 넷인데 슬롯 이름만으로 묶으면 값 넷이 한 자리에 앉아 충돌이 된다. **그런데 그건 충돌이 아니라 성장이다.**

## 결정

### 1. 슬롯의 키는 이름이 아니라 **(이름, 한정어, 시점)** 이다

```
자리 = (슬롯, 한정어, 시점)

한 자리에 서로 다른 값이 둘 이상  →  전부 충돌
한 자리에 값이 하나              →  같은 (슬롯, 한정어) 중 시점이 가장 늦으면
                                     현재값, 아니면 이전값
```

**규칙 하나로 코퍼스의 함정 둘이 갈린다.**

| | 자리 | 결과 |
|---|---|---|
| 직원 수 7 · 8 · 10 · 15 | 시점이 넷 다 다르다 | **시계열** |
| 시드 3억 · 3억 · 2.8억 | 셋 다 2025-09 | **충돌** |

**시점이 다르면 성장이고 같으면 모순이다.** 앞을 충돌로 세우면 오탐이고 뒤를 시계열로 세우면 거짓이다.

**한정어**는 같은 슬롯 안의 종류다 — 조달의 `시드` · `정책자금`, 수혜 이력의 `예비창업패키지` · `소상공인 정책자금`. 이게 없으면 시드 3억(2025-09)과 정책자금 5천만(2025-04)이 시계열로 서서 "조달액이 3억에서 5천만으로 줄었다"가 된다.

**근거 수로 값을 정하지 않는다.** 시드는 2 대 1 이지만 다수결로 풀지 않고 둘 다 보관한다(F1-1-7).

### 2. 정형 슬롯은 열넷이다

| 슬롯 | 시점 | 자격 판별 | 코퍼스 근거 |
|---|:---:|:---:|---|
| `company_name` 상호 | | | 문서 4건 |
| `business_no` 사업자등록번호 | | **✓** | 문서 4건 |
| `corp_no` 법인등록번호 | | | 사업계획서 · 등록증 |
| `founded_on` 개업연월일 | | **✓** | 문서 4건 |
| `ceo_name` 대표자 | | | 문서 4건 |
| `ceo_birth` 대표자 생년월일 | | **✓** | 신청서 · 사업계획서 |
| `location` 소재지 | ✓ | **✓** | 문서 5건 |
| `industry` 업종(업태) | ✓ | **✓** | 문서 3건 |
| `industry_item` 업종(종목) | ✓ | **✓** | 문서 4건 |
| `headcount` 직원 수 | ✓ | **✓** | 문서 4건 · **네 시점** |
| `capital` 자본금 | ✓ | | 문서 4건 |
| `revenue` 매출액 | ✓ | | 문서 3건 |
| `funding` 조달액 | ✓ · 한정어 | | 시드 · 정책자금 |
| `gov_program` 정부지원 수혜 이력 | ✓ · 한정어 | **✓** | **HWPX 에만** 3건 |

**업력과 만 나이는 저장하지 않고 계산한다.** 공고마다 기준일이 다르다(`SPEC.md` F1-2). 코퍼스의 성남시 신청서에 `업력 1년 6개월` 이 박혀 있는데 2025-08 기준이라 지금은 틀렸다 — 슬롯이 없어서 **검토 대기로 선다. 버리지는 않는다.**

**업태와 종목을 한 슬롯에 넣지 않는다.** 등록증도 사업계획서도 두 칸으로 준다. 하나로 접으면 `정보통신업` 과 `응용 소프트웨어 개발 및 공급업` 이 같은 자리에 값 둘로 앉아 **없는 충돌이 생긴다.**

**`gov_program` 이 [ADR-0021](0021-인프라-선정을-미룬다.md) 이 안 물어본 자리다.** 구상도의 이벤트 계열 `application_history` 가 여기로 왔고, **이벤트가 아니라 자격 판별 입력**이다 — 중복수혜 제한. 셋 다 HWPX 한 건에만 있어서 **HWP 파서를 빼면 못 받는 공고를 받을 수 있다고 말하게 된다.**

### 3. 서술 노드는 아홉이다. `SPEC.md` F1-2 그대로다

`problem` 문제 인식 · `solution` 솔루션과 기술 · `customer` 목표 고객 · `market` 시장과 경쟁 · `region` 지역 연계 · `traction` 매출과 성과 · `team` 팀 구성 · `roadmap` 로드맵 · `finance` 자금 현황.

**늘리지 않는다.** 집필 단위와 맞춰 둔 것이고 `DESIGN.md` §4.1 의 노드 분류색 셋과 [ADR-0017](0017-위키-그래프-궤도-배치.md)의 궤도 배치가 이 위에 선다.

### 4. **구상도의 topic 22개로는 서술 노드 아홉 중 둘에 못 닿는다**

이게 코퍼스를 보고 나서야 나온 발견이다.

| 없는 topic | 노드 | 코퍼스에 있는 것 |
|---|---|---|
| `region_link` | 지역 연계 | 성남산업진흥원 입주 · 상인회 3개소 협약 · 파일럿 12곳 반경 15km |
| `roadmap` | 로드맵 | 1·2·3단계 사업화 일정 · 브리지 라운드 5억 목표 |

[plan/12](../plan/12-사업-위키-구축.md)가 지역 연계 하나는 이미 지적했다. **로드맵은 여기서 처음 잡혔고, 둘 다 코퍼스에 풍부하다.** 지역 연계는 지자체 공고 매칭에 직결된다. 그래서 topic 둘을 더해 **25개**로 간다.

**이벤트 계열 넷 중 셋은 뺀다.** `meeting` · `decision` · `action_item` 은 사업계획서 · IR · 재무제표에서 나오지 않는다 — 코퍼스 7건에서 하나도 안 나왔다. 도면이 스스로 적은 `선형 증가` 가 F1-4 의 "노드가 열다섯이라 검색이 필요 없다"를 첫날부터 깬다.

### 5. topic 은 목적지가 아니다. **라벨이다**

25개 topic 이 14개 슬롯 + 9개 노드로 모인다. 라벨은 세밀할수록 좋고 노드는 집필 단위와 맞아야 해서 방향이 반대다.

**어느 슬롯인지는 topic 이 아니라 별칭 표가 정한다.** 도면은 `company_profile` 을 topic 하나로 뒀는데 자격 판별은 사업자등록번호 · 개업일 · 소재지 · 업종을 **각각** 본다.

```
상시 근로자 · 종업원 수 · 구성원 · 임직원  →  headcount
```

**문자열이 다르다고 슬롯이 갈리면 안 된다.** 코퍼스에 직원 수가 네 이름으로 있고, 표에 없는 이름은 **버리지 않고 검토 대기로 세운다.**

### 6. 같은 사실을 묶는 것은 문장이 아니라 `fact_key` 다

재구매율 34→51% 가 네 문서에 **다른 문장으로** 있다.

```
월 재구매율은 도입 3개월 차 34%에서 5개월 차 51%로 상승했다   (신청서)
월 재구매율이 도입 3개월 차 34%에서 5개월 차 51%로 올랐습니다  (회사소개서)
34% → 51%                                                  (피치덱)
```

문자열로는 못 묶는다. 추출기가 같은 `fact_key` 를 준다 — **사실 하나에 근거 넷이어야 하고 사실 넷이 되면 틀렸다.**

[plan/12](../plan/12-사업-위키-구축.md) T-0046 의 "서술 노드는 합치지 않고 근거를 쌓는다"와 안 부딪힌다. **합치지 않는다는 것은 문장을 하나로 요약하지 않는다는 뜻이고**, 같은 사실을 두 번 세우지 않는 것은 별개다.

### 7. 값은 정규화하고, 문서가 쓴 표현은 따로 남긴다

`24,100천원 (2024년)` · `2,410만원` · `24100000` 이 코퍼스에 다 있고 **같은 값이다.** 표기를 그대로 두면 셋이 서로 다른 값이 돼 없는 충돌이 생긴다.

- `Fact.value` — 정규화된 값. 단위 환산과 날짜 ISO 변환은 **추출기의 일이다**
- `Fact.text` — 문서가 쓴 표현. 사람이 읽는 자리에 이게 나간다
- 비교할 때 **공백을 전부 지운다.** OCR 이 `응용 소프트웨어개발및공급업` 을 내는데, 안 지우면 OCR 노이즈가 전부 충돌로 둔갑한다

## 결과

**표가 둘이 아니라 하나다.** `wiki_fact` 한 표가 슬롯 · 노드 · 검토 대기를 다 담고 `dedupe_key` 가 병합의 전부다. 근거는 `wiki_evidence` 로 나가고 **근거 없는 행은 만들지 않는다.**

`wiki/topics.py` 가 이 ADR 의 실행본이다. **별칭 표와 목적지 표가 코드로 있는 이유는 라우팅이 결정론이어야 하기 때문이다** — 같은 파일을 두 번 넣으면 같은 배치가 나온다.

**측정.** 코퍼스 7건에서 사실 65건 · 근거 118개 · 슬롯 14개 · 노드 9개. **서술 노드 아홉이 전부 찼고** 자격 판별 입력 여섯도 전부 찼다 — OCR 을 꺼서 사업자등록증이 빠진 상태에서도 그랬다.

**포기한 것과 아직 모르는 것.**

- **회사가 하나다.** 별칭 표가 다시로의 문서 일곱에서만 나왔다. 새 회사의 새 표현이 오면 검토 대기가 늘고, **그때 표에 한 줄을 더한다.** 미리 채우지 않는다
- **슬롯 열넷이 충분한지 모른다.** 코퍼스가 넓지 않다. 늘어날 것을 전제하고 만들었다
- **`vision` 을 `solution` 으로 보냈다.** 이 매핑이 가장 약하다. 코퍼스에서 비전 문장("소상공인이 재고를 세지 않게 한다")이 한 줄 정의와 같은 자리에 쓰여서 그렇게 갔고, 다른 회사에서 갈릴 수 있다
- **`source_type` 자리는 만들었고 `user_stated` 는 아직 안 쓴다.** [ADR-0028](0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md)이 질문 답변을 그 등급으로 저장하라고 했고, F1-7 이 붙기 전에 자리가 있어야 나중에 데이터를 다시 안 만든다
