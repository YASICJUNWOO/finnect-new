# ADR-0073: hwp 를 갈 때 글자모양과 줄정보를 같이 간다

- 상태: 채택됨
- 날짜: 2026-08-26
- 채우는 것: [ADR-0070](0070-hwp-를-바이트로-읽고-쓴다.md) 결정 2 가 「레코드 규칙 넷을 실측으로 확정했다」고 적었는데 **넷이 전부 `nChars` 와 `PARA_TEXT` 쪽**이었다. 문단에 매달린 나머지 둘(`PARA_CHAR_SHAPE`·`PARA_LINE_SEG`)이 빠져 있었다
- 좁히는 것: [ADR-0070](0070-hwp-를-바이트로-읽고-쓴다.md) 결정 5 — 라벨 규칙에 **아닌 것 둘**을 더한다. 뒤집는 것이 아니다
- 그대로 사는 것: [ADR-0070](0070-hwp-를-바이트로-읽고-쓴다.md) 결정 1·3·4 · [ADR-0060](0060-양식을-채워서-원본-포맷으로-돌려준다.md) 결정 1·2·6 · [ADR-0063](0063-서술-항목의-좌표를-문단으로-준다.md) 전부
- 실측: [2026-08-26 hwp 되쓰기 — 글자모양과 줄정보](evidence/2026-08-26-hwp-되쓰기-글자모양과-줄정보.md) (HWP5 20건 · 칸 4,336 · **한/글 육안 0건**)

## 맥락

`forms/hwp5.py` 의 `edit()` 이 **글자만 갈았다.**

문단에 매달린 것이 넷이고 **셋이 글자 수를 기준으로 산다.** `PARA_TEXT` 를 갈고 `nChars` 만 고치면 `PARA_CHAR_SHAPE` 의 위치 쌍과 `PARA_LINE_SEG` 의 줄 시작 위치가 옛 글자 수를 가리킨 채 남고, 머리의 `nCharShapes`·`nLineSegs` 도 그대로다.

**`forms/hwplib.py` 가 판본 B~I 로 이미 잡아 둔 것이다.** 그 파일에 셋이 다 있다.

- `_reshape` — 「글자를 갈면 `CharShape` 의 위치 쌍이 옛 글자 수 기준으로 남아 **문자열 밖을 가리킨다**」
- `deleteLineSeg` — 「캐시는 옛 글자 기준이라 남겨 두면 한/글이 넣은 글을 그 자리에 그려서 **글자가 겹친다.** 판본 B(색만 고침)에서 겹쳤고 C(캐시 삭제)에서 풀렸다」
- `_recount` — 「문단 머리의 개수 셋을 다시 적는다. **옛 글자 수가 남으면 안 열린다**」

**ADR-0070 이 바이트 경로로 갈아 끼우면서 셋이 안 따라왔다.** 실측에서 채운 문단 5,082개 중 조각이 갈린 것 361 · 조각이 글 밖인 것 69 · 줄정보가 두 줄 이상인 것 382 · 줄정보가 글 밖인 것 94 였다.

같은 실측에서 **좌표는 안 틀렸다** — 빈 칸 821개를 채워 되읽었을 때 오배치 0 · 부수피해 0 · 격자 변형 0 이다. 「밀려서 씀」의 뿌리가 쓰는 층이 아니라 서식 층이다.

그리고 이름 층에 하나 더 있었다. `_is_label` 이 「글자가 있고 플레이스홀더가 아니면 이름」이라, **단위만 든 칸**(`명`)과 **통째로 괄호에 싸인 안내문**(`(기업의 경우만 작성)`)이 이름으로 섰다. 육안에서 `아이템명 × 사무직`·`법인등록번호 × 명`·`… › 백만원 › 업종/업태 × 명` 이 나왔다. **좌표가 아니라 이름이 틀리는 것이고, `label_paths` 가 항목을 만드는 경로에서는 그 문자열이 그대로 집필 프롬프트다.**

## 결정

### 1. 글자모양 조각을 하나로 접는다

`PARA_CHAR_SHAPE` 를 **첫 쌍 하나**(위치 0)로 다시 쓰고 `nCharShapes` 를 1 로 적는다(`hwp5.one_char_shape`).

**첫 쌍의 모양을 남기는 이유는 그것이 그 자리에 원래 쓰인 서식이라서다** — hwplib `_reshape` 판본 I 와 같은 판단이다. **중립으로 만들지 않는다**(정하지 않은 것 1).

**빈 문단에서는 아무 일도 안 한다** — 실측 2,012문단 전부가 이미 한 쌍이었다. 바뀌는 것은 글자가 있던 문단뿐이다.

### 2. 줄 나눔 캐시를 버린다. 빈 표 칸에서는 안 버린다

`PARA_LINE_SEG` 레코드를 안 내보내고 `nLineSegs` 를 0 으로 적는다. 한/글이 다시 계산한다 — **원본에도 그 상태가 있다**(줄정보가 없고 `nLineSegs` 가 0 인 문단 11 / 8,910).

**버리는 조건이 「글자가 있었거나 최상위 문단」이다.** hwplib 의 `if into_para or overwriting` 과 같은 규칙이고, 바이트 경로에서는 `level == 0` 이 표 밖 문단이라는 뜻이다.

- **글자가 있던 문단** — 캐시가 옛 글자 기준이라 겹친다(판본 B→C)
- **표 밖 문단** — 서술 자리라 여러 줄이 된다. 비어 있어도 버린다
- **비어 있던 표 칸** — **안 버린다.** 거기는 지금 그대로 정상이고(ADR-0060 육안 165칸) 칸은 크기가 정해져 있어 한/글이 다시 계산한다. **재 보지 않은 것을 같이 고치지 않는다**

### 3. 머릿수 셋을 다 적는다

`nChars`(offset 0) · `nCharShapes`(12) · `nLineSegs`(16). **하나만 고치면 나머지 둘이 옛 글자 수를 가리킨다.**

**레코드가 없으면 0 을 적는다.** 없는 것을 1 이라고 적으면 개수와 실제가 어긋나고, 그것은 낡은 값이 남는 것과 같은 종류의 거짓이다.

### 4. 단위만 든 칸과 통째로 괄호에 싸인 칸은 이름이 아니다

`_is_label` 이 아닌 것을 셋 본다 — 플레이스홀더(전부터) · **단위 단독** · **통째로 괄호에 싸인 것**.

- **단위는 혼자 있을 때만 걸린다.** `인원(명)` 은 이름이라 그대로 라벨이다
- **괄호는 통째로 싸인 것만 본다.** `(1) 사업 개요` 는 번호가 붙은 진짜 이름이고 `(주)가나다` 는 값이다 — 여는 괄호만 보면 앞엣것을 잃는다

**값 자리 판정을 안 건드린다.** 단위 칸은 글자가 있고 플레이스홀더가 아니므로 여전히 채울 자리가 아니다 — 이름 노릇만 못 하게 된다.

### 5. 머리 행에는 이름 아닌 글자가 없다

라벨 셋 이상(`_HEADER_ROW_MIN`)에 조건 하나를 더한다. 그 행에 **이름 아닌 글자가 섞여 있으면 머리 행이 아니다.**

`종업원수 | 사무직 | 00 명 | 기술직 | 00 명 | …` 이 「라벨 셋 이상」을 통과해서 아래 칸이 `아이템명 × 사무직` 을 들고 있었다. 그 행은 머리가 아니라 **자기 값을 든 데이터 행**이고, 가르는 재료가 「이름 아닌 글자가 섞였는가」다.

**빈 칸은 섞인 것이 아니다** — 진짜 머리 행의 왼쪽 위 모서리가 비어 있다.

## 정하지 않은 것

- **값 글자모양의 색과 크기.** 빈 값 칸 892개 중 라벨과 색이 다른 것 6.1% · 크기가 다른 것 10.2% 다. 고치려면 `align_substitutes` 처럼 **DocInfo 를 늘리지 않고 대신할 모양을 찾아야** 한다(같은-크기 제약이 `DocInfo` 에도 걸린다). **굵기 17.9% 는 고칠 것이 아니다** — 라벨이 굵고 값이 보통인 것이 정상이다
- **넘침 예보.** 칸 폭·높이와 글자 크기로 「이 값은 몇 줄이 된다」를 계산할 수 있지만 **렌더가 없어서 보정할 수단이 없다.** 어림값을 `FillReport` 에 실으면 그것이 근거 없는 수치가 된다
- **같은 크기 포장이 안 되는 파일.** 2,000자 값에서 20건 중 6건이다. `olefile` 이 CFB 를 새로 못 만드는 것이 뿌리이고 ADR-0070 이 남긴 자리 그대로다. Java 가 없는 서버에서는 그 파일이 `FormsUnavailable` 이다
- **`label_paths` 의 긴 이름.** `대표자명 › 대표자명 › 대표 › 연락처 › 010-****-**** › e-mail` 처럼 여섯 단인 것이 19자리 남았다. `010-****-****` 는 별표라 플레이스홀더 규칙(`00`)에 안 걸린다 — **규칙을 넓히면 진짜 이름을 잃을 수 있어서 재고 나서 정한다**

## 결과

- 채운 문단에서 조각 잘림 361 → 0 · 조각이 글 밖 69 → 0 · 줄정보 겹침 382 → 0 · 줄정보가 글 밖 94 → 0
- 이름 붙은 자리가 842 → 791 로 줄고 **유일한 이름은 243 → 245 로 늘었다.** 줄어든 51개는 단위 칸이나 안내문이 이름을 대던 자리다
- **이름이 바뀌었으므로 좌표를 다시 심어야 한다.** ADR-0070 결과 절의 재심기와 같은 작업이고 아직 안 했다 — `plant_anchors(redo=True)` 는 **그 파일에 쓴 초안을 지운다**(FK CASCADE)
- 폴백(`forms/hwplib.py`)을 안 지운다. 저기가 셋을 이미 하고 있고, **여기에 한/글 육안이 0건이다**
