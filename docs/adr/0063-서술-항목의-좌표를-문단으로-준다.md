# ADR-0063: 서술 항목의 좌표를 문단으로 준다

- 상태: 채택됨
- 날짜: 2026-08-23
- 채우는 것: [ADR-0060](0060-양식을-채워서-원본-포맷으로-돌려준다.md) 「정하지 않은 것」의 **사실칸과 서술칸을 갈라 다른 파이프라인에 태울 것인가** — 저기 실측이 사실칸만 다뤘다
- 그대로 사는 것: [ADR-0060](0060-양식을-채워서-원본-포맷으로-돌려준다.md) 결정 1·2·3(hwp 는 빈 자리만) · [ADR-0061](0061-양식-파싱의-입력을-파일-구조로-바꾼다.md) 결정 3·5
- 실측: 이 문서 «실측» 절 (2026-08-23 · 판본 넷 · 한/글 육안)

## 맥락

[ADR-0061](0061-양식-파싱의-입력을-파일-구조로-바꾼다.md) 결정 3 을 구현하자 **서술 항목이 486 → 1,701 개**가 됐다. 그런데 그중 **좌표를 가진 것이 0개**였다.

```
narrative  좌표     0 /  1,701      ← 하나도 예외가 없다
field      좌표   956 /  4,299
```

채우기가 `if not di.anchor` 에서 전부 건너뛰므로, **화면은 「썼어요」라고 말하는데 파일에는 안 들어갔다.** 사용자가 그것을 먼저 봤다.

원인은 좌표의 모양이다. `Anchor` 가 `(구역, 표, 행, 열)` 인데 **서술 항목의 글 자리는 표가 아니다.**

```
문단 16   1. 목적 및 필요성           ← 제목
문단 17   - 참가하고자 하는 …작성      ← 지시문
문단 18   (빈 문단)                  ← 글이 들어갈 자리
문단 25   2. 수주 활동 대상           ← 다음 항목
```

[ADR-0060](0060-양식을-채워서-원본-포맷으로-돌려준다.md)이 「앵커는 **표의 (행, 열) 좌표**여야 한다」고 못 박은 것은 맞았지만 **사실칸에 한해서였다.** 같은 문서가 그 한계를 「정하지 않은 것」에 적어 뒀다.

## 결정

### 1. 좌표가 둘이고 한 문자열에서 갈린다

`Anchor`(셀)에 `ParaAnchor`(문단)를 더한다. DB 에는 `p:0:18` 로 앉고, **`p:` 가 없으면 셀이다.**

```
0:3:1:2    셀   — 옛 값이 그대로 읽힌다
p:0:18     문단 — 구역과 문단 번호
```

**마이그레이션을 만들지 않는다.** 이미 심긴 셀 좌표 956개가 손대지 않아도 그대로 읽힌다. 컬럼이 문자열인 것이([ADR-0060](0060-양식을-채워서-원본-포맷으로-돌려준다.md) 실측이 정한 모양) 여기서 값을 한다.

**문단 번호는 `getParagraph(i)` 의 `i` 그대로다.** 표를 건너뛰며 다시 세지 않는다 — 표를 하나 더 찾거나 덜 찾는 날 좌표가 통째로 밀린다.

### 2. 제목 다음의 첫 빈 문단이 글 자리다

**다음 제목을 넘지 않는다.** 넘으면 항목 둘이 같은 문단을 가리키고, 나중 항목의 글이 앞 항목 자리에 앉는다.

**셋 중 하나면 안 준다.**

- 제목이 파일에 없다
- 제목이 파일에서 겹친다
- 제목 다음에 빈 문단이 없다(바로 표가 오는 양식이 있다)

셋 다 결과가 같다 — 좌표가 NULL 이고 그 항목은 안 채워진다. **아무 문단이나 고르면 글이 엉뚱한 데에 앉고 파일은 정상으로 열려서** 제출 직전에야 드러난다. 셀 좌표에서 겹치는 라벨을 아예 버리는 것과 같은 판단이다.

**제목 대조가 `endswith` 다.** 항목 제목은 `outline` 이 번호를 떼어 낸 값(`목적 및 필요성`)이고 문단은 번호를 달고 있다(`1. 목적 및 필요성`). 앞에 붙을 수 있는 길이를 여섯 자로 막는다 — 늘리면 `사업 계획` 이 `향후 사업 계획` 에 걸린다.

### 3. 빈 문단의 글자 모양을 중립으로 바꾼다

**빈 문단이라고 서식이 중립인 것이 아니다.** 실측한 양식에서 글 자리가 이랬다.

```
문단 16  1. 목적 및 필요성   → 검정 · 굵게
문단 17  - …에 대하여 작성    → 파랑 · 기울임
문단 18  (빈 문단)          → 빨강 · 기울임   ← 우리가 쓰는 자리
```

양식 작성자가 거기에 작성 예시를 적었다가 지운 흔적이고, **글을 넣으면 그 서식을 그대로 받는다.** 빨간 기울임으로 나갔다.

**색과 기울임만 뺀다.** 굵기와 취소선은 안 건드린다 — 실측이 본 것이 그 둘이고, 보지 않은 것을 고치면 그것이 지어낸 규칙이 된다.

**글자가 있는 문단도 쓰는 서식이면 안 건드린다.** 고치면 남의 글 색이 같이 바뀐다. 실측한 파일에서는 그 서식을 쓰는 문단이 **전부 빈 문단이었다**(글자 있는 문단 0개).

**세는 시점이 글자를 넣기 전이다.** 넣고 나서 세면 방금 채운 문단이 「글자가 있는 문단」으로 잡혀서 그 서식이 보호 대상이 되고, 아무것도 안 고쳐진다. 실제로 한 번 그렇게 짰다.

### 4. 문단은 줄 나눔 캐시를 지운다. 표 셀은 안 지운다

**빈 문단의 캐시는 「이 문단은 빈 줄 하나」라고 적혀 있다.** 남겨 두면 한/글이 넣은 글을 **한 줄에 다 그려서 글자가 겹친다.**

판본으로 갈랐다(아래 «실측»). **색만 고친 B 는 겹쳤고 캐시를 지운 C 에서 풀렸다.**

**표 셀에는 안 한다.** 거기는 지금 그대로 정상이고([ADR-0060](0060-양식을-채워서-원본-포맷으로-돌려준다.md) 실측 165칸), 셀은 크기가 정해져 있어 한/글이 다시 계산한다. **되는 것을 건드리지 않는다.**

## 정하지 않은 것

- **hwpx 어댑터.** 문단 좌표 399개가 **전부 hwp 다** — hwpx 는 어댑터가 아직 없고(`forms.PLANNED`) 코퍼스의 14%다.
- **여러 문단에 나눠 넣을 것인가.** 지금은 첫 빈 문단 하나에 통째로 넣는다. 빈 문단이 일곱 개 있어도 여섯은 그대로 남는다.
- **표가 글 자리인 서술 항목.** `1. 목적` 바로 밑에 큰 병합 셀이 오는 양식이 있는데 지금은 안 준다. 그 비율을 안 쟀다.
- **미리보기 복구.** [ADR-0060](0060-양식을-채워서-원본-포맷으로-돌려준다.md) 결정 4 가 `PrvText` 재생성과 `DocOptions/_LinkDoc` 이전을 정했는데 **제품 코드에 없다.** `hwp.py` 에 `_prv_text()` 가 있고 `save()` 가 안 부른다 — 이 회차에서 붙이려다 hwplib 이 `DocOptions` 를 디렉터리가 아니라 스트림으로 만들어 둔 것에 걸렸다.

## 결과

- **서술 항목 1,701개 중 399개(23.5%)가 글 자리를 얻었다.** 전에는 0개였다.
- **좌표가 있는 파일이 5 → 135 가 됐다**(칸 서식 파일 228 중).
- **포기하는 것** — 문단 좌표가 전부 hwp 라, hwpx·docx 양식의 서술 항목은 여전히 사람이 옮긴다.
- **늘어나는 위험** — 빈 문단을 고르는 규칙이 틀리면 글이 엉뚱한 자리에 앉는다. 셋 중 하나라도 애매하면 안 주는 것으로 막지만, **틀려도 파일은 정상으로 열린다**는 성질은 그대로다.

## 실측 (2026-08-23)

`bizinfo:PBLN_000000000125577` 활동계획서(hwp)에 판본 넷을 만들어 **한/글로 눈으로 봤다.**

| 판본 | 무엇을 했나 | 한/글 |
|---|---|---|
| A | 문단에 글만 넣음 | **빨간 기울임 · 글자 겹침** |
| B | A + 색을 검정으로, 기울임 해제 | 색은 정상 · **글자 겹침** |
| C | B + **줄 나눔 캐시 삭제** | **정상 · 줄 구분됨** |
| D | C + 문단 글자 수 갱신 | 정상 |

**C 와 D 가 같아서 C 를 택했다.** 글자 수 갱신은 없어도 되고, 최소한만 건드린다.

되읽어 대조하니 **구역 1 · 문단 113 · 셀 132 가 원본과 같았다.**

서술 항목 아홉 중 다섯이 자리를 찾았고, 못 찾은 넷은 **서식 제목 둘과 표 제목 둘**이라 글 쓰는 자리가 아니다.

```
✓ 목적 및 필요성       p:0:18
✓ 수주 활동 대상       p:0:27
✓ 수주관련 주요 보유 인증 p:0:31
✓ 활동 계획           p:0:35
✓ 기대효과           p:0:44
✗ 지원기업 현황 · 기타 현황 · 서식 제목 둘
```

**전량에서는 23.5% 다.** 이 파일이 5/5 인 것을 코퍼스 비율로 읽으면 안 된다 — 못 여는 포맷(pdf·hwpx)과 제목이 안 걸리는 양식이 나머지다.
