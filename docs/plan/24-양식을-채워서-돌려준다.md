# plan/24 — 양식을 채워서 돌려준다

> 상태: **동선이 화면까지 이어졌다** (2026-08-23) — 초안 값이 원본 양식의 제자리에 뜬다(hwp·docx 둘 다 실측). **다만 채우는 칸이 적고 원인이 파싱에 있다** — [ADR-0061](../adr/0061-양식-파싱의-입력을-파일-구조로-바꾼다.md)이 그 자리를 다시 정했고 T-0157 부터가 그 일이다. T-0150 ~ T-0160
> 종류: 파일 입출력 + 저장 + 화면 (스택에 JVM 이 붙는다)
> 선행: [16](16-항목마다-초안을-쓴다.md) 초안 집필 · [11](11-작성-항목-추출과-표시.md) 작성 항목 추출
> 근거: [ADR-0060](../adr/0060-양식을-채워서-원본-포맷으로-돌려준다.md) · [ADR-0061](../adr/0061-양식-파싱의-입력을-파일-구조로-바꾼다.md) · [ADR-0019](../adr/0019-집필의-축을-양식으로.md)

레포 첫 줄이 「들어가면 **문서가 이미 써져 있다**」인데 **그 문서가 파일로 안 나간다.** `src/finnect/draft/` 에 파일을 쓰는 코드가 한 줄도 없어서, 집필기가 만든 글을 사용자가 화면에서 복사해 한/글에 손으로 옮긴다.

여기서 **받은 양식 파일에 값을 넣어 같은 포맷으로 돌려준다.**

## 무엇이 되고 무엇이 안 되나

| | hwp | hwpx | docx |
|---|---|---|---|
| 빈 칸 채우기 | 가능 | 가능 | 가능 |
| **덮어쓰기** | **불가** | 가능 | 가능 |
| 미리보기 | 텍스트만 재생성 · **이미지 소실** | 해당 없음 | 해당 없음 |
| 런타임 | **JVM** | 순수 파이썬 | 순수 파이썬 |
| 코퍼스 비율 | **73%** | 14% | 5% |

**hwp 제약이 이 계획의 축이다.** 가장 많은 포맷에서 가장 적게 할 수 있다.

## 태스크

### T-0150 포맷마다 무엇이 되는지 잰다 — **완료** (2026-08-23)

받아 둔 첨부에서 양식 20건을 뽑아 라벨로 칸을 찾아 채우고 되읽어 대조했다. **165칸을 채웠고 20건 모두 정상으로 열린다.**

- `spike/form_values.py` — 값 사전과 대조 규칙. 포맷 셋이 공유한다. **라이브러리는 달라도 「라벨을 찾아 옆 빈 칸에 넣는다」는 규칙이 하나여야 포맷 간 결과를 비교할 수 있다**
- `spike/hwp_fill.py`(JVM) · `spike/hwpx_fill.py` · `spike/docx_fill.py`
- 표본은 `data/신청서/` 에 있고 **`.gitignore` 에 있다** — 첨부에서 복사한 것이라 재생성된다
- 판본 일곱 개로 hwp 의 경계를 갈랐다. **F(원래와 똑같은 값을 다시 써넣기)가 답을 줬다** — 그것도 밀렸으니 값·길이·캐시가 원인이 아니라 **갈아 끼우는 행위 자체**다
- 한/글로 눈으로 본 것은 **hwp 4건 · hwpx 1건 · docx 1건**이다. 나머지는 프로그램 검증만 했다

### T-0151 포맷 어댑터를 제품 코드로 세운다 — **완료** (2026-08-23)

`src/finnect/forms/` 를 만들고 spike 셋을 인터페이스 하나 뒤로 넣는다.

- `open(path) → Form` · `Form.blanks() → [Blank]` · `Form.fill(anchor, value)` · `Form.save(path)`
- **`Blank` 가 앵커를 든다** — 표 좌표 `(표 번호, 행, 열)` + 섹션. **누름틀에 기대지 않는다**(hwpx 9건 중 1건뿐)
- **덮어쓰기 가부를 어댑터가 답한다.** hwp 어댑터는 이미 글자가 있는 칸에 `False` 를 준다 — 부르는 쪽이 포맷을 알아서 분기하면 그 지식이 두 곳에 산다
- **JVM 을 hwp 어댑터 안에만 가둔다.** `import finnect.forms` 가 jpype 를 끌고 오면 안 된다 — `api/service.py` 가 `match.service` 를 임포트하지 않는 것과 같은 함정이다
- 미리보기 복구(`PrvText` 재생성 · `PrvImage` 포기)는 hwp 어댑터의 `save` 안에 있다

### T-0152 앵커를 저장한다 — **완료** (2026-08-23)

지금 `document_item` 은 **첨부 텍스트 안의 구간만** 안다. 파일 안 어디인지를 모르므로 채운 값을 되돌려 넣을 자리가 없다.

- 표 좌표를 `document_item` 에 붙일지 새 표로 뺄지 정한다
- **`document` 는 회사와 무관하다**(콘텐츠 주소). 앵커도 회사와 무관하므로 같은 성질로 둔다
- **나중에 붙일 수 없다** — 위치정보는 파싱 단계에서만 심을 수 있다([ADR-0014](../adr/0014-통합-그래프와-근거-청크.md))

### T-0153 빈칸을 LLM 이 가른다 — **다음 회차**

[ADR-0060](../adr/0060-양식을-채워서-원본-포맷으로-돌려준다.md) 결정 6. **규칙으로 못 한다.**

```
기업명 → 'OOOOO (법인등기부등본 및 사업자등록증상 상호명)'
```

실측에서 양식 하나가 이것 때문에 표 115개에서 **한 칸도 안 걸렸다.** 플레이스홀더만 있으면 정규식으로 갈리는데 안내문이 붙으면 안 갈리고, 안내문은 양식마다 다르게 쓰여 있다.

- 무엇을 묻는 칸인지 · 어디까지가 안내인지를 LLM 이 답한다
- **정확도를 재고 나서 붙인다.** 틀리면 안내문 위에 값이 얹히거나 진짜 값이 지워진다
- 이 칸들은 **덮어쓰기가 필수**라 hwp 에서는 손을 못 댄다(결정 3)

### T-0154 사실칸을 위키에서 채운다 — **완료** (2026-08-23)

실측은 손으로 만든 라벨 사전 26개를 썼다. 제품에서는 위키가 그 값을 내야 한다.

- 라벨 → 위키 자리 대응. `Company/회사소개` 와 매칭 정보 열다섯이 이미 그 값을 들고 있다([plan/23](23-자리표를-기획-트리로-고정한다.md) T-0148 과 같은 자리를 본다)
- **값에 단위를 붙이는 자리는 `profile.display()` 하나다** — 양식 칸에 넣을 때 `120000000` 을 그대로 쓸지 `1억 2천만 원` 으로 쓸지는 양식이 정한다
- **사실칸과 서술칸을 가를지는 여기서 정한다.** 실측은 사실칸만 다뤘다

### T-0155 채운 파일을 내려받는 길을 연다 — **완료** (2026-08-23)

- 쓰기 API 가 셋뿐임을 `tests/test_draft_start.py` 가 잠가 두고 있다. **내려받기는 읽기라 그 셋에 안 든다** — 계약 문서(`api-contract.md`)를 같은 커밋에 고친다
- **파일을 저장할지 그때 만들지 정한다.** 위키 마크다운을 저장하지 않기로 한 것과 같은 자리다 — 저장하면 초안이 바뀌었을 때 둘 중 하나가 먼저 낡는다
- 화면이 **「열어서 확인하세요」를 말해야 한다.** 값이 길면 셀이 두 줄이 되고 표가 다음 쪽으로 밀린다(ADR-0060 포기하는 것 ③)
- hwp 를 돌려줄 때 **못 지운 플레이스홀더 목록을 같이 준다.** 조용히 남기면 사용자가 `000-0000-0000` 을 그대로 제출한다

### T-0157 양식 파싱의 입력을 파일 구조로 바꾼다 — **다음 회차**

[ADR-0061](../adr/0061-양식-파싱의-입력을-파일-구조로-바꾼다.md) 결정 1·2. **이것이 뿌리다** — 아래 셋이 전부 여기서 갈라져 나온다.

- `forms` 어댑터가 **항목을 만든다.** 표 칸은 `(구역, 표, 행, 열)` 과 함께 처음부터 `document_item` 이 된다
- **좌표를 나중에 안 붙인다.** `plant_anchors()` 가 없어진다 — 그 함수는 순서가 뒤집혀 있어서 생긴 것이다
- 텍스트는 **pdf·스캔본이 물러날 자리**로 남는다. `attach/` 는 안 바뀐다
- **이미 깔린 `document_item` 을 어떻게 옮길지 정한다** — 다시 깔면 초안이 지워진다(FK CASCADE)

### T-0158 갈래를 문서에서 칸으로 내린다 — **다음 회차**

[ADR-0061](../adr/0061-양식-파싱의-입력을-파일-구조로-바꾼다.md) 결정 3. **한 신청서에 표와 서술이 같이 있는 것이 흔하다.**

```
붙임 2. 모집공고신청서류.hwp   →  1. 기본지원서   표
                                  2. 활동계획서   목차   ← 통째로 유실됐다
                                  사용인감 · 청렴서약서 · 자격확인서
```

- `document.kind` 로 추출기를 고르는 스위치를 없앤다
- `document_item.input_kind` 와 `item_need.place_kind` 가 축이다 — **모델은 이미 있다**
- `kind` 는 「채울 것이 있나」로 뜻이 약해진다

### T-0159 항목 추출을 LLM 하나로 합친다 — **다음 회차**

[ADR-0061](../adr/0061-양식-파싱의-입력을-파일-구조로-바꾼다.md) 결정 4·5. 표 라벨 정규식과 목차 규칙이 각자 뽑던 것을 한 번의 호출로 합친다.

- **위치는 코드가 준다.** LLM 은 좌표를 받아 「이 칸이 무엇을 묻나」만 답한다
- 서술 항목은 **제목 문자열**을 받아 원문에서 찾는다. 못 찾으면 버린다(앵커 대조)
- **정확도를 재고 나서 붙인다.** 손 분류와 대조하고 불일치를 전부 나열한다
- 규칙이 못 걸러 낸 것 둘이 대조군이다 — `=기업 기본 정보`(표 구분선) · `▸민사집행법에…`(안내문 전체)

### T-0160 다시 뜯는 경로를 막는다 — **다음 회차**

**`extract --redo` 가 초안을 지운다.** `draft_item.document_item_id` 의 FK 가 CASCADE 라 항목을 다시 깔면 그 항목에 쓴 초안과 **사람이 고친 글**이 같이 없어진다([ADR-0055](../adr/0055-사람이-고친-글을-집필-출력-위에-덮지-않는다.md)가 지키려던 값).

T-0159 가 붙으면 더 아파진다 — LLM 은 같은 파일을 매번 똑같이 안 쪼갠다.

- 초안이 있는 문서를 다시 뜯을 때 무엇을 할지 정한다
- 위키 쪽 `--rebuild` 가 같은 문제를 어떻게 풀었는지 본다

### T-0156 hwp 제출 요구 비율을 재고 변환을 정한다 — **다음 회차**

hwp 를 hwpx 로 바꾸면 덮어쓰기가 살아나고 JVM 도 변환 한 번에만 필요해진다. 대가는 **제출 포맷이 달라지는 것**이다.

- 공고 본문에서 「hwp 로 제출」을 요구하는 비율을 센다
- 낮으면 변환이 이긴다. 높으면 hwp 제약을 안고 간다
- **재기 전에는 안 정한다** — 반려되면 그 손해를 우리가 못 갚는다

```bash
uv run --with python-docx python spike/docx_fill.py
```
