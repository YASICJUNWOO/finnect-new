# ADR-0050: 상단을 한 단으로 합치고, 좌측 레일을 200px 사이드바로 넓혀 브랜드를 그 위에 올린다

- 상태: 채택됨
- 날짜: 2026-08-22
- 대체: [ADR-0042](0042-좌측-레일을-넓은-화면에서만-세운다.md) 결정 1(레일 60px) · 결정 4(상단 2단) · 결정 6(레일 글자 12px). **ADR-0042 의 나머지는 그대로 산다** — 결정 2(3축은 폭마다 한 자리) · 결정 3(`AXES` 배열 하나) · 결정 5(아이콘 대신 글자)가 이 결정의 전제다
- 관련: [ADR-0047](0047-브레이크포인트를-1024와-640으로-못-박는다.md) 폭 경계 · [ADR-0039](0039-설치되는-앱으로-만들되-서비스-워커는-안-붙인다.md) 하단 탭 바 · [ADR-0045](0045-목록-제목-굵기를-500으로-둔다.md) 500 굵기

## 맥락

넓은 화면에서 껍데기가 이랬다.

```
┌────┬─────────────────────────────────┐
│ ▪  │ ▪ 라스트마일            운영 도구 │ 44px  ← 1단
│    ├─────────────────────────────────┤
│지원│ 지원사업 › 전체 공고              │ 44px  ← 2단
│사업├─────────────────────────────────┤
│    │                                 │
│내  │                                 │
│사업│           main                  │
└────┴─────────────────────────────────┘
  60px
```

**세 가지가 겹쳐서 낭비였다.**

1. **상단 1단이 거의 비어 있었다.** 3축이 레일로 내려가면서 그 줄에 남은 것이 브랜드와 운영 도구 둘뿐이고, 1440px 폭에서 그 둘이 쓰는 자리가 240px 남짓이다. ADR-0042 결정 4 는 「1단이 비기 때문에」 2단을 만들었는데, 비었으면 단을 더할 게 아니라 아래 것을 올려야 했다. **껍데기가 88px 을 먹는다.**
2. **레일 60px 에 브랜드 문구가 안 들어간다.** 마크(18px 사각형)만 얹혀 있고 글자는 상단 막대에만 있었다. 브랜드가 화면 왼쪽 위 두 곳(레일 마크 · 막대 로고타입)에 나뉘어 있었던 것이다.
3. **60px 레일의 글자가 12px 두 줄이다.** ADR-0042 결정 6 이 11px 대신 12px 을 고른 것은 타입 스케일을 지키려는 판단이었지만, 애초에 `word-break: keep-all` 로 '신청 / 현황' 을 접어야 했던 것은 **폭이 모자랐기 때문이다.** 축 이름이 셋 다 4~5글자라 200px 이면 한 줄에 든다.

## 결정

**1. 상단을 한 단으로 합친다.** 높이 56px. 넓은 화면에서 담는 것은 현재 위치와 운영 도구다. 2단이 들고 있던 현재 위치가 그 줄로 올라오고 `.tier2` 는 없어진다.

```
┌──────────────┬───────────────────────────┐
│ ▪ 라스트마일  │ 지원사업 › 전체 공고  운영도구 │ 56px  ← 한 단
│              ├───────────────────────────┤
│  지원사업     │                           │
│  내 사업      │          main             │
│  신청 현황    │                           │
└──────────────┴───────────────────────────┘
     200px
```

**2. 좌측 레일을 200px 사이드바로 넓힌다.** 이름도 「레일」에서 「사이드바」로 바꾼다 — 60px 아이콘 레일과 200px 라벨 사이드바는 다른 물건이고, 문서가 같은 말로 부르면 다음 사람이 60px 을 전제한 규칙을 200px 에 적용한다.

**3. 브랜드를 사이드바 위에 올린다.** 마크와 문구가 한 덩어리로 거기 하나만 있다. **상단 막대의 브랜드는 그 폭에서 꺼진다** — ADR-0042 결정 2 가 3축에 건 규칙(같은 것이 화면에 두 번 있으면 안 된다)을 브랜드에도 그대로 적용한다. 마크업은 두 벌이고 CSS 가 폭마다 하나를 끈다.

| 폭 | 브랜드 | 3축 | 현재 위치 |
|---|---|---|---|
| ≥1024px | 사이드바 위 | 사이드바 | 상단 막대 |
| 641~1023px | 상단 막대 | 상단 막대 | 꺼짐 |
| ≤640px | 상단 막대 | 하단 탭 바 | 꺼짐 |

**4. 사이드바 축 이름을 16px 왼쪽 정렬 한 줄로 둔다.** ADR-0042 결정 6 의 12px 가운데 정렬 두 줄을 대체한다. 16px 은 `.menu`·`.tabs` 와 같은 값이다 — **표시 방법이 자리마다 다르면 같은 메뉴로 안 읽힌다**(결정 2 의 논리). 활성 표시도 그대로 색과 굵기뿐이고 배경을 얹지 않는다.

**5. 현재 위치를 16px 로 올린다.** 둘째 단일 때는 `--t-aux`(넓은 화면에서 13px)였다. 그때는 축 이름 아래 딸린 보조 줄이었고 지금은 막대에서 화면 이름을 말하는 유일한 글자다. 굵기는 `--w-mid`(500)다 — `--w-medium`(600)은 20px 섹션 제목의 굵기라 16px 에 걸면 계층이 섞인다(ADR-0045 가 목록 제목에서 한 판단과 같다).

**6. 브레이크포인트 1024px 을 그대로 둔다.** [ADR-0047](0047-브레이크포인트를-1024와-640으로-못-박는다.md) 의 산수(「레일 60 + 콘텐츠 992 = 1052」)는 이 결정으로 **안 맞게 된다** — 1024px 창에서 콘텐츠가 992 가 아니라 824px 이다. 그래도 경계를 안 올린다. 200 + 992 + 48 = 1240 으로 올리면 1024~1239px 이 상단 막대로 떨어지는데, 거기가 노트북과 가로 태블릿이라 **사이드바를 가장 많이 볼 폭이다.** 824px 에서 공고 행 4열 그리드가 그대로 서는 것을 확인했다(128 · 1fr · 92 · 64 에서 1fr 이 약 460px).

## 결과

- 껍데기가 넓은 화면에서 **88px 에서 56px 로** 줄고 그만큼 첫 화면에 공고가 더 든다.
- 브랜드가 화면에 한 번만 있다. 마크와 문구가 갈려 있던 것이 붙는다.
- 사이드바 축 이름이 접히지 않는다. `word-break: keep-all` 은 남겨 둔다 — 넷째 축이 길게 들어오는 날 아무 글자에서나 접히는 것보다 띄어쓰기에서 접히는 쪽이 낫다.
- `DESIGN.md` §1 · §5 의 표와 산수 문단이 같이 바뀐다. **ADR-0047 본문은 안 고친다** — append-only 이고, 산수가 안 맞게 된 사실은 여기와 `DESIGN.md` 에 적는다.
- **포기하는 것 ①** — 1024~1239px 에서 콘텐츠가 824px 다. 공고 제목이 그 폭에서 더 일찍 잘린다. 4열 그리드는 서지만 1440px 만큼 여유롭지 않다.
- **포기하는 것 ②** — 1024px 을 넘나들 때 튀는 것이 하나 늘었다. 사이드바가 나타났다 사라지고 행이 접혔다 펴지는 데 더해 **브랜드가 왼쪽 위에서 사이드바 위로 옮겨 간다.** ADR-0047 이 이미 받아들인 대가와 같은 종류다.
- **포기하는 것 ③** — 200px 은 관측 밖 값이다. 근거는 산수뿐이다: 안여백 12 + 항목 안여백 12 + 마크 18 + 간격 8 + 「라스트마일」 16px 로 약 80 = 142px 이 최소이고, 200 은 넷째 축이 길게 들어와도 안 접히는 여유다. **지어낸 것을 관측인 척하지 않는다.**
