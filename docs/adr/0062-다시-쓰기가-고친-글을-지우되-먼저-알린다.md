# ADR-0062: 초기화가 고친 글을 지우되 먼저 알린다

- 상태: 채택됨
- 날짜: 2026-08-23
- 관련: [ADR-0055](0055-사람이-고친-글을-집필-출력-위에-덮지-않는다.md) 사람이 고친 글 · [ADR-0054](0054-초안을-만드는-길을-api-에-열고-공고-회사-단위로-잠근다.md) 초안 시작 · [ADR-0028](0028-초안을-먼저-완성하고-못-채운-자리에서-묻는다.md) 질문 타이밍 · [plan/21](../plan/21-동선을-끝까지-잇는다.md) T-0161
- 대체하지 않는 것: [ADR-0055](0055-사람이-고친-글을-집필-출력-위에-덮지-않는다.md). 저 결정은 **집필기가 사람 글을 덮지 않는다**는 것이고, 여기는 사람이 스스로 「새로 써 줘」를 누른 자리다

## 맥락

화면에 **「다시 쓰기」 버튼이 오래 있었고 아무 일도 안 했다.** 그 이름과 자리도 같이 정리했다.

`POST …/draft` 가 `build_draft` 를 부르는데 `redo` 를 안 넘겼다. 기본값이 `False` 라 `_draft_row` 가 이미 있는 `Draft` 행을 찾으면 `None` 을 돌려주고 `_build_one` 이 그대로 돌아간다. 사용자는 `started: true` 를 받고 폴링이 돌다가 **예전 초안이 그대로 남는 것**을 본다. 오류도 없고 「다시 썼어요」도 없다.

버튼 옆 카피는 **「못 쓴 항목만 다시 써요. 내가 고친 글은 그대로 둬요.」** 였다. 뒷문장은 우연히 맞았고 **앞문장은 거짓이었다** — 못 쓴 항목도 안 다시 썼다.

**그리고 버리는 자리가 늦었다.** `_draft_row` 는 저장 직전이라 배분(`allotter.allot`)과 집필(`_run`)이 이미 끝난 뒤다. 항목 수십 개를 LLM 으로 다 쓰고 나서 통째로 버렸다. 화면에는 아무 흔적이 없고 `BuildReport` 에도 자리가 없어서, **돈이 나간 것을 사용자도 로그도 못 봤다.**

CLI 에는 `--redo` 가 있었다. 그것은 `DraftItem` 을 통째로 지우는데 **거기에 `edited_body` 가 같이 산다**(ADR-0055). 그 길을 그대로 화면에 열면 사람이 고친 글이 조용히 사라진다.

## 결정

**1. `redo` 를 API 에 연다. 쿼리 파라미터다.**

```
POST /api/notices/{source}/{external_id}/draft?company={id}&redo=true
```

**경로를 안 늘린다.** 쓰기 API 는 여전히 셋이고 `tests/test_draft_start.py` 가 잠근 목록이 그대로 산다.

**2. `redo` 가 아니면 LLM 을 부르기 전에 건너뛴다.**

`build_draft` 의 조립 단계(①)에서 `_drafted_documents()` 로 이미 초안이 있는 문서를 읽고 그 `_FormPlan` 을 걷어낸다. `_draft_row` 의 확인은 **경합 대비로 남긴다** — 두 프로세스가 같은 순간에 들어오는 경우가 있고, 락은 `(회사, 공고)` 단위라 그것을 못 막는다.

**3. 건너뛴 수를 보고한다.** `BuildReport.skipped` 이고 `line()` 에 나온다. 조용히 건너뛰면 「왜 안 늘었지」를 되짚을 자리가 없다.

**4. 다시 쓰기는 그 양식을 통째로 다시 쓴다. 고친 글도 사라진다.**

`_draft_row` 의 `delete(DraftItem)` 을 그대로 둔다. 고친 항목만 남기는 길을 안 고른 이유는 **새 글과 옛 글이 한 문서에 섞이기 때문**이다. 두 벌의 근거가 서로 다른 사실을 가리키게 되고, 그러면 F6-13 의 대조가 항목 단위로는 맞는데 문서 단위로는 안 맞는다. 「원본 양식 기준으로 처음부터」가 사용자가 그 버튼에서 기대하는 것이기도 하다.

**5. 버튼을 둘로 가른다. 「초기화」가 상단이고 「쓰기」가 하단이다.**

| | 자리 | 언제 뜨나 | `redo` | 무엇을 하나 |
|---|---|---|---|---|
| **초기화** | 머리줄 오른쪽 | 초안이 있을 때 | `true` | 그 공고의 초안을 통째로 지우고 원본 양식에 처음부터 다시 쓴다 |
| **초안 쓰기 · 남은 양식 쓰기** | 아래 | 안 쓴 양식이 있을 때 | `false` | **더하기만 한다.** 이미 쓴 양식은 API 가 건너뛴다 |

**한 버튼에 두 뜻을 안 싣는다.** 예전에는 같은 자리가 초안 유무에 따라 「초안 쓰기」와 「다시 쓰기」로 갈렸다 — 더하는 동작과 지우는 동작이 같은 자리에 있으면 **누르기 전에 어느 쪽인지 화면을 읽어야 한다.**

**초기화는 주 버튼이 아니다.** §4 가 채운 검정을 화면당 하나로 묶어 뒀고 그 자리는 「쓰기」가 갖는다. 지우는 동작에 액센트를 주면 그것이 권하는 말이 된다. 선 버튼(§4 «오버레이 트리거»)이다.

**다 쓴 뒤에는 하단 버튼이 사라진다.** 채울 것이 없는데 버튼을 두면 눌러도 아무 일이 안 일어나고, 그것은 고장 난 것으로 읽힌다(실측 `kstartup:178881`).

**6. 무엇이 사라지는지 먼저 말하고 누르게 한다.**

고친 항목이 하나라도 있으면 초기화가 바로 안 돌고 머리줄 아래에 확인 줄이 펼쳐진다.

```
직접 고친 항목이 3개 있어요. 초기화하면 그 글이 사라지고 원본 양식에 처음부터 다시 써요.
[그래도 초기화]  [그만두기]
```

**고친 것이 없으면 안 묻는다.** 잃을 것이 없는데 확인을 받으면 그다음의 진짜 경고까지 같이 흘려보게 된다.

**확인 줄이 머리줄 안이 아니라 아래다.** 머리줄이 「초안 · 개수 · 초기화」로 이미 셋이라(§10 한 항목에 덩어리 넷 이하) 거기서 더 늘리면 읽는 순서가 무너진다. `DraftThread` 에서는 머리줄이 스크롤 밖에 고정된 자리라는 이유가 하나 더 있다.

**말로 시켜도 같은 자리로 간다.** `DraftThread` 의 「다시 써 줘」와 「초기화」가 둘 다 그 확인을 거친다 — 버튼에만 붙이면 입력칸으로 들어온 사람의 글이 조용히 사라진다. **화면에 적힌 말을 그대로 쳤는데 못 알아들으면 그 버튼이 없는 것으로 읽히므로** `readCommand` 가 「초기화」도 받는다.

**7. 카피를 고친다.** 「못 쓴 항목만 다시 써요. 내가 고친 글은 그대로 둬요.」 → 하단은 **「아직 안 쓴 양식 N개를 채워요. 이미 쓴 것은 그대로 둬요.」** 이고, 지우는 말은 확인 줄로 옮겼다.

**8. 두 화면이 같은 조각을 쓴다.** `StartRow` · `ResetButton` · `ConfirmRow` 셋이고 스타일만 받는다. 예전에는 `DraftView` 와 `DraftThread` 가 카피를 각자 들고 있었고 **둘 다 거짓이었다.**

## 결과

- 머리줄의 「초기화」가 초안을 실제로 다시 세운다. 하단 「쓰기」는 **안 쓴 양식만** 채운다
- **같은 초안을 두 번 만들 때 LLM 을 안 부른다.** 그전에는 다 부르고 버렸다
- 사람이 고친 글은 **확인을 거쳐야** 사라진다. ADR-0055 의 `edited_body` 는 그대로 살아 있고, 집필기가 그 위를 덮는 일은 여전히 없다
- 되돌리기가 없다. 확인하고 누른 뒤에는 옛 글이 DB 에 없다 — 버전을 쌓으려면 `draft` 유니크 키(`company_id`, `notice_id`, `document_id`)를 바꿔야 하고 그것은 다른 결정이다

## 안 한 것

**초안 버전을 쌓지 않는다.** 같은 회사·공고·문서에 초안은 여전히 하나다. 쌓으려면 컬럼과 유니크 키와 화면의 버전 고르기가 같이 와야 하는데, **지금 필요한 것은 「다시 써 줘」 하나**였다.

**채운 파일을 저장하지 않는다.** 「원본 문서로 교체」가 이미 성립한다 — `filled_document` 가 요청마다 원본(`data/attachments/<sha256>`)을 열어 그때의 초안을 넣는다. 회사별 사본을 디스크에 두면 그 사본과 DB 초안 중 어느 쪽이 정본인지 정해야 하고, 그것은 위키 마크다운을 저장하지 않기로 한 자리와 같다.

**되돌리기 창을 두지 않는다.** 지운 항목을 잠깐 들고 있다가 「방금 것 되살리기」를 여는 길이 있는데, 그것은 버전 쌓기의 절반을 이름만 바꿔 만드는 일이다. 확인 줄이 그 자리를 대신한다.
