## 태스크

### T-0059 올리기 API

> **완료** (2026-08-18). `POST /api/wiki/{company_id}/files` · `wiki/service.py` `receive`/`decode` · [ADR-0034](../adr/0034-업로드를-같은-api-에-두고-못-쓰는-곳에서는-503-으로-답한다.md).

- **받는 것과 읽는 것을 나눴다.** `ingest_file` 하나였던 것을 `receive`(바이트 → `uploaded` 행)와 `decode`(해독 → 청크)로 갈랐다. **붙어 있으면 다섯 개를 올렸을 때 해독이 끝난 것부터 한 줄씩 나타나고, 그동안 화면은 나머지가 올라오긴 한 건지 말할 수 없다**
- **202 다.** 저장까지만 하고 답한다. 해독과 구축은 응답을 보낸 뒤 스레드가 한다 — OCR 이 걸린 파일 하나에 요청이 몇 분씩 묶이면 안 된다
- **한 회사에 하나만 돈다.** `ingest/jobs.py` 의 락을 그대로 쓴다. 그 모듈은 DB 도 네트워크도 모르는 단일 실행 보장 프리미티브다
- **못 읽는 포맷도 받는다**(F1-1-1). 거절하면 사용자는 그 파일이 왜 안 쓰이는지 영영 모른다. 거절은 빈 파일과 크기 초과 둘뿐이다
- **이 경로가 토큰을 부른다.** 같은 날 [ADR-0035](../adr/0035-api와-워커를-자체-서버로-내리고-vercel은-화면만-맡는다.md)가 API 를 자체 서버로 내리면서 Vercel Authentication 이 없어졌고, **대체물 없이 두면 여기가 인터넷에 열린 업로드 창구가 된다.** 로컬은 토큰이 비어 있어 지금까지처럼 돈다
- **못 쓰는 곳에서는 503 이다** — [ADR-0034](../adr/0034-업로드를-같은-api-에-두고-못-쓰는-곳에서는-503-으로-답한다.md). 판정은 환경 이름이 아니라 **실제로 써 보는 것**이다. 같은 날 [ADR-0035](../adr/0035-api와-워커를-자체-서버로-내리고-vercel은-화면만-맡는다.md)가 API 를 자체 서버로 내려서 **지금은 안 걸린다**

**만들면서 하나 고쳤다.** `openpyxl` 이 **파일 이름의 확장자를 보고 거절한다.** 우리 저장소는 콘텐츠 주소라 이름에 확장자가 없고(`data/user-files/<회사>/ab/abcd…`), `decode` 가 원본 경로 대신 저장된 파일을 읽게 되면서 재무제표가 통째로 `failed` 가 됐다. 경로가 아니라 **열어서 넘기도록** 고쳤다(`attach/hwp.py` `sheets_from_xlsx`). 첨부 쪽은 `ATTACHMENT_FORMATS` 에 xlsx 가 없어서 이 버그를 안 만났다.

### T-0060 진행 API

> **완료** (2026-08-18). `GET /api/wiki/{company_id}/progress` · `wiki/progress.py` · `tests/test_wiki_progress.py` 13건.

**상태는 이미 DB 에 있었다.** `UserFileStatus` 일곱을 `service.ingest_file` 과 `build.build_company` 가 실제로 밟고 있었고, 없던 것은 그걸 밖으로 내는 경로와 사람이 읽는 이름이었다.

- **단계 이름을 프론트가 짓지 않는다.** `topics.display()` 가 단위를 한 자리에서 붙이는 것과 같은 이유다. 화면과 API 가 각자 라벨을 들면 갈리고, 갈린 순간 어느 쪽이 진짜 상태인지 알 수 없게 된다
- **`chunked` 하나가 두 가지 뜻을 갖는다.** 막 넣었을 때는 "사실을 뽑을 차례"이고, 빌드가 끝난 뒤에도 `chunked` 면 "추출기가 몰라서 되돌려놨다"다(`build._shelve`). **행만 봐서는 구분이 안 돼서** `running` 을 같이 본다. 값은 DB 가 아니라 `jobs` 의 락에서 온다 — 컬럼을 만들면 배포 DB 에도 마이그레이션을 돌려야 하고, 이건 프로세스가 죽으면 같이 죽는 게 맞는 종류다
- **자리 라벨을 같이 준다.** `files[].nodes` 가 영문 키(`where`·`biz`)라 이게 없으면 화면이 이름을 짓는다
- **아무것도 안 올렸어도 200 이고 단계 다섯이 온다.** 처음 온 사람도 무엇이 일어날지 먼저 볼 수 있어야 한다(DESIGN.md §7-5)

### T-0061 올리기 화면 (S1)

> **완료** (2026-08-18). `web/app/(product)/wiki/files/` · `components/Upload.tsx` · `app/api/wiki/[company]/`.

- **끌어다 놓기와 골라 넣기 둘 다 된다.** 하나만 두면 키보드만 쓰는 사람이나 드래그가 어려운 사람이 이 화면을 못 쓴다
- **백분율을 안 쓴다.** 칸 다섯을 점으로 그린다. DESIGN.md §6 이 막은 것은 눈금 없는 숫자이고 여기는 눈금이 다섯으로 정해져 있다. 그래도 %로 바꾸지 않는다 — **단계마다 걸리는 시간이 달라서 60%가 시간의 60%를 뜻하지 않는다**
- ~~**단계 범례는 빈 화면에서만 나온다.**~~ 파일이 하나라도 생기면 사라지게 했는데 **틀렸다** — 점 다섯만 남아서 `●●●✕○` 를 보고 몇 번째 칸이 멈춘 것인지 세어야 했다. [T-0062](#t-0062-칸마다-무엇이-나왔나)가 칸 목록으로 되돌렸다
- **색을 두 자리에만 쓴다.** 멈춘 파일(`--urgent`)과 확인이 필요한 파일(`--blank`)이다. 진행 자체는 색으로 말하지 않는다(DESIGN.md §3-6)
- **자리 이름에 노드 분류색을 안 썼다.** 궤도에서는 색이 종류를 말하지만(`--n-identity` 등) 한 줄에 자리가 열넷까지 붙어서, 색을 얹으면 줄이 알록달록해지고 화면의 상태색 둘과 경쟁한다. **이 화면에서 색이 뜻하는 것은 "손대야 함" 하나로 뒀다**
- **브라우저가 API 주소를 모른다.** 화면은 같은 앱의 라우트 핸들러(`app/api/wiki/[company]/…`)를 치고 그쪽이 `lib/wiki.ts` 로 나간다. 서버 액션이 아닌 이유는 **본문이 기본 1MB 로 잘려서**다 — 사업계획서와 피치덱이 그걸 우습게 넘는다
- **로딩을 따로 만들었다.** `wiki/loading.tsx` 를 물려받으면 "위키를 불러오는 중이에요"라고 말하는데 이 화면에 오는 것은 위키가 아니다

### T-0062 칸마다 무엇이 나왔나

> **완료** (2026-08-18). `api/wiki_schemas.py` `FileProgressOut` +3필드 · `api/wiki_service.py` · `components/Upload.tsx` `Cell`·`yieldOf` · `tests/test_wiki_progress.py` 16건.

**점 다섯에 이름이 없었다.** 단계 이름은 빈 화면에서 한 번 나오고 사라졌고(T-0061), 그래서 `●●●✕○` 를 보고 **몇 번째 칸이 멈춘 것인지 세어야 했다.** 어디서 멈췄는지가 이 화면에서 알아야 할 거의 전부인데 그것이 점의 개수로만 있었다.

```
┌───────────────────────────────────────────────────────────
│ 「민관협력…」_공공기관_제안_협업_과제_모집공고.hwpx        hwpx
│ ●●●■·  사실을 못 뽑았어요                     [ 단계 숨기기 ]
│ ──────────────────────────────────────
│  ●  1  파일 받기                        294KB
│  ●  2  글자 읽기                  글자 4,812자
│  ●  3  조각 내기                      조각 8개
│  ■  4  사실 뽑기                      사실 0개    ← 여기서 멈췄다
│  ·  5  자리에 놓기
└───────────────────────────────────────────────────────────

┌───────────────────────────────────────────────────────────
│ 사업자등록증_스캔.pdf                                  pdf
│ ●●●●●  다 됐어요                              [ 단계 보기 ]
│ (우리가 하는 일)(사업자 정보)(소재지)(업종)(대표자)
└───────────────────────────────────────────────────────────

펼치면 ↓  1쪽 · 글자 281자 · 사진에서 읽었어요 · 조각 1개 · 사실 7개 · 자리 5곳
```

- **접혀 있고 손대야 하는 파일만 저절로 열린다.** 도는 중 · 멈춤 · 검토 필요 셋이다. 파일 일곱이면 칸이 서른다섯이라 전부 펼쳐 두면 보드를 못 읽고, **다 된 파일에는 볼 일이 없다.** 한 번 누르면 그 뜻이 규칙을 이긴다 — `null`(안 눌렀다)과 `false`(접었다)를 갈라 둬야 도는 파일이 저절로 열린다
- **끝났거나 멈춘 칸만 숫자를 갖는다.** 도는 칸의 `0` 은 "세어 봤더니 없다"가 아니라 "아직 안 셌다"인데 화면에서는 둘이 같아 보인다. 실제로 `chunk_count` 는 실패한 파일에도 `0` 이 적혀 있다
- **칸마다 세는 단위가 바뀐다.** 파일 하나 → 쪽 → 조각 → 사실 → 자리. 이 파이프라인이 실제로 하는 일이 그것이고, 진행률 하나로 뭉치면 그게 사라진다(아래 `안 만든 것`의 세 번째와 같은 이유)
- **멈춘 점을 네모로 바꿨다.** 색만 다르면 색을 못 보는 사람에게 끝난 칸과 같아 보인다. 점 다섯과 칸 목록이 **같은 함수(`cellState`)를 쓴다** — 둘이 다른 말을 하면 어느 쪽이 참인지 알 수 없다
- **크기와 조각 수를 줄 머리에서 뺐다.** 칸 안에서 한 번씩 말한다 — 같은 수를 두 곳에 적으면 어느 쪽이 그 칸의 결과인지 흐려진다
- **파서 이름을 안 보여 준다.** `pdf/plumber` 는 우리 사정이고 사용자가 조작하는 대상이 아니다(DESIGN.md §8.3-1). 화면이 보는 것은 `ocr/` 접두사 하나이고, 사진에서 읽은 글자는 굵은 제목이 깨져서([ADR-0030](../adr/0030-OCR은-rapidocr-로컬로-하고-검출은-server-를-쓴다.md)) 위키 값이 이상할 때 사용자가 이유를 알아야 한다. **접두사가 바뀌면 화면이 조용히 그 말을 안 해서** 테스트가 막아 둔다
- **사실 수는 컬럼이 아니라 근거에서 온다.** `wiki_evidence` 가 파일과 사실을 잇는 유일한 자리다. **다 더해도 위키의 사실 수가 아니다** — 병합된 사실은 근거가 여럿이라 두 파일에서 각각 세어진다
- **칸 목록 너비를 52ch 로 잡았다.** 카드 너비를 다 쓰면 이름과 숫자 사이가 700px 벌어져서 어느 이름의 숫자인지 눈으로 이어야 한다(DESIGN.md §8.2 줄길이)

### T-0095 관계없는 문서가 「다 됐어요」로 끝난다 (완료 · 2026-08-22)

**실제 추출기를 켜자 위 T-0062 의 화면이 뜻을 잃는 경우가 생겼다.**

저 목업은 사실 0개를 `■`(멈춤)으로 그렸다. 스텁이 모르는 파일을 `chunked` 로 되돌렸기
때문이다(`build._shelve`). 2026-08-21 `WIKI_EXTRACTOR=llm` 을 켜고 **예비군 훈련 안내문**을
넣어 보니 이렇게 됐다.

```
23년_예비군_훈련_안내문_2.hwp   status done · 사실 0 · 채운 자리 없음
  ●●●●●  다 됐어요
```

화면이 「다 됐어요」라고만 하고 **무엇도 채우지 않았다는 말을 안 한다.** 사용자는
둘을 못 가른다.

- 이 문서에는 회사 얘기가 없다
- 추출기가 놓쳤다

**처음에 여기 「추출기가 옳게 답했다」고 적었다. 그 문장을 지운다** — 2026-08-22 같은
파일을 다시 넣으니 **사실 24건**이 나왔다([실측](../adr/evidence/2026-08-22-관계없는-문서를-삼킨다/README.md)).
그날 0건이었던 것은 판단이 아니라 운이다. 그쪽은 [plan/12](12-사업-위키-구축.md) T-0077 이다.

**그래도 이 태스크는 성립한다.** 파일이 진짜로 아무것도 안 낼 수 있고(사진 한 장, 빈
양식) 그때 화면이 할 말이 있어야 한다. **바뀌는 것은 이 화면이 T-0077 의 대체물이
아니라는 것뿐이다** — 「사업 정보를 못 찾았어요」가 「관계없는 문서였어요」를 뜻하지 않는다.

`progress.EMPTY_LABEL` 로 갈랐다. 판정은 **자리 수**로 한다(`nodes` 가 비었나) — 사실
수가 아니다. 사실은 파일 사이에 겹치지만 자리는 "이 파일이 위키에 무엇을 보탰나" 다.

**`ok` 는 `True` 로 둔다.** 파이프라인은 성공했다 — 실패로 칠하면 T-0093 이 남기는 진짜
실패와 섞인다. `failed`·`needs_review` 에는 이 말을 안 쓴다(글자를 못 얻은 것이라 원인을
숨기게 된다). 테스트가 둘 다 막아 둔다.

**T-0093([plan/12](12-사업-위키-구축.md))과 다른 문제다.** 저기는 «실패한 이유를 잃는
것»이고 여기는 «성공했는데 결과가 빈 것»이다. 화면에서는 둘이 같아 보였다.

### `.md` · `.txt` 를 안 받는다 — 아직 결정이 아니다

`user_file_formats` 가 `hwp,hwpx,docx,docm,pdf,xlsx,pptx,jpg,png` 다. 2026-08-21 사용자가
올린 `.md` 둘이 `failed/unsupported` 로 남았다.

**목록에 넣는 것은 설정 한 줄이지만 청킹을 그 포맷으로 한 번도 재 본 적이 없다.**
마크다운은 `#` 과 목록이 구조라 지금 규칙이 어떻게 쪼개는지 모른다. 태스크로 만들지
않는다 — 재기 전에 켜면 첨부 목록에 xlsx 를 더하는 것과 같은 실수가 된다(CLAUDE.md).

## 안 만든 것과 이유

**파일 지우기와 다시 읽기.** 지금은 실패한 파일을 고칠 길이 없다 — 같은 파일을 다시 올려도 `duplicate` 로 튕긴다(`service.receive`). CLI 에 `--purge`(전부) 와 `--rebuild`(사실만) 가 있지만 화면에는 없다. **한 파일만 지우는 것은 근거가 걸린 사실을 같이 지우는 일이라** 무엇을 지울지 규칙을 먼저 정해야 한다 — F1-4-7 "어느 파일을 지우면 무엇이 사라지나"가 그 자리이고 [14](14-사업-위키-화면.md)의 `원본 파일` 탭이 이미 답을 보여 주고 있다. 규칙이 정해지면 그때 붙인다.

**올리는 중 취소.** 응답이 0.1초에 나가서 취소할 구간이 사실상 없다. 취소해야 하는 것은 그 뒤의 해독인데, 그건 스레드라 중간에 끊으면 반쯤 쓴 청크가 남는다.

**진행률 하나로 뭉치기.** F1-1-8 이 파일별 독립을 요구하고 실제로 다섯 중 하나가 실패해도 넷으로 위키가 선다. 막대 하나로 뭉치면 그 사실이 사라진다.

**사실을 못 뽑은 구체적 이유.** 4번 칸은 "여기서 멈췄다"까지만 말한다. `build._shelve` 가 이유(`UnknownFile: …`)를 `BuildReport` 에만 담고 **DB 에 남기지 않아서** 조회 경로가 그걸 볼 수 없다. 컬럼 하나면 되지만 **배포 DB 마이그레이션이 붙는다**(CLAUDE.md 함정). 지금은 보드 아래 각주가 "시험용 추출기라 준비된 예시 파일에서만 돌아요"로 대신 말한다 — 추출기가 진짜가 되는 날 이 각주가 사라지고 그때 이유가 필요해진다.

**칸별 시각과 소요 시간.** `uploaded_at` 과 `parsed_at` 둘뿐이다. 조각·사실·자리의 시각을 말하려면 컬럼을 세 개 만들어야 하고 같은 마이그레이션 문제가 붙는다. **단계마다 걸리는 시간이 달라서** 백분율을 안 쓰기로 한 것과 같은 자리다.

**큐와 워커.** [ADR-0021](../adr/0021-인프라-선정을-미룬다.md) F 가 그대로 남는다. 스레드 하나로 버티는 것은 사용자가 한 명이고 파일이 열 개 안쪽이기 때문이다. 프로세스가 죽으면 `uploaded` 로 남는데, 다음 올리기가 그 행을 이어받게 해 뒀다(`_stranded`). **그것으로 안 되는 날이 큐를 고르는 날이다.**
