## 태스크

### T-0110 트리를 API 로 낸다

`export.py` 가 CLI 말고 API 도 먹인다.

- `FOLDERS` — 기획 폴더 열의 한국어 이름. **자리 제목과 겹치면 안 된다**(`# 경쟁 상대` 밑의 `## 경쟁사`). `TOPIC_LABELS` 가 orbit 라벨과 안 겹치게 고른 것과 같은 규율이고, 테스트가 겹침 0을 막는다
- `Spot.folder` — 경로의 첫 마디
- `WikiSpotOut` · `WikiOut.spots` · `WikiOut.folders`. **`nodes` 와 `sectors` 는 뺀다** — 두 어휘를 같이 들고 가지 않는다
- `api-contract.md` 를 같은 커밋에 고친다

### T-0111 파일 머리를 기획 §5 로

`grade` · `source` · `source_path` · `base_date` · `updated_at`.

- 뒤 넷은 우리가 이미 들고 있다. `Evidence` 에 `sha256` 을, `Value`·`Statement` 에 `source_type`·`updated_at` 을 더해 `build.read_orbit` 이 채운다
- **`grade` 는 셋만 낸다** — `실측`(전부 `user_stated`) · `1차`(문서에서 나왔다) · `미정`(비었다). `2차`·`가정` 은 **추출기가 출처를 판정하지 않아서 못 낸다**([ADR-0052](../adr/0052-위키-자리를-기획-트리로-바꾸고-구획을-폴더로-세운다.md) 결정 4). 없는 판정을 그럴듯한 등급으로 채우지 않는다
- **시각을 넣되 만든 시각은 안 넣는다.** `updated_at` 은 `wiki_fact` 값이라 같은 DB 면 같다 — 바이트 비교가 안 깨진다

### T-0112 방사형을 다시 그린다

**`Orbit.tsx` 를 지우지 않는다.** 자리가 15 → 47 이 되고 구획이 폴더 열이 된다.

- 구획 크기가 **자리 수에 비례한다** — `Plan/` 7 이 `Competitor/` 2 보다 넓다
- 링 하나. **안팎 궤도를 버린다** — 링을 가르던 `kind` 가 트리 자리에 안 맞는다(`Financial/매출.md` 가 value·event 를 같이 받는다)
- 중심은 회사와 「찬 자리/전체」. 살은 **폴더마다 하나씩 열 개** — 47개를 그리면 별 모양이 된다
- **점마다 이름을 안 붙인다**(ADR-0052 포기 ③). 47 라벨이 원 밖에 안 들어간다 — 글자로 서는 것은 폴더 이름뿐이고 자리 이름은 고르거나 올렸을 때 뜬다
- 상태 셋을 **색 없이** 가른다 — 채운 점 · 점선 빈 점 · 더 작은 흐린 점(채울 topic 이 없다)
- **노드 분류색을 안 쓴다**(ADR-0052 포기 ④). 폴더 구획이 이미 묶어 준다. `DESIGN.md` §2·§8 이 같이 바뀐다
- `WikiPanel.tsx` — 머리의 `sectorLabel` 이 폴더 라벨 + 경로로 바뀐다

### T-0113 파일이 채운 자리를 트리 경로로

`build.read_files` 가 궤도 키 대신 자리 경로를 돌려준다. **S1 진행 화면(`ProgressOut.places`)도 같이 간다** — 두 화면이 다른 이름으로 같은 자리를 부르면 사용자가 그것을 다른 자리로 읽는다.

### T-0114 마크다운 전체를 트리로

`get_markdown` 이 `export.bundle()` 을 쓴다. 자리 47장이 순서대로 붙는다.

### T-0115 CLI 를 트리로

`--wiki` 출력이 폴더 열과 자리 47로 바뀐다. `--export` 는 그대로다 — **같은 `TREE` 를 읽으므로 둘이 갈릴 수 없다.**

### T-0116 빈 자리 21을 채운다 — **다음 회차**

topic 23 으로는 자리 46 중 25 밖에 못 채운다. 기획 문서 §6 마지막 줄이 이미 적어 뒀다 — 「topic 온톨로지도 신설 폴더에 맞춰 늘려야 한다. 지금 23개인데 `Plan/` 일곱 개와 `Competitor/` 두 개가 빠져 있다」.

**이번에 안 한다.** topic 을 늘리면 추출 프롬프트가 바뀌고, 프롬프트가 바뀌면 [정확도를 다시 재야 한다](../adr/evidence/2026-08-22-어휘-교체-전후-추출-정확도.md). 그 실측이 지금 n=2 로 회차 간 변동(1.7%p) 안이라 **여기에 프롬프트 변경을 하나 더 얹으면 무엇이 움직였는지 못 가른다.**

빈 21 자리의 내역은 [대조표](../adr/evidence/2026-08-21-위키-자리-구조/04-기획-트리-대조표.md)에 있다.
