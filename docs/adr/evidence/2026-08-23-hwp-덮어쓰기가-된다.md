# hwp 덮어쓰기가 된다 — 실측 (2026-08-23)

[ADR-0060](../0060-양식을-채워서-원본-포맷으로-돌려준다.md) 결정 3 이 「hwp 는 빈 칸만
채운다. 덮어쓰기를 금지한다」로 못 박아 둔 자리다. **그 결정을 정한 바로 그 파일에서
덮어쓰기가 통했다.**

```
sha256  e679598ef461124b9024e6245e3d18756f2e6df8c3a0724f9b90e51425676481
        bizinfo:PBLN_000000000125460 · 서울창업허브M+ 신청서 · 셀 65개
```

`spike/hwp_overwrite_retry.py` 가 판본 I 로 제안해 두고 **육안 확인에서 멈춰 있던**
경로다. 그 확인을 했고 한/글에서 정상이었다.

## 무엇이 문제였나

ADR-0060 이 판본 일곱 개로 경계를 갈랐고 결론이 이랬다.

> **F 가 답을 줬다.** 값이 완전히 같은데도 밀렸으니 값도, 길이도, 캐시도 원인이
> 아니다. **hwplib 으로 기존 글자를 갈아 끼우는 것 자체가 배치를 깨뜨린다.**

이 문장이 한 칸 넓었다. **판본 A~G 가 전부 `ParaText` 객체를 살려 둔 채 안에 든
문자 리스트만 갈아 끼웠다.**

```python
# 판본 C~G — 열리기는 하나 표가 다음 쪽으로 밀린다
cl = tx.getCharList()
keep = [제어 문자와 개체 앵커]          # 이것들은 지키면서
cl.clear()                             # 일반 글자만 비우고
for ch in value:
    tx.addNewNormalChar().setCode(ord(ch))
for c in keep:
    cl.add(c)
```

## 무엇이 달랐나

`ParaText` **객체 자체를 없앴다가 새로 만든다.**

```python
def _reset(para, value: str) -> None:
    cs = para.getCharShape()
    first = int(cs.getPositonShapeIdPairList().get(0).getShapeId()) if cs else 0

    para.deleteText()                       # ParaText 를 통째로 없앤다
    para.createText()                       # 새로 만든다 — 이 순간 빈 칸과 같은 상태다
    para.getText().addString(value or " ")  # 165칸에서 검증된 그 경로(판본 D)

    para.deleteCharShape()                  # 위치 쌍을 하나로 되돌린다
    para.createCharShape()
    para.getCharShape().addParaCharShape(0, first)
    para.deleteLineSeg()                    # 줄 나눔 캐시는 옛 글자 기준이다

    h = para.getHeader()
    h.setCharacterCount(para.getText().getCharSize())
    h.setCharShapeCount(para.getCharShape().getPositonShapeIdPairList().size())
    h.setLineAlignCount(0)
```

**가설은 이렇다.** 빈 칸이 통했던 이유가 「글자가 없어서」가 아니라 **「`ParaText` 가
아예 없어서」**다. `deleteText()` 가 그 상태를 만들어 주므로, 덮어쓰기가 「지우고 →
빈 칸에 쓰기」로 바뀐다. 판본 D 가 이미 165칸에서 검증한 경로를 그대로 타는 것이다.

딸린 처리 셋이 있고 어느 것이 필수인지는 아직 안 갈랐다.

| 무엇 | 왜 |
|---|---|
| `CharShape` 위치 쌍 리셋 | 글자 수가 달라져 옛 쌍이 문자열 밖을 가리킬 수 있다 |
| `LineSeg` 삭제 | 줄 나눔 캐시가 옛 글자 기준이라 남기면 한/글이 그대로 그린다 |
| 헤더 카운트 갱신 | 글자 수와 글자모양 수를 다시 센다 |

**개체 앵커가 든 문단은 건너뛴다.** 판본 B 가 안 열린 첫 원인이 거기였다 — 비어
보이는 칸에 그림이 매달려 있었고, 지우니 컨트롤은 남고 닻이 없어졌다. 판정은
`HWPCharControlExtend` 와 `HWPCharControlInline` 을 찾는 것으로 한다.
`HWPCharControlChar` 는 문단 끝 문자라 **앵커가 아니다** — 이것까지 피하면 손댈 수
있는 문단이 거의 없어진다.

## 딸려 나온 것 넷

### 1. 글자 0개짜리 `ParaText` 를 만들면 저장이 죽는다

```
java.lang.IndexOutOfBoundsException: Index 0 out of bounds for length 0
    at kr.dogfoot.hwplib.writer.HWPWriter.toFile
```

가이드 문구가 여러 줄인 칸에서 아랫줄을 **비우려다** 걸렸다. `createText()` 만 하고
`addString()` 을 안 하면 글자 0개인 `ParaText` 가 생기는데, **원본의 빈 문단은 그런
상태가 아니다** — `ParaText` 가 아예 없다. 그런데 `CharShape` 에는 위치 0 을 가리키는
쌍이 하나 들어 있어서 저장할 때 어긋난다.

**지우는 자리에는 공백 한 칸(`" "`)을 넣는다.** 화면에서는 빈 줄로 보이고 문단 수가
그대로라 레이아웃도 같다.

### 2. 셀 하나가 문단 여럿이다

관공서 양식은 가이드 문구를 여러 줄로 적는다. **첫 문단만 갈면 안내가 아래에 남는다.**

```
표6[2,0] 문단 5
  p0  '* 1) 제안하시는 협업 모델과 구체적인 협업 방식(시나리오)을 작성해 주세요.'
  p1  '* 2) 구체적인 협업 산출물은 무엇인가요.'
  p2  '     프로젝트 종료 후 도출되는 최종 결과물의 정량·정성적 성과를 …'
  p3  '* 3) 협업 프로젝트의 추진 로드맵(약 6개월)을 …'
  p4  '     (단, 6개월 이상의 장시간이 필요할 경우, …)'
```

**한 칸에서 여러 가지를 묻는 자리다.** 한 문단에 답을 몰아넣으면 어느 질문에 답한
것인지 읽는 사람이 갈라야 한다. 문단 수에 맞춰 나눠 넣으면 원래 리듬이 유지된다.

### 3. 체크박스는 개체가 아니라 글자다

`□` 와 `☑` 가 그냥 문자라서 **문자열 치환으로 표시된다.**

```
'□ 스마트 기술'  →  '☑ 스마트 기술'
'□ 없음'        →  '☑ 없음'
```

**셀 전체를 덮어쓰면 안 된다** — 라벨이 같은 문단에 있어서 같이 지워진다. 문단 안
부분 치환(`old.replace(find, repl)`)을 하고 그 결과로 문단을 다시 써야 한다.

### 4. 좌표를 어떻게 잡나

라벨 대조(`label_targets`)가 안 통하는 양식이 있다. ADR-0060 결정 6 이 적은
「안내문이 붙으면 정규식으로 안 갈린다」가 그것이고, 실측 양식 둘 다 그랬다.
**눈으로 확인한 양식이라면 좌표를 직접 드는 것이 빠르다.**

```python
def cell_at(f, ti, ri, ci):
    for i, t in enumerate(tables(f)):   # 구역 → 문단 → ControlTable 순
        if i != ti:
            continue
        rows = t.getRowList()
        cells = rows.get(ri).getCellList()
        return cells.get(ci) if ci < cells.size() else None
```

표 번호는 **구역 안에서 이어지고** 순회 순서가 좌표를 정한다(`forms/base.py` 의
`Anchor` 와 같은 규약이다). 빈 칸 판정은 `getParagraph(0).getText() is None` 이다.

## 무엇을 쟀나

| 양식 | 셀 | 채운 자리 | 구조 대조 | 한/글 |
|---|---:|---:|---|---|
| 서울창업허브M+ 신청서 (`e679598e…`) | 65 | 30 | 통과 | **정상** |
| 현대모비스 CSV 오픈 이노베이션 신청서 | 105 | 38 | 통과 | 안 봤다 |

구조 대조는 문단·표·셀 수와 서식 넷(글자모양·문단모양·스타일·테두리)이 원본과
같은지를 본다. **밀림은 여기서 안 잡힌다** — 판본 C~G 도 구조는 멀쩡했다.

확인된 범위는 이렇다.

- **값이 길어지는 칸**도 됐다(기타실적 17자 → 39자, 협업 제안은 한 문단 200자 넘음)
- **문단 일곱 개짜리 셀의 가운데 문단만** 갈아 끼우는 것도 됐다(서명란)
- **표 105개짜리 문서**에서 38자리를 한 번에 갈아도 됐다

## 아직 모르는 것

- **육안이 1건이다.** ADR-0060 은 양식 20건과 판본 7개로 정해졌다. 뒤집으려면 같은
  규모로 재고 여러 건을 한/글로 열어 봐야 한다
- **딸린 처리 셋 중 무엇이 필수인지 안 갈랐다.** `spike/hwp_overwrite_retry.py` 의
  판본 J·K·L 이 하나씩 뺀 것이고 아직 안 돌렸다
- **개체 앵커가 든 문단은 여전히 미지수다.** 건너뛰었을 뿐 시도하지 않았다
- **미리보기 이미지는 그대로 잃는다**(ADR-0060 결정 4). 서울창업허브M+ 는 `PrvImage`
  45,859바이트가 빠져 67,584 → 17,920 바이트가 됐다. 본문 손실은 아니다
