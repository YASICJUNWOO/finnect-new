# design/voice.md — 화면에 쓰는 말

Polaris 방식을 따른다. **사용자 행동 중심으로 쓴다.**

---

## 1. 표현 대조

| 상황 | 쓰지 않는 표현 | 쓰는 표현 |
|------|----------------|-----------|
| 목록 요약 | 7건을 찾았습니다 | 신청할 수 있는 공고 7건 |
| 마감 | 마감이 임박했습니다 | 마감 7일 이내 1건 |
| 분석 결과 | 분석이 완료되었습니다 | 분석했습니다 |
| 초안 생성 | 완성했습니다 | 초안을 만들었습니다. 확인하고 고쳐 쓰세요 |
| 신청 상태 | 신청했습니다 | 실제로 제출한 뒤 직접 표시하세요 |
| 최종 고지 | (없음) | 최종 자격 확인과 제출 판단은 사용자 책임입니다 |
| 대행 경계 | 대신 작성해 드립니다 | 초안 작성을 돕습니다 |

---

## 2. 규칙 넷

1. **초안을 완성본으로 부르지 않는다.** 최종 확인과 제출은 사용자 몫이다.
2. **공고 내용을 임의로 요약해 단정하지 않는다.** 원문이 말하지 않은 것을 말하지 않는다.
3. **버튼은 무엇이 일어나는지를 쓴다.** "확인", "완료" 대신 "준비 시작", "이어서 쓰기".
4. **확정 어투를 쓰지 않는다.** "받을 수 있습니다"가 아니라 "신청할 수 있습니다".

---

## 3. 숫자를 말하는 방식

사용자에게 의미 없는 숫자는 빼거나 바꾼다.

| 안 씀 | 씀 | 왜 |
|-------|-----|-----|
| 42건 중 7건 | 신청할 수 있는 공고 7건 | 42는 사용자에게 의미가 없다 |
| 정확도 95% | (화면에 안 씀) | 판별 정확도는 화면의 언어가 아니다 |
| 신뢰도 0.87 | (화면에 안 씀) | 내부 값이다 |

---

## 4. 배점을 말할 때

**공고가 배점을 주지 않으면 배점을 말하지 않는다.** 추정하거나 일반적인 값으로 채우지 않는다.

| 공고가 배점을 | 쓰는 표현 |
|---------------|-----------|
| 준다 | 문제인식 30점 항목에 씁니다 |
| 안 준다 | 문제인식 항목에 씁니다 |

실측 결과 주요 공고가 배점을 공개하지 않는다. 자세한 것은 [ADR-0010](../adr/0010-배점-전제-폐기.md).
